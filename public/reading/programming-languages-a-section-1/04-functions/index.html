同一种计算要反复做，怎样只写一次规则

上一篇分别算了两次页数合计：先用 12 和 18 得到 30，后来用 20 和 18 得到 38。每次写一条加法当然能完成，但如果以后还要换很多组页数呢？

我们希望把“两个数相加”保存成一条可重复使用的规则。每次明确交给它两个输入，它就为这次输入算一个结果。函数就是这里需要的东西：定义计算规则，调用时再提供具体输入。

下面的 sum_two_days 表示“计算两天的页数合计”。先看完整代码和两次结果，再拆开写法：

original_total 得到 30，revised_total 得到 38。我们没有在两个地方各写一次加法，而是两次使用同一个函数。

第一行的 fun 表示要建立函数绑定，sum_two_days 是函数名。括号中的 first、second 是这条规则给输入起的名字，叫作参数；: int 说明相应输入必须是整数。等号后面的 first + second 是函数体，也就是实际描述计算的表达式。

调用 sum_two_days (12,18) 时，12 交给这次的 first，18 交给这次的 second，函数体便得到 12 + 18 = 30。下一次调用重新接收 20 和 18，再算出 38。这里没有让两个不同调用共用一对不停被修改的参数。

“定义函数”与“执行一次函数”，要分开看

这表示函数已经准备好，可以调用了。fn 告诉我们得到的是一个函数值；它没有说“刚才已经替某一天算好了合计”。定义时还没有这次输入的 12 和 18，因此不会立即执行一次 first + second。

类型 int * int -> int 可以从箭头两边读：左边表示一起交入的一对整数，右边表示结果是整数。这里类型中的 * 表示组合，不是把两个类型相乘。下一篇会正式解释这对输入的数据结构——二元组。

原课此时先用“两个参数”的说法讲解。我们可以沿用这个说法理解输入的两个位置，同时记住逗号和括号把它们组织成一份整体，不能随意把调用改成别的结构。

一次调用，先算输入，再进入函数体

传入的也可以不是现成数字，而是一段能算出数字的表达式：

这次先把输入表达式 12 + 8 算成 20，再把 20 和 18 交给函数体。所以结果为 38。函数体里的 first 已经对应 20，并不会每次使用它时都重新执行 12 + 8。

把整个调用过程写清楚，可以分成三步：

  1. 找到 sum_two_days 对应的函数。
  2. 把实际交入的表达式求成值，这里得到 20 和 18。
  3. 给本次参数建立对应关系，在这次调用中执行 first + second，得到 38。

这种先把输入表达式算完、再进入函数体的方式叫急切求值。即使某个函数体最终没有用到其中一个参数，相应的输入表达式也需要先完成求值。后面讨论短路布尔运算时，还会用这个规则作对照。

当重复次数也由输入决定：原课的 pow

前面的加法每次只做一步。原课进一步用幂运算提出一个新问题：如果想算 2 的 3 次方，需要做三次相乘；算 2 的 5 次方，则需要五次。重复多少次由输入决定，不能把乘法次数永远写死。

幂运算有一个现成的关系：指数为零时结果为 1；正指数时，先求小一阶的幂，再多乘一次底数。例如 2³ = 2 × 2²。把这个关系直接写进函数：

x 表示底数，y 表示指数。这个版本的使用前提是 y >= 0。函数体中出现了对 pow 自己的调用，这叫递归：用同一个函数先解决一个更小的问题，再据此完成当前问题。

先不把递归当成特殊技巧，跟着 pow (2,3) 算一遍：

每一次递归的指数都小 1，最终到达 y = 0。这一层直接给出 1，外面等待的乘法才能逐层完成。我们需要的不是“函数调用自己”这句口号，而是这两个条件：问题在变小，而且存在不再递归的终点。

如果输入负指数，y-1 会继续远离零，这份代码便不能按上述方式正常结束并给出预期答案。int 只说明输入是整数，没有替我们保证它非负；普通整数的范围在一些实现中也有限制，大结果还可能溢出。

cube：已有规则可以继续组成新的规则

如果经常计算立方，也就是三次方，就不必每次都把第二个输入写成 3。原课又定义了：

cube 4 先把 4 作为本次的 x，再由函数体调用 pow (4,3)，最终得到 64。这里 cube 没有重新写一套乘法或递归，而是使用先前已经定义好的 pow。

一个输入的简单调用可以写 cube 4，也可以写 cube(4)。pow 的输入结构不同，需要一对整数，例如 pow (2,3)；不要把省略单个输入外层括号的经验，扩展成所有调用都可以随意拆开。

参数的名字，只服务这次函数体

定义 sum_two_days 不会让文件顶层突然出现一个可直接使用的 first。这些参数名只在相应函数体内发挥作用：它们告诉函数，这次输入的各个值在计算里怎样使用。

同理，pow 与 cube 都用了名字 x，但它们不是在抢同一个全局变量。调用 cube 4 时，cube 这次的 x 对应 4；它调用 pow (4,3) 后，pow 又有自己这次的参数绑定。每个调用可以按照自己的输入独立理解。

这与上一篇的规则是一致的：同样的名字出现在不同范围或不同调用里，不等于它们都在修改同一个位置。

返回类型通常不用我们单独写。以 pow 为例，y = 0 是布尔条件，then 给整数 1，else 做整数乘法，因此整个函数体的结果为整数。ML 从函数体建立这些类型约束，得到 int * int -> int。

这叫类型推断：根据代码中的约束推导类型，不是先用某个输入运行一次再猜类型。原课后面会展开推断过程；这里先分清“定义时检查类型”与“调用时计算结果”。

函数还会使用定义它时已经知道的名字

参数不是函数体唯一可以用的名字。第二篇的窗口会记住已经建立的绑定，函数定义也有自己的可见环境。补充一个阅读计划例子，把它和上一篇的遮蔽接起来：

for_days 定义时，外面的 daily_pages 对应 12。它的函数体把这个定义处的绑定用于计算。后来出现一个同名的新绑定 daily_pages = 20，不会把前一个绑定改写，所以 planned 为 12 * 5 = 60，而不是 100。

调用时，参数 days 接收这次明确交入的 5；其他名字则按照函数定义时的环境解释。后续课程会深入闭包，这里先把这个具体规则记清：调用给函数带来这次的输入，不会随意替换它定义时看到的其他绑定。

如果希望每天页数也随调用变化，就把它也设计成输入。这样函数接收什么、这次用什么值，都能从调用处看见，而不必期待同名绑定自动改变过去的规则。

看过这些例子后，再读一般形式：

它不是新增的一段待运行程序，而是描述写法的模板：f 代表函数名，xi 代表各个参数名，ti 代表相应类型，e 代表函数体。

检查 e 时，可以使用先前已有的名字、参数名字，以及函数自身的名字 f；最后一项让 pow 的递归合法。定义完成后，后续环境得到的是函数绑定，参数并不会因此变成顶层名字。调用时则先求出函数和输入的值，再在定义环境上为这次参数建立绑定，计算函数体。

声明的顺序仍然有意义。cube 使用 pow，所以这个普通例子中先定义 pow，再定义 cube；不能随意用后面才出现的普通定义。函数自身递归是规则允许的情况，多个函数相互递归则有后续专门学习的写法。
