函数把一次计算，变成可以反复使用的规则

前面每条 val 都在当时算出一个结果。如果我们想对不同输入执行同一种计算，就需要函数。函数接收输入，用函数体计算，最后得到一个结果；在这节 ML 代码里，不需要先把它放进类，也不需要 this 或 return。

本课初期把这里称作“两个参数”，便于描述；更准确地看，ML 的 int * int 是一对整数的元组类型。这一层结构在下一篇讲元组时再展开，不妨先准确使用 f(x,y) 这样的写法。

pow(x,y) 表示这份程序计算的 x 的 y 次方，前提是 y >= 0。它先看指数：如果为零，就直接得到 1；否则，把问题缩成指数小一的 pow(x,y-1)，再乘上一次 x。

cube 使用先前定义的 pow，把指数固定为三。因此 cube(4) 得到 64。一个参数的调用可以省略外围括号，写 cube 4；但不要凭这个经验把 pow(2,3) 的元组结构随意拆掉。

fn 在这里表示结果是一个函数，不是报错，也不要求你把函数体再抄一遍。int * int -> int 表示输入是一对整数、结果为整数；int -> int 表示输入和结果都是整数。类型里的 * 不是乘法，它用于组合输入类型；表达式中的 x * y 才是乘法。

定义函数时，动态环境记住这个可调用的函数，不会立刻把函数体拿来计算一次。cube 的参数 x 还没有具体数值，函数体当然也还没有为某次调用产生结果。等到 cube(4) 出现，才会给这次调用建立 x → 4 并计算函数体。

不过，“没有运行函数体”不等于“不检查函数体”。函数定义时，类型检查器就要确认函数体中的各个表达式能够符合类型规则。下面即使从不调用，也有类型错误：

课程给函数绑定的一般写法是：

检查函数体 e 时，它能使用三类名字：先前环境里已有的名字、这次函数的参数名字，以及函数自己 f。最后一项让递归调用成为可能。例如检查 pow 的函数体时，知道 x : int、y : int，也允许 pow 按相应的函数类型被调用。

参数名字只在函数体中使用，不会因为定义了函数，就在顶层多出一个可以直接读取的 x。函数定义成功后，加入后续环境的是函数名及其类型；参数并没有获得一个全局值。

返回类型没有被我们写出来，但 ML 能根据函数体推断。以 pow 为例，y = 0 是布尔判断；then 分支是整数 1；else 分支要进行整数乘法，递归调用的结果也要与之相容。整个条件表达式得到 int，因此返回类型为 int。

这叫类型推断，不是“运行一次以后再看看返回了什么”。关于推断算法的细节，课程后面还会专门讲；现在先理解它建立的是运行前的类型约束。

调用一个函数，按三个步骤走

看这个带表达式实参的调用：

第一步，求函数位置的表达式 pow，从动态环境中找到可调用的函数。第二步，先求所有实参的值：2 已经是值，2 + 2 则要先算成 4。第三步，用这些值建立本次调用的参数绑定，再计算函数体。因此这次函数体看到的是 x → 2、y → 4，并不知道这个 4 原先来自加法。

这种“先把实参算完，再进入函数体”的方式，称作急切求值。先抓住这一点：即使函数体最终不用某个参数，相应的实参表达式也需要先完成求值。

调用本身也要检查类型。函数位置得有函数类型；实参结构和各部分的类型必须匹配；满足后，整个调用表达式的类型就是函数的结果类型。pow(2,true) 不会因为函数体“也许碰不到 y”而放行，因为第二个位置要求 int。
