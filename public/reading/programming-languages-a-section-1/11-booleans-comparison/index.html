尾部没有答案时，为什么没有读出错

上一篇已经让 max_option 明确返回两种结果：空列表得到 NONE，非空列表得到 SOME 最大值。现在继续看它处理一条阅读记录 [12] 的过程：当前头部是 12，剩下的尾部却是空列表。

函数先向尾部询问最大值，因此 tailAnswer 得到 NONE。接下来要判断“尾部有答案，而且尾部答案比当前的 12 更大”，才能决定是否沿用它。这里真正的问题是：还没有答案时，怎样避免去读取那个不存在的整数？

下面摘出上一篇函数中这一步判断。pages 是正在处理的非空记录，max_option 仍是上一篇已经定义好的函数；这几行只是把同一次递归中的中间结果单独摆出来：

isSome tailAnswer 先得到 false。到了这里，andalso 已经知道两个条件不可能同时成立，于是直接得到 false，不再执行右边的 valOf tailAnswer。max_option 因而走到另一个分支，把当前的 12 包成 SOME 12。

如果真的执行 valOf NONE，它会抛出 Option 异常。保护它的不是变量名，也不是 NONE 会自动变成 0，而是这条明确的执行顺序。

andalso：先满足左边，才需要右边

这里的 andalso 表示“并且”。左边必须成立，右边才有继续检查的必要；这种可以提前结束、不计算剩余部分的行为，叫作短路求值。

继续沿用 max_option 的判断，三种情况就都接上了：

当前头部 尾部答案 判断怎样进行 是否沿用尾部答案
12 NONE 左边为 false，跳过读取 否
12 SOME 18 左边为 true，继续比较 18 > 12 是
12 SOME 8 左边为 true，继续比较 8 > 12 否

把具体名字换成任意表达式，就是 e1 andalso e2：先计算 e1；它为 false，整体就是 false；它为 true，才计算 e2，并把右边的布尔结果作为最终结果。这与下面的 if 具有相同的求值含义：

这里的 e1、e2 是说明规则用的占位名字，不是另外定义的函数。两边都必须有 bool 类型，整体也才有 bool 类型；所以 false andalso 3 仍然是类型错误。运行时会跳过一个表达式，不代表类型检查时可以不看它。

这也解释了为什么不能随便交换左右两边。若先写 valOf tailAnswer > hd pages，程序会先尝试读取 NONE，还来不及执行后面的检查就已经失败。“先确认存在，再读取”既是我们读代码的顺序，也是代码必须遵守的执行顺序。

orelse：左边已经足够，就不用再检查

另一个方向也很常见。假如我们想判断一份记录“要么没有数据，要么第一天读了正数页”，空列表本身已经足以让判断成立，就不该再对它使用 hd。

下面的函数输入一份整数列表，输出这个判断的真假。orelse 表示“或者”：

对 []，null xs 已经是 true，右边的 hd xs 不会执行。对 [12,0]，左边是 false，程序再看 12 > 0；对 [0,12]，它再看 0 > 0，得到 false。这个函数检查的是第一项，后面有没有读过更多页，并不影响它的结果。

一般的 e1 orelse e2 先计算左边；若为 true，立即返回 true；只有左边为 false，才计算右边。它对应 if e1 then true else e2，同样要求两边都是 bool。

所以，把函数体改成 hd xs > 0 orelse null xs 就改变了安全性：遇到空列表，首先执行的会是 hd []。逻辑学中的“或”可以交换，但这里写的是有执行顺序、并且可能失败的程序。

写对名字，也要知道它是不是普通函数

到这里，两个运算都已经有了具体用途：andalso 让必要条件逐个成立，orelse 在已有条件足够时提前结束。若熟悉其他语言，可以把它们分别联系到常见的 &&、||；SML 使用的是这两个完整单词，不是 &&、||，也不是 and、or。

还有一个操作是取反：把 true 变成 false，把 false 变成 true。SML 把它写作普通函数 not，输入和输出的类型都是 bool：

在 REPL 里单独输入 not;，可以看到它是一个已有函数，类型为 bool -> bool。单独输入 andalso 却不能得到这样的函数：它需要左、右两个表达式，REPL 可能继续等待输入，或者在不完整输入结束时报告语法错误。

这个差别与求值有关。普通函数调用会先计算实参，再进入函数体；但 andalso、orelse 有时必须跳过一个部分，因此它们需要专门的语言规则，不能直接换成普通函数。

例如，下面尝试用函数写“并且”。它的两个参数是布尔值，结果也为布尔值，函数体看起来没有问题：

可一旦调用 both (isSome tailAnswer, valOf tailAnswer > 0)，两个实参就都要先被计算。当 tailAnswer = NONE 时，第二个实参仍会读取不存在的值，根本进不到 both 的函数体。前面的 andalso 能跳过读取，恰好是普通函数调用不能代替的部分。

取反没有这个要求：它总要先知道输入的真假，再反过来，因此 not 完全可以是普通函数。在其他语言里常见的 !，在 SML 中另有用途，涉及后面的可变引用；这里使用 not 即可。

条件已经给出了真假，就直接使用它

有了 if，其实可以表达这三种操作：

想表达的意思 等价的条件写法 更直接的写法
两个条件都成立 if e1 then e2 else false e1 andalso e2
至少一个条件成立 if e1 then true else e2 e1 orelse e2
把真假反过来 if e then false else true not e

专门的写法并没有增加这些计算的表达能力，却让读代码的人更容易认出意图。原课也特别提醒：if e then true else false 只是把 e 的结果原样交回来，直接写 e 就够了。

例如，判断是否有阅读记录，写 isSome answer 就已经得到 bool；不必再包成 if isSome answer then true else false。只有要根据真假选择不同结果时，才需要那一层选择。

读到的数，怎样继续比较

现在可以安全取得一个整数了，接下来才轮到“它是否达到目标”“两个结果是否相同”等判断。第一节中的比较写法可以放到阅读数据里一起看：

问题 示例 结果
页数是不是零 0 = 0 true
两天页数是否不同 12 <> 18 true
是否少于或多于目标 12 < 20、24 > 20 都是 true
是否至多或至少达到目标 20 <= 20、24 >= 20 都是 true

这里的 = 是相等判断，不是给某个变量重新赋值；不等写作 <>，不写 !=。也不要把其他语言的 == 搬过来。

<、>、<=、>= 还可以用于 SML 支持的实数、字符串和字符等类型，但两边要在相应运算支持的同一种类型上匹配。字符串按字符序列的词典序比较，不是按中文含义排序。

例如，整数 3 与实数 3.0 是不同类型。3 > 2 和 3.0 > 2.0 都合法，混写 3 < 4.0 却不能直接通过类型检查。确实需要跨这两个类型比较时，先明确转换：

相等比较还要看里面的数据类型

但函数不能直接用 = 判等，SML 的 real 也不允许使用这里的通用 = 和 <>。因此 3.0 = 3.0 不是一个合法例子；这类限制后续会用“相等类型”进一步说明。

原课借实数提醒我们：浮点计算可能有舍入误差，很多问题应当比较两个结果是否足够接近，而不是要求它们直接相等。一个示意判断是 Real.abs (x-y) < 0.000001；其中 x、y 是要比较的实数，容差要由实际问题的尺度与误差要求决定，不是所有计算都用这个常数。

最后分清减法和取负

阅读页数本身通常非负，但比较两个数的差，仍可能得到负数。SML 用 - 表示两个数相减，用 ~ 表示把一个数取负：

所以负七写成 ~7，不写 -7。对整数来说，~e 与 0 - e 表达同样的数值运算；取负也可以用于实数，例如 ~2.5。

回到开头，max_option 中那一行判断现在可以顺着读完了：先用 isSome 确认尾部有答案，andalso 决定是否继续读取，再用 > 比较两个整数。每一部分既在表达一个判断，也有明确的类型与执行顺序。
