小运算符也有完整的语言规则

前一篇中，isSome answer andalso valOf answer > 0 能安全运行，靠的是 andalso 的求值规则。布尔运算不只是记住一个符号；它还决定右边会不会执行。

这一篇把第一节用到的布尔运算、比较和取负补齐。继续沿用相同的方法：它怎样写、需要什么类型、最后怎样得到值。

andalso：前面的条件成立，才继续检查

e1 andalso e2 要求两边的类型都是 bool，整个表达式也为 bool。执行时先计算 e1：若为 false，结果立即为 false；若为 true，才求值 e2。

直接写 andalso 更简洁，也更清楚地表达“两个条件都要满足”。这与许多语言中的 && 扮演类似角色，但 SML 写的是 andalso，不是 &&，也不是 and。and 是语言里的另一个关键字，后面会遇到。

短路不会免除类型检查。false andalso 3 仍然不合法：即使运行时用不到右边，它也必须有 bool 类型。与 if 一样，要把静态检查和动态求值分开理解。

orelse：第一个条件足够，就不再往下算

e1 orelse e2 同样要求两边都是 bool。先计算 e1，如果已经是 true，整个结果就是 true；只有它为 false 时，才求值右边。

它对应 if e1 then true else e2。SML 用的是 orelse，不是 || 或 or。

注意先后顺序也是算法的一部分。把表达式交换成 hd xs > 0 orelse null xs，对空列表就会先读头部并抛异常。虽然逻辑学中的“或”可交换，但可能失败或有副作用的程序表达式，还必须考虑执行顺序。

not 是普通函数，短路运算需要特殊规则

not 的类型是 bool -> bool，可以理解成这样定义的函数：

函数调用会先求出实参的值，再进入函数体。因此，不能把 andalso 随意换成一个接收两个布尔参数的普通函数来保留短路。

调用 both (false, 1 div 0 = 0) 时，第二个实参仍然需要先被求值，因而会除零失败；false andalso (1 div 0 = 0) 则直接得到 false。这个差别来自函数调用和条件表达式各自的求值规则。

在其他语言里取反常写 !；在 SML 里写 not。! 有另外的用途，涉及后面才学习的可变引用。

还有一个常见的冗余写法：if e then true else false。它只是把 e 的布尔结果原样返回，直接写 e 即可。这里的前提是 e 本身为布尔表达式；相反的 if e then false else true 则可以写成 not e。这些改写说明：有 if 就足以表达这些逻辑，但专门的布尔写法更容易让读者认出意图。

相等、不等与大小比较

目的 SML 写法 例子
相等 = 3 = 3 得到 true
不等 <> 3 <> 4 得到 true
小于或大于 <、> 3 < 4 得到 true
不大于或不小于 <=、>= 4 >= 4 得到 true

这里的 = 是相等判断，不是赋值。<> 表达“不等”比 not (e1 = e2) 更直接；不要照搬 == 或 !=。

大小比较不仅能用于整数，也能用于 SML 支持的实数、字符串和字符等类型，但两边必须在相应运算支持的同一种类型上匹配。语言不会自动把一个整数和一个实数混合起来比较。例如 3 < 4.0 不能直接通过类型检查，需要先明确转换。字符串的顺序是字符序列的词典序，不是中文语义上的排序。

相等运算的适用范围也有限制。整数、布尔值、字符串，以及元素允许相等比较的列表和元组，都可以进行相等比较。函数不能拿来直接判等；SML 的 real 也不属于允许使用通用 = 的相等类型，因此 3.0 = 3.0 不是一个合法例子。这些限制会在后续讲多态和 equality types 时进一步展开。

原课借此提醒：浮点计算可能有舍入误差，很多数值问题真正关心的是两个结果的差是否在允许范围内，而不是直接判等。补充一个示意写法：Real.abs (x-y) < 0.000001；实际容差应由问题的尺度、误差要求等决定，这个常数不是通用标准。

此时只需记住：一个运算符能用于某种类型，是这门语言的规则决定的；不能因为符号看起来熟悉，就默认所有语言的规则完全一样。

所以负七写作 ~7，不写 -7。对整数来说，~e 与 0 - e 表达同样的数值运算，前者更直接。取负也可以用于实数，譬如 ~2.5。
