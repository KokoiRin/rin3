怎样同时交回总页数和达标结果？

上一节我们已经能写函数：给它输入，函数体完成计算，再交回一个结果。现在继续记录阅读情况。假设周一读了 12 页，周二读了 18 页，我们希望一次得到两项信息：两天总共读了多少页，以及是否达到 25 页的目标。

只交回整数 30，没有直接给出是否达标；只交回 true，又丢掉了具体页数。SML 可以把这两个部分组成一个完整的结果：

调用时，monday 对应 12，tuesday 对应 18。函数体的第一部分算出 30；第二部分先算出 30，再用 >=（大于或等于）比较 30 >= 25，得到 true。最后组成的 (30,true) 才是函数交回的那个值。

这种把两个部分合成一个值的结构，叫作二元组，英文是 pair。更一般地，固定数量的部分可以组成元组，英文是 tuple。这里的两个位置有明确含义：第一项是总页数，第二项是是否达标；程序不会靠变量名自动记住这些业务含义，需要我们约定并保持一致。

从完整结果中，取出现在需要的部分

假设后面的计算只需要总页数，或者只需要达标结果，就要能分别读取这两个位置。SML 暂时用 #1 读取第一项，用 #2 读取第二项；编号从 1 开始。

#1 report 先找到整个 (30,true)，再取出整数 30。#2 report 取出布尔值 true。取出以后，它们就是前面已经认识的普通整数和布尔值，可以继续参加相应的计算。

到这里，二元组已经完成了一次完整的“构造与使用”：我们把两个结果放在一起，再从中取回各部分。后面遇到其他数据结构，也要同时弄清楚这两面；只知道怎样写出数据，还不足以用它完成任务。

元组类型把结构写清楚了

report 的类型是 int * bool：第一项是整数，第二项是布尔值。类型里的 * 表示这两部分的组合，不是把两个东西相乘。即使总页数换成 300，这份结果仍然可以有相同类型。

元组的位置数量、位置顺序、各部分类型都属于结构。(30,true) 与 (true,30) 就有不同类型，分别是 int * bool 和 bool * int。而三元组 (30,true,25) 有三个直接组成部分，类型是 int * bool * int。

这也意味着元组不是运行到一半可以随意多出一个位置的结构。对一个二元组读取 #3，会在类型检查时遇到错误，而不是先成功运行，再报告某个数组下标越界。需要多少项随记录数量改变的数据时，我们会在下一篇换一种结构。

构造时先算出各部分，之后才有元组值

把阅读报告的数字缩小，原课还用这样的表达式观察求值：

构造 p 时，需要先计算 1 + 2 和 3 < 4，然后得到 (3,true)。它没有保存两段尚未执行的代码，等待以后读取时再算。因此，(1+2,3<4) 还是需要计算的表达式，(3,true) 才是各部分都已算好的元组值。

同样，#1 (1+2, 8 div 0) 会在构造元组时遇到除零异常。即使只打算取第一项，也不能跳过第二项的求值。这里讨论的是构造完整值所需的计算，不需要额外猜测两部分之间的具体求值先后。

类型检查则分别确定两部分的类型，再组成整体类型。例如，if true then (1,true) else (2,3) 是预期的类型错误：两个分支的第二项分别是 bool 和 int，整体结构不能按条件表达式的规则统一。条件恰好写着 true，也不会免除另一个分支的类型检查。

原课的 swap：改变位置，不改变原数据

有时接收结果的代码要求把布尔值放在前面、整数放在后面。原课用 swap 展示这种位置调整。它接收 int * bool，取出两项后反过来组成新二元组：

pr 是输入元组的名字。读取第二项得到 true，把它放到新结果的第一项；读取第一项得到 7，把它放到第二项。因此函数的类型是 int * bool -> bool * int，箭头左边描述输入结构，右边描述结果结构。

这里没有把输入的两格原地交换。输入 (7,true) 保持原样，函数构造了另一个结果。后面讨论不可变数据时，我们会继续解释，为什么“返回新结果”和“修改原数据”的区别值得关注。

这次调用里，pr1 对应 (1,2)，pr2 对应 (3,4)。四次读取分别拿到 1、2、3、4，再相加得到 10。两个内层元组都是“两个整数”，所以这里的输入结构是 (int * int) * (int * int)。

它与直接传入四元组 (1,2,3,4) 不同。两层括号表达了“有两份记录，每份有两部分”，不能只数出四个整数就把结构摊平。原课此时沿用“两个参数”的说法，后续会再从一个元组参数的角度统一理解这些调用；现在先把实际形状看准确。
