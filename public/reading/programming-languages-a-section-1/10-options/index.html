还没有阅读记录，最高页数应该是多少

上一篇，我们已经能用 good_max 高效地求出一周的最高阅读页数。现在把它放进实际记录过程：新的一周刚开始，列表还是 []；另一个时候，我们已经记下一天，只是那天读了 0 页，列表是 [0]。这两份记录含义不同，旧函数却都返回 0。

拿到这个 0 的人无法判断：是已经有记录，最大值确实是 0，还是压根没有数可比较？空列表不存在某个整数可以称作它的最大值，因此随便返回一个整数，会把“没有答案”伪装成“答案就是这个数”。

换成 ~1 看似能避开真实的零页记录，但我们的函数接收 int list，这个类型也允许负数；[~1] 的最大值正是 ~1。除非另加输入范围的约定，否则换一个数字仍可能冲突。我们这次要让结果本身清楚地区分两种情况。

阅读记录 结果需要表达什么
[] 没有最大值
[0] 有最大值，这个值是 0
[12,18,10,15,0,20,25] 有最大值，这个值是 25

先区分“有”和“没有”，再装入数字

SML 已经提供了表达这两种情况的写法。NONE 表示没有携带答案；SOME 25 表示有答案，而且答案是 25。这里 SOME 后面的数字就是我们真正想要的最大值，SOME 0 因而能与 NONE 明确区分。

这种“可能没有，也可能有一个值”的类型叫作 option。普通的整数类型是 int，可能缺失的整数答案就写作 int option。先不急着改递归函数，可以在解释器里直接建立这几种结果，看看它们的形状和类型：

missing 没有装入任何整数，另外两个分别装着 25 和 0。它们不是三个不同的整数，而是同一种结果类型里的两种形状：NONE，或带着一个整数的 SOME。这正好对应我们需要表达的“无答案”和“有答案”。

option 也不限于整数。下面先算出括号里的表达式，再把结果放在 SOME 中；第二行则装入一个字符串：

所以 SOME e 的规则可以从例子看出来：先把 e 算成值，再得到带着这个值的 SOME。如果 e 的类型是 t，整体类型就是 t option。它不会推迟 e 的执行，若 e 在计算时出错，外面这一层 SOME 也不能阻止错误。

NONE 里面没有值，单独看不要求答案必须是整数或字符串，解释器可能把它的类型显示为 'a option。'a 在这里表示尚未确定的元素类型，和空列表显示为 'a list 相似。一旦像 missing 那样明确规定为 int option，就不能把同一个结果再当成 string option 使用。

有答案后，怎样把里面的整数取出来

假设已经得到 SOME 25，接下来还想比较它是不是超过 15 页。SOME 25 整体不是整数，不能直接代替 25 去做整数运算；需要先确认有值，再拿出里面的数。

原课先使用两个现成操作：isSome 回答“是不是 SOME 形状”，valOf 取出其中的值。下面先建立一个有答案的结果，再分别询问形状和内容。

isSome 总是给出布尔值：有值为 true，没有值为 false。注意它与列表的 null 判断方向相反：null [] 为真，isSome NONE 却为假。valOf (SOME 25) 则给出内部的整数 25。它们不只服务于整数，类型分别是 'a option -> bool 和 'a option -> 'a：装入哪种类型，取出时就得到哪种类型。

但 valOf NONE 没有内容可取，会在运行时引发名为 Option 的异常。它与 hd [] 很像：代码可以通过类型检查，执行时仍然可能因为没有元素而失败。因此下面改写最大值函数时，关键不只是返回 option，还要让读取发生在确定有值之后。

第一个版本：尾部有答案，就拿来比较

还是沿用“当前第一个数，与尾部最大值比较”的递归思路，只把每一层的回答改成 option。例如处理 [4] 时，尾部是 []，尾部只能回答 NONE；这说明没有另一个数需要比较，当前的 4 就是最大值，应返回 SOME 4。

处理 [2,4] 时，尾部回答 SOME 4，取出 4，与当前的 2 比较，仍保留尾部答案。处理 [6,2,4] 时，尾部也回答 SOME 4，但 4 不大于当前的 6，于是应返回 SOME 6。我们给这个“尾部的回答”起名叫 tailAnswer。

下面的 max_option 接收整数列表，空列表返回 NONE，非空列表返回 SOME 包着的最大整数。条件里的 andalso 表示“左边成立，而且右边也成立”；它会先看左边，若左边已经为假，就不再执行右边。这样只有 isSome tailAnswer 为真时，才会去用 valOf 取值。

按刚才的三个输入，值会这样逐层返回。最下方的空列表先给出 NONE，外面的每一层再根据自己的头部决定答案：

特别看 [4] 那一层：isSome NONE 为假，于是跳过 valOf tailAnswer > hd xs，直接进入 else，得到 SOME 4。这种“前面已经足以决定结果，就不执行后面”的求值方式叫作短路求值，下一篇会继续展开。此处它保证我们不会从 NONE 中硬取整数。

函数类型现在是 int list -> int option，箭头右边明确说明答案可能缺失。它仍像上一篇改好的版本一样，每层只递归求一次尾部；进入 then 时还会直接返回已有的 tailAnswer，不需要每一层都新造一个 SOME。

第二个版本：先排除空列表，内部只求整数

第一个版本已经正确。还可以换一种组织方法：最外面先判断是否有记录；没有就回答 NONE，有记录才交给一个只处理非空列表的辅助函数。这个辅助函数每层直接返回整数，全部算完以后，最外面再包一次 SOME。

这正好用到第八篇的局部函数：辅助函数只在外层检查之后使用，不需要让外面的代码直接调用它。下面的 max_option_local 对同一份输入给出与 max_option 相同的答案；局部的 max_nonempty 则接收非空列表，返回其中最大的普通整数。

例如输入 [6,2,4]，最外层发现它非空，才调用辅助函数。辅助函数求 [4] 得到 4，返回上一层比较 2 和 4 得到 4，再返回上一层比较 6 和 4 得到 6。最后，外层的 SOME (...) 得到 SOME 6。

为什么这个辅助函数不检查空列表，也能安全运行

注意 max_nonempty 一进来就读取 tl ys，如果收到 [] 就会出错。它之所以可用，不是因为函数名字里写着“非空”，而是代码安排了两道具体保障。

第一，最外层只有在 null xs 为假时才第一次调用它，所以初次输入一定非空。第二，内部若发现尾部为空，就直接返回头部；只有尾部非空时，才把这个尾部传给下一次递归。因此从第一次到后面每一次，它实际收到的列表都至少有一个元素。

局部范围又让外面不能绕过这次检查，直接拿 [] 调用这个辅助函数。这样，“只处理非空列表”不是一句希望，而是可以顺着每处调用逐一确认的条件。

现在，空记录和真实的零终于分开了

下面把新函数用于三种输入：还没有记录、一般整数列表，以及包含真实零的列表。阅读页数通常不为负；保留负整数这个例子，是为了确认函数本身仍然按照它接受的 int list 正确比较整数。

原视频还用 [3,7,5] 演示怎样继续使用最大值。下面先得到 SOME 7，取出里面的 7，才把它加一得到 8。

如果直接把 max_option [3,7,5] 与 1 相加，就是在把 int option 当作 int 使用，会在类型检查时被拒绝。这与 valOf NONE 不同：后者的类型可以成立，却在执行取值时失败。

两种实现的外部结果类型相同，都是 int option。一个在递归中一直携带有无答案的信息；另一个把空的情况放在最外层，内部只比较整数。这里学到的是两种组织同一任务的方法，不需要把其中一种理解成另一个完全错误。

补充：为什么不用空列表表示没答案

也可以人为约定：[] 表示没答案，[25] 表示答案是 25。问题是 int list 还允许 [25,30] 这样的值；如果只看类型，无法知道这里究竟是许多个整数，还是“最多一个答案”。int option 则直接把形状限制为无值或一个整数。

这也不代表 NONE 就是空列表。SOME [] 表示有一个值，而这个值刚好是空列表，与根本没有携带值的 NONE 不同。要先看外层是 SOME 还是 NONE，再看有值时里面放着什么。

原课还提到，空输入也可以用抛异常的方式处理，后续课程会介绍。这里用 option，是让“没有最大值”成为正常返回结果的一种形状；不过，使用结果的人仍须先检查再取值，直接写 valOf NONE 依然会出错。下一篇就沿着这个例子，继续讲清楚布尔条件怎样控制执行顺序。
