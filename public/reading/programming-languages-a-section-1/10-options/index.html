没有答案，也是接口需要表达的情况

求最大值的算法已经足够快，但 good_max [] 仍然返回 0。这不是算术上的最大值，而是我们随手选的一个替代数字。若列表是 [0]，结果也为 0，调用者无法区分“最大值是零”和“根本没有数”。

换成 ~1 或一个很小的整数也解决不了问题，因为它们都可能是合法输入。我们需要让结果同时表达两件事：有没有答案，以及有答案时答案是什么。

option 是“可能有一个值”的类型

SML 提供 option。若普通答案的类型是 int，可能缺失的答案类型就是 int option。它的值只有两种形状：

NONE 表示没有携带值，SOME 12 表示有值，而且这个值是 12。SOME 0 和 NONE 明确不同，SOME [] 与 NONE 也不同：前者有一个值，这个值恰好是空列表。

若 e 的类型是 t，则 SOME e 的类型是 t option。求值时，先把 e 求成值 v，再得到 SOME v。所以 SOME (3+4) 得到 SOME 7；包一层 SOME 并不会推迟计算，也不会阻止内部表达式抛出异常。

单独的 NONE 可以用于不同元素类型，类型常显示为 'a option。这与 [] 的 'a list 类似：里面没有元素，不会强迫元素类型是整数或字符串。可是一旦确定为 int option，就不能再把同一个结果当作 string option 使用。

SOME 12 自己也不是整数，不能直接拿它加一。需要先处理有无答案，再取出内部整数进行算术，不能把包装层当作透明的。

为什么不用长度为零或一的列表

确实可以约定：[] 表示没答案，[12] 表示答案是 12。但 int list 也允许 [12,13] 这样的值，类型没有准确表达我们的意图。

int option 把结果限定在“零个或一个整数”。它不是一种特殊列表，虽然两者都可以描述空的情况，但类型与可用操作不同。让类型更贴近业务含义，读代码的人就少需要记一条额外约定。

先检查，再取出

本节用两个已有操作读取 option：

操作 类型 含义
isSome 'a option -> bool 是否是携带值的 SOME
valOf 'a option -> 'a 取出 SOME 内的值；遇到 NONE 抛异常

valOf NONE 在类型上可以成立，运行时却没有东西可取，会引发 Option 异常。这与 hd [] 的情况相似：类型正确并不自动保证每次运行都成功。

这里先认识原课的读取方式。下一节会学习更适合同时区分形状和取得内容的模式匹配；现在不需要提前把所有例子换成它。

第一个完整版本：每层都返回 option

函数的类型是 int list -> int option。对空列表，直接返回 NONE；对非空列表，先询问尾部的答案。如果尾部有最大值，而且比当前头部大，就沿用尾部的答案，否则把当前头部包装成 SOME。

andalso 会短路：左边是 false 时，不求值右边。因此在 tailAnswer = NONE 时，不会执行 valOf tailAnswer。先检查再取值，既是阅读顺序，也是保证安全的执行顺序。下一篇会完整解释布尔运算规则。

第二个版本：在入口处理缺失，在内部处理数值

上一个版本正确，也没有重复求解昂贵的子问题。但每层都要检查尾部的 option，再决定返回已有答案还是包装当前头部，代码有些绕。可以让外层处理空列表，让一个局部辅助函数专门处理非空列表。

外部调用者仍然只看到 int list -> int option，两个实现对输入给出相同结果。内部的 max_nonempty 则返回普通 int，最后才包装一次。

安全性的关键不在函数名，而在调用路径：只有外层确认 xs 非空后才第一次调用它；只有当前列表不止一个元素时才继续递归，因此递归得到的尾部也非空。辅助函数被限制在局部，外部无法绕过检查直接调用它。局部作用域在这里帮助我们维持一个明确的使用条件。

补充理解：类型表达缺失，并不代替全部检查

int option 让“可能没有答案”进入函数接口，提醒使用者处理缺失。但如果调用者不检查就写 valOf answer，仍然可能出错。类型设计让一个条件显式可见，并不意味着本节这些读取操作已经把所有错误用法都禁止了。

抛异常也是处理空输入的一种选择，原课提到稍后会学习。这里选择 option，是为了让“没有最大值”作为正常结果的一种形状返回，而不用借一个合法整数冒充它。
