学一门语言，究竟是在学什么

第一节看起来只做了几件小事：绑定几个名字，写递归，拼接列表，求最大值。但 Dan 最后把镜头拉远：这些例子的价值，不仅是学会一套 SML 写法，而是建立理解任何程序语言的方法。

原课把学习一门语言分成五个方面：语法、语义、惯用法、库和工具。实际写程序时五个方面都重要，但它们回答的是不同问题。把它们分清，遇到陌生代码时才能知道自己究竟卡在哪里。

五个方面各自负责什么

方面 它回答的问题 第一节里的例子
语法（syntax） 合法代码怎样写？ val x = e、if … then … else …、let … in … end
语义（semantics） 代码是什么意思？ 怎样检查类型，按照什么规则求值
惯用法（idioms） 哪种问题通常适合怎样写？ 把专用辅助函数藏在局部，用 let 保存递归结果
库（libraries） 已经有哪些可用的功能？ 列表操作、文件读写、现成数据结构
工具（tools） 怎样更方便地编写、运行和排查？ 编辑器、REPL、格式化工具、调试器

语法让你能够把程序写出来，但“符号写对了”只是起点。语义让你知道它是否通过类型检查、何时执行什么、最终会得到什么。比如同样看到一个名字出现两次，你需要理解环境与作用域，才能判断它们是不是同一个绑定。

惯用法则比规则多走一步。语言允许在 let 里定义函数，这是语法和语义；当一个辅助函数只服务一个外层函数时，通常把它放在局部，这是使用经验。知道能做什么，与知道何时值得这样做，是两种相关但不同的能力。

库与工具也不能混成一件事

库提供可调用、可组合的功能。有些功能需要语言实现或运行环境提供底层支持，例如文件读写不能仅凭整数加法和递归就凭空接触磁盘。另一些功能，例如树、哈希表、列表，可以在具备足够语言构造后自己实现，也可以直接使用现成库。

现在我们使用语言提供的列表，后续会看到如何定义类似的数据结构。使用现成功能很有价值，但也应能区分：这是语言表达能力的限制，还是暂时没有学习相应库。

工具帮助人工作，例如 REPL 让我们快速尝试表达式，调试器帮助观察运行，格式化工具统一排版。REPL 属于某个语言实现提供的工具，不是 SML 语义本身。 同一种语言可以有不同的实现和工具体验；不能因为某个实现的报错方式不友好，就据此判断语言的求值规则。

把这几层分开，也能避免另一种误判：一套框架的 API 用不熟，不代表不理解程序语言；背熟语法却看不懂执行顺序，也不能单靠换一个编辑器解决。

为什么这门课特别重视语义和惯用法

Dan 并不否认语法、库、工具的重要性。只是它们会不断变化，也很容易让学习陷入个人偏好的争论。课程更想训练一种能迁移的能力：准确理解构造的规则，认出常见问题的结构，再选择清楚、可靠的写法。

学习语义时反复问“类型规则是什么、求值规则是什么”，并不是为了增加术语，而是为了减少猜测。学习惯用法时反复问“为什么要局部辅助函数、为什么保存中间结果”，则是为了让正确的规则变成可靠的程序。

这种能力也会帮助你学习新库：库函数接收什么输入、承诺什么结果、怎样失败、通常怎样组合？它们与分析语言构造时问的问题相通。因此，课程没有逐个介绍大型应用框架，并不意味着它与实际开发脱节。

先看输入输出的整体约定：best_day 的类型是 int list -> int option。列表允许天数变化；option 让空输入与真实最大值为零分开。这里没有给“页数必须非负”建立专门类型；补充说明，函数对任意整数列表都会求最大值，非负是应用场景的额外条件。

再看执行过程。外层 if 判断是否为空；不为空时才进入局部辅助函数。辅助函数把列表拆成头和尾，以一个元素为终点递归。每一层用 let 保存尾部最大值，再进行一次比较。整个过程中没有修改原来的 week。

最后看作用域。best_nonempty 只在外层函数内部可用，外部不能绕开入口检查；bestRest 只在对应的局部表达式内可用。每次递归都有自己的参数绑定，不能把不同调用中的同名 xs 误当作一个不停被改写的变量。

这段代码用到的符号并不多，但已经连起了类型、求值、环境、递归、复合数据、局部绑定、效率和不可变性。这就是第一节想建立的基础。

这些小例子与实际开发怎样连接

最大值和列表拼接容易让人觉得“离应用太远”。原课选择它们，是为了把框架、网络和 UI 的额外复杂度暂时拿走，让语言规则能够完整地看清。它们不能用来衡量 SML、Racket 或 Ruby 是否能够开发真实系统；这些语言也有自己的库和应用生态，课程只是没有把教学重点放在那里。

补充一个熟悉的场景：网络请求返回一组条目，程序要处理空结果、选出一个条目、组合新状态，再交给页面。这里同样要理解数据形状、缺失、函数调用、局部计算、共享与修改。具体 API 会变化，这些问题一直存在。

接下来学习模式匹配时，我们会换一种更清楚的方式拆开列表、元组和 option；学习高阶函数时，又能把许多相似递归抽成共同模式。先把本节建立的关系理解稳，再看新语法，就能认出它是在改善已经见过的哪一个问题。
