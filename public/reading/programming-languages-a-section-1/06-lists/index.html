已经记了三天，还能用同一种类型吗？

上一篇用元组组合了两天的页数，也把“总页数加达标标记”组成了一份结果。元组适合这些位置已经确定的记录。现在我们想保存一周每天的阅读页数：周三时只有三项，周日时有七项，还没开始记录时则一项都没有。

如果为三天写三元组、为七天写七元组，结构和类型都会跟着改变。我们希望后面求总页数的函数不必关心“今天记到了星期几”，同一类输入就能覆盖这些情况。SML 的列表正是用来组织这一类数据的：

这三份数据都能有 int list 类型，也就是整数列表。[] 表示没有记录，[0] 则表示已经有一项记录、这一天读了零页；它们不能混为一谈。列表类型不写长度，所以同一种类型能够容纳零项、三项或七项。

这里的“长度可以不同”，是在比较不同的列表值，不是说程序会原地把某个已有列表不断改长。我们马上会看到，构造新列表时旧值仍然保留。

先分清“一个元素”是什么

在 week_pages 里面，每一个元素都是一天的整数页数。SML 要求同一个列表的全部元素有共同类型，因此不能把整数和布尔值直接混在这一层，例如 [12,true] 是预期的类型错误。

不过，共同类型也可以是前面学过的复合类型。假如另一份记录保存的是“每天页数与完成标记”，就可以让每一项都是二元组：

第一份列表的每个元素都是 int * bool，所以各元素类型一致。第二份只记录布尔标记，每项都是 bool。位置数量可变化，但元素类型保持一致，是列表与元组各自承担的不同职责。

构造列表也会先计算里面的表达式。原课用小整数演示这个过程，例如 [3,4+3,7] 得到 [3,7,7]。计算完成后保存的是三个整数值，而不是三段等待以后执行的代码。

把三天记录拆成“第一天与剩余两天”

要理解列表怎样被构造，可以先看一份更短的记录。假设剩余两天的页数已经是 [18,10]，我们希望在它前面放上第一天的 12，得到 [12,18,10]：

:: 读作 cons，它的作用是把一个元素放到一个已有列表的前面。左边的 12 是一个整数，右边的 tail 是整数列表，结果仍然是整数列表。它不是把 12 放到末尾，也没有把 tail 原地改掉；后面再读取 tail，仍然得到 [18,10]。

我们把新列表的第一个元素叫作头部，把其余元素组成的列表叫作尾部。对 whole 而言，头部是整数 12，尾部是列表 [18,10]。头部与尾部处在不同层次：一个是元素，另一个仍是列表。

最短的非空列表也符合这个结构：12 :: [] 的头部是 12，尾部是空列表。继续套用，就得到：

从最里面开始，10 :: [] 先得到 [10]，再把 18 放到前面，最后放入 12。不写括号的版本会向右结合，也就是按上面的分组方式理解。这样，固定的“一个头部加一个尾部”结构，就能组成任意有限长度的列表。

为什么两个列表不能直接拿 cons 拼起来

:: 两侧的类型要求是：若左边为 t，右边就需要是 t list，结果也为 t list。这里的 t 只是某种类型的占位记号。

因此，12 :: 18 是预期的类型错误，因为右边不是列表。[12] :: [18,10] 也不符合要求：右边要求每项为整数，左边却是一份整数列表。把两份页数记录首尾连接起来，需要另一种计算，下一篇会写这个函数。

但“左边是列表就一定错误”也不准确。假如我们要保存几周的数据，外层列表的一项本身就是一周页数列表：

这一次，左边的一个元素是 [12]，类型为 int list；右边保存同类元素，类型为 int list list，所以符合规则。类型里的两个 list 表示两层列表，不要求各周的记录天数相同。

为了继续计算，先问是否为空，再读头部和尾部

保存列表之后，我们想让函数把所有页数相加。第一步需要知道还有没有记录；如果有，就读取一天的页数，再处理剩下的部分。原课先给出三个现成函数来完成这些动作：null、hd、tl。

null 回答“列表是不是空的”，结果是布尔值。它是接收列表的函数，不是 Java 中那个空引用值；ML 的空列表写 []。hd 取头部，tl 取尾部，所以两者的结果分别是一个元素和一个列表。

如果要读取第二天，就先取得尾部 [18,10]，再从这个列表中取头部：

每次 tl 都去掉一个头部；它不会直接把最后一个元素当作结果交回。所以 [10] 的尾部是 []，而不是整数 10。原视频用 x=[7,8,9] 做同样演示，逐次得到 [8,9]、[9]、[]，只是数字与我们这份阅读记录不同。

到了空列表，就不能再取头尾

下面四次计算揭示了一个重要边界：

tl [7] 可以执行，因为输入是有一个头部的非空列表，取走它后恰好没有剩余元素。tl [] 则一开始就没有可供拆开的非空结构；hd [] 同样没有第一个元素可取。两者都会在求值时引发 Empty 异常。

这不是列表类型本身无法确定。即使写成 hd ([] : int list)，类型检查器也能知道结果类型应该是 int，运行时却仍然没有元素可以交回。因此我们要先判断是否为空，再在已经确认非空的分支里使用 hd、tl。下一篇的列表求和会把这个顺序完整用起来。

空列表为什么显示成 'a list

有时工具对 [] 显示的类型是 'a list，其中 'a 通常读作 alpha。这里表示“可以选定某一种元素类型”：空列表没有任何现有元素与这个选择冲突，所以它既可以用于整数列表，也可以用于布尔列表。

这不等于空列表没有类型，也不等于某份列表能随意混入不同类型。上面第一条明确选定 int list 后，给它前面接整数符合规则，接布尔值就不符合。

刚才三个函数的类型也可以使用相同的占位记号理解：

函数类型 读法
null : 'a list -> bool 输入某种元素的列表，回答是否为空
hd : 'a list -> 'a 输入某种元素的列表，取出同种类型的一个元素
tl : 'a list -> 'a list 输入与结果保持同样的元素类型

例如 hd daily_reports 得到整个 (12,true)，因为这里的一个元素就是二元组。若只要里面的页数，还要再写 #1 (hd daily_reports)。我们始终先看外层是什么，再进入它的一个组成部分。

层层组合时，仍然沿实际结构读取

原课还比较了这两种形状：

前者是两条配对记录组成的列表，hd a 得到一对整数 (1,2)。后者是一对列表，#1 b 得到完整的 [1,3]。里面都有相似的数字，但外层结构决定了第一步该用哪个读取操作。

同理，[[],[1,2],[3]] 可以统一为 int list list；其中几份整数列表长短不同，并没有破坏类型。[[1],[true]] 则是预期的类型错误，因为内层分别是整数列表和布尔列表，外层各项没有共同的元素类型。

现在我们已经能够保存一周长短不同的记录，也知道怎样判断空、读取一天、得到剩余天数。下一篇就把这些动作接起来，让同一个函数算出任意有限份阅读记录的总页数。
