当数据有多少项，要等运行时才知道

元组能把固定数量的部分组合起来。但假设一个函数接收今天所有订单的金额，订单可能有 0 笔，也可能有 100 笔。不能为每种数量都准备一个不同长度的元组类型；我们需要一种类型，允许数据长度变化。

这就是 SML 的列表。例如 [3,5,8] 是一个整数列表，类型写作 int list。列表长度不写进这个类型，所以 []、[3]、[3,5,8] 都可以是整数列表。代价是：同一个列表的所有元素必须有相同类型。

元组和列表因此分别适合不同问题。元组的数量固定，各部分可有不同类型；列表的数量可以变化，各项却要有共同类型。这是数据结构的区别，不是两种不同的括号风格。

先看元素类型，再看外面的 list

最后一个列表并没有违反“同一类型”：其中的每一项都是 int * bool 二元组。共同类型可以是复合类型，并不只限于整数或布尔值。相反，[1,true] 把 int 和 bool 直接放在同一层，是类型错误。

构造列表时，每个元素表达式都要求值。例如 [1+2,2*4] 的结果是 [3,8]。它保存的是两个计算结果，不是两段留待以后执行的代码。只有各个组成部分已经是值，整个非空列表才是一个列表值。

'a 读作“alpha”或“quote a”，这里表示可以统一选择某种元素类型。空列表没有任何元素与这个选择冲突，所以它可以用于整数列表，也可以用于布尔列表。这不是说列表没有类型，更不是说它能在运行中随意混入各种类型；一旦上下文确定了某个列表的元素类型，相关运算都必须遵守。

非空列表由一个头部和一个尾部组成

方括号便于直接列出几个元素，但理解递归时，更重要的是 ::，读作 cons。表达式 e1 :: e2 先把左边求成一个元素，把右边求成一个列表，再构造一个以该元素开头的新列表。

类型规则说明了两边的角色：若左边是 t，右边就必须是 t list，结果仍是 t list。所以 3 :: 5 错在右边不是列表；true :: [3,5] 错在布尔值与整数列表的元素类型不一致。

还要注意，:: 不是把两个普通列表接起来的运算。若两个操作数都是 int list，左边的整个列表不能充当右边所要求的一个 int。例如 [1] :: [2,3] 是类型错误。但左边本身是列表也并非一概不行：

null、hd、tl 各自回答什么

目前还没有引入模式匹配，原课先用三个现成函数读取列表。它们都接收列表，但结果的层次不同。

操作 对 [3,5,8] 的结果 类型关系
null false 'a list -> bool
hd 3 'a list -> 'a
tl [5,8] 'a list -> 'a list

这里的 null 是一个接收列表的普通函数，不是 Java 里表示空引用的 null 值；[] 才是 SML 的空列表。null 检查是否为空；hd 返回第一个元素；tl 返回去掉第一个元素后剩下的列表。tl 的结果仍然是列表，这一点非常重要：即使只剩零项，它也返回空列表，而不是返回某个元素。

但空列表没有头部，也没有可供取出的尾部。因此 hd [] 与 tl [] 都会引发 Empty 异常。特别要区分 tl [7] 和 tl []：前者是在合法的非空列表上取尾部，结果恰好为空；后者一开始就没有可以拆开的非空结构。

这也说明类型检查与运行时安全不是同一件事。int list 并没有说明“至少有一个元素”，所以仅仅知道参数是列表，不足以保证调用 hd、tl 安全。接下来写列表函数时，要先处理空列表，再在非空分支读取头部和尾部。

列表里的列表也可以有不同长度，例如 [[],[1,2],[3]] 是 int list list。外层要求各项都是整数列表，却没有要求它们长度相同。[[1],[true]] 则不成立，因为内层列表的元素类型已经不一致。

“任意类型”不等于“一次调用混用类型”

hd 的 'a list -> 'a 表示它可以用于各种元素类型的列表，但一次调用里，输入与输出必须使用同一个类型。传入整数列表，结果类型是整数；传入二元组列表，结果类型就是相应二元组，而不会突然变成其中某个字段。

例如 hd [(1,true),(2,false)] 的结果是 (1,true)。若只要里面的整数，还要再用 #1 读取。反过来，对 hd ([] : int list)，类型检查仍然能够确定结果应该是 int；但运行时根本没有那个元素，所以会发生异常。静态地知道结果类型，与保证这次计算一定产生一个值，必须分开理解。

长度变化本身没有这个困难。条件表达式 if true then [] else [1,2] 的两个分支都能统一成 int list，所以类型没有冲突。列表类型故意不记录长度，正是为了容纳这种变化；它保留的是元素类型的一致性。

构造新列表，不会改掉旧列表

回到 val whole = 3 :: tail：它不会把 tail 的内容从 [5,8] 改成 [3,5,8]。后续再读取 tail，仍然得到 [5,8]。tl whole 则得到 [5,8]，因为新列表的尾部就是原来那段列表结构。

在通常的链表实现中，这允许新列表与旧列表共享尾部，不必为了前面增加一个元素就复制整个尾部。这里先把“值没有被修改”理解清楚；共享为什么安全，会在后面的不可变数据一篇展开。
