Kotlin 多平台项目通过编译（compilation）生成产物。每个目标可以具有一个或多个编译，例如分别用于生产代码和测试代码。

对于每个目标，默认的编译包括：

  • 对于 JVM、JS 和 Native 目标，包含 main 和 test 编译。

  • 对于 Android 目标，每个 Android 构建变体都有一个对应的编译。

如果除了生产代码和单元测试，还需要编译其他内容，例如集成测试或性能测试，可以创建自定义编译。

你可以在以下范围内配置产物的生成方式：

  • 一次配置项目中的所有编译。

  • 配置某一个目标的编译，因为一个目标可以具有多个编译。

  • 配置某一个具体编译。

有关适用于所有目标或特定目标的设置，请参阅编译参数列表和编译器选项。

配置所有编译

以下示例配置了一个适用于所有目标的公共编译器选项：


kotlin {
    compilerOptions {
        allWarningsAsErrors.set(true)
    }
}


kotlin {
    compilerOptions {
        allWarningsAsErrors = true
    }
}

配置某个目标的编译


kotlin {
    jvm {
        compilerOptions {
            jvmTarget.set(JvmTarget.JVM_1_8)
        }
    }
}


kotlin {
    jvm {
        compilerOptions {
            jvmTarget = JvmTarget.JVM_1_8
        }
    }
}

配置某一个编译


kotlin {
    jvm {
        val main by compilations.getting {
            compileTaskProvider.configure {
                compilerOptions {
                    jvmTarget.set(JvmTarget.JVM_1_8)
                }
            }
        }
    }
}


kotlin {
    jvm {
        compilations.main {
            compileTaskProvider.configure {
                compilerOptions {
                    jvmTarget = JvmTarget.JVM_1_8
                }
            }
        }
    }
}

创建自定义编译

如果除了生产代码和单元测试，还需要编译其他内容，例如集成测试或性能测试，就需要创建自定义编译。

对于自定义编译，所有依赖都需要手动配置。自定义编译的默认源集不会依赖 commonMain 和 commonTest 源集。

例如，要为 jvm 目标的集成测试创建自定义编译，可以在 integrationTest 和 main 编译之间建立 associateWith 关系：


kotlin {
    jvm {
        compilations {
            val main by getting
            val integrationTest by creating {
                // Import main and its classpath as dependencies and establish internal visibility
                associateWith(main)
                defaultSourceSet {
                    dependencies {
                        implementation(kotlin("test-junit"))
                        /* ... */
                    }
                }
            }

            // Create a test task to run the tests produced by this compilation:
            testRuns.create("integration") {
                // Configure the test task
                setExecutionSourceFrom(integrationTest)
            }
        }
    }
}


kotlin {
    jvm {
        compilations.create('integrationTest') {
            def main = compilations.main
            // Import main and its classpath as dependencies and establish internal visibility
            associateWith(main)
            defaultSourceSet {
                dependencies {
                    implementation kotlin('test-junit')
                    /* ... */
                }
            }
        }

        // Create a test task to run the tests produced by this compilation
        testRuns.create('integration') {
            // Configure the test task
            setExecutionSourceFrom(compilations.integrationTest)
        }
    }
}

关联编译后，主编译的输出会被添加为依赖，同时会在这些编译之间建立 internal 可见性。

其他情况下也可能需要自定义编译。例如，希望在最终产物中组合面向不同 JVM 版本的编译结果，或者已经在 Gradle 中配置了源集，希望将其迁移到多平台项目。

要为 android 创建自定义编译，请通过 Android Gradle 插件配置构建变体。

JVM 编译

在多平台项目中声明 jvm 目标后，Kotlin Multiplatform Gradle 插件会自动创建 Java 源集，并将其纳入 JVM 目标的编译。

通用源集不能包含 Java 资源，因此应将这些资源放在多平台项目中相应的子目录下。例如：

目前，Kotlin Multiplatform Gradle 插件会替换 Java 插件配置的部分任务：

  • JAR 任务：使用与产物名称相关的目标专用任务，替代标准的 jar。例如，声明 jvm() 目标时使用 jvmJar，声明 jvm("desktop") 时使用 desktopJar。

  • 测试任务：使用与产物名称相关的目标专用任务，例如 jvmTest，替代标准的 test。

  • 资源处理：由相应的编译任务处理资源，不再使用 *ProcessResources 任务。

声明目标时，这些任务会自动创建。不过，必要时也可以手动定义并配置 JAR 任务：


// Shared module's `build.gradle.kts` file
plugins {
    kotlin("multiplatform") version "2.4.21"
}

kotlin {
    // Specify the JVM target
    jvm {
        // Add the task for JAR generation
        tasks.named<Jar>(artifactsTaskName).configure {
            // Configure the task
        }
    }

    sourceSets {
        jvmMain {
            dependencies {
                // Add JVM-specific dependencies
            }
        }
    }
}


// Shared module's `build.gradle` file
plugins {
    id 'org.jetbrains.kotlin.multiplatform' version '2.4.21'
}

kotlin {
    // Specify the JVM target
    jvm {
        // Add the task for JAR generation
        tasks.named<Jar>(artifactsTaskName).configure {
            // Configure the task
        }
    }

    sourceSets {
        jvmMain {
            dependencies {
                // Add JVM-specific dependencies
            }
        }
    }
}

此目标由 Kotlin Multiplatform Gradle 插件发布，无需执行 Java 插件专用的步骤。

Kotlin 提供与原生语言的互操作能力，以及为某个具体编译配置互操作的 DSL。

Kotlin 只能使用带有 @objc 属性的 Swift 声明。

一个编译可以与多个原生库交互。可以通过定义文件中可用的属性，或构建文件中的 cinterops 块配置互操作：


kotlin {
    linuxX64 { // Replace with a target you need.
        compilations.getByName("main") {
            val myInterop by cinterops.creating {
                // Def-file describing the native API.
                // The default path is src/nativeInterop/cinterop/<interop-name>.def
                definitionFile.set(project.file("def-file.def"))
                
                // Package to place the Kotlin API generated.
                packageName("org.sample")
                
                // Options to be passed to compiler by cinterop tool.
                compilerOpts("-Ipath/to/headers")
              
                // Directories to look for headers.
                includeDirs.apply {
                    // Directories for header search (an equivalent of the -I<path> compiler option).
                    allHeaders("path1", "path2")
                    
                    // Additional directories to search headers listed in the 'headerFilter' def-file option.
                    // -headerFilterAdditionalSearchPrefix command line option equivalent.
                    headerFilterOnly("path1", "path2")
                }
                // A shortcut for includeDirs.allHeaders.
                includeDirs("include/directory", "another/directory")
            }
            
            val anotherInterop by cinterops.creating { /* ... */ }
        }
    }
}


kotlin {
    linuxX64 { // Replace with a target you need.
        compilations.main {
            cinterops {
                myInterop {
                    // Def-file describing the native API.
                    // The default path is src/nativeInterop/cinterop/<interop-name>.def
                    definitionFile = project.file("def-file.def")
                    
                    // Package to place the Kotlin API generated.
                    packageName 'org.sample'
                    
                    // Options to be passed to compiler by cinterop tool.
                    compilerOpts '-Ipath/to/headers'
                    
                    // Directories for header search (an equivalent of the -I<path> compiler option).
                    includeDirs.allHeaders("path1", "path2")
                    
                    // Additional directories to search headers listed in the 'headerFilter' def-file option.
                    // -headerFilterAdditionalSearchPrefix command line option equivalent.
                    includeDirs.headerFilterOnly("path1", "path2")
                    
                    // A shortcut for includeDirs.allHeaders.
                    includeDirs("include/directory", "another/directory")
                }
                
                anotherInterop { /* ... */ }
            }
        }
    }
}

Android 编译

Android 目标默认创建的编译与 Android 构建变体绑定：每个构建变体都会创建一个同名的 Kotlin 编译。

接着，对于各个变体编译时使用的每个 Android 源集，会创建一个 Kotlin 源集，其名称是在原源集名称前加上目标名称。例如，Android 源集 debug 和名为 android 的 Kotlin 目标，对应的 Kotlin 源集名为 androidDebug。这些 Kotlin 源集随后会被添加到相应变体的编译中。

默认源集 commonMain 会被添加到每个生产变体（应用或库）的编译中。同样，commonTest 源集会被添加到单元测试变体和插桩测试变体的编译中。

也支持使用 kapt 进行注解处理，但受当前限制影响，必须先创建 Android 目标，再配置 kapt 依赖。依赖需要配置在顶层 dependencies {} 块中，而不是 Kotlin 源集的依赖块中。


kotlin {
    android { /* ... */ }
}

dependencies {
    kapt("com.my.annotation:processor:1.0.0")
}

源集层级的编译

Kotlin 可以通过 dependsOn 关系构建源集层级。

如果源集 jvmMain 依赖源集 commonMain，则有以下关系：

  • 每当将 jvmMain 编译到某个目标时，commonMain 也会参与该编译，并被编译为相同目标的二进制格式，例如 JVM class 文件。

  • jvmMain 的源码能够“看到” commonMain 的声明，包括内部声明；也能够看到 commonMain 的依赖，即使这些依赖声明为 implementation。

  • jvmMain 可以为 commonMain 的预期声明提供平台专用实现。

  • commonMain 的资源始终会与 jvmMain 的资源一起处理和复制。

  • jvmMain 和 commonMain 的语言设置应保持一致。

语言设置按以下方式检查一致性：

  • jvmMain 设置的 languageVersion 应大于或等于 commonMain 的值。

  • jvmMain 应启用 commonMain 已启用的所有不稳定语言特性；缺陷修复类特性没有这一要求。

  • jvmMain 应使用 commonMain 所使用的所有实验性注解。

  • apiVersion、缺陷修复类语言特性和 progressiveMode 可以自由设置。

在 Gradle 中配置 Isolated Projects 功能

此功能为实验性功能，目前在 Gradle 中处于 pre-alpha 阶段。只能在 Gradle 8.10 或更高版本中使用，并且仅用于评估。此功能可能随时被移除或更改。欢迎在 YouTrack 中提供反馈。使用时需要显式选择启用，详见下文。

Gradle 提供 Isolated Projects 功能，通过相互“隔离”各个项目来提升构建性能。它将不同项目的构建脚本和插件隔离开来，使它们能够安全地并行运行。

要启用此功能，请按 Gradle 的说明设置系统属性。

有关 Isolated Projects 功能的更多信息，请参阅 Gradle 文档。
