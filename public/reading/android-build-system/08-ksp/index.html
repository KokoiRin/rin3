Kotlin 符号处理（Kotlin Symbol Processing，KSP）是面向 Kotlin 的源码生成框架。借助 KSP API，你可以创建处理器，检查源码中的静态信息，并据此生成新代码。最常见的用法是根据注解生成代码。

KSP 旨在简化轻量级编译器插件的开发。使用 KSP 构建的编译器插件称为符号处理器，简称处理器。KSP 通过定义清晰的 API 隔离编译器的变化，因此你无需花费太多精力维护处理器。不过，这种做法也有取舍。例如，基于 KSP 的处理器不能检查表达式或语句，也不能修改源代码。

基于 KSP 的插件通常用于以下场景：

  • 依赖注入（Dagger）

  • 序列化（Moshi）

  • 数据库管理（Room）

要了解如何创建第一个基于 KSP 的处理器，请参阅 KSP 入门。

KSP 如何参与编译过程

KSP 根据 Kotlin 语法，将 Kotlin 源码表示为具有层级关系的符号。处理器通过这些符号检查类、函数、属性和类型等声明。

KSP 对声明和类型信息进行建模，但不允许处理器访问表达式或函数体。

KSP 按以下方式参与编译过程：

  1. KSP 处理器分析源码和资源。

  2. 处理器生成源文件或其他输出。

  3. Kotlin 编译器将原始源码与生成的代码一起编译。

KSP 如何运行处理器

KSP 使用 SymbolProcessorProvider 的实现作为入口，创建 SymbolProcessor 实例：


interface SymbolProcessorProvider {
    fun create(environment: SymbolProcessorEnvironment): SymbolProcessor
}

SymbolProcessor 接口包含处理逻辑。KSP 调用 process() 函数，并提供一个 Resolver，处理器通过它访问源码中的符号：


interface SymbolProcessor {
    fun process(resolver: Resolver): List<KSAnnotated>
    fun finish() {}
    fun onError() {}
}

有关实现和注册处理器的分步说明，请参阅 KSP 入门。
