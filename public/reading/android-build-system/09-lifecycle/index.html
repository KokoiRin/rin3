构建生命周期是 Gradle 为了将构建脚本、源代码等转化为完成的工作而依次执行的各个阶段：先初始化构建环境，再配置项目，最后执行任务。

构建阶段

一个 Gradle 构建有三个不同的阶段。

Gradle 按顺序运行这些阶段：

阶段 1：初始化阶段 2：配置阶段 3：执行

- 查找 settings 文件
- 创建一个 Settings 实例
- 对 settings 文件求值，确定哪些项目以及哪些被包含的构建组成当前构建
- 为每个项目创建一个 Project 实例

- 对参与构建的每个项目的构建文件求值
- 对任务的配置（输入和输出）求值
- 为请求运行的任务创建任务图

- 调度并执行选定的任务

下面的例子展示了 settings 文件和构建文件中的哪些部分分别对应各个构建阶段：

settings.gradle.kts
rootProject.name = "basic"
println("This is executed during the initialization phase.")
build.gradle.kts
// Configuration Phase
println("This is executed during the configuration phase.")

tasks.register("configured") {
    println("This is also executed during the configuration phase.")
}

// Execution Phase
tasks.register("test") {
    doLast {
        println("This is executed during the execution phase.")
    }
}

// Configurations AND Execution Phase
tasks.register("testBoth") {
    println("This is executed during the configuration phase as well.")
    doFirst {
        println("This is executed first during the execution phase.")
    }
    doLast {
        println("This is executed last during the execution phase.")
    }
}

阶段 1：初始化

在初始化阶段，Gradle 会确定参与构建的项目集合（包括根项目和子项目）以及被包含的构建。

Gradle 首先对 settings 文件 settings.gradle(.kts) 求值，并实例化一个 Settings 对象。

随后，Gradle 会为构建所包含的每个项目实例化 Project 对象；这些项目通过 settings 文件中的 includeBuild() 或 include() 加入构建。

阶段 2：配置

在配置阶段，Gradle 会向初始化阶段找到的项目添加任务和其他属性。

Gradle 会根据任务之间的依赖关系构建任务图。

阶段 3：执行

在执行阶段，Gradle 运行任务。

Gradle 根据配置阶段生成的任务执行图确定要执行哪些任务。Gradle 可以并行执行任务。

任务图

作为构建编写者，你通过定义任务并声明任务之间的依赖关系来编写构建逻辑。Gradle 会根据这些信息，在配置阶段构建一个描述这些任务之间关系的任务图。

例如，项目中有 buildHtml、assembleDocs 和 createDocs 等任务。你声明 assembleDocs 依赖 buildHtml，createDocs 依赖 assembleDocs 后，Gradle 构建出的图会形成这样的顺序：buildHtml → assembleDocs → createDocs。

Gradle 会在执行任何任务之前构建任务图。

在构建的所有项目中，任务共同形成一个有向无环图（DAG）。

随着构建逻辑变得更复杂，你可能需要在特定构建阶段执行自定义操作。Gradle 提供了多个 API，让你能够监听生命周期中的关键事件，或对这些事件作出响应。
