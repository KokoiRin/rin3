增量编译

Kotlin Gradle 插件支持增量编译，并在 Kotlin/JVM 和 Kotlin/JS 项目中默认启用。增量编译会跟踪两次构建之间类路径中文件的变化，只编译受这些变化影响的文件。它可以与 Gradle 构建缓存配合使用，并支持编译规避。

对于 Kotlin/JVM，增量编译依赖类路径快照。快照记录模块的 API 结构，用于判断何时需要重新编译。为优化整个编译流程，Kotlin 编译器使用两种类路径快照：

  • 细粒度快照：包含属性、函数等类成员的详细信息。检测到成员级别的变化时，Kotlin 编译器只重新编译依赖于被修改成员的类。为保持性能，Kotlin Gradle 插件会为 Gradle 缓存中的 .jar 文件创建粗粒度快照。

  • 粗粒度快照：只包含类的 ABI 哈希。当 ABI 的某一部分发生变化时，Kotlin 编译器会重新编译所有依赖于该类的类。这适用于外部库等不经常变化的类。

Kotlin/JS 项目采用另一种基于历史文件的增量编译方式。

你可以通过以下几种方式禁用增量编译：

  • 对于 Kotlin/JVM，设置 kotlin.incremental=false。

  • 对于 Kotlin/JS 项目，设置 kotlin.incremental.js=false。

  • 使用命令行参数 -Pkotlin.incremental=false 或 -Pkotlin.incremental.js=false。

    此后每次构建都需要添加该参数。

禁用增量编译后，增量缓存会在构建结束后失效。首次构建始终不是增量构建。

有时，增量编译的问题在出错后经过几轮构建才会显现。可以使用构建报告跟踪代码变化与编译的历史，从而提交能够复现问题的缺陷报告。

要进一步了解当前增量编译方式的工作原理，以及它与旧方式的区别，请阅读我们的博客文章。

Gradle 构建缓存支持

Kotlin 插件使用 Gradle 构建缓存保存构建输出，供后续构建复用。

要禁用所有 Kotlin 任务的缓存，请将系统属性 kotlin.caching.enabled 设为 false，也就是在运行构建时添加参数 -Dkotlin.caching.enabled=false。

Gradle 配置缓存支持

Kotlin 插件使用 Gradle 配置缓存，在后续构建中复用配置阶段的结果，从而加快构建。

有关如何启用配置缓存，请参阅 Gradle 文档。启用此功能后，Kotlin Gradle 插件会自动开始使用它。

Kotlin 守护进程及其与 Gradle 的配合方式

Kotlin 守护进程的特点如下：

  • 与 Gradle 守护进程配合，完成项目编译。

  • 使用 IntelliJ IDEA 内置构建系统编译项目时，会独立于 Gradle 守护进程运行。

在 Gradle 的执行阶段，某个 Kotlin 编译任务开始编译源码时，Kotlin 守护进程就会启动。它会随 Gradle 守护进程一起停止，或者在连续两小时没有 Kotlin 编译工作后停止。

Kotlin 守护进程使用与 Gradle 守护进程相同的 JDK。

设置 Kotlin 守护进程的 JVM 参数

以下设置方式按优先级从低到高排列，后面的设置会覆盖前面的设置：

  • 从 Gradle 守护进程继承参数

  • kotlin.daemon.jvm.options 系统属性

  • kotlin.daemon.jvmargs 属性

  • kotlin 扩展

  • 针对具体任务的定义

从 Gradle 守护进程继承参数

默认情况下，Kotlin 守护进程会从 Gradle 守护进程继承一组特定参数；但直接为 Kotlin 守护进程指定的 JVM 参数会覆盖继承的参数。例如，如果在 gradle.properties 文件中添加以下 JVM 参数：


org.gradle.jvmargs=-Xmx1500m -Xms500m -XX:MaxMetaspaceSize=1g

那么 Kotlin 守护进程的 JVM 参数会包含以下内容：


-Xmx1500m -XX:ReservedCodeCacheSize=320m -XX:MaxMetaspaceSize=1g -XX:UseParallelGC -ea -XX:+UseCodeCacheFlushing -XX:+HeapDumpOnOutOfMemoryError -Djava.awt.headless=true -Djava.rmi.server.hostname=127.0.0.1 --add-exports=java.base/sun.nio.ch=ALL-UNNAMED

要进一步了解 Kotlin 守护进程处理 JVM 参数时的默认行为，请参阅 Kotlin 守护进程如何处理 JVM 参数。

kotlin.daemon.jvm.options 系统属性

如果 Gradle 守护进程的 JVM 参数中包含 kotlin.daemon.jvm.options 系统属性，可以在 gradle.properties 文件中按以下方式使用：


org.gradle.jvmargs=-Dkotlin.daemon.jvm.options=-Xmx1500m,Xms500m

传入参数时，请遵循以下规则：

  • 只有 Xmx、XX:MaxMetaspaceSize 和 XX:ReservedCodeCacheSize 这几个参数前面需要使用减号 -。

  • 使用逗号（,）分隔参数，不要加空格。空格之后的参数会传给 Gradle 守护进程，而不是 Kotlin 守护进程。

如果同时满足以下所有条件，Gradle 会忽略这些属性：

  • Gradle 使用 JDK 1.9 或更高版本。

  • Gradle 版本介于 7.0 和 7.1.1 之间，包含这两个版本。

  • Gradle 正在编译 Kotlin DSL 脚本。

  • Kotlin 守护进程尚未运行。

要解决这一问题，请将 Gradle 升级到 7.2 或更高版本，或者使用 kotlin.daemon.jvmargs 属性，详见下一节。

kotlin.daemon.jvmargs 属性

你可以在 gradle.properties 文件中添加 kotlin.daemon.jvmargs 属性：


kotlin.daemon.jvmargs=-Xmx1500m -Xms500m

请注意，如果这里和 Gradle 的 JVM 参数中都没有指定 ReservedCodeCacheSize，Kotlin Gradle 插件会采用默认值 320m：


-Xmx1500m -XX:ReservedCodeCacheSize=320m -Xms500m

kotlin 扩展

你可以在 kotlin 扩展中指定参数：


kotlin {
    kotlinDaemonJvmArgs = listOf("-Xmx486m", "-Xms256m", "-XX:+UseParallelGC")
}


kotlin {
    kotlinDaemonJvmArgs = ["-Xmx486m", "-Xms256m", "-XX:+UseParallelGC"]
}

针对具体任务的定义

你可以为某个具体任务指定参数：


tasks.withType<CompileUsingKotlinDaemon>().configureEach {
    kotlinDaemonJvmArguments.set(listOf("-Xmx486m", "-Xms256m", "-XX:+UseParallelGC"))
}


tasks.withType(CompileUsingKotlinDaemon).configureEach { task ->
    task.kotlinDaemonJvmArguments = ["-Xmx1g", "-Xms512m"]
}

在这种情况下，任务执行时可能会启动一个新的 Kotlin 守护进程实例。详见 Kotlin 守护进程如何处理 JVM 参数。

Kotlin 守护进程如何处理 JVM 参数

配置 Kotlin 守护进程的 JVM 参数时，请注意：

  • 如果不同子项目或任务使用不同的 JVM 参数，同时运行多个 Kotlin 守护进程实例是正常现象。

  • 只有当 Gradle 运行相关编译任务，而现有 Kotlin 守护进程没有使用相同的 JVM 参数时，才会启动新的实例。假设项目包含很多子项目：大多数只需要一定大小的 Kotlin 守护进程堆内存，而其中一个模块需要很大的堆内存，但很少编译。在这种情况下，应为这个模块单独指定 JVM 参数。这样，只有处理该模块的开发者才会启动堆内存更大的 Kotlin 守护进程。

    如果已经有一个正在运行的 Kotlin 守护进程，其堆大小足以处理本次编译请求，即使请求中的其他 JVM 参数有所不同，也会复用该守护进程，而不会启动新实例。

如果没有指定以下参数，Kotlin 守护进程会从 Gradle 守护进程继承它们：

  • -Xmx

  • -XX:MaxMetaspaceSize

  • -XX:ReservedCodeCacheSize。如果既没有指定，也没有继承，默认值为 320m。

Kotlin 守护进程具有以下默认 JVM 参数：

  • -XX:UseParallelGC。只有未指定其他垃圾收集器时，才会应用这个参数。

  • -ea

  • -XX:+UseCodeCacheFlushing

  • -Djava.awt.headless=true

  • -D{java.servername.property}={localhostip}

  • --add-exports=java.base/sun.nio.ch=ALL-UNNAMED。只有 JDK 16 或更高版本才会应用这个参数。

Kotlin 守护进程的默认 JVM 参数列表可能随版本而变化。你可以使用 VisualVM 等工具，检查 Kotlin 守护进程等运行中的 JVM 进程的实际设置。

回退到旧版编译器

从 Kotlin 2.0.0 开始，默认使用 K2 编译器。

如果要在 Kotlin 2.0.0–2.3.21 中使用旧版编译器，可以选择以下任一方式：

  • 在 build.gradle.kts 文件中，将语言版本设为 1.9。

    或者

  • 使用编译器选项 -language-version 1.9。

从 Kotlin 2.4.0 开始，无法再回退到旧版编译器。

要进一步了解 K2 编译器的优势，请参阅 K2 编译器迁移指南。

试用最新语言版本

从 Kotlin 2.0.0 开始，可以在 gradle.properties 文件中设置 kotlin.experimental.tryNext 属性，试用最新语言版本。使用该属性后，Kotlin Gradle 插件会将语言版本设为当前 Kotlin 版本所默认使用的语言版本的下一版。例如，Kotlin 2.0.0 的默认语言版本为 2.0，设置该属性后使用的语言版本就是 2.1。

你也可以运行以下命令：


./gradlew assemble -Pkotlin.experimental.tryNext=true

在构建报告中，可以查看每个任务编译时使用的语言版本。

构建报告

构建报告包含各编译阶段的耗时，以及无法进行增量编译的原因。当编译耗时过长，或者同一项目的编译耗时出现差异时，可以通过构建报告排查性能问题。

Gradle 构建扫描以单个 Gradle 任务为分析粒度；相比之下，Kotlin 构建报告能帮助你更高效地排查构建性能问题。

对于耗时较长的编译，分析构建报告通常能帮助你解决以下两类问题：

  • 本次构建不是增量构建。分析原因，并修复根本问题。

  • 本次构建是增量构建，但耗时仍然过长。可以尝试重新组织源文件，例如拆分大文件，将不同类保存到各自的文件中，重构大型类，将顶层函数声明到不同文件中等。

构建报告还会显示项目使用的 Kotlin 版本。此外，从 Kotlin 1.9.0 开始，你也可以在 Gradle 构建扫描中查看编译代码时使用的是哪一种编译器。

了解如何阅读构建报告，以及 JetBrains 如何使用构建报告。

启用构建报告

要启用构建报告，请在 gradle.properties 中声明构建报告输出的保存位置：


kotlin.build.report.output=file

输出支持以下值，也支持将它们组合使用：

选项

说明

file

将构建报告以便于阅读的格式保存到本地文件。默认路径为 ${project_folder}/build/reports/kotlin-build/${project_name}-timestamp.txt。

single_file

将构建报告以对象格式保存到指定的本地文件。

build_scan

将构建报告保存到构建扫描的 custom values 部分。请注意，Gradle Enterprise 插件会限制自定义值的数量和长度。在大型项目中，部分值可能会丢失。

http

通过 HTTP(S) 提交构建报告。使用 POST 方法，以 JSON 格式发送指标。你可以在 Kotlin 仓库中查看当前发送的数据格式，并在这篇博客文章中找到 HTTP 端点示例。

json

将构建报告以 JSON 格式保存到本地文件。默认路径为 ${project_folder}/build/reports/kotlin-build/${project_name}-build-<date-time>-<index>.json。

以下列出了 kotlin.build.report 可用的选项：


# Required outputs. Any combination is allowed
kotlin.build.report.output=file,single_file,http,build_scan,json

# Mandatory if single_file output is used. Where to put reports 
# Use instead of the deprecated `kotlin.internal.single.build.metrics.file` property
kotlin.build.report.single_file=my/directory/path/some_filename

# Optional. Output directory for file-based or JSON reports. Default: build/reports/kotlin-build/
kotlin.build.report.file.output_dir=kotlin-reports

# Optional. Label for marking your build report (for example, debug parameters)
kotlin.build.report.label=some_label

仅适用于 HTTP 的选项：


# Mandatory. Where to post HTTP(S)-based reports
kotlin.build.report.http.url=http://127.0.0.1:8080

# Optional. User and password if the HTTP endpoint requires authentication
kotlin.build.report.http.user=someUser
kotlin.build.report.http.password=somePassword

# Optional. Add a Git branch name of a build to a build report
kotlin.build.report.http.include_git_branch.name=true|false

# Optional. Add compiler arguments to a build report
# If a project contains many modules, its compiler arguments in the report can be very heavy and not that helpful
kotlin.build.report.include_compiler_arguments=true|false

自定义值的数量上限

Kotlin 构建报告使用 Gradle 的自定义值收集构建扫描统计信息。你和不同的 Gradle 插件都可以向自定义值写入数据。自定义值的数量有上限，当前最大数量请参阅构建扫描插件文档。

如果项目规模较大，这类自定义值可能会很多。当数量超过上限时，日志中会出现以下消息：


Maximum number of custom values (1,000) exceeded

要减少 Kotlin 插件产生的自定义值，可以在 gradle.properties 中设置以下属性：


kotlin.build.report.build_scan.custom_values_limit=500

关闭项目属性与系统属性的收集

HTTP 构建统计日志可能包含一些项目属性和系统属性。这些属性会影响构建行为，因此将它们记录在构建统计中有助于排查问题。不过，它们也可能包含敏感数据，例如密码或项目的完整路径。

你可以在 gradle.properties 中添加 kotlin.build.report.http.verbose_environment 属性，禁用这类统计信息的收集。

JetBrains 不会收集这些统计信息。报告保存在哪里，由你自己决定。
