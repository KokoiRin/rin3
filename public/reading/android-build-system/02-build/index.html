一般来说，构建脚本（build.gradle(.kts)）会具体描述构建配置、任务和插件。

每个 Gradle 构建都至少包含一个构建脚本。

构建脚本

构建脚本可以是用 Groovy 编写的 build.gradle 文件，也可以是用 Kotlin 编写的 build.gradle.kts 文件。

Gradle 脚本只接受 Groovy DSL 和 Kotlin DSL 这两种语言。

在多项目构建中，每个子项目通常都有自己的构建文件，位于该子项目的根目录。

在构建脚本中，通常需要指定：

  • 插件：扩展 Gradle 功能的工具，可用于编译代码、运行测试或打包产物等任务。

  • 依赖：项目使用的外部库和工具。

具体来说，构建脚本中主要有两类依赖：

  • Gradle 和构建脚本的依赖：包括 Gradle 本身或构建脚本逻辑所需的插件和库。

  • 项目依赖：项目源代码为了正确编译和运行而直接需要的库。

下面来看一个例子，并逐项说明：

app/build.gradle.kts
plugins {   (1)
    // Apply the application plugin to add support for building a CLI application in Java.
    application
}
dependencies {  (2)
    // Use JUnit Jupiter for testing.
    testImplementation(libs.junit.jupiter)

    testRuntimeOnly("org.junit.platform:junit-platform-launcher")

    // This dependency is used by the application.
    implementation(libs.guava)
}
application {   (3)
    // Define the main class for the application.
    mainClass = "org.example.App"
}
app/build.gradle
plugins {   (1)
    // Apply the application plugin to add support for building a CLI application in Java.
    id 'application'
}
dependencies {  (2)
    // Use JUnit Jupiter for testing.
    testImplementation libs.junit.jupiter

    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'

    // This dependency is used by the application.
    implementation libs.guava
}
application {   (3)
    // Define the main class for the application.
    mainClass = 'org.example.App'
}
1添加插件。
2添加依赖。
3使用约定属性。

1. 添加插件

插件可以扩展 Gradle 的功能，并为项目添加任务。

将插件加入构建称为应用插件，这会使额外的功能可用。

app/build.gradle.kts
plugins {   (1)
    // Apply the application plugin to add support for building a CLI application in Java.
    application
}
app/build.gradle
plugins {   (1)
    // Apply the application plugin to add support for building a CLI application in Java.
    id 'application'
}

application 插件方便你创建可执行的 JVM 应用程序。

应用 Application 插件时，也会隐式应用 Java 插件。java 插件为项目添加 Java 编译、测试和打包功能。

2. 添加依赖

项目需要使用外部库来进行编译、运行和测试。

在这个例子中，项目使用 JUnit Jupiter 进行测试，并在应用程序的主要代码中使用 Google 的 Guava 库：

app/build.gradle.kts
dependencies {  (2)
    // Use JUnit Jupiter for testing.
    testImplementation(libs.junit.jupiter)

    testRuntimeOnly("org.junit.platform:junit-platform-launcher")

    // This dependency is used by the application.
    implementation(libs.guava)
}
app/build.gradle
dependencies {  (2)
    // Use JUnit Jupiter for testing.
    testImplementation libs.junit.jupiter

    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'

    // This dependency is used by the application.
    implementation libs.guava
}

3. 使用约定属性

插件会为项目添加任务，也会添加属性和方法。

application 插件定义了用于打包和分发应用程序的任务，例如 run 任务。

Application 插件提供了一种声明 Java 应用程序主类的方式；执行代码时需要知道这个主类。

app/build.gradle.kts
application {   (3)
    // Define the main class for the application.
    mainClass = "org.example.App"
}
app/build.gradle
application {   (3)
    // Define the main class for the application.
    mainClass = 'org.example.App'
}

在这个例子中，主类（即程序开始执行的位置）是 org.example.App。

构建脚本在构建的配置阶段求值，是定义某个项目或子项目构建逻辑的主要入口。除了应用插件和设置约定属性，构建脚本还可以：

  • 声明依赖

  • 配置任务

  • 引用共享设置（来自版本目录或约定插件）
