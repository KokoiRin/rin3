Enable app optimization with R8

Android 技能

R8 Analyzer

使用 R8 Analyzer 这项 Android 技能，分析构建文件，并找出冗余、范围过宽或已被其他规则涵盖的保留规则。
要通过 Android CLI 安装这项技能，请运行：
android skills add r8-analyzer

为了给用户带来更好的体验，应优化应用，尽量减小体积并提高运行速度。我们的应用优化器名为 R8，它会移除未使用的代码和资源、重写代码以改善运行时性能，并执行其他优化。对用户而言，这意味着：

  • 启动更快。
  • 内存占用更少。
  • 渲染与运行时性能更好。
  • ANR 更少。
重要提示：应始终为应用的 release 构建启用优化；但通常不希望为测试或库启用优化。有关在测试中使用 R8 的更多信息，请参阅测试优化结果并排查问题。有关从库中启用 R8 的更多信息，请参阅面向库作者的优化指南。

R8 优化概览

R8 通过多个阶段来优化应用的体积和速度。主要操作包括：

  • 代码缩减（也称为 tree shaking）：R8 会识别并移除应用及其依赖库中不可达的代码。它会分析应用的入口点，例如清单中定义的 Activities 或 Services，构建代码引用图，并移除其中没有被引用的部分。

  • 逻辑优化：R8 会重写代码，提高执行效率并减少开销。主要技术包括：

    • 方法内联：R8 用被调用方法的实际方法体替换方法调用处的代码。这既能消除函数调用的开销，也能让 R8 继续进行其他优化。

    • 类合并：R8 会把一组类和接口合并为一个类，减少应用中的类数量，从而减轻内存压力并提高启动速度。

  • 混淆（也称为 minification）：为了减小 DEX 文件的体积，R8 会缩短类、字段和方法的名称。例如，com.example.MyActivity 可能变为 a.b.a。

从 Android Gradle Plugin（AGP）8.12.0 开始，R8 也会在优化阶段处理资源。详情请参阅优化后的资源缩减。

启用优化

要启用应用优化，请根据项目使用的 AGP 版本选择合适的 DSL。我们建议只对发布前要测试的最终版本启用应用优化，通常就是 release 构建。这是因为优化会增加项目的构建时间，而且它对代码的修改可能使调试更困难。

AGP 9.3 及更高版本

要在 AGP 9.3 及更高版本中启用应用优化，请执行以下操作：

  • 在应用级构建脚本中，为 release 构建的 optimization 块设置 enable = true。
  • 将保留规则写入 src/<variant>/keepRules 源集内以 .keep 为后缀的文件中，例如 src/main/keepRules/custom-rules.keep。
注意：更新后的 DSL 会同时启用代码优化和资源优化。它还包含一组适用于 Android 平台的默认保留规则，等同于 "proguard-android-optimize.txt"。如果不想使用这些默认规则，请参阅不使用默认规则。

Kotlin

android {
    buildTypes {
        release {
            optimization {
                enable = true // Enables code and resource optimizations.
            }
        }
    }
}

Groovy

android {
    buildTypes {
        release {
            optimization {
                enable = true // Enables code and resource optimizations.
            }
        }
    }
}

低于 AGP 9.3 的版本使用的旧版 DSL

要启用应用优化，请在应用级构建脚本的 release 构建配置中设置 isMinifyEnabled = true，以启用代码优化；并设置 isShrinkResources = true，以启用资源优化。我们建议始终同时启用这两个设置。

旧版 DSL（Kotlin）

android {
    buildTypes {
        release {

            // Enables code optimizations.
            isMinifyEnabled = true

            // Enables resource shrinking.
            isShrinkResources = true

            proguardFiles(
                // Default file with automatically generated optimization rules.
                getDefaultProguardFile("proguard-android-optimize.txt"),

                ...
            )
            ...
        }
    }
    ...
}

旧版 DSL（Groovy）

android {
    buildTypes {
        release {

            // Enables code optimizations.
            minifyEnabled = true

            // Enables resource shrinking.
            shrinkResources = true

            // Default file with automatically generated optimization rules.
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt')

            ...
        }
    }
}

改善 R8 的优化效果

R8 带来的性能收益，与它能够优化的代码范围直接相关。要尽可能发挥 R8 的作用，请遵循以下最佳实践：

  • 启用 R8 的完整模式。
  • 启用混淆、优化和缩减。
  • 启用资源缩减和优化后的资源缩减。
  • 细化保留规则，尽可能允许 R8 优化类、字段和方法。

可以使用 R8 Configuration Analyzer 来帮助细化保留规则。

R8 Configuration Analyzer 可以帮助你：

  • 通过其报告提供的指标，跟踪并改善 R8 配置的整体质量。
  • 找出范围最广、阻止优化最多的保留规则。
  • 了解这些规则阻止了哪些优化，以便进一步细化规则。

R8 Configuration Analyzer 从 AGP 9.3.0-alpha05 或 R8 9.3.7-dev 开始提供。详情请参阅分析 R8 配置。

优化资源缩减，进一步减小应用体积

AGP 8.12.0 引入了优化后的资源缩减，旨在把资源优化和代码优化结合起来，进一步减小应用体积并提高运行速度。在此之前，Android Asset Packaging Tool（AAPT2）生成的保留规则，实际上使资源缩减与代码优化相互独立，因此经常保留彼此引用、但实际上不可达的代码或资源。

采用优化后的资源缩减后，资源会被视为程序代码的一部分，一同构成引用图。如果一组代码或资源没有被引用，也没有保留规则保护，就可以将其移除。

启用优化后的资源缩减

要在 AGP 8.12 或 8.13 中启用新的资源缩减优化管线，请在项目的 gradle.properties 文件中加入以下内容：

android.r8.optimizedResourceShrinking=true

如果使用 AGP 9.0.0 或更新版本，就无需设置 android.r8.optimizedResourceShrinking=true。在构建配置中启用 isShrinkResources = true 后，就会自动应用优化后的资源缩减。

核对并配置 R8 优化设置

要让 R8 使用完整的优化能力，请检查项目的 gradle.properties 文件；如果其中存在下面这一行，请将其移除：

android.enableR8.fullMode=false

请注意，启用应用优化后，堆栈轨迹可能变得难以理解，尤其是在 R8 重命名了类或方法的情况下。要获得能够正确对应源代码的堆栈轨迹，请参阅恢复原始堆栈轨迹。

启用 R8 后，还应创建 Startup Profile，进一步改善启动性能。

如果启用应用优化后出现错误，可以采用以下解决办法：

  • 添加保留规则，让部分代码保持不变。
  • 逐步采用优化。
  • 更新代码，采用更适合优化的库。
警告：替换或修改 R8 输出的工具，可能对运行时性能产生负面影响。R8 会在代码层面、DEX 布局以及正确生成 Baseline Profile 等方面，谨慎地引入并测试多种优化。其他工具生成或修改 DEX 文件时，可能破坏这些优化，或以其他方式造成性能下降。

如果希望提高构建速度，请参阅配置 R8 的运行方式，了解如何根据自身环境配置 R8。

AGP 与 R8 各版本的行为变化

下表列出了不同 Android Gradle Plugin（AGP）和 R8 编译器版本引入的主要功能。

AGP 版本引入的功能
9.3简化的 DSL：新的 optimization {} 块需要的配置更少：优化后的资源缩减始终启用，默认 Android 保留规则则可选择不使用。

keepRules 源集：如果使用新的 DSL，必须将保留规则放在 src/<variant>/keepRules 源集内以 .keep 为后缀的文件中。旧版 DSL 也兼容这些源集。

KMP（Kotlin MultiPlatform）使用方规则：KMP 不再要求设置 publish = true，并支持在 src/<variant>/keepRules 源集中使用 .keep 扩展名。

请注意，旧版 DSL 仍然受支持。
9.1默认重新打包类：R8 默认会重新打包类，将它们移到顶层的未命名包，以进一步压缩 DEX，不再需要指定 -repackageclasses 选项。有关其工作方式以及如何停用这一行为，请参阅全局选项。
9.0优化后的资源缩减：默认启用，由 android.r8.optimizedResourceShrinking 控制。优化后的资源缩减将资源缩减整合进代码优化管线，从而生成体积更小、运行更快的应用。它同时优化代码与资源的引用关系，识别并移除那些仅被未使用代码引用的资源，相比之前相互独立的优化流程有明显改善。

对于不同设备形态版本之间共享大量资源和代码的应用，这尤其有用，实测应用体积缩减幅度超过 50%。体积缩减后，下载更小、安装更快，用户也能得到更快的启动、更好的渲染和更少的 ANR。

库规则过滤：不再支持在库的使用方规则中配置全局选项，例如 -dontobfuscate；应用会将这些选项过滤掉。详情请参阅添加全局选项。

Kotlin 空值检查：默认优化，由 -processkotlinnullchecks 控制。这个版本还显著提高了构建速度。详情请参阅用于进一步优化的全局选项。

优化指定包：可以通过 packageScope 优化指定包。这项支持目前属于实验性质。详情请参阅使用 packageScope 优化指定包。

默认启用优化：不再支持 getDefaultProguardFile("proguard-android.txt")，因为该文件包含应避免使用的 -dontoptimize。应改用 "proguard-android-optimize.txt"。如果需要在整个应用中禁用优化，请手动将该标志添加到 proguard 文件。
8.12优化后的资源缩减：首次提供支持，由 android.r8.optimizedResourceShrinking 控制。优化后的资源缩减将资源缩减整合进代码优化管线。在这个 AGP 版本中，必须手动启用。

Logcat 堆栈还原：支持在 Android Studio 的 Logcat 窗口中自动还原堆栈轨迹。
8.6改进的堆栈还原：对于所有 minSdk 级别，默认都支持还原文件名和行号。此前在 8.2 版本中，需要 minSdk 为 26 或更高版本。

更新 R8 有助于确保混淆构建中的堆栈轨迹能够清楚、方便地阅读。这个版本改善了行号与源文件的映射，让 Android Studio Logcat 等工具更容易将崩溃还原到原始源代码。
8.0默认启用完整模式：R8 完整模式提供了显著增强的优化能力，并且默认启用。可以通过 android.enableR8.fullMode=false 停用它。
7.0提供完整模式：通过 android.enableR8.fullMode=true 可选择启用。完整模式会对代码使用反射和其他动态特性的方式作出更严格的假设，从而实施更强的优化。它能减小应用体积并改善性能，但可能需要额外的保留规则，防止必要代码被移除。

配合其他构建系统使用 R8

AGP 是 Android 应用推荐使用且得到官方支持的构建系统。不过，你也可能使用 Bazel 等其他构建系统。如果使用 Bazel，可以将 R8 整合进构建管线，对应用进行缩减、混淆和优化。

有关使用 Bazel 优化 Android 应用的信息，请参阅 Bazel 的 rules_android 文档。请注意，Bazel 并未得到 Android 应用开发的官方支持。
