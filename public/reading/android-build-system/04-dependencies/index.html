Gradle 内置了对依赖管理的支持。

依赖管理是一种自动化技术，用于声明和解析项目所需的外部资源，也就是依赖。

依赖包括支持项目构建的 JAR、库或源代码。它们在构建脚本中声明。

Gradle 会自动下载、缓存和解析这些依赖，让你无需手动管理。它还会处理版本冲突，并支持灵活的版本声明方式。

声明依赖

要为项目添加依赖，请在 build.gradle(.kts) 文件的 dependencies {} 块中指定它。

下面的 build.gradle(.kts) 文件为项目添加了两个依赖：

build.gradle.kts
plugins {
    id("java-library")  (1)
}

dependencies {
    implementation("com.google.guava:guava:32.1.2-jre") (2)
    api("org.apache.juneau:juneau-marshall:8.2.0")      (3)
}
build.gradle
plugins {
    id("java-library")  (1)
}

dependencies {
    implementation("com.google.guava:guava:32.1.2-jre") (2)
    api("org.apache.juneau:juneau-marshall:8.2.0")      (3)
}
1应用 Java Library 插件。
2添加对 Google Guava 库的依赖，用于生产代码。
3添加对 Apache Juneau Marshall 库的依赖，用于库代码。

在 Gradle 中，依赖会被分组放入称为配置（configuration）的容器中。配置决定依赖在何时、何处以及以何种方式使用，也就是定义依赖的作用范围。在上面的例子中：

  • implementation 用于编译和运行生产代码所需的依赖。

  • api 用于应当暴露给库使用方的依赖。

应用某些插件后，Gradle 会自动为项目创建相应的配置，让你可以直接使用。

例如，应用 java 或 java-library 会添加 implementation、api、compileOnly、runtimeOnly 和 testImplementation 等配置，让你无需额外设置就可以在正确的位置声明依赖。

Android Gradle Plugin（AGP）会添加感知变体的配置，例如 debugImplementation、releaseImplementation、androidTestImplementation，甚至还包括按构建类型和产品风味划分的配置，例如 freeDebugImplementation。

Kotlin Multiplatform（KMP）会创建作用于特定源集的配置，例如 commonMainImplementation、commonTestImplementation、androidMainImplementation、iosArm64MainImplementation 等，让你可以准确地在代码运行的位置声明依赖。

查看项目依赖

可以使用 dependencies 任务检查依赖树。例如，要查看 :app 项目的依赖：

$ ./gradlew :app:dependencies

使用版本目录

版本目录提供了一种集中且一致的方式，用于管理整个构建中的依赖坐标和版本。你不必在每个 build.gradle(.kts) 文件中直接声明版本，而是在 libs.versions.toml 文件中统一定义一次。

这样可以更方便地：

  • 在子项目之间共享常用的依赖声明

  • 避免重复声明和版本不一致

  • 在大型项目中强制统一依赖和插件的版本

版本目录通常包含四个部分：

  1. [versions]：声明插件和库将引用的版本号。

  2. [libraries]：定义构建文件中使用的库。

  3. [bundles]：定义一组依赖。

  4. [plugins]：定义插件。

下面是一个例子：

gradle/libs.versions.toml
[versions]
guava = "32.1.2-jre"
juneau = "8.2.0"

[libraries]
guava = { group = "com.google.guava", name = "guava", version.ref = "guava" }
juneau-marshall = { group = "org.apache.juneau", name = "juneau-marshall", version.ref = "juneau" }

将此文件命名为 libs.versions.toml，放在项目的 gradle/ 目录下。Gradle 会自动识别它，并通过构建脚本中的 libs 访问器提供其内容。IntelliJ 和 Android Studio 等 IDE 也会读取这些元数据，以提供代码补全。

定义完成后，就可以在构建文件中直接引用这些别名：

build.gradle.kts
dependencies {
    implementation(libs.guava)
    api(libs.juneau.marshall)
}
build.gradle
dependencies {
    implementation(libs.guava)
    api(libs.juneau.marshall)
}
