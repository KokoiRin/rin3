ViewModel、UI State 与状态所有权

页面不是状态仓库。Activity、Fragment、View 或 Composable 负责显示和转发事件；屏幕级状态持有者负责把业务事实整理成 UI 可直接消费的状态。

学习主线

找到唯一权威状态，让 UI state 向下流动、用户事件向上返回；ViewModel 解决屏幕级状态和配置变化，不替代持久化，也不持有 UI 对象。

一个完整闭环

ViewModel持有屏幕级状态
→
UI State不可变快照
→
UIView / Compose 渲染
→
用户事件拖动、点击、输入
→
ViewModel处理并产生新状态

UI 只依据当前 state 渲染，用户操作转换成明确事件。ViewModel 处理事件、调用需要的业务边界并发布新 state。这样旋转重建后的 UI 可以重新订阅同一状态，而不是从散落的 View 字段拼回页面。

ViewModel 能做什么，不能做什么

能力结论边界
屏幕级 state holder适合状态属于某个 ViewModelStoreOwner 的 scope
跨配置变化缓存状态适合Activity/Fragment 重建时仍可取得同一实例
封装相关业务逻辑适合复杂领域逻辑仍可下沉到独立用例或 Repository
跨进程死亡保住全部数据不能单独做到组合 SavedStateHandle 与持久数据源
持有 View / Activity不应该会把短生命周期 UI 对象泄漏到更长作用域

状态提升到“真正共同读写它”的最低层

如果一个把手只在单个自定义 View 内部读写，局部状态可以留在那里。如果时间轴、播放头、预览和提交按钮都依赖同一 durationMs，它应该提升到这些消费者共同的状态所有者，而不是让四个组件各存一份。

权威事实

某一时刻只有一个明确来源能决定当前值，其他层观察或派生。

UI State

为当前屏幕准备的可渲染快照，可包含加载、错误和内容。

用户事件

描述用户意图，如 DurationChanged，而不是直接从 UI 到处改字段。

副作用

导航、Toast、写盘等不是稳定 UI 快照，要有明确的一次性处理边界。

selectedIndex 不一定是业务事实列表会重排、刷新或过滤。若业务需要恢复“选中了哪个贴纸”，稳定 ID 往往比位置下标更可靠；UI 可以从 ID 和当前列表派生 index。

最小代码：不可变 UI State + 明确事件

data class DurationUiState(
    val selectedStickerId: String? = null,
    val durationMs: Long = 3_000L,
    val canApply: Boolean = true,
)

class DurationViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(DurationUiState())
    val uiState: StateFlow<DurationUiState> = _uiState.asStateFlow()

    fun onDurationChanged(durationMs: Long) {
        _uiState.update { current ->
            current.copy(
                durationMs = durationMs.coerceIn(500L, 15_000L),
                canApply = true,
            )
        }
    }
}
@Composable
fun DurationRoute(viewModel: DurationViewModel = viewModel()) {
    val state by viewModel.uiState.collectAsStateWithLifecycle()

    DurationScreen(
        state = state,
        onDurationChanged = viewModel::onDurationChanged,
    )
}

在 View 页面中也可以观察同一个 ViewModel，只是绑定方式不同。架构主线不依赖 UI 工具包：宿主读取 state、渲染，再把事件交回状态所有者。

动手练习

练习 1：消灭双写

Activity、滑动条和 ViewModel 各有一个 durationMs，滑动时三处互相回调同步。把它改成单向数据流，写出谁保存权威值、谁只渲染、事件怎样返回。

展开参考答案

若它是屏幕级编辑状态，由 ViewModel 保存权威 durationMs；Activity/Fragment 只订阅并绑定 UI；滑动条展示 state，并把 onDurationChanged(value) 事件交给 ViewModel。若最终提交后成为业务事实，再由 ViewModel 调用领域边界写入 Repository，而不是让 View 直接写 NLE。

练习 2：找最低共同所有者

两个兄弟 Composable 都需要 selectedStickerId，父级还要据此启用提交按钮。状态至少应提升到哪里？需要立刻进入 ViewModel 吗？

展开参考答案

至少提升到三个消费者的最低共同父级。如果它只影响一个可复用组件内部且无需屏幕级业务逻辑，不一定进 ViewModel；若它参与屏幕提交、恢复或多个区域协作，ViewModel 更合适。
