Intent、Task 与返回栈

Intent 表达“我要做什么或去哪里”；Task 把一次用户任务中的 Activity 排成栈；Back 与 Home 对这条用户路径做的是两件不同的事。

学习主线

先画实例栈，再推导生命周期。不要只看当前显示哪个类，也不要一开始就背启动模式和 flags 组合表。

Task 是用户为完成某件事而交互的一组 Activity；back stack 按打开顺序保存它们。默认情况下，新 Activity 压到栈顶并获得焦点，前一个 Activity 留在栈中并停止。Back 移除栈顶 Activity，前一个恢复。

Intent 有两种基本表达方式

显式 Intent

明确指定目标组件，常用于应用内部从 A 打开已知的 B。

隐式 Intent

描述 action、data 等能力，让系统查找能处理它的组件，常用于跨应用打开网页或分享。

// 显式：目标类已知
startActivity(Intent(this, EditorActivity::class.java))

// 隐式：只表达“查看这个网页”
val intent = Intent(Intent.ACTION_VIEW, Uri.parse("https://developer.android.com"))
startActivity(intent)

隐式 Intent 的接收方通过 Manifest 中的 intent filter 声明能力。发送方不是直接调用接收方类，而是让系统解析可处理请求的组件。

Back、Home、图标入口的差别

用户动作对当前 Activity / Task 的典型影响用户语义
Back当前栈顶 Activity 出栈并结束，前一个恢复回到上一层用户路径
Home整个 Task 转到后台，栈通常保留暂时离开，不等于逐页返回
点击应用图标把已有 Task 带到前台，或创建新 Task 并打开根 Activity进入该应用的主任务

Manifest 中带 `MAIN` action 与 `LAUNCHER` category 的 Activity 是启动器图标入口。它定义“从桌面进入时谁是根”，不意味着应用只能从这里启动；深链、分享或其他应用也可能进入别的 Activity。

启动模式与 flags 先学问题模型它们本质上在回答：要不要新建实例？放进哪个 Task？已有实例上方的页面要不要清掉？本阶段先画目标栈和期望 Back 行为，再查最小配置；不要背一张脱离场景的组合表。

最小代码：A → B → C，并观察实例

class PageActivity : ComponentActivity() {
    override fun onCreate(state: Bundle?) {
        super.onCreate(state)
        val page = intent.getStringExtra("page") ?: "A"
        Log.d("BackStackDemo", "$page created: ${hashCode()}")

        setContent {
            Button(onClick = {
                val next = when (page) { "A" -> "B"; "B" -> "C"; else -> null }
                next?.let {
                    startActivity(Intent(this, PageActivity::class.java).putExtra("page", it))
                }
            }) { Text("当前 $page，打开下一页") }
        }
    }
}

这个练习为了观察“同一 Activity 类也能产生多个实例”。页面类相同，不代表返回栈里只有一个对象。

动手练习

练习 1：画栈，不猜页面

A 打开 B，B 打开 C。分别写出此时按一次 Back、按 Home 后点图标返回、连续按三次 Back 后的栈变化。

展开参考答案

一次 Back：`[A,B,C] → [A,B]`；Home 后点图标通常是已有 `[A,B,C]` Task 回前台；连续 Back 会依次移除 C、B、A，Task 结束或回到之前的任务。具体自定义导航仍需以实现为准。

练习 2：选择 Intent

“应用内部打开已知编辑页”“让任意浏览器打开帮助网页”“把一张图片分享给其他应用”分别适合显式还是隐式 Intent？

展开参考答案

已知编辑页用显式 Intent；打开网页和跨应用分享通常用隐式 Intent，分别描述 VIEW 或 SEND 能力，并提供正确的 URI、MIME type 与必要授权。
