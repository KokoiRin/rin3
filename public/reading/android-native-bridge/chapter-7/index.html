View 树、事件分发与绘制

View 页面不是一张静态 XML 图。运行时它是一棵对象树：父节点约束孩子的大小和位置，也参与决定一串触摸事件最终交给谁。

一串触摸事件怎样找到消费者

dispatchTouchEvent分发当前 MotionEvent
→
父容器判断onInterceptTouchEvent
→
目标子 View继续接收事件序列
→
onTouchEvent消费 DOWN / MOVE / UP

父 ViewGroup 的 onInterceptTouchEvent() 返回 true 时，事件不再交给子 View，而由父容器自己的 onTouchEvent() 处理。若父容器在事件序列中途开始拦截，先前的子目标通常会收到 ACTION_CANCEL，让它终止按压或拖动状态。

不要逐个 MotionEvent 孤立思考一次手势通常从 ACTION_DOWN 开始，经过多个 ACTION_MOVE，以 ACTION_UP 或 ACTION_CANCEL 结束。消费者必须维护整段序列的一致状态。
class TimelineLayout(context: Context, attrs: AttributeSet?) :
    FrameLayout(context, attrs) {

    private var startX = 0f

    override fun onInterceptTouchEvent(event: MotionEvent): Boolean {
        when (event.actionMasked) {
            MotionEvent.ACTION_DOWN -> startX = event.x
            MotionEvent.ACTION_MOVE -> {
                val horizontalDrag = kotlin.math.abs(event.x - startX) > 24f
                if (horizontalDrag) return true
            }
        }
        return false
    }

    override fun onTouchEvent(event: MotionEvent): Boolean {
        // 示例：父容器接管横向时间轴拖动
        return true
    }
}

示例只展示拦截模型。真实代码应使用像素密度与 touch slop，处理多指、取消、父子冲突和可访问性，不应把 24f 当成通用阈值。

measure、layout、draw 分别回答什么

阶段核心问题父子关系
measure每个 View 应该多大？父级向下给约束，子级记录测量尺寸
layout每个 View 放在哪里？父级根据已测尺寸定位每个孩子
draw最终画什么？遍历树绘制背景、内容与子节点

Android 的布局过程先 measure、再 layout；绘制随后遍历树渲染。invalidate() 请求重绘，requestLayout() 请求重新测量/布局，它们的成本和语义不同。一个只改颜色的操作通常不需要重新测量整棵树。

练习 2：父子手势冲突

父容器负责横向滑动时间轴，子 View 负责点击贴纸。用户 DOWN 在子 View，之后明显横向 MOVE。父容器若接管，应发生什么？

展开参考答案

父容器先观察序列，超过合适阈值后在 onInterceptTouchEvent() 返回 true；子 View 收取消信号并清理点击/按压状态；后续事件由父容器处理。阈值和方向锁定要避免轻微抖动误拦截。
