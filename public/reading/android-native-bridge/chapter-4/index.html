第 4 章 · 恢复模型

配置变化、进程死亡与状态恢复

恢复不是“把整个旧页面对象保存下来”。正确做法是保留足以重建用户体验的最小事实，并从权威数据源重新派生其余内容。

学习主线

先判断状态要跨越哪种破坏：重组、配置重建、进程死亡还是应用重启；再选择 UI 内存、ViewModel、saved state 或持久存储。

用户看到“同一页”，系统可能已换了对象

旧 Activity用户正在编辑
→
配置变化例如旋转
→
旧实例销毁对象字段失效
→
新实例创建重新建立 UI
→
恢复状态用户继续任务

配置变化通常会重建 Activity，以便重新加载适合新配置的资源。用户没有“退出编辑页”，但旧实例确实结束了。仅保存在 Activity 字段里的值会随对象一起消失。

四种状态容器不是竞争关系

容器能跨过什么适合保存不适合保存
UI / View 内存状态当前对象存活期间动画瞬时值、当前按压态需要恢复的用户进度
ViewModel配置变化屏幕级 UI state、派生逻辑跨进程死亡的唯一副本
saved state / SavedStateHandle系统重建宿主或进程后的恢复小型、可序列化、重建页面必需的事实Bitmap、大列表、完整业务对象
本地持久存储进程死亡和应用重启草稿、数据库记录、业务事实每帧变化的短暂视觉状态

一个页面通常组合使用它们：数据库保存草稿事实，saved state 保存当前选中的草稿 ID 和游标位置，ViewModel 根据两者构造 UI state，UI 再保存只与本次绘制相关的瞬时值。

ViewModel 不是进程级保险箱它能让新 Activity 在配置变化后取得同一个 ViewModel 实例，但进程死亡会清掉内存。需要跨进程恢复的事实必须进入 saved state 或持久存储。

先问“恢复事实是什么”

不要保存一张 Bitmap 只为了恢复“用户选中了第 7 张贴纸”。保存 `selectedStickerId = 7`，再从 Repository 或磁盘重新加载图片。前者是恢复事实，后者是可重建产物。

事实

用户选择、输入、业务提交等无法从别处可靠推导的信息。

派生值

可由事实重新计算，例如格式化文字、缩略图、总时长显示。

缓存

为了速度保存的副本，丢失后能回源，不应冒充权威数据。

资源对象

View、Context、Bitmap 等通常有生命周期或体积约束，不应直接塞入 saved state。

最小代码：SavedStateHandle 保存恢复事实

data class EditorUiState(
    val selectedStickerId: String?,
    val durationMs: Long,
)

class EditorViewModel(
    private val savedStateHandle: SavedStateHandle,
) : ViewModel() {
    val uiState: StateFlow<EditorUiState> =
        savedStateHandle.getStateFlow(
            "editor_state",
            EditorUiState(selectedStickerId = null, durationMs = 3_000L),
        )

    fun selectSticker(id: String) {
        savedStateHandle["editor_state"] = uiState.value.copy(
            selectedStickerId = id,
        )
    }
}

示例刻意只保存小型恢复事实。若 `durationMs` 已经提交为业务草稿，它的权威来源应该是 Repository / 本地存储；`SavedStateHandle` 只帮助快速恢复屏幕，不应制造第二套业务真相。

动手练习

练习 1：给状态找家

为“按钮按下波纹”“当前选中贴纸 ID”“尚未提交但需进程死亡后恢复的输入文字”“已保存草稿”“预览 Bitmap”选择容器，并解释理由。

展开参考答案

波纹属于 UI 内存；选中 ID 可在 ViewModel，并按恢复需要进入 saved state；未提交文字若用户期望恢复，可进入 saved state 或自动草稿；已保存草稿进持久存储；Bitmap 通常重建或缓存，不放 saved state。

练习 2：设计恢复最小集

一个编辑页包含草稿 ID、20 张缩略图、当前选中下标、播放头毫秒值和一个 NLE 对象。写出进程死亡后恢复页面需要保存的最小事实。

展开参考答案

通常保存草稿 ID、选中项的稳定 ID（优于易漂移下标）和用户需要继续的播放头位置；缩略图和 NLE 对象从草稿或数据源重建。具体还要看播放头是否属于用户可感知且应恢复的编辑进度。
