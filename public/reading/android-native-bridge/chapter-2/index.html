项目结构、Manifest 与资源

项目目录不是文件收纳习惯，而是构建系统、Android 系统和资源匹配器共同读取的一份契约。

学习主线

Gradle 决定“怎样构建”，source set 决定“哪些输入参与”，Manifest 告诉系统“应用提供什么”，资源目录让同一个逻辑适配不同设备配置。

先读懂最小项目树

MyApp/
├── settings.gradle.kts          // 项目包含哪些 module
├── build.gradle.kts             // 项目级插件或公共配置
└── app/
    ├── build.gradle.kts         // Android module 的构建配置
    └── src/
        ├── main/
        │   ├── AndroidManifest.xml
        │   ├── kotlin/.../MainActivity.kt
        │   └── res/
        │       ├── layout/activity_main.xml
        │       ├── drawable/...
        │       └── values/strings.xml
        ├── test/                // 本机 JVM 测试
        └── androidTest/         // 设备或模拟器测试

test 运行快，但真实 Android 系统调用需要 fake、stub 或模拟；androidTest 能访问设备环境，速度更慢。选择测试位置时先问“这个行为是否必须由真实 Android 环境提供”，而不是按文件名习惯摆放。

Manifest 是系统侧目录，不是业务配置大全

Manifest 声明组件、权限、设备能力和系统需要知道的应用元数据。一个 Activity 类即使写进源码，如果系统需要启动它却没有对应声明，系统也无法从这个入口创建它。

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application android:label="@string/app_name">
        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
    </application>
</manifest>
不要把所有版本信息都塞进 ManifestminSdk、targetSdk 等通常由 Gradle 构建配置提供，构建时参与 Manifest 合并。看到最终 Manifest 与源码文件不同并不奇怪，应检查合并后的结果和来源。

资源 ID 把代码与设备配置隔开

构建工具为资源生成 ID，例如 R.string.app_name、R.drawable.logo、R.layout.activity_main。代码引用的是稳定的逻辑名称，运行时资源系统再根据语言、方向、屏幕等配置选择最匹配的具体文件。

位置保存什么为什么不直接写死在 Kotlin
values/strings.xml文字资源支持翻译与配置匹配
drawable/图片或 drawable XML支持密度和状态变体
layout/View 层级 XML把 View 结构与 Activity 代码分开
layout-land/横屏布局变体系统自动选择，不靠业务代码到处 if

Compose 应用不一定使用 XML 布局，但仍会使用 res 下的字符串、图标等资源。因此“Compose 不用资源系统”也是误解。

最小代码：从资源到 View

// res/values/strings.xml
<resources>
    <string name="screen_title">贴纸时长</string>
</resources>

// Activity 中使用资源
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        findViewById<TextView>(R.id.title).setText(R.string.screen_title)
    }
}

练习 1：为文件找位置

把“纯 Kotlin 业务单测”“入口 Activity 声明”“横屏 XML 布局”“设备上的 UI 测试”分别放进最合适的位置。

展开参考答案

依次是 src/test、src/main/AndroidManifest.xml、src/main/res/layout-land、src/androidTest。

练习 2：补齐入口

新建一个 Activity 并让它成为桌面图标入口。你至少需要在哪两个文件中做什么？

展开参考答案

在 Kotlin 源码中创建 Activity 子类；在 Manifest 的 下声明它，并用 MAIN action 与 LAUNCHER category 标记启动器入口。若使用 Android 12 及以上目标版本且组件含 intent filter，还要明确 android:exported。

主动回忆

  1. settings.gradle.kts 与 module 的 build.gradle.kts 各决定什么？
  2. test 与 androidTest 的证据能力有什么差别？
  3. 为什么同一个 R.string.title 能在不同语言设备上显示不同文字？

项目迁移题：在真实 Android 工程中找到贴纸时长或文字模式所属 module，沿着 settings → module 构建文件 → Manifest / source set 说出它怎样进入最终应用。
