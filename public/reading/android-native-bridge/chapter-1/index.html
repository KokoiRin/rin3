Android 应用是怎么运行起来的

先放下“程序从 main() 开始”的习惯：Android 系统会在需要时创建应用进程，并从被请求的组件进入你的代码。

学习主线

安装包提供代码、资源与组件声明；系统根据用户或系统事件找到组件，必要时创建进程，再在主线程调用组件生命周期。

先跟一遍用户点击图标

点击图标Launcher 发出请求
→
系统解析入口Manifest 的 MAIN / LAUNCHER
→
创建进程若应用尚未运行
→
创建 Activity回调 onCreate()
→
显示并交互onStart() / onResume()

这条链里，Launcher 不是直接调用你的 MainActivity.main()。它向 Android 系统表达一个启动意图，系统根据安装时掌握的组件声明找到目标类。若进程不存在，系统先创建 Linux 进程和主线程；随后实例化 Activity 并调用生命周期回调。

APK、AAB 与正在运行的应用不是一回事

APK

设备安装并在运行时使用的应用包，包含当前设备需要的代码和资源。

AAB

发布格式，不能直接安装。应用商店可据此为具体设备生成优化后的 APK。

进程

组件需要运行时由系统创建；应用离开前台不等于进程立即消失。

应用沙箱

默认情况下，每个应用拥有独立 Linux 用户 ID、进程和文件权限边界。

先纠正一个常见说法“关闭页面就是退出进程”不准确。Activity 实例、Task、应用进程是三层不同对象；系统可以销毁某个 Activity，也可以保留后台进程，还可以在需要内存时终止整个进程。

四类组件是四种系统入口

组件它解决的系统问题先记住的例子
Activity承载一次有界面的用户交互拍摄页、编辑页、设置页
Service执行没有页面的持续或跨进程能力用户可感知的后台音乐播放
BroadcastReceiver接收系统或应用广播事件，入口应保持轻量收到某类系统状态变化后安排后续工作
ContentProvider以 URI 和统一接口发布、访问数据系统联系人、对外共享一张图片

它们不是“必须全部用到”的架构清单。关键是理解：Android 允许系统或其他应用从不同组件进入你的应用，因此应用不能假设永远从某个首页按固定顺序启动。

最小代码：让系统进入 Activity

下面代码本身没有 main()。它依赖 Manifest 声明和系统回调：

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            Text("Android 系统已经进入 MainActivity")
        }
    }
}

真正的因果顺序是：组件被声明 → 启动请求命中组件 → 系统创建实例 → 调用 onCreate() → 你的代码提供 UI。

动手练习

练习 1：排列启动链

把以下词语排成因果链：onCreate()、用户点击图标、系统创建应用进程、解析入口 Activity、页面显示。

展开参考答案

用户点击图标 → 系统解析入口 Activity → 若需要则创建应用进程 → 创建 Activity 并调用 onCreate() → 页面显示。注意：进程可能已存在，所以“创建进程”是条件步骤。

练习 2：选择组件

分别为“编辑视频页面”“其他应用读取你授权分享的图片”“系统事件到达后做极少量分发”选择最贴近的组件。

展开参考答案

依次是 Activity、ContentProvider、BroadcastReceiver。真实产品还会有更多配套类，但题目考的是系统入口的业务定位。
