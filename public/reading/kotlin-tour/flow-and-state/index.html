Flow 与状态

Flow 表达随时间到来的多个值；StateFlow 表达当前状态，SharedFlow 表达共享广播。关键是先确定谁拥有状态。

阅读约定

本章是基于 Kotlin 官方资料整理翻译的结构化精读，不是逐段完整翻译。保留项目阅读所需的核心概念、关键边界和代表性代码，暂缓与当前学习目标关系较弱的高级细节。

本章主线

读 Flow 代码要分清上游生产、操作符变换、下游收集，以及冷流何时启动、热流由哪个作用域维持。

1. 从一个值走向一串值

fun observeCards(): Flow<List<Card>> = repository.cards
    .map { cards -> cards.filter(Card::isVisible) }
    .distinctUntilChanged()

挂起函数通常在一次调用中返回一个结果；Flow<T> 可以随时间发出多个 T。流水线由生产者、若干中间操作符和收集者组成。

2. 冷流：收集才开始

val updates = flow {
    emit(loadInitial())
    emitAll(watchChanges())
}

updates.collect { render(it) }

普通 Flow 通常是冷的：每个收集者都会启动一遍上游。看到某个函数返回 Flow，不要假设工作已经开始；要继续找到 collect、first、launchIn、stateIn 等终端位置。

3. StateFlow：始终有“当前值”

private val _state = MutableStateFlow(ScreenState())
val state: StateFlow<ScreenState> = _state

fun select(id: ItemId) {
    _state.update { it.copy(selectedId = id) }
}

StateFlow 是热的状态容器，始终有一个当前 value，新订阅者会立即拿到最新状态。常见边界是内部持有可变的 MutableStateFlow，对外只暴露只读 StateFlow。

4. SharedFlow：共享广播，不等于状态

SharedFlow 也是热流，但不要求一定有当前值。它适合多个订阅者共享通知或数据流。若业务问题是“界面现在是什么状态”，优先建模为 StateFlow；若是“发生了一次通知”，才考虑事件流，同时明确无人订阅时是否允许丢失。

5. 把冷流转成热状态

val state: StateFlow<ScreenState> = repository.items
    .map(::toScreenState)
    .stateIn(
        scope = scope,
        started = SharingStarted.WhileSubscribed(5_000),
        initialValue = ScreenState.Loading
    )

stateIn 的关键不是函数名，而是三个决策：由哪个 Scope 维持、什么时候启动/停止、订阅前的初始状态是什么。这三项共同决定资源和生命周期。

6. 操作符表达时间语义

  • map：转换每次发出的值。
  • combine：任一输入变化时，用各自最新值计算。
  • flatMapLatest：新输入到来时取消旧的子流。
  • collectLatest：新值到来时取消仍在处理的旧值。
  • catch：处理上游异常，但不应吞掉取消。
容易误用
  • 把一次性事件塞进 StateFlow，旋转屏幕或重新订阅后重复消费。
  • 把 MutableStateFlow 公开出去，任何调用方都能改状态。
  • 只看 Flow 的声明，不追踪最终在哪个 Scope 中收集，导致重复订阅或资源泄漏。
