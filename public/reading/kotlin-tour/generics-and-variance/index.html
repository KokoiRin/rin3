泛型：in、out 与 where

Kotlin 中的类可以拥有类型参数，就像在 Java 中一样：


class Box<T>(t: T) {
    var value = t
}

要创建此类类的实例，只需提供类型参数：


val box: Box<Int> = Box<Int>(1)

如果编译器能够推断出类型参数（例如，通过构造函数的参数），则无需显式指定它们：


val box = Box(1) // 1 的类型是 Int，因此编译器推断出它是 Box<Int>

型变

Java 类型系统中最棘手的一个方面是通配符类型（参见 Java 泛型常见问题解答）。Kotlin 没有通配符类型；取而代之的是声明处型变和类型投影。

Java 中的型变与通配符

让我们思考一下，Java 为什么需要这些神秘的通配符。首先，Java 中的泛型是不变型的，这意味着 List<String> 不是 List<Object> 的子类型。如果 List 不是不变型的，那它就和 Java 的数组没什么两样，因为以下代码虽然能编译通过，但在运行时会引发异常：


// Java
List<String> strs = new ArrayList<String>();

// Java 会在编译时在此处报告类型不匹配。
List<Object> objs = strs;

// 如果它没有报告呢？
// 那么我们就能将一个 Integer 放入一个 String 列表中。
objs.add(1);

// 然后在运行时，Java 会抛出
// 一个 ClassCastException：Integer 无法转换为 String
String s = strs.get(0);

Java 禁止此类操作，以确保运行时安全。但这会带来一些影响。例如，考虑 Collection 接口中的 addAll() 方法。该方法的签名是什么？直观来看，你会这样写：


// Java
interface Collection<E> ... {
    void addAll(Collection<E> items);
}

那样的话，你就无法执行以下操作（而这完全是安全的）：


// Java

// 如果采用对 addAll 的简单声明，以下代码将无法编译：
// Collection<String> 不是 Collection<Object> 的子类型
void copyAll(Collection<Object> to, Collection<String> from) {
    to.addAll(from);
}

正因如此，addAll() 的实际签名如下：


// Java
interface Collection<E> ... {
    void addAll(Collection<? extends E> items);
}

通配符类型参数 ? extends E 表示该方法接受由 E 或 E 的子类型对象组成的集合，而不仅仅是 E 本身。这意味着你可以安全地从 items 中读取 E（该集合的元素是 E 的子类的实例），但无法向其中写入，因为你不知道哪些对象符合 E 的那个未知子类型。作为这一限制的回报，你将获得期望的行为：Collection<String> 是 Collection<? extends Object> 的子类型。换言之，带有 extends 上界的通配符会使类型变为协变。

理解其工作原理的关键其实很简单：如果你只能从一个集合中取出元素，那么使用一个由 String 组成的集合并从中读取 Object 是完全没问题的。反之，如果你只能向集合中添加元素，那么取一个由 Object 组成的集合并向其中添加 String 也是可以的：在 Java 中有 List<? super String> 类型，它接受 String 或其任何超类型。

后者被称为逆变性，你只能在 List<? super String> 上调用那些以 String 为参数的方法（例如，你可以调用 add(String) 或 set(int, String)）。如果你在 List<T> 中调用某个返回 T 的方法，你得到的不是 String，而是 Object。

约书亚·布洛赫（Joshua Bloch）在其著作《高效Java编程（第3版）》中对此问题进行了很好的阐述（第31条：“使用有界通配符来提高API的灵活性”）。他将仅用于读取的对象称为“生产者”（Producers），将仅用于写入的对象称为“消费者”（Consumers）。他建议：

“为了获得最大的灵活性，请在表示生产者或消费者的输入参数上使用通配符类型。”

随后，他提出了以下记忆法：PECS 分别代表“生产者继承（Producer-Extends）”和“消费者超类（Consumer-Super）”。

如果你使用一个生产者对象，例如 List<? extends Foo>，则不允许对该对象调用 add() 或 set()，但这并不意味着它是不可变的：例如，没有任何东西能阻止你调用 clear() 来移除列表中的所有项，因为 clear() 根本不接受任何参数。

通配符（或其他类型的型变）唯一能保证的是类型安全。不可变性则是完全另一回事。

声明处型变

假设有一个泛型接口 Source<T>，它不包含任何以 T 为参数的方法，只有返回 T 的方法：


// Java
interface Source<T> {
    T nextT();
}

那么，将 Source<String> 实例的引用存储在类型为 Source<Object> 的变量中是完全安全的——因为没有需要调用的消费者方法。但 Java 并不知道这一点，仍然禁止这样做：


// Java
void demo(Source<String> strs) {
    Source<Object> objects = strs; // !!! 在 Java 中不允许
    // ...
}

要解决这个问题，你应该声明类型为 Source<? extends Object> 的对象。这样做毫无意义，因为你可以像之前一样在这样的变量上调用所有相同的方法，因此更复杂的类型并没有带来任何额外价值。但编译器并不知道这一点。

在 Kotlin 中，有一种方法可以向编译器说明这种情况。这被称为“声明处型变”：你可以对 Source 的类型参数 T 添加注解，以确保它仅由 Source<T> 的成员返回（生成），且绝不会被消耗。要实现这一点，请使用 out 修饰符：


interface Source<out T> {
    fun nextT(): T
}

fun demo(strs: Source<String>) {
    val objects: Source<Any> = strs // 这没问题，因为 T 是一个输出参数
    // ...
}

一般规则如下：当类 C 的类型参数 T 被声明为 out 时，它只能出现在 C 的成员中的输出位置，但返回类型 C<Base> 可以安全地是 C<Derived> 的超类型。

换言之，可以说类 C 在参数 T 上是协变的，或者说 T 是一个协变的类型参数。你可以将 C 视为 T 的生产者，而非 T 的消费者。

out 修饰符被称为“型变注解”，由于它在类型参数声明处提供，因此属于“声明处型变”。这与 Java 的“使用处型变”形成对比——在 Java 中，类型使用处的通配符会使类型具有协变性。

除了 out 之外，Kotlin 还提供了一个互补的型变注解：in。它使类型参数变为逆变，这意味着该类型只能被消耗，而永远不会被生成。逆变类型的典型示例是 Comparable：


interface Comparable<in T> {
    operator fun compareTo(other: T): Int
}

fun demo(x: Comparable<Number>) {
    x.compareTo(1.0) // 1.0 的类型是 Double，它是 Number 的子类型
    // 因此，你可以将 x 赋值给一个类型为 Comparable<Double> 的变量
    val y: Comparable<Double> = x // 好的！
}

“in”和“out”这两个词似乎不言自明（因为它们在 C# 中已经成功使用了一段时间），因此上述助记词其实并不必要。事实上，它可以以更高的抽象层次重新表述：

存在式 转换：in 表示消费者，out 表示生产者！:-)

类型投影

使用处型变: 类型投影

虽然将类型参数 T 声明为 out 并避免在使用处出现子类型问题非常简单，但有些类实际上无法被限制为仅返回 T！Array 就是一个很好的例子：


class Array<T>(val size: Int) {
    operator fun get(index: Int): T { ... }
    operator fun set(index: Int, value: T) { ... }
}

该类在 T 上的变体既不能是协变的，也不能是逆变的。这会带来一定的灵活性限制。考虑以下函数：


fun copy(from: Array<Any>, to: Array<Any>) {
    assert(from.size == to.size)
    for (i in from.indices)
        to[i] = from[i]
}

该函数旨在将一个数组中的元素复制到另一个数组中。让我们尝试在实际中应用它：


val ints: Array<Int> = arrayOf(1, 2, 3)
val any = Array<Any>(3) { "" }
copy(ints, any)
// ^ 类型为 Array<Int>，但预期为 Array<Any>

这里你会遇到同样熟悉的问题：Array<T> 在 T 中是不变型的，因此 Array<Int> 和 Array<Any> 彼此都不是对方的子类型。为什么不行？原因依然在于 copy 可能会产生意料之外的行为，例如，它可能会尝试将 String 写入 from，而如果你实际传入了一个 Int 的数组，稍后就会抛出 ClassCastException 异常。

要禁止 copy 函数向 from 写入数据，你可以这样做：


fun copy(from: Array<out Any>, to: Array<Any>) { ... }

这是类型投影，这意味着 from 并非一个简单的数组，而是一个受限（投影）的数组。你只能调用返回类型参数 T 的方法，在本例中，这意味着你只能调用 get()。这是我们实现协变的方法，它与 Java 的 Array<? extends Object> 对应，但略微简单一些。

你也可以使用 in 对类型进行投影：


fun fill(dest: Array<in String>, value: String) { ... }

Array<in String> 对应于 Java 中的 Array<? super String>。这意味着你可以将 String、CharSequence 或 Object 的数组传递给 fill() 函数。

星投影

有时你可能希望表明自己对类型参数一无所知，但仍希望以安全的方式使用它。这里所说的安全方式，是指定义该泛型类型的投影，使得该泛型类型的每个具体实例化都是该投影的子类型。

Kotlin 为此提供了所谓的星号投影语法：

  • 对于 Foo<out T : TUpper>，其中 T 是具有上界 TUpper 的协变类型参数，Foo<*> 等同于 Foo<out TUpper>。这意味着当 T 未知时，你可以安全地从 Foo<*> 中读取 TUpper 的值。

  • 对于 Foo<in T>，其中 T 是具有上界 Foo<*> 的协变类型参数，Foo<in Nothing> 等同于 Foo<*>。这意味着当 T 未知时，无法以安全的方式向 Foo<*> 写入任何内容。

  • 对于 Foo<T : TUpper>，其中 T 是一个上界为 TUpper 的不变类型参数，Foo<*> 在读取值时等同于 Foo<out TUpper>，在写入值时等同于 Foo<in Nothing>。

如果一个泛型类型有多个类型参数，则每个类型参数都可以独立进行投影。例如，如果类型声明为 interface Function<in T, out U>，你可以使用以下星投影：

  • Function<*, String> 表示 Function<in Nothing, String>。

  • Function<Int, *> 表示 Function<Int, out Any?>。

  • Function<*, *> 表示 Function<in Nothing, out Any?>。

星投影与 Java 的原始类型非常相似，但更加安全。

捕获类型

当你使用类型投影（如 out T 或 in T）时，编译器会在内部将未知具体类型表示为 捕获类型。捕获类型是一种已知上下界但具体类型未知的类型。

捕获类型是不可指称的，因此你不能直接在 Kotlin 代码中写出它们。相反，你最常在编译器诊断信息中看到捕获类型，例如 CapturedType(out X)。例如，以下类型不匹配的诊断信息中就包含一个捕获类型：


val array: Array<out CharSequence> = arrayOf("str")
val item: Int = array.get(0)
// 初始化器类型不匹配：预期为 'Int'，实际为 'CapturedType(out CharSequence)'

编译器在读取操作中使用捕获类型的上界，在写入操作中使用其下界来确定哪些值是类型安全的：


// 投影类型为 Array<out CharSequence>
val array: Array<out CharSequence> = arrayOf("Kotlin")

// get() 读取操作使用了捕获类型的上界 CharSequence
val item = array.get(0)

// set() 写入操作使用了捕获类型的上界 CharSequence，
// 这将导致错误
array.set(0, "New value")
// 接收者类型 'Array<out CharSequence>' 包含 out 投影
// 这禁止使用 'fun set(index: Int, value: T): Unit'

在此示例中：

  • 变量 array 的投影类型为 Array<out CharSequence>。编译器将投影类型参数 out CharSequence 表示为一个捕获类型，其上界为 CharSequence，下界为 Nothing。

  • 对于 get() 操作，编译器将捕获类型近似为其上界 CharSequence，并推断 CharSequence 为 item 的类型。

  • 对于 set() 操作，捕获类型的下界为 Nothing。由于 Nothing 没有实例，将值赋给投影类型是不类型安全的，会导致错误。

泛型函数

不仅类可以包含类型参数。函数也可以。类型参数位于函数名之前：


fun <T> singletonList(item: T): List<T> {
    // ...
}

fun <T> T.basicToString(): String { // 扩展函数
    // ...
}

要调用泛型函数，请在调用位置的函数名后指定类型参数：


val l = singletonList<Int>(1)

如果类型参数可以从上下文中推断出来，则可以省略，因此以下示例同样有效：


val l = singletonList(1)

泛型约束

可以替换给定类型参数的所有可能类型的集合可能会受到泛型约束的限制。

上界

最常见的约束类型是上界，它对应于 Java 中的 extends 关键字：


fun <T : Comparable<T>> sort(list: List<T>) {  ... }

冒号后指定的类型是上界，表示只有 Comparable<T> 的子类型才能替换 T。例如：


sort(listOf(1, 2, 3)) // 好的。Int 是 Comparable<Int> 的子类型
sort(listOf(HashMap<Int, String>())) // 错误：HashMap<Int, String> 不是 Comparable<HashMap<Int, String>> 的子类型

默认的上界（如果未指定）是 Any?。尖括号内只能指定一个上界。如果同一个类型参数需要多个上界，则需要单独的 where 子句：


fun <T> copyWhenGreater(list: List<T>, threshold: T): List<String>
    where T : CharSequence,
          T : Comparable<T> {
    return list.filter { it > threshold }.map { it.toString() }
}

传入的类型必须同时满足 where 子句的所有条件。在上例中，T 类型必须同时实现 CharSequence 和 Comparable。

绝对不可为空的类型

为了更方便地与泛型 Java 类和接口进行互操作，Kotlin 支持将泛型类型参数声明为“绝对不可空”。

要将泛型类型 T 声明为“绝对不可空”，请使用 & Any 声明该类型。例如：T & Any。

一个绝对不可空的类型必须包含一个可空的 上界。

声明绝对不可空类型最常见的用例是，当你想要重写一个包含 @NotNull 作为参数的 Java 方法时。例如，考虑 load() 方法：


import org.jetbrains.annotations.*;

public interface Game<T> {
    public T save(T x) {}
    @NotNull
    public T load(@NotNull T x) {}
}

要成功在 Kotlin 中重写 load() 方法，需要将 T1 声明为绝对不可空类型：


interface ArcadeGame<T1> : Game<T1> {
    override fun save(x: T1): T1
    // T1 绝对是非空的
    override fun load(x: T1 & Any): T1 & Any
}

仅使用 Kotlin 时，你通常无需显式声明绝对不可空的类型，因为 Kotlin 的类型推断会自动为你处理这一点。

类型擦除

Kotlin 对泛型声明用法进行的类型安全检查是在编译时完成的。在运行时，泛型类型的实例不保留任何关于其实际类型参数的信息。这种类型信息被称为“被擦除”。例如，Foo<Bar> 和 Foo<Baz?> 的实例会被擦除为仅 Foo<*>。

泛型类型检查与强制类型转换

由于类型擦除，在运行时无法通过通用方法检查泛型类型的实例是否是使用特定的类型参数创建的，且编译器禁止进行诸如 ints is List<Int> 或 list is T（类型形参）之类的 is 检查。不过，你可以通过星号投影类型来检查实例：


if (something is List<*>) {
    something.forEach { println(it) } // 这些项的类型为 `Any?`
}

同样地，当你已经对实例的类型参数进行了静态检查（在编译时）时，你可以进行 is 检查或涉及类型中非泛型部分的类型转换。请注意，这种情况下省略了尖括号：


fun handleStrings(list: MutableList<String>) {
    if (list is ArrayList) {
        // `list` 被智能转换为 `ArrayList<String>`
    }
}

对于不考虑类型参数的强制类型转换，可以使用相同的语法但省略类型参数：list as ArrayList。

泛型函数调用的类型实参同样仅在编译时进行检查。在函数体内部，类型形参不能用于类型检查，且对类型形参（foo as T）的类型转换不会被检查。唯一的例外是带有 具型参数 的内联函数，其实际类型实参会在每个调用位置被内联。这使得对类型形参的类型检查和强制类型转换成为可能。但是，对于在检查或强制类型转换中使用的泛型类型的实例，上述限制仍然适用。例如，在类型检查 arg is T 中，如果 arg 本身是泛型类型的实例，则其类型实参仍会被擦除。


//sampleStart
inline fun <reified A, reified B> Pair<*, *>.asPairOf(): Pair<A, B>? {
    if (first !is A || second !is B) return null
    return first as A to second as B
}

val somePair: Pair<Any?, Any?> = "items" to listOf(1, 2, 3)


val stringToSomething = somePair.asPairOf<String, Any>()
val stringToInt = somePair.asPairOf<String, Int>()
val stringToList = somePair.asPairOf<String, List<*>>()
val stringToStringList = somePair.asPairOf<String, List<String>>() // 虽然能编译通过，但破坏了类型安全！
// 展开示例以查看更多详细信息

//sampleEnd

fun main() {
    println("stringToSomething = " + stringToSomething)
    println("stringToInt = " + stringToInt)
    println("stringToList = " + stringToList)
    println("stringToStringList = " + stringToStringList)
    //println(stringToStringList?.second?.forEach() {it.length}) // 由于列表项不是 String 类型，这将抛出 ClassCastException
}

未检查的强制类型转换

向带有具体类型参数（如 foo as List<String>）的泛型类型进行的类型转换无法在运行时进行检查。
当类型安全性由高级程序逻辑隐含保证，但编译器无法直接推断出来时，可以使用这些未经检查的类型转换。请参见下面的示例。


fun readDictionary(file: File): Map<String, *> = file.inputStream().use {
    TODO("Read a mapping of strings to arbitrary elements.")
}

// 我们将一个包含 `Int` 的 Map 保存到了此文件中
val intsFile = File("ints.dictionary")

// 警告：未检查的类型转换：将 `Map<String, *>` 转换为 `Map<String, Int>`
val intsDictionary: Map<String, Int> = readDictionary(intsFile) as Map<String, Int>

最后一行中的强制类型转换会触发警告。编译器无法在运行时对其进行完全检查，也无法保证映射中的值是 Int。

为了避免未检查的强制类型转换，可以重新设计程序结构。在上例中，可以使用 DictionaryReader<T> 和 DictionaryWriter<T> 接口，并针对不同类型提供类型安全的实现。可以通过引入合理的抽象，将未检查的强制类型转换从调用点转移到实现细节中。正确使用 泛型 型变 也有帮助。

对于泛型函数，使用 具型参数 会使类似 arg as T 的类型转换被检查，除非 arg 的类型本身具有会被擦除的类型参数。

可以通过 @Suppress("UNCHECKED_CAST") 注解出现警告的语句或声明，来抑制未检查的强制类型转换警告：


inline fun <reified T> List<*>.asListOfType(): List<T>? =
    if (all { it is T })
        @Suppress("UNCHECKED_CAST")
        this as List<T> else
        null

在 JVM 上：数组类型 (Array<Foo>) 会保留其元素被擦除类型的相关信息，且向数组类型的类型转换会进行部分检查：元素类型的可空性及其实际类型参数仍会被擦除。例如，如果 foo 是一个包含任意 List<*> 的数组（无论该类型是否可空），则类型转换 foo as Array<List<String>?> 将成功。

类型实参的下划线操作符

下划线操作符 _ 可用于类型实参。显式指定其他类型时，可以用它让编译器自动推断相应类型：


abstract class SomeClass<T> {
    abstract fun execute() : T
}

class SomeImplementation : SomeClass<String>() {
    override fun execute(): String = "Test"
}

class OtherImplementation : SomeClass<Int>() {
    override fun execute(): Int = 42
}

object Runner {
    inline fun <reified S: SomeClass<T>, T> run() : T {
        return S::class.java.getDeclaredConstructor().newInstance().execute()
    }
}

fun main() {
    // 由于 SomeImplementation 继承自 SomeClass<String>，因此 T 被推断为 String
    val s = Runner.run<SomeImplementation, _>()
    assert(s == "Test")

    // 由于 OtherImplementation 继承自 SomeClass<Int>，因此 T 被推断为 Int
    val n = Runner.run<OtherImplementation, _>()
    assert(n == 42)
}
