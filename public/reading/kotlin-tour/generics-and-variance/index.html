泛型与型变

泛型是在不丢失类型信息的前提下复用规则；in 与 out 则说明一个边界消费什么、生产什么。

阅读约定

本章是基于 Kotlin 官方资料整理翻译的结构化精读，不是逐段完整翻译。保留项目阅读所需的核心概念、关键边界和代表性代码，暂缓与当前学习目标关系较弱的高级细节。

本章主线

遇到复杂泛型先找 T 从哪里进入、从哪里出去。生产者用 out，消费者用 in，同时读写则通常保持不变。

1. 泛型保留了调用方的类型

class ResultBox<T>(val value: T)

fun <T> firstOrNull(items: List<T>): T? = items.firstOrNull()

T 是一个类型参数：调用者传入 List<User>，返回值就是 User?。如果这里改成 Any?，虽然“什么都能放”，调用者却失去了具体类型信息。

2. 为什么泛型默认不变

即使 Cat 是 Animal，MutableList<Cat> 也不能当作 MutableList<Animal>。否则另一个调用者就可以向其中加入 Dog，破坏原列表只含 Cat 的承诺。

3. Producer out，Consumer in

interface Source<out T> {
    fun load(): T
}

interface Sink<in T> {
    fun save(value: T)
}
声明T 的角色你可以怎样理解
out T只生产 T可以从边界安全地读出 T
in T只消费 T可以向边界安全地写入 T
T既生产又消费保持不变，防止错误替换

例如 Source<Cat> 可以交给需要 Source<Animal> 的地方，因为它生产出的 Cat 一定也是 Animal。反过来，能够保存任意 Animal 的 Sink<Animal>，当然也能承担只保存 Cat 的工作。

4. 使用处投影与星投影

fun copy(from: Array<out Any>, to: Array<Any>) { /* 只从 from 读取 */ }
fun describe(box: ResultBox<*>): String = box.value.toString()

当类型本身既读又写、无法在声明处标为 out 或 in 时，可以在某次使用处限制能力。* 表示具体参数未知，只使用编译器仍能保证安全的部分。

5. 约束表达算法真正需要的能力

fun <T> maxOf(items: List<T>): T
    where T : Comparable<T> = items.max()

where 不是装饰：它告诉调用者，算法并不接受任意 T，而是需要 T 能够相互比较。

容易误用
  • 把 out 理解成“不可变”；型变只保证类型安全，不保证对象不会变化。
  • 为了消除编译错误随手写 * 或强制转换，掩盖了边界职责不清。
  • 把泛型加到只服务一种业务类型的 API 上，得到没有真实复用价值的抽象。
