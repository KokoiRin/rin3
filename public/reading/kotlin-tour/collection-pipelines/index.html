集合式数据处理

把 map、filter、associate、groupBy 和 fold 看成数据形状的连续变换，而不是一串炫技调用。

阅读约定

本章是基于 Kotlin 官方资料整理翻译的结构化精读，不是逐段完整翻译。保留项目阅读所需的核心概念、关键边界和代表性代码，暂缓与当前学习目标关系较弱的高级细节。

本章主线

读集合链时，每一步都问“输入是什么、输出变成什么、原集合有没有被修改”，长链就会重新变得可读。

1. 先看数据形状，不要先看函数名

val cardsByOwner: Map<UserId, List<Card>> = cards
    .filter { it.isVisible }
    .sortedByDescending { it.updatedAt }
    .groupBy { it.ownerId }

这段代码的主线是：List<Card> → 过滤后仍是列表 → 排序后仍是列表 → 按 owner 分组后成为 Map<UserId, List<Card>>。只要写出中间类型，链条的意图就清楚了。

操作问题典型结果
map每个元素要变成什么？元素类型可能改变，数量通常不变
filter哪些元素留下？类型不变，数量可能减少
associateBy用什么作为唯一键？Map<K, V>
groupBy按什么把多个元素归组？Map<K, List<V>>
fold如何从初始值累计？任意累积结果

2. 返回新集合，还是原地修改

多数常用集合操作返回结果而不修改原集合。filter() 的结果如果既不保存也不继续传递，就会丢失。可变集合才有写操作；还要区分 sorted()（返回新列表）与 sort()（原地修改）。

val source = mutableListOf(3, 1, 2)
val copy = source.sorted() // source 仍是 3, 1, 2
source.sort()              // source 变成 1, 2, 3

3. List 与 Sequence 的执行方式

集合链通常逐步产生中间集合；Sequence 延迟执行，并按元素穿过整条流水线。数据量小、步骤少时直接用集合更清楚；链很长、数据量大或需要尽早停止时，再评估 asSequence()。

val firstMatch = records
    .asSequence()
    .map(::parse)
    .filter { it.isValid }
    .firstOrNull()
容易误用
  • 默认把所有链都改成 Sequence；额外抽象并不保证更快。
  • 在 map 里偷偷修改外部状态，让流水线难以推理。
  • 十几步链条仍不命名中间概念；此时拆成有业务含义的函数通常更好。

4. 从语法读回业务

最终不要只说“这里用了 groupBy”，而要说“这里把可见卡片按所有者归组，供下一步逐个所有者展示”。函数是手段，数据形状变化才是业务叙事。
