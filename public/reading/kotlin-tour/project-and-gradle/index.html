Kotlin Multiplatform 项目结构基础

借助 Kotlin Multiplatform，您可以在不同平台之间共享代码。本文将介绍共享代码的限制条件、如何区分代码中的共享部分和平台特定部分，以及如何指定该共享代码适用的平台。

您还将学习 Kotlin Multiplatform 项目配置的核心概念，例如 共享代码、目标、平台特定代码和 中间源码集，以及测试集成。这将有助于您今后配置多平台项目。

本文介绍的模型与 Kotlin 实际使用的模型相比有所简化。不过，对于大多数情况而言，这个基本模型已经足够。

共享代码

共享代码是指在不同平台之间共享的 Kotlin 代码。

考虑一个简单的“Hello, World”示例：


fun greeting() {
    println("Hello, Kotlin Multiplatform!")
}

跨平台共用的 Kotlin 代码通常位于 commonMain 目录中。代码文件的位置非常重要，因为它会影响该代码被编译的目标平台列表。

Kotlin 编译器以源代码作为输入，并生成一组特定于平台的二进制文件作为输出。在编译多平台项目时，它可以从同一份代码生成多个二进制文件。例如，编译器可以从同一个 Kotlin 文件生成 JVM .class 文件和本机可执行文件：

并非每一段 Kotlin 代码都能编译到所有平台。如果某段代码无法编译到其他平台，Kotlin 编译器会阻止你在共享代码中使用特定于该平台的函数或类。

例如，你不能在共享代码中使用 java.io.File 依赖项。它是 JDK 的一部分，而共享代码也会被编译为原生代码，在原生代码环境中无法使用 JDK 类：

在共享代码中，你可以使用 Kotlin 多平台库。这些库提供了一个通用的 API，该 API 在不同平台上可以有不同的实现。在这种情况下，特定于平台的 API 作为附加部分存在，若尝试在共享代码中使用此类 API，将会引发错误。

例如，kotlinx.coroutines 是一个支持所有目标平台的 Kotlin 多平台库，但它还包含一个特定于平台的部分，用于将 kotlinx.coroutines 并发原语转换为 JDK 并发原语，例如 fun CoroutinesDispatcher.asExecutor(): Executor。API 的这一附加部分在 commonMain 中不可用。

要了解可用的 Kotlin 多平台库，请参阅 klibs.io。

目标

目标定义了 Kotlin 将共享代码编译到的平台。这些平台可以是 JVM、JS、Android、iOS 或 Linux 等。前面的示例将共享代码编译到了 JVM 和原生目标。

Kotlin 目标是一个用于描述编译目标的标识符。它定义了生成的二进制文件的格式、可用的语言结构以及允许的依赖项。

目标（Targets）也可称为平台（platforms）。请参阅完整的 支持的目标列表。

你应首先声明一个目标，以指示 Kotlin 为该特定目标编译代码。在 Gradle 中，你可以在 kotlin {} 代码块内使用预定义的 DSL 调用来声明目标：


kotlin {
    jvm() // 声明一个 JVM 目标
    iosArm64() // 声明一个对应于 64 位 iPhone 的目标
}

通过这种方式，每个多平台项目都会定义一组支持的目标。请参阅 分层项目结构 部分，了解有关在构建脚本中声明目标的更多信息。

要了解哪些代码将被编译为特定的目标，你可以将目标视为附加在 Kotlin 源文件上的标签。Kotlin 利用这些标签来确定如何编译你的代码、生成哪些二进制文件，以及该代码中允许使用哪些语言结构和依赖项。

如果你的项目只有一个目标（例如 JVM），你可以从共享代码中访问具有适当可见性的目标特定符号。但是，一旦添加了第二个目标，目标特定符号在共享代码中将不可用。在迁移和其他项目过渡阶段，请务必牢记这一限制。

如果你还想将 greeting.kt 文件编译为 .js，只需声明 JS 目标即可。此时，commonMain 中的代码会获得一个额外的 js 标签，该标签对应于 JS 目标，用于指示 Kotlin 生成 .js 文件：

这就是 Kotlin 编译器处理共享代码的方式，这些代码会被编译为所有已声明的目标。请参阅 源码集 以了解如何编写特定于平台的代码。

源码集

Kotlin 源码集是一组具有独立目标、依赖关系和编译器选项的源文件集合。这是在多平台项目中共享代码的主要方式。

多平台项目中的每个源码集：

  • 在给定项目中具有唯一的名称。

  • 包含一组源文件和资源，通常存储在与源码集同名的目录中。

  • 指定本源码集中的代码将编译成的目标集。这些目标会影响本源码集中可用的语言结构和依赖项。

  • 定义其自身的依赖项和编译器选项。

Kotlin 提供了一系列预定义的源码集。其中之一是 commonMain，它存在于所有多平台项目中，并编译为所有声明的目标。

在 Kotlin 多平台项目中，您将源码集视为 src 内的目录进行操作。例如，一个包含 commonMain、iosMain 和 jvmMain 源码集的项目具有以下结构：

在 Gradle 脚本中，您可以在 kotlin.sourceSets {} 块内通过名称访问源码集：


kotlin {
    // 目标声明：
    // …

    // 源码集声明：
    sourceSets {
        commonMain {
            // 配置 commonMain 源码集
        }
    }
}

除 commonMain 之外，其他源码集可以是特定于某个平台或中间源码集。

平台专用源码集

虽然仅使用共享代码很方便，但这并非总是可行。commonMain 中的代码会编译为所有已声明的目标，且 Kotlin 不允许你在其中使用任何平台特定的 API。

在包含原生和 JS 目标的多平台项目中，commonMain 中的以下代码无法编译：


// commonMain/kotlin/common.kt
// 在通用代码中无法编译
fun greeting() {
    java.io.File("greeting.txt").writeText("Hello, Multiplatform!")
}

作为解决方案，Kotlin 会创建平台专用源码集，也称为平台源码集。每个目标都有一个对应的平台源码集，该源码集仅针对该目标进行编译。例如，jvm 目标有一个对应的 jvmMain 源码集，该源码集仅编译为 JVM 格式。Kotlin 允许在这些源码集中使用平台专用的依赖项，例如 jvmMain 中的 JDK：


// jvmMain/kotlin/jvm.kt
// 你可以在 `jvmMain` 源代码集中使用 Java 依赖项
fun jvmGreeting() {
    java.io.File("greeting.txt").writeText("Hello, Multiplatform!")
}

编译到特定目标

针对特定目标的编译支持多个源码集。当 Kotlin 将多平台项目编译为特定目标时，它会收集所有标记为该目标的源码集，并据此生成二进制文件。

考虑一个包含 jvm、iosArm64 和 js 目标的示例。Kotlin 会为共享代码创建 commonMain 源码集，并为特定目标创建相应的 jvmMain、iosArm64Main 和 jsMain 源码集：

由于 Kotlin 将 commonMain 和 jvmMain 合并编译，生成的二进制文件中包含来自 commonMain 和 jvmMain 的声明。

在处理多平台项目时，请记住：

  • 若希望 Kotlin 将代码编译为特定平台，请声明相应的目标。

  • 要选择用于存储代码的目录或源文件，首先需确定希望在哪些目标之间共享该代码：

    • 若代码在所有目标之间共享，则应在 commonMain 中声明。

    • 如果代码仅用于一个目标，则应将其定义在该目标的 平台专用源码集 中（例如，JVM 的 jvmMain）。

  • 在平台专用源码集中编写的代码可以访问通用源码集中的声明。例如，jvmMain 中的代码可以使用 commonMain 中的代码。但是，反之则不成立：commonMain 无法使用 jvmMain 中的代码。

  • 在平台专用源码集中编写的代码可以使用相应的平台依赖项。例如，jvmMain 中的代码可以使用仅限 Java 的库，如 Guava 或 Spring。

中间源码集

简单的多平台项目通常仅包含通用代码和平台专用代码。commonMain 源码集代表所有声明的目标之间共享的代码。平台专用源码集（如 jvmMain）则代表仅编译到相应目标的平台专用代码。

在实际应用中，通常需要更细粒度的代码共享。

假设你需要支持所有现代 Apple 设备和 Android 设备：


kotlin {
    android()
    iosArm64()   // 64 位 iPhone 设备
    macosArm64() // 基于 Apple Silicon 的最新款 Mac
    watchosArm64() // 最新款 64 位 Apple Watch 设备
    tvosArm64()  // 最新款 Apple TV 设备
}

并且你需要一个源码集来添加一个函数，该函数为所有 Apple 设备生成一个 UUID：


import platform.Foundation.NSUUID

fun randomUuidString(): String {
    // 您想调用苹果专有的 API
    return NSUUID().UUIDString()
}

你无法将此函数添加到 commonMain 中。commonMain 会被编译到所有声明的目标中，包括 Android，但 platform.Foundation.NSUUID 是 Apple 专有的 API，在 Android 上不可用。如果你尝试在 commonMain 中引用 NSUUID，Kotlin 会报错。

你可以将这段代码复制并粘贴到每个 Apple 专用的源码集：iosArm64Main、macosArm64Main、watchosArm64Main 和 tvosArm64Main 中。但不建议采用这种方法，因为此类代码复制容易导致错误。

要解决这个问题，可以使用中间源码集。中间源码集是一种 Kotlin 源码集，它会编译成项目中部分（但并非全部）的目标。中间源码集有时也被称为分层源码集，或简称为分层结构。

Apple 设备和模拟器目标

使用 Kotlin Multiplatform 开发 iOS 移动应用时，通常会使用 iosMain 源码集。虽然你可能会认为这是针对 ios 目标的 ios 源码集，但实际上并不存在单一的 ios 目标。大多数移动项目至少需要两个目标：

  • 设备目标用于生成可在 iOS 设备上执行的二进制文件。目前 iOS 只有一个设备目标：iosArm64。

  • 模拟器目标用于生成在您的机器上启动的 iOS 模拟器所用的二进制文件。如果您拥有 Apple silicon 架构的 Mac 电脑，请选择 iosSimulatorArm64 作为模拟器目标。

如果你只声明了 iosArm64 设备目标，就无法在本地机器上运行和调试你的应用程序及测试。

像 iosArm64Main 和 iosSimulatorArm64Main 这样的平台专用源码集通常为空，因为 iOS 设备和模拟器的 Kotlin 代码通常是相同的。您可以仅使用 iosMain 中间源码集在所有平台之间共享代码。

这同样适用于其他非 Mac 的 Apple 目标。例如，如果你有针对 Apple TV 的 tvosArm64 设备目标，以及针对 Apple 硅设备上 Apple TV 模拟器的 tvosSimulatorArm64 模拟器目标，你可以为所有这些目标使用 tvosMain 中间源码集。

与测试的集成

实际项目中，除了主生产代码外，还需要测试代码。这就是为什么默认创建的所有源码集都带有 Main 和 Test 后缀。Main 包含生产代码，而 Test 包含针对该代码的测试。它们之间的关联会自动建立，测试无需额外配置即可使用 Main 代码提供的 API。

Test 的对应项也是与 Main 类似的源码集。例如，commonTest 是 commonMain 的对应项，它会编译为所有声明的目标，从而允许您编写通用测试。平台特定的测试源码集（如 jvmTest）用于编写平台特定的测试，例如 JVM 特定的测试或需要使用 JVM API 的测试。

除了需要一个源码集来编写通用测试外，你还需要一个多平台测试框架。Kotlin 提供了一个默认的 kotlin.test 库，其中包含 @kotlin.Test 注解以及 assertEquals 和 assertTrue 等各种断言方法。

你可以像编写常规测试一样，在各个平台的源码集中编写针对该平台的测试。与主代码类似，你可以为每个源码集配置平台特定的依赖项，例如 JVM 平台使用 JUnit，iOS 平台使用 XCTest。要运行针对特定目标的测试，请使用 <targetName>Test 任务。

在 测试多平台应用教程 中了解如何创建和运行多平台测试。

添加 Kotlin Multiplatform 库依赖

每个程序都需要一组库才能正常运行。Kotlin 多平台项目可以依赖适用于所有目标平台的多平台库、特定于某个平台的库以及其他多平台项目。

要添加对某个库的依赖，请更新项目中包含共享代码的目录下的 build.gradle(.kts) 文件。在 dependencies {} 代码块中设置所需 类型（例如 implementation）的依赖：

Kotlin


kotlin {
    //...
    sourceSets {
        commonMain.dependencies {
            implementation("com.example:my-library:1.0") // 所有源码集共用的库
        }
    }
}

Groovy


kotlin {
    //...
    sourceSets {
        commonMain {
            dependencies {
                implementation 'com.example:my-library:1.0'
            }
        }
    }
}

对 Kotlin 库的依赖

标准库

每个源码集中的标准库（stdlib）依赖会自动添加。标准库的版本与 kotlin-multiplatform 插件的版本相同。

对于平台专用源码集，将使用该库对应的特定平台变体，而其余情况则会添加一个通用的标准库。Kotlin Gradle 插件将根据您的 Gradle 构建脚本中的 compilerOptions.jvmTarget 编译器选项 选择合适的 JVM 标准库。

了解如何 更改默认行为。

测试库

对于多平台测试，可使用 kotlin.test API。创建多平台项目时，您可以在 commonTest 中添加单个依赖项，将其添加到所有源码集中：

Kotlin


kotlin {
    //...
    sourceSets {
        commonTest.dependencies {
            implementation(kotlin("test")) // 自动引入所有平台依赖项
        }
    }
}

Groovy


kotlin {
    //...
    sourceSets {
        commonTest {
            dependencies {
                implementation kotlin("test") // 自动引入所有平台依赖项
            }
        }
    }
}

kotlinx 库

如果您使用多平台库且需要 依赖共享代码，只需在共享源码集中设置一次依赖项。请使用库的基础工件名称，例如 kotlinx-coroutines-core：

Kotlin


kotlin {
    //...
    sourceSets {
        commonMain.dependencies {
            implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0")
        }
    }
}

Groovy


kotlin {
    //...
    sourceSets {
        commonMain {
            dependencies {
                implementation 'org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0'
            }
        }
    }
}

如果您需要用于 平台特定依赖 的 kotlinx 库，仍可在相应平台的源码集中使用该库的基础工件名称：

Kotlin


kotlin {
    //...
    sourceSets {
        jvmMain.dependencies {
            implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0")
        }
    }
}

Groovy


kotlin {
    //...
    sourceSets {
        jvmMain {
            dependencies {
                implementation 'org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0'
            }
        }
    }
}

对 Kotlin 多平台库的依赖

您可以添加对已采用 Kotlin 多平台技术的库的依赖，例如 SQLDelight。这些库的作者通常会提供将依赖项添加到您项目中的指南。

在 klibs.io 上探索可用的 Kotlin 多平台库。

所有源码集共用的库

若要使用来自所有源码集的库，只需将其添加到“common”源码集中即可。Kotlin Multiplatform Gradle 插件会自动将相应部分添加到其他任何源码集中。

您不能在“common”源码集中设置对特定平台库的依赖。

Kotlin


kotlin {
    //...
    sourceSets {
        commonMain.dependencies {
            implementation("io.ktor:ktor-client-core:3.5.2")
        }
        androidMain.dependencies {
            // 依赖项
        }
    }
}

Groovy


kotlin {
    //...
    sourceSets {
        commonMain {
            dependencies {
                implementation 'io.ktor:ktor-client-core:3.5.2'
            }
        }
        androidMain {
            dependencies {
                // 对 ktor-client 平台部分的依赖
            }
        }
    }
}

您还可以在顶级 dependencies {} 代码块中配置通用库。请参阅 在顶级配置依赖项。

在特定源码集中使用的库

若只想在特定源码集中使用某个多平台库，可将其仅添加到这些源码集中。这样，指定的库声明将仅在这些源码集中可用。

在此类情况下，请使用通用的库名称，而非特定于某个平台的名称。例如，如下面的示例中所示，应使用 native-driver，而非 native-driver-iosx64。请在库的文档中查找确切的名称。

Kotlin


kotlin {
    //...
    sourceSets {
        commonMain.dependencies {
            // kotlinx.coroutines 将包含在所有源代码集中
            implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0")
        }
        androidMain.dependencies {

        }
        iosMain.dependencies {
            // SQLDelight 仅包含在 iOS 源代码集中，但不会包含在 Android 或 common 源代码集中
            implementation("com.squareup.sqldelight:native-driver:2.3.2")
        }
        wasmJsMain.dependencies {

        }
    }
}

Groovy


kotlin {
    //...
    sourceSets {
        commonMain {
            dependencies {
                // kotlinx.coroutines 将包含在所有源代码集中
                implementation 'org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0'
            }
        }
        androidMain {
            dependencies {}
        }
        iosMain {
            dependencies {
                // SQLDelight 仅包含在 iOS 源代码集中，但不会包含在 Android 或 common 源代码集中
                implementation 'com.squareup.sqldelight:native-driver:2.3.2'
            }
        }
        wasmJsMain {
            dependencies {}
        }
    }
}

对另一个多平台项目的依赖

您可以将一个多平台项目作为依赖项连接到另一个项目。要实现这一点，只需将项目依赖项添加到需要它的源码集即可。如果您希望在所有源码集中使用该依赖项，请将其添加到公共源码集中。在这种情况下，其他源码集将自动获取相应的版本。

Kotlin


kotlin {
    //...
    sourceSets {
        commonMain.dependencies {
            implementation(project(":some-other-multiplatform-module"))
        }
        androidMain.dependencies {
