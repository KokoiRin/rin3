我们已经会递归，但不想为每个小变化再写一次

假设需要把一个起始数连续翻倍四次：从 7 依次得到 14、28、56、112。如果明天改成连续加一，后天改成连续取列表尾部，我们不应该把“计数减一、到零停止”再复制两遍。这篇要解决的就是：把重复过程留下，把每次做什么作为输入交进去。

先看原课里很直接的一组值。元组的前两项放函数，第三项才是执行函数后得到的整数。

double 这个名字求值得到一个函数值，不会自动开始翻倍。double (incr 7) 才先算 incr 7 = 8，再算 double 8 = 16。所以元组可以理解为“函数、函数、16”；#1 a_tuple 取出第一个函数，再用 9 调用，结果是 18。

这种“函数可以像其他值一样被存放、传递、返回”的能力叫一等函数（first-class functions）。你熟悉的 Kotlin 可以把 lambda 放进变量或作为参数，属于同一类能力；这里要研究的是它背后的类型与求值规则。

函数式编程通常把“尽量避免修改数据”和“把函数当值使用”作为重要风格，但这两件事可以分别讨论。递归、接近数学的写法或惰性求值并不是它唯一的定义，更不能简单理解成“凡是不用对象的程序”。一种语言可以同时支持多种风格；本节先把函数值的能力看清。

接收函数或返回函数的函数叫高阶函数。n_times 接收 f，因此是高阶函数；函数放进元组则只是展示一等函数，元组本身并不是高阶函数。

高阶与多态，是两件可以分开看的事

下面的函数接收一个整数变换，反复调用它，数到输入变成零为止。times_until_zero (fn x => x - 1, 3) 得到 3。

前者是高阶函数，但 x = 0 和算术运算已经把类型限定为整数，它的类型是 (int -> int) * int -> int。后者可以数任意元素类型的列表，类型是 'a list -> int，却既不接收函数，也不返回函数。

还有两个适用条件不能从类型里读出来：本篇 n_times 要求 n >= 0，负数不能按预期递减到零，可能持续递归，也可能先发生整数溢出；传入 tl 时，次数还不能超过列表长度。times_until_zero 也不能保证任意 f 都会到零，例如从正数不断加一，就不能按预期到达零，还可能先溢出。类型正确并不等于终止条件自动成立。

这里的两个递归都还在等待递归结果回来后再做一次工作，因此不是尾递归。现在的重点是抽出共同结构；以后判断效率时，仍要回到实际调用过程。
