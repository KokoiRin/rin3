先取绝对值，再转换，再开方，能不能直接表达这条过程

现在有三个现成操作：整数绝对值 abs、整数转实数 Real.fromInt、实数开方 Math.sqrt。输入 ~9，依次得到 9、9.0、3.0。这篇不再写遍历，而是把已有函数组合成新的函数。

先保留最直白的写法，再定义“组合”本身。compose (f,g) 返回的函数会先调用 g，再把它的结果交给 f。

小写字母 o 是 SML 已提供的函数组合运算符，不是数字零。读 Math.sqrt o Real.fromInt o abs 时，从右边开始：先 abs，再转换，最后开方。它本身求值得到函数，之后给这个函数一个整数才开始整个转换。

闭包在这里保存要连接的 f、g。类型把连接条件写得很清楚：若 g : 'a -> 'b，f : 'b -> 'c，就能得到 'a -> 'c；前一步输出必须能成为后一步输入。REPL 可能用不同字母表示类型变量，但关系不变。

想按执行顺序读，可以定义管道

如果更习惯从左到右读“数据经过哪些步骤”，可以写一个很小的中缀函数。infix |> 告诉解析器把它放在两个输入之间；定义仍然是普通函数调用。

它按 (i |> abs) |> Real.fromInt |> Math.sqrt 逐步求值，结果仍为 3.0。管道没有增加后台线程或流式系统，只是把 f x 改写成更便于阅读的顺序。原视频因当时 Emacs 编辑模式处理 |> 有问题，临时写成 !>；那是工具兼容选择，不是 SML 语义要求。

fun sqrt_of_abs i = (Math.sqrt o Real.fromInt o abs) i 还可以缩成前面的 val sqrt_of_abs = ...，因为组合表达式已经产生我们要的函数。是否省略包装，应以类型条件与读者能否看懂为准。

组合也可以是“先尝试，没有结果再用备用方案”

有时并不是把两个函数都执行一遍。假设首选查询返回 option：找到答案是 SOME value，没找到是 NONE；备用查询总能给一个默认答案。下面把这种策略写成可复用组合。

它的类型是 ('a -> 'b option) * ('a -> 'b) -> ('a -> 'b)。首选与备用接收同一种输入；首选多一层 option，用来表示“这次无法提供结果”。把 SOME 0 当作找不到会错，真正的零仍然是一个已找到的答案。

异常版备用，处理的是另一种失败约定

原课还有一个异常版本。首选函数与备用函数都直接返回结果，首选执行时若抛异常，就改用备用方案。

recovered 是 0。这里的 _ 匹配任意异常，因此既可能处理预期的 Missing，也可能把首选函数中的程序错误一起掩盖。实际程序通常应该明确要恢复哪些异常。

它也不会挽救永远不返回的计算；备用函数自己抛出的异常也不会再次被这个同一个处理器重试。option 版和异常版表达的是两套失败约定，应当按函数原本的行为来选，不能只因写起来短就随意互换。
