三个输入不一定要一次装进同一个元组

前两节已经说明：SML 函数每次接收一个值，“三个参数”可以是一份三元组。现在换一个角度：先交一个整数，得到等下一个整数的函数；再交一个，得到等最后一个整数的函数。我们就能逐步提供配置，而不必一次给齐。

原课用“这三个数是否从小到大排列”展示这个过程。先写旧的元组形式，再写新形式；输入 7、9、11，两者最终都是 true。

sorted3 7 还没有判断大小。它得到的闭包记住 x=7，等一个 y；再用 9 调用，得到记住 x=7、y=9、等一个 z 的闭包；最后交 11，才执行两个比较，得到布尔值。

这种把概念上的多项输入变成一连串单输入函数的组织方式叫柯里化（currying）。它没有改变“每次只传一个值”的规则，而是在反复运用“函数可以返回函数”。

两条结合规则，让短写法不再神秘

原课会把层层括号去掉。函数应用向左结合，因此下面两条调用相同：

fun sorted3_nicer x y z = ... 是连续返回函数的方便写法。它不是让一个原先只接收单值的 SML 函数突然同时接收三份独立输入。

类型箭头则向右结合：int -> int -> int -> bool 等于 int -> (int -> (int -> bool))。把这两条规则放在一起就能读懂：调用从左边一步步给输入，类型从右边描述尚待完成的函数结果。

这也说明为什么中途停下并不是“参数太少错误”。sorted3 7 的类型是 int -> int -> bool，sorted3 7 9 的类型是 int -> bool。它们都是完整合法的函数值，只是尚未收到最后的输入。
