先固定筛选规则，以后只交记录

如果每次都要检查列表中有没有零，就没必要让调用处反复写判断函数。上一篇的柯里化允许我们先提供前面的输入，把还没有提供的数据留到以后。这叫部分应用：得到的仍然是普通函数，不是一个没填完、无法使用的表达式。

先用原课的 sorted3 看最短过程。固定前两项都是零，最后的判断就变成“第三项是否非负”。

sorted3 0 得到保存 x=0 的函数，再交一个 0，得到保存 x=0、y=0 的 int -> bool。判断尚未发生，只有最后交来 12 或 ~1，才分别得到 true、false。

标准库常把处理函数放在第一位，再放列表，正是便于这种用法。fun countup j = range 1 j 也能表达同一个操作，但只是把现成的 range 1 再包装一下。短写法合适时能直接表达“先固定起点”，不意味着所有包装都应机械删除。

一个看似合理的多态例子，会碰到值限制

若想给列表每一项配上数字 1，自然会尝试下面的部分应用。它与只处理整数的 incrementAll 不同：我们希望得到的函数既能接收字符串列表，也能接收布尔列表。

这不是函数体的逻辑写错，也不是所有部分应用都失败。SML 对某些右侧表达式的类型泛化施加限制；函数调用这样的表达式，不能把尚未确定的类型变量一律变成任意可选类型。不同实现可能显示弱类型变量、不可用的占位类型或相应警告，因此不要依赖它成为通用函数。

目前可用的修复是把等待列表的函数显式写出来。函数值可以正常泛化，两种元素类型就能分别使用：

pairStrings 则选择了另一种处理：明确只服务字符串，不再要求多态。最后一个函数本来就被 x+1 限定为整数，也没有待泛化的元素类型，所以正常成立。

这个规则叫 value restriction（值限制）。它与语言同时支持多态和可变引用时的类型安全有关，并不表示眼前这个纯 map 偷偷进行了修改。下一篇会看到引用是什么；现在记住症状、原因边界和两种修复就够了。
