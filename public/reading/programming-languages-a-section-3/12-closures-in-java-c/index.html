Java：用一个对象携带方法与配置字段

原课把函数类型换成单方法接口：Func<B,A> 的 m 接收 A、返回 B，Pred<A> 则返回布尔值。注意原课把返回类型变量写在前面，这是命名选择，不是 Java 泛型自动颠倒。本计数例只需要 Pred；原课的 map 则通过 Func.m 把每个 A 变成 B。

下面抽出计数例子的关键部分，可独立编译。为减少与闭包无关的样板，数据容器使用 Java 自带列表，仍保留“先 filter，再 length”的控制结构。

输出 2。new Pred<Integer>() { ... } 创建匿名内部类对象；方法 m 承担判断代码，被捕获的 final int n 承担环境。因为 n 是 int，x==n 会把 Integer x 拆箱成整数比较，不是在比较两个 Integer 对象的身份。数据里的 null 则会在拆箱时出错。

若库把匿名对象保存到以后再调用，捕获的 n 也随对象保持可达，不是偷偷保存已经返回的调用栈局部地址。

也可以写一个有名字的 IsN 类，让它有 int n 字段，通过构造器接收配置；两种形式都在明确安排“方法加数据”。原视频使用 final，现代 Java 还允许捕获 effectively final 的局部变量，但不是允许任意修改被捕获的局部变量。

原课完整版本自己定义 List<T>，用 head/tail 表示节点、null 表示空表；静态泛型方法的类型变量写在返回类型前，如 static <A,B> List<B> map(...)。若直接改成 xs.map(...) 这样的实例方法，空表 null 就没有可接收调用的对象；可以改用 Empty/Cons 两个子类解决，而不必认定空表一定要用 null。

递归版 map/filter 对照 SML 最短，却不适合在 Java 长链表上无条件照搬：不能假设普通 Java 实现会消除尾调用栈。改写循环还要维护输出节点顺序，必要时维护尾指针或反转中间结果。这些是实现选择，不是闭包语义本身。

C：函数指针以外，再明确传一份环境

代价也更明确：void* 不会替你检查环境结构是否匹配，保存多久由程序负责。上例同步完成遍历，config 一直有效；若把回调保存到函数返回以后再执行，就不能让环境指针仍指向已经失效的局部变量，必须安排更长生命周期及释放责任。

原课通用链表还把 void* 用于元素，并演示把 intptr_t 整数转成指针再转回。阅读笔记明确提醒：不能仅凭整数放得下就把这种来回转换当成标准 C 的可移植保证。可以传真实数字的指针，或设计明确使用 intptr_t 的数据接口。一次编译通过不等于跨平台语义安全。

这三种语言都能完成任务，但闭包把哪些工作自动化、类型检查覆盖哪些关系、生命周期由谁负责，很不一样。理解这些差别，比把一种语法机械翻译成另一种更有价值。
