不直接交出列表，只交出能操作它的函数

这一篇是选学。我们想表示整数集合：插入数字、检查是否存在、询问元素个数；使用者不必知道里面是不是列表。你熟悉对象把私有数据与方法放在一起，这里看看仅靠闭包，能否做出相似的使用方式。

先约定公开形状。集合提供三个操作；insert 返回一个新集合，member 返回布尔值，size 接收 () 后返回整数。

这里不是用三个构造器表示三种集合，而是用单个 S 包住一份函数记录。不能直接写递归的 type set = {insert:int -> set,...}：SML 类型别名不能这样引用自身，所以原课用单构造器 datatype 表达递归类型。

每次建立集合，都让操作记住那份数据

下面的 make_set xs 接收表示集合内容的私有列表，返回三个保存它的操作。contains 负责检查数字是否已在列表中，外面无需反复写同一段查找。

初次调用 make_set []，三个操作围绕空列表建立。插入 34 时，旧列表不含它，于是用 [34] 再建立一份操作；以后询问新集合大小，保存 [34] 的 size 返回 1。旧空集合仍围绕原来的 [] 工作。

若再次插入 34，代码进入 make_set xs，保留相同内容，并不会变成 [34,34]。这段实现仍建立新的包装与闭包，不能据此宣称返回了物理上完全相同的对象；保证的是集合内容与大小不变。

用它的人只需知道操作约定

原课客户端如下。val S s1 = empty_set 拆开外层构造器，得到那份函数记录，再通过 #insert 等字段使用操作。

s1 内容为空，s2 是 {34}，s3 还是 {34}，s4 才是 {19,34}。最后既不是取 s4 的大小，也不是得到 19；42 不在 s4 中，19 在，于是计算 17 + size(s3) = 18。

使用者能拆出函数记录，却没有一个公开字段能直接取到私有 xs。闭包内部通过保存的绑定继续使用它；数据不必为了活过创建函数的返回而变成顶层全局变量。这正是“代码带着环境走”可以实现的另一种封装。

这段实现展示的是表达能力，不是最快的集合

把具体数据表示藏在操作背后、只通过约定操作使用它，是抽象数据类型的核心想法。这里还没用下一节正式的模块系统，只展示闭包足以承载这种组织方式。

当前 member 需要沿列表查找，size 每次也用 length 遍历，插入还得先检查重复。大集合有更合适的树或哈希结构；同一份操作接口也可以换实现。重要的是分清这里的接口是不可变的：插入返回新集合，不会修改先前建立的集合。若改用引用，也能设计成可变版本，但那将是另一套行为约定。
