想记清一条阅读记录，先决定它应该装什么

第一周，我们已经能处理每天的页数列表。现在希望一条记录不只保存 12，还能说明读的是哪本书、这次计划是否完成。输入的数据可以是“书名 SML、读了 12 页、尚未完成”，我们想从中准确取得页数 12，而不靠记忆猜某个位置的含义。

ML 可以给每一项起名字。下面大括号里的整体叫作记录，book、pages、finished 叫作字段；字段负责给里面的一项数据命名。#pages session 的意思是读取 session 的 pages 字段。

执行第一行，三个字段分别得到字符串、整数、布尔值，再共同组成一条记录。后两行已经不需要记“页数到底是第二项还是第三项”，只按字段名取值。这不是把三个独立变量放到顶层；外面建立的名字是 session，pages 是它里面的字段名。

同时具有几项，还是从几种情况中选一种

先用阅读记录把本周的整体框架建立起来。记录同时具有书名、页数和完成标记，少一项就不是刚才那种记录。原课把这种“各项都有”的组合叫作 each-of；第一周的元组也是这种组合，例如 int * bool 的值同时具有一个整数和一个布尔值。

另一种需求是“有一个页数答案，或者没有答案”。第一周的 int option 就属于这一类：SOME 12 与 NONE 是两种不同情况，而不是同时拥有两项。原课称之为 one-of，意思是从若干种形状中取一种；下一篇会让我们自己定义这些形状。

第三种需求是“数据里面还可以装同一种数据”。例如非空整数列表包含一个整数，以及另一个整数列表；再往后拆，最终可以到 []。这叫自引用：类型定义中再次提到自己，才能描述任意长的列表或树，而不预先写死层数。

我们要描述的数据 需要的组合关系
一条记录有书名、页数和完成标记 各项都有：each-of
一次查询有答案或没有答案 若干形状之一：one-of
列表为空，或有一个元素和剩余列表 选择 + 组合 + 自引用

这些是理解类型的三个角度，不是必须背下来的 ML 关键字。原课也提醒，这三个英文叫法是为讲解而选的；其他语言会用不同写法提供相似能力。例如 Java 字段组合体现“各项都有”，子类关系也能表达“若干情况之一”，后面的课程还会比较这些设计。

基本类型如 int、bool、unit、char、real 描述各类基本值；元组、记录、列表、option 则可以把已有类型组合起来。组合还能继续嵌套：一条记录的字段可以是列表，列表元素也可以是记录，不限于刚才的三个简单字段。

记录的字段顺序，不决定字段含义

如果把字段换个书写顺序，我们希望 pages 仍表示页数。下面两条记录具有相同的字段与对应值，因而属于同一种记录类型。

session 的类型是 {book:string, finished:bool, pages:int}。写值时用 = 连接字段与表达式；写类型时用 : 连接字段与类型。ML 不要求先声明一个“阅读记录类”才能建立这个值，而会从各字段表达式推断出整条记录的类型。

字段顺序不影响记录的含义，解释器可能为了统一展示而按字段名排序。一个记录中的字段名必须不同，但不同记录可以使用相同字段名，甚至装不同类型。字段名本身不是顶层变量，也没有规定所有叫 id 的字段都必须是整数。

按名字，还是按位置

对于两个很清楚的数，元组通常简短方便；但如果一条信息有八个字段，记住“第七项是什么”就容易出错。这时字段名能直接说明用途，代码长一点，却省去了反复查位置的负担。

这是一个更普遍的设计选择：一组信息靠名字区分，还是靠位置区分。第一周函数调用 (12,18) 在调用处按位置组织输入，函数体内却通过参数名使用它们，是两种方式的结合。这里的“按名字识别字段”也不要与后续可能看到的“按名调用”求值策略混为一谈；本节没有改变实参先求值的规则。

元组原来就是一种特殊记录

原课接着展示：元组不仅与记录相似，在 ML 的定义中，它就是字段名为 1、2、……的那类记录的方便写法。下面 another_pair 用数字作字段名，字段写反了顺序，得到的仍是第一项为 6、第二项为 5 的二元组。

#1 因而既可以理解为“取第一项”，也可以理解为“取名字为 1 的字段”。类型 int * bool 也就是 {1:int, 2:bool} 的另一种写法。注意，a_record 的名字是 first、second，它并不会因此变成数字字段的那种元组。

数字字段必须恰好组成对应的位置，才能写成元组。下面第一条缺少字段 2，仍是一条普通记录；第二条具有 1、2、3，解释器就能显示成三元组。

语法糖：方便写法可以沿用已有规则

这种“写成 A，可以完整解释为写成 B”的关系叫作语法糖。它不是说元组是假数据，而是说元组的类型与求值规则，可以借助等价的记录写法说明，不需要再发明一套独立含义。日常写元组仍应使用 (4,6)，没有必要刻意改成难读的数字字段记录。

我们其实已见过另一例：e1 andalso e2 可以解释为 if e1 then e2 else false。两者都只在 e1 为真时求值 e2，所以解释也保留了短路行为。语言可以用少量核心规则支持丰富而方便的表面写法，这正是原课引入“语法糖”一词的目的。
