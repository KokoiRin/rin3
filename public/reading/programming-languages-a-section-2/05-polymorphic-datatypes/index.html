用新学会的模式，重新读懂页数列表

第一周求和时，我们先问列表空不空，再用 hd、tl 取内容。现在已经知道如何从一种形状中同时认出情况、取出数据，能不能把这三步合起来？目标不变：输入三天记录 [12,18,10]，仍得到总页数 40。

内置列表只有两种形状：空列表 []，或者一个头部接着尾部。:: 不只用于构造，也能放在模式中，把两部分分别交给变量。下面把剩余列表叫作 xs'，末尾撇号是普通名字的一部分，常读作“xs prime”，不是新的运算符。

第一层匹配 x::xs'，得到 x=12、xs'=[18,10]；下一层得到 18 和 [10]；再下一层得到 10 和 []。空列表返回 0，再依次完成 10+0、18+10、12+28，答案为 40。取头部和尾部已经包含在成功的模式匹配里，不会出现“这一分支已经知道为空，却仍去取头部”的写法。

为什么列表能使用模式？V10 先用我们已经掌握的 datatype 定义一份整数列表：它或者是 Empty，或者是一个整数与另一份同类型列表的组合。下面不依赖内置列表，完整构造原视频中的三个整数，并写出连接两份自造列表的函数。

构造 birthday 时，最内层先把 2008 接到 Empty，再接 23，最后接 4。连接函数也沿第一份列表往下：到 Empty 就直接返回第二份，再逐层用 Cons 接回前面的整数。2019 年课堂代码改用 1、2、3 演示，同样是这种嵌套形状。

我们不是为了以后重新发明整数列表。原课用这个例子说明，列表的结构不需要特殊魔法：选择、自引用和构造器就能表达；实际程序仍应优先使用大家熟悉的内置列表。

NONE 与 SOME，也就是两种构造器

第一周的 option 同样来自数据类型定义。NONE 是无数据的构造器，SOME 携带一个值，因此它们既能出现在构造表达式中，也能出现在模式中。

原课的 inc_or_zero 接收可能有的整数：没有时返回 0，有时给内部整数加一。这里返回 0 是这个小函数明确选择的默认规则，不是在定义“所有缺失答案都应该当成零”。

SOME i 成功时，i 已经对应内部整数，可以直接做加法；NONE 分支没有内容要取。我们不再需要把“检查 isSome”与“调用 valOf”分成两段，完整的模式列表也让遗漏一种情况更容易被检查器发现。

V10 对第二次作业特别要求使用模式匹配来处理列表和 option，不再依赖 null、hd、tl、isSome、valOf。这是练习新方法的要求，不是这些库函数突然失效；它们在某些短小表达式里方便，也可以把它们本身传给另一个函数使用，下一单元会进一步解释。

为什么同一个 append 还能连接书名

刚才的自造 my_int_list 把元素固定成了 int。内置列表却可以是 int list、string list，甚至列表的列表。这是 V11 补上的另一块：列表类型带有一个可以替换的类型位置。

list 单独还不是一个完整类型；给它 int，才得到 int list。这种“接收类型后形成类型”的名字叫作类型构造器。它与 SOME 这样的值构造器负责不同层面：option 用来写类型，SOME 12 用来造具体值，不是在运行时把 int 交给一个函数。

'a 是可替换的类型参数，原课读作 alpha。换成 int，SOME 中就装整数；换成 string，就装字符串。同一个具体类型里所有 'a 都要一致，不能一处换整数、一处又换字符串。

我们也能定义这样的数据类型。为与前面的固定整数列表放在同一份练习中，下面给构造器取不同名字；它与原课泛型列表示意的结构相同。

递归位置必须写 'a mylist，不能只写 mylist，因为尾部也要明确使用同一种元素类型。这里叫作多态，意思是一份结构定义可以用于多种一致的类型，而不是一份具体列表可以随意混装所有类型。'a 开头的撇号属于类型参数写法，与普通变量名 xs' 末尾的撇号不同。

两个类型参数：树节点与叶子可以装不同东西

原课最后用双参数树展示更丰富的替换。Node 有自己的数据和左右子树；Leaf 只有叶子数据。'a 规定内部节点的数据类型，'b 规定叶子数据类型，二者可以相同，也可以不同。

reading_groups 的内部节点装字符串，两个叶子装整数；这不是任意混用，而是两个类型参数各自保持一致。原课再写三个处理函数，让我们看到函数怎样限制这些参数。

sum_tree 把所有数据相加，所以两种数据都必须是整数，类型为 (int,int) tree -> int。sum_leaves 只加叶子，不使用内部的 i，因此类型为 ('a,int) tree -> int；内部装书名也没关系。num_leaves 两边数据都不用，只认结构，所以类型是 ('a,'b) tree -> int。

函数 实际使用的数据 输入可以是什么类型
sum_tree 内部数据与叶子数据都相加 (int,int) tree
sum_leaves 只相加叶子数据 ('a,int) tree
num_leaves 只看结构，不使用数据 ('a,'b) tree

这些构造与匹配没有新求值规则：仍是按构造器分支、取局部数据、递归处理。变化主要在类型检查上——它必须确认每个参数都用得一致。原课把自己声明多态数据类型视为补充内容，第二次作业不要求掌握所有写法；但它帮助我们完整理解内置列表、option 并不特殊。
