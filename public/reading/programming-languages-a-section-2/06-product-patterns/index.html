三天的页数，能不能直接拆成三个名字

前一篇已经能用模式把列表拆成头部与尾部。这次输入不是长短不定的列表，而是恰好三天的页数 (12,18,10)。我们希望分别拿到三个整数，相加得到 40，同时避免反复写 #1、#2、#3。

模式也能用于元组。下面函数参数位置的 (x,y,z) 会把输入三元组的三项分别交给三个名字；右边再使用它们完成求和。这其实就是第一周已经见过的函数写法，只是现在能说明它为什么成立。

第一次调用时，整个输入值是 (12,18,10)。模式让 x=12、y=18、z=10，函数体便得到 40。模式需要恰好三项，不能拿二元组来匹配；三个位置又都用于整数加法，所以输入类型是 int * int * int，结果类型是 int。

这次不是挑一种形状，而是拆开各个部分

此前对 exp 的 case，需要区分常量、取负、加法、乘法。元组的情况不同：类型已经确定为三元组，就知道三部分都存在，主要工作只是给各部分起名字。记录也是同样道理，字段模式按名字找对应部分，不依赖书写顺序。

例如阅读记录同时有书名、页数和完成标记。下面把字段的值分别取名为 title、count、done，函数只返回我们关心的页数。

book、pages、finished 是字段名，title、count、done 才是模式新建立的局部变量名。这里并没有 book=title 这样的赋值过程；模式从已有记录读取对应部分。函数体没使用的字段值仍可被匹配，只是后面会学习更简洁地忽略它们。

先用一条 case，看看拆解到底做了什么

V12 用三种写法逐步解释，最后回到我们开头的简洁版本。第一种先把输入整体叫作 triple，再用只有一条分支的 case 取得三部分。下面函数对 (3,4,5) 仍得到 12。

这条模式不会在几个构造器之间选择，而是把已经知道有三项的值拆开。写成 case 能帮助我们看懂过程，却显得像在判断多个情况，因此原课不把它作为处理 each-of 数据的首选风格。

记录也可以用相同办法。^ 是字符串连接运算，下面把名、中间名、姓及两个空格连起来。这里三个字段都保存普通字符串，与前篇“中间名可能缺失”的另一种记录类型不同。

匹配时 x 得到 first 中的字符串，y 得到 middle，z 得到 last。这里没有字符串求和：^ 把字符串连接成另一个字符串，所以函数结果类型是 string。

val 左边原来也可以放模式

第一周我们把 val 介绍成“给一个结果起名字”。现在补全规则：val 左边可以是模式，单个变量名只是最简单的一种模式。右边先完整求成值，再用左边模式把里面的部分交给不同名字。

更直接：把模式放在函数参数位置

既然调用时本来就要取得输入，再给函数体建立局部名字，可以把上面的拆解移到参数位置。下面是原课第三种写法，与开头的函数具有同样结构；记录函数也直接接收字段模式。

case、局部 val、参数模式，三种方式都能让三个变量对应输入的三部分；后两种表达“这里只是拆开数据”更直接。参数模式与函数体已经给出充分结构信息，工具就能推断类型。省略标注没有取消类型检查，只是不用程序员把已能推知的信息再写一遍。

所谓三个参数，其实是一份三元组输入

现在就能回答原课的关键问题：fun sum_triple3 (x,y,z)=... 到底是接收三个输入，还是接收一个三元组后拆开？在 ML 的语言定义中，是后者——每次函数应用接收一个参数值，这里那个值刚好是三元组。

所以，int * int * int -> int 中箭头左边是一种完整的三元组类型。平时把它简称“三参数函数”没有问题，但不要因此以为逗号分开的是三次独立函数应用。后续看到返回函数的写法，也要按一次次函数应用分别理解。

这份设计带来的方便是：一个函数返回元组后，另一个函数可以直接接收整个结果，不需要手动取出三项再拼回去。原课用旋转三元组说明这一点：

第一次左旋把 3 移到最后，得到 (4,5,3)；再左旋一次，得到 (5,3,4)，恰好相当于原三元组右旋一次。rotate_left 的结果能直接作为下一次调用的实参，因为它返回的本来就是一份完整值；求和函数也照样接收这份值。

没有有意义输入时，也会传入一个值

fun f () = ... 并没有成为例外。调用时传入的是 unit 类型的唯一值 ()，参数位置的 () 是匹配这个值的模式，只是没有建立一个命名变量。

下面函数忽略外部输入的变化，返回固定的一天页数 12；调用仍然明确写出 ()。

原阅读笔记还从这里解释 unit 的预定义数据形状：它只有一个不携带内容的构造值，写法恰好是 ()。所以单变量、元组模式、记录模式、unit 模式，都能放回同一条函数调用规则：先取得一份实参值，再按参数模式建立本次函数体要使用的名字。

V12 要求第二次作业用模式匹配替代 # 读取，也是为了让我们熟悉这种统一理解。实际语言仍保留字段投影；它并没有因为更推荐另一种风格而消失。
