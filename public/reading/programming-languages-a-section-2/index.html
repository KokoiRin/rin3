这一周真正要连起来的关系

第一周已经认识了绑定、函数、元组、列表和递归。第二周向前走一步：数据可以有哪些形状？每种形状应该怎样处理？程序又怎样知道这些处理是类型正确的？最后，我们再区分递归完成了多少工作，以及调用过程中占用了多少空间。

前半段用结构化阅读记录和小型表达式计算器，把构造数据与处理数据连成一个过程。后半段会读到配对列表、异常传播、累加器与反转列表。每篇先说明具体目标和输入输出，再整理规则，不需要重新从安装软件和基本加法开始。

遇到分步图，先看高亮的代码，再观察本步的结构、绑定和结果。可以随时跳到某一步，也可以展开完整过程。原课截图保留出处；分步图用中文把过程拆开，方便按自己的速度阅读。

第 1 部分

先把数据的形状设计清楚

从带字段的记录走到几种互斥的选择，再让数据递归地包含同类数据。

01先设计数据的形状：记录与元组分清“各部分都要有”与“几种情况选一种”，再用字段记录相关信息，理解元组为何是记录的简写。对应 V01 / V02 / V0302列清几种可能，再用 case 逐一处理用 datatype 表达互斥的情况，跟着构造和匹配的完整过程，读懂构造器、附带数据与分支检查。对应 V04 / V0503把算式存成一棵树，再沿树计算从纸牌和形状不同的数据，走到 Constant、Add 等表达式节点，观察递归数据与递归函数怎样配合。对应 V06 / V07 / V0804type：给已有类型起一个名字用清楚的类型名表达用途，并与 datatype 真正建立的新类型区分开，避免同名定义带来的混淆。对应 V0905list、option 和类型参数，原来是一套规则把熟悉的列表和可选值还原成 datatype，再看同一个数据形状怎样容纳不同元素类型。对应 V10 / V11
第 2 部分

沿着数据结构拆开、匹配和检查

把第一周的投影操作换成模式，理解嵌套匹配、函数输入，以及类型怎样从约束中得来。

06用模式拆开记录、元组和函数输入通过解构绑定和函数参数，看清一个模式怎样同时取得各部分，以及“多个参数”背后的实际结构。对应 V1207类型推导：从代码约束里找出答案不运行程序也能推导类型；沿着变量、列表操作和相等比较，分清普通类型参数与相等类型参数。对应 V13 / V1408嵌套模式：把几层结构一起写清楚让三份列表按位置配对、再拆回来，观察短列表、相邻元素和通配符怎样减少重复判断。对应 V15 / V1609模式究竟怎样匹配，多分支函数怎样读逐层确认匹配条件与新绑定，分清模式和表达式，再把 case 与多分支函数的写法对应起来。对应 V17 / V18
第 3 部分

看清失败和递归怎样改变执行过程

异常怎样离开当前计算，递归又留下了哪些待办；最后比较累加器的收益与代价。

10异常：这次计算无法交回答案时跟着一次失败传播到处理处，理解 raise、handle、异常携带的数据，以及它与 option 的取舍。对应 V1911递归之后还有没有事情要做对照两种阶乘的调用过程，找出等待的乘法，再用尾位置规则判断一次调用能否直接交回结果。对应 V2012累加器：把等待的工作带到下一步用阶乘、求和与反转列表，理解累加器保存什么，怎样选择初值，以及顺序为什么可能改变。对应 V2113尾递归的取舍：空间、工作量与可读性把调用栈与输出数据分开计算成本，理解尾递归能改善什么、不能改善什么，以及何时值得改写。对应 V22
