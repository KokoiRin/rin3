不写类型，系统怎么知道函数能接什么

前面我们已经能用模式，把一条记录或一个元组拆成需要的部分。接下来有个很实际的问题：为什么把 #1 triple 改成 (x,y,z) 之后，函数参数上的类型往往也能删掉？系统究竟知道了什么？

先看一个完整例子。输入是三个整数，输出是它们的和；模式负责把三项分别命名，函数体负责相加。

total 是 12。这里没有写 int，但函数仍然有确定的类型 int * int * int -> int。类型推导省掉的是程序员手写的说明，不是程序必须满足的类型规则。 程序在求值前仍要通过类型检查。

从代码已经提供的信息开始

模式 (x,y,z) 首先告诉系统：参数恰好是三项元组。接着，函数体中的加法要求这些项属于相容的数值类型；本例没有其他数值类型说明，推导得到整数加法，结果也是整数。于是输入、内部变量和输出能够连起来。

这与观察几次运行结果、猜测下一次输入不同。系统会检查代码中所有分支和表达式的要求，即使某个分支这次没有执行，也不能随意违反类型规则。类型是在静态检查中推出来的，不是运行到哪里才临时决定。

如果删去这个版本的类型说明，三个编号只告诉系统“至少存在编号为1、2、3的字段”。它们没有说明记录是否还有第4项、第5项，或者其他名字的字段。三项整数元组、四项整数元组，以及前三项是整数的更多结构，都可能符合这点信息。

因此，下面是单独的预期类型错误，不要把它当成可正常装入的函数定义。

问题不是加法不会算，而是参数记录的完整形状没有确定。原课程使用的 SML/NJ 会报告未解决的灵活记录；Poly/ML 的报错措辞可能不同。使用完整的元组、记录模式，通常能直接给出这份信息，因此 ML 代码经常省略参数类型。类型说明仍然可以保留，用来表达意图或帮助定位问题。

“更一般”的类型，要怎样读

如果题目要求 int * int * int -> int，而 partial_sum 得到 int * 'a * int -> int，不必为了让打印结果完全相同而加一堆限制。只要把 'a 一致地换成 int，就得到题目需要的类型。这个函数可以接收所需输入，而且还能接收更多合适的输入。

“一致地换”很关键。下面是已经熟悉的列表拼接，这次也省略了类型说明。

它的类型是 'a list * 'a list -> 'a list。一次使用中，所有相同的 'a 都要替换成同一个类型；所以两个输入列表与输出列表的元素类型一致。它可以用于字符串，也可以用于整数，却不能用同一个调用把字符串列表和整数列表拼成普通列表。多态提供的是有规则的通用性，不是取消列表元素类型一致的要求。

原课还把这条规则与类型别名、记录字段次序放在一起。设 type foo = int * int，那么 {quux:'b,bar:int*'a,baz:'b} 可以通过一致替换 'a=int、'b=string，得到 {quux:string,bar:foo,baz:string}。把后者改写成 {baz:string,quux:string,bar:int*int}，仍然是相同的具体记录类型：字段只是换了书写次序，foo 也只是被展开成原来的类型。不同类型变量可以选择相同或不同的替换类型，但同一个变量的各次出现必须始终一致。

两个单引号，多了一条相等比较的要求

最后看一个把相等比较包装起来的函数。输入两个值，相等时返回 "yes"，否则返回 "no"。

结果依次是 "yes"、"no"、"yes"。is_three 被整数常量 3 限定为 int -> string。same_thing 则通常显示为 ''a * ''a -> string：两个操作数要有相同类型，而且这个类型必须支持 ML 的相等比较。这里的 ''a 是两个单引号；SML 的相等运算符仍然是 =，不是 ==。

原课 REPL 还可能提示 calling polyEqual，提醒这里使用了多态相等比较；它不是说这个合法函数未通过类型检查。不同实现可能不显示相同警告，阅读时仍以两个相同的相等类型变量为准，不必为了消除显示差异，把通用函数强行限定成只能比较整数。

整数、布尔值、字符串支持这种比较；所有组成部分都支持相等比较的元组也支持，例如 int * (string * bool)。函数类型不支持它，ML 不会靠运行几个输入来判断两个函数永远等价。real 也不属于这种相等类型；浮点近似值的比较需要另外考虑。

因此，same_thing (1.0,1.0) 是预期类型错误，两个函数之间用 = 比较也一样。''a 不能像普通 'a 那样替换成任意类型，它带着“必须能做相等比较”的约束。这一篇先能读懂这些类型就够了；下一篇会把注意力移回数据本身，看模式怎样沿着多层结构继续拆下去。

读到一个较长类型时，可以分三步对回函数：先找整体输入与输出，再把相同的类型变量连起来，最后检查有没有 ''a 这样的额外要求。比如 ''a list * ''a -> bool 表示一份列表与一个待检查元素，二者元素类型相同，而且该类型可做相等比较；它不是“列表可以是任何类型，而第二项再任选另一种”。

这些信息能排除很多不合法调用，但不能代替函数本身的业务含义。partial_sum 若误写成 x-z，仍可能得到相同的输入输出类型，却不会完成“加第一项与第三项”的任务。因此确认类型更一般以后，仍应把具体输入带回原问题，像前面那样核对结果8。类型说明允许哪些数据进入，函数体则决定进入后究竟做什么。
