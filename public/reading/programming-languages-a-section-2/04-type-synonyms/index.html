一段记录类型太长，能不能给它取个名字

前面用记录保存书名、页数与完成状态。如果几个函数都要接收这种记录，每次写 {book:string,pages:int,finished:bool} 很繁琐。现在想给这套现成结构取一个简短名字 reading_record，让函数说明更容易读。

ML 使用 type 名字 = 已有类型 建立这种名称。它叫作类型别名，负责给同一种类型增加另一种写法。下面的函数读取记录中的页数；输入一条读了 12 页的记录，仍返回整数 12。

day 没有经过名叫 reading_record 的构造器，也不需要额外包一层。它原本就是具有这三个字段的记录，所以可以直接传给函数。reading_record 与大括号写出的完整类型，在这里可以互相替换。

别名没有建立另一种不相容的数据

下面故意对同一个值写两种类型说明，再把它们都交给刚才的函数。: 类型 是已有的类型标注，让检查器确认值确实具有该类型。

两条定义都能通过，两个结果也相同。解释器有时显示 reading_record，有时显示完整记录类型，只是选了不同写法，不能据此判断我们定义了不同类型。它也不会因为多了这个名字，就自动增加字段或改变记录的求值。

原阅读笔记用更小的例子强调这一点：type foo = int 后，foo 与 int 完全可以互换。下面函数的输入输出写成 foo，仍可接收普通整数，结果也能继续与整数相加。

对整数另取名字的收益不大，但记录和复杂元组越长，别名就越能帮助表达用途。它主要改善表达，不会替我们施加“页数必须非负”一类新约束。

回到原课：一张牌就是花色与牌面的组合

上一篇的纸牌例子很适合取名：每张牌同时有一个 suit 和一个 rank。为让本段可单独运行，下面重新列出它需要的两个数据类型，再把 suit * rank 命名为 card。

c1、c2、c3 都是同一种类型的值，恰好都是黑桃 A。函数要求 card，并不会拒绝用 suit * rank 说明的值；它先用 #1 读取花色，再用 #2 读取牌面，判断二者是否分别为 Spade、Queen。

因此，当练习要求一个 card -> bool 的函数，而解释器显示 suit * rank -> bool 时，类型要求没有被违反。后面改用模式匹配而省略参数标注后，工具更可能自行选择展开写法；只要两种类型确实由这个别名相连，就可以按相同类型理解。

datatype 与 type，差别要看有没有新的数据边界

容易混淆的是：二者都可以引入一个类型名，但 datatype 会建立新的类型，而 type 只是同一类型的别名。假设想把页数明确包装成一种数据，可以定义下面这个只有一种形状的新类型；它与原来的 int 不再是同一类型。

什么时候值得取别名

当同一段结构多次出现，或者类型名能直接说明它的用途时，别名很有用。它让人看到“这是牌”“这是阅读记录”，同时保留与原结构完全互通的便利。

但别名不是隐藏实现或禁止混用的机制。原课后续讲模块时会在这项能力上继续构建更强的规则；本节只需要把当前结论把握准确：换一个类型名称，不等于换一种数据类型。
