匹配成功时，名字到底绑定到了哪里

上一篇我们用一条模式拆开了多层列表和元组。现在回到一个更小的问题：看到模式与数据时，怎样不靠“看起来差不多”，而是逐层判断它们是否匹配，并准确写出每个名字的值？

先看完整例子。输入是一份列表，列表中的每一项都是“两对整数组成的一对”；函数取第一项的四个整数，以及后面还剩多少项。

parts 是 SOME (12,18,10,7,1)。最外层 :: 拆开头部与尾部，头部的元组模式再拆成两个二项元组，最后把四个整数交给四个变量。这整个过程只做结构检查和绑定，没有计算 a+b，也没有修改列表。

从最小规则，拼出整条匹配过程

把“一个模式是否匹配一个值”当成一个小问题。若模式内部还有模式，就对对应的内部值继续问同样的问题；任何一处失败，整条模式就失败。这是递归定义，和我们处理表达式树时的思路一样。

模式形状 怎样判断成功 成功后留下什么
变量 x 匹配传来的整个值 绑定 x 到这个值
通配符 _ 匹配任意值 不绑定名字
整数常量，如 37 值就是该整数 不绑定名字
无附带数据的构造器，如 NONE 值使用同一个构造器 不绑定名字
C p 外层也是 C，里面的值匹配 p 保留内部匹配产生的绑定
(p1,p2,...,pn) 对应的每一项都匹配 合并各项产生的绑定

记录模式也按字段递归匹配；字段书写次序不改变对应关系。以上讨论都以代码先通过类型检查为前提：同一个 case 里的模式与被检查的值必须有相容的类型。不能把“拿一个整数去试元组模式”当成类型正确的运行分支选择。

应用到开头的例子，rest 接到的是整个剩余列表，而不是它的头部。若输入为空，第一条模式在最外层就失败，然后尝试 [] 分支；若输入只有一项，第一条仍然成功，此时 rest=[]。

构造器先认外层，再检查里面

继续沿用计算器的数据定义，下面给出自足版本。Add 携带两个子表达式组成的元组；我们想识别“两边直接都是整数常量”的加法。

simple 是 SOME 30，deeper 是 NONE。第二个输入虽然最外层也是 Add，但第二项是 Negate ...，不符合里面的 Constant y，所以整条嵌套模式失败。它不会先绑定 x，再勉强带着半份匹配结果执行分支。

如果模式写成 Add pair，同样可以成功识别任意 Add，但 pair 会接收整个子表达式元组。这揭示了一个和函数参数相似的事实：构造器可以不带数据，也可以携带一个数据；看起来携带“两项”的 Add(e1,e2)，实际携带的是一个二项元组。元组模式只是继续拆开这一个值。

列表的 :: 也可以这样理解：它组合头部与尾部，所以 a::b::c::rest 能逐层拆开。末尾的 rest 匹配任意剩余列表；若换成 []，就额外要求在那里结束。这就是“至少三项”与“恰好三项”的精确差别。

名字不是一个隐藏的相等测试

变量模式总会绑定当前值，不会偷偷比较外层同名变量。因此同一条模式里也不能重复使用一个变量，期望它表达“两项必须相等”。下面这段是预期编译错误。

应当给两项不同名字，再显式写比较。例如 fun equal_pair (x,y) = x=y。两个名字分别接住两个值，相等关系由表达式里的 = 判断。这样也更容易分清：模式负责描述结构，分支里的代码负责计算结构中各部分的关系。

如果外层已经有同名变量，分支内的变量模式会引入新的局部绑定，而不是拿旧值来比较。下面故意让外层 x 为99；分支匹配成功时，里面的 x 接到12，所以 inside 得到30，而 outside 仍是99。

这沿用上周的遮蔽规则，没有修改外层的绑定。也正因为变量模式如此通用，想识别固定值时要使用相应的常量或构造器模式，想检查两个值的关系时则使用分支里的表达式。

case 会先把 of 前面的表达式算成一个值，再按源代码顺序尝试各条模式，选择第一条成功的分支。成功分支引入的名字只用于相应分支表达式；下一条分支不会沿用这次的局部绑定。把 _ 放在前面会使后续情况永远到不了；编译器通常会指出冗余模式。

相反，如果没有任何模式覆盖某些可能的输入，编译器会给出不完整匹配警告。警告不等于已经处理失败情况：运行时真的遇到未覆盖值，匹配仍会失败。前一篇 multsign 的兜底 _ 很短，但它也可能遮住漏写分支，因此要确认它接住的所有情况确实该有同一个结果。

函数开头也可以直接列出多个模式

原课程还介绍一种可选写法。下面是同一个计算器求值函数，这次直接把不同输入形状写在函数定义上；完整输入是表达式树，输出是整数。

answer 是 10。只有第一行写 fun，后面的每条用 |，但都重复函数名 eval。它是单个函数，不是定义四个互相覆盖的同名函数。按输入模式选择分支的规则，仍然与函数体里写 case 一样。

熟悉的拼接也可以改成 fun append ([],ys) = ys | append (x::rest,ys) = x :: append (rest,ys)。外层仍是一个二项元组参数，里面才分别检查两份列表的形状。这种写法属于语法糖，既没有改变参数个数，也没有增加新计算能力。

使用它时要保留构造器模式所需的括号。若原来的分支还需要整个原参数的名字，就不能直接删掉 case 前那个名字却在分支继续使用它；可以保留原写法。反过来把多分支函数改成 case 时，也应选择一个不会遮住分支所需外层变量的新参数名。两种风格都可读，关键是明确同一套匹配规则。
