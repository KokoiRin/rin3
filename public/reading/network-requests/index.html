先带着一个场景读

你在 Android 页面点击“刷新”，应用请求 https://api.example.com/feed，再把返回的 JSON 显示成列表。先不管网络库内部有多少层，抓住这几件事：

  1. 找到地址：需要时通过 DNS 将域名解析为可连接的地址。
  2. 准备连接：可能复用已有连接，也可能新建；HTTPS 还需要安全连接和身份校验。
  3. 交换消息：客户端发送方法、路径、标头和可选请求体，服务器返回状态码、标头和可选响应体。
  4. 决定是否复用：有些响应能从缓存直接使用，有些需要向服务器验证；连接也可能留给后续请求。

这只是导读模型，不是每次请求都固定执行四步：缓存可能避免网络访问，DNS 和连接也可能复用。后面的正文会逐步补上条件。

怎么读比较合适

第一次先读 N01～N03。其中 N01 的域名购买部分可以略读，重点看 DNS 查询；N03 可以对照一条工作中的请求日志，把 URL、请求标头、状态码、响应体分别找出来。

接着读 N04、N05，理解复用连接和 HTTPS。N06 缓存篇较长，可以先读到“不要缓存”的几个小节，之后再看刷新与工程模式。最后用 N07 把 HTTP/1.1、HTTP/2、HTTP/3 串起来。

这里还没有展开 TCP 拥塞控制算法，也没有假定你的项目使用某个特定网络库。连接池参数、超时、取消和自动重试，需要下一步结合真实请求代码学习；不把浏览器策略当成 Android 通用规则。
