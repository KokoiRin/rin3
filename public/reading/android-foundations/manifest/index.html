每个应用项目都必须在项目源集的根目录下包含一个名为 AndroidManifest.xml 的文件，名称必须完全一致。清单文件向 Android 构建工具、Android 操作系统和 Google Play 描述应用的基本信息。

清单文件必须声明的内容包括但不限于：

  • 应用的组件，包括所有 Activity、Service、广播接收器和内容提供程序。每个组件都必须定义基本属性，例如其 Kotlin 或 Java 类的名称。组件还可以声明自身能力，例如它能处理哪些设备配置，以及描述如何启动该组件的 Intent Filter。后文将进一步介绍应用组件。
  • 应用访问系统或其他应用受保护部分所需的权限。清单还会声明其他应用访问本应用内容时必须具备的权限。后文将进一步介绍权限。
  • 应用所需的硬件和软件功能，这会影响哪些设备能够从 Google Play 安装该应用。后文将进一步介绍设备兼容性。

如果使用 Android Studio 构建应用，系统会为你创建清单文件，并在你构建应用的过程中添加大部分必要的清单元素，尤其是在使用代码模板时。

文件功能

以下各节说明应用的一些重要特性如何体现在清单文件中。

应用组件

对于你在应用中创建的每个应用组件，都应在清单文件中声明相应的 XML 元素：

  • 每个 Activity 子类对应一个 <activity>
  • 每个 Service 子类对应一个 <service>
  • 每个 BroadcastReceiver 子类对应一个 <receiver>
  • 每个 ContentProvider 子类对应一个 <provider>

如果继承了上述任意组件，却没有在清单文件中声明它，系统就无法启动它。

使用 name 属性指定子类名称，并包含完整的包路径。例如，Activity 子类的声明如下：

<manifest ... >
    <application ... >
        <activity android:name="com.example.myapp.MainActivity" ... >
        </activity>
    </application>
</manifest>

不过，如果 name 值的第一个字符是句点，系统就会在名称前加上应用的命名空间，即模块级 build.gradle 文件中 namespace 属性的值。例如，如果命名空间为 "com.example.myapp"，下面的 Activity 名称就会解析为 com.example.myapp.MainActivity：

<manifest ... >
    <application ... >
        <activity android:name=".MainActivity" ... >
            ...
        </activity>
    </application>
</manifest>

有关设置包名或命名空间的更多信息，请参阅设置命名空间。

如果应用组件位于子包中，例如 com.example.myapp.purchases，则 name 值必须包含缺失的子包名称，例如 ".purchases.PayActivity"，或者使用完全限定的包名。

Intent Filter

应用的 Activity、Service 和广播接收器由 Intent 激活。Intent 是由 Intent 对象定义的消息，描述要执行的操作，包括操作涉及的数据、预期执行该操作的组件类别，以及其他指令。

应用向系统发出 Intent 时，系统会根据各应用清单文件中声明的 Intent Filter，寻找能够处理该 Intent 的应用组件。系统会启动匹配组件的实例，并将 Intent 对象传给该组件。如果多个应用都能处理该 Intent，用户就可以选择使用哪个应用。

应用组件可以拥有任意数量的 Intent Filter（通过 <intent-filter> 元素定义），每个 Filter 描述该组件的一种不同能力。

更多信息请参阅 Intent 与 Intent Filter 文档。

图标与标签

许多清单元素具有 icon 和 label 属性，分别用于向用户显示对应应用组件的小图标和文本标签。

在所有情况下，父元素设置的图标和标签，都会成为所有子元素的默认 icon 和 label 值。例如，<application> 元素设置的图标和标签，就是应用中每个组件（例如所有 Activity）的默认图标和标签。

每当某个组件作为满足 Intent 的选项呈现给用户时，系统就会显示该组件 <intent-filter> 中设置的图标和标签。默认情况下，这个图标继承自父组件中声明的图标，也就是 <activity> 或 <application> 元素中的图标。

如果某个 Intent Filter 提供一种独特操作，而你希望在选择器对话框中更清楚地表示这一点，就可以为它更换图标。更多信息请参阅允许其他应用启动你的 Activity。

权限

Android 应用必须请求权限，才能访问联系人、短信等敏感用户数据，或相机、互联网访问等某些系统功能。每项权限都由唯一的标签标识。例如，需要发送短信的应用必须在清单中加入下面这一行：

<manifest ... >
    <uses-permission android:name="android.permission.SEND_SMS"/>
    ...
</manifest>

从 Android 6.0（API 级别 23）开始，用户可以在运行时批准或拒绝某些应用权限。不过，无论应用支持哪个 Android 版本，都必须在清单中使用 <uses-permission> 元素声明所有权限请求。如果权限获准，应用就可以使用受保护的功能；否则，访问这些功能的尝试就会失败。

应用也可以使用权限保护自己的组件。它可以使用 Android 定义的任意权限（列于 android.Manifest.permission），也可以使用另一个应用声明的权限。应用还可以定义自己的权限，新的权限通过 <permission> 元素声明。

更多信息请参阅 Android 权限。

设备兼容性

清单文件还可用于声明应用需要哪些类型的硬件或软件功能，进而说明应用与哪些类型的设备兼容。如果设备不具备应用所需的功能或系统版本，Google Play 商店就不会允许用户在该设备上安装应用。

有多个清单标签用于定义应用兼容的设备。以下是其中一些最常见的标签。

<uses-feature>

<uses-feature> 元素允许你声明应用需要的硬件和软件功能。例如，如果应用在没有指南针传感器的设备上无法实现基本功能，可以使用以下清单标签，将指南针传感器声明为必需功能：

<manifest ... >
    <uses-feature android:name="android.hardware.sensor.compass"
                  android:required="true" />
    ...
</manifest>

注意：如果希望应用能在 Chromebook 上使用，需要考虑一些重要的硬件和软件功能限制。更多信息请参阅 Chromebook 的应用清单兼容性。

<uses-sdk>

每个后续平台版本通常都会增加前一版本中没有的新 API。要指明应用兼容的最低版本，清单必须包含 <uses-sdk> 标签及其 minSdkVersion 属性。

不过，请注意，<uses-sdk> 元素中的属性会被 build.gradle 文件中的对应属性覆盖。因此，如果使用 Android Studio，应改在该文件中指定 minSdkVersion 和 targetSdkVersion 的值：

Groovy

android {
    defaultConfig {
        applicationId 'com.example.myapp'

        // Defines the minimum API level required to run the app.
        minSdkVersion 23

        // Specifies the API level used to test the app.
        targetSdkVersion 36
        ...
    }
}

Kotlin

android {
    defaultConfig {
        applicationId = "com.example.myapp"

        // Defines the minimum API level required to run the app.
        minSdkVersion(23)

        // Specifies the API level used to test the app.
        targetSdkVersion(36)
        ...
    }
}

有关 build.gradle 文件的更多信息，请阅读如何配置构建。

要进一步了解如何声明应用对不同设备的支持，请参阅设备兼容性概览。

文件约定

本节介绍通常适用于清单文件中所有元素和属性的约定及规则。

元素
只有 <manifest> 和 <application> 元素是必需的，并且各自必须且只能出现一次。其他大多数元素可以出现零次或多次。不过，要使清单文件发挥作用，其中一些元素必须存在。

所有值都通过属性设置，而不是作为元素内的字符数据设置。

同一级别的元素通常没有顺序要求。例如，<activity>、<provider> 和 <service> 元素可以按任意顺序放置。此规则有两个重要例外：

  • <activity-alias> 元素必须位于其所指代的 <activity> 之后。
  • <application> 元素必须是 <manifest> 元素内的最后一个元素。
属性
从技术上讲，所有属性都是可选的。不过，为使元素发挥其作用，许多属性必须指定。对于真正可选的属性，参考文档会说明其默认值。

除根 <manifest> 元素的少数属性外，所有属性名都以 android: 为前缀，例如 android:alwaysRetainTaskState。由于此前缀通用，文档在按名称提及属性时通常将其省略。

多个值
如果可以指定多个值，几乎总是通过重复元素实现，而不是在单个元素内列出多个值。例如，一个 Intent 过滤器可以列出多个操作：
<intent-filter ... >
    <action android:name="android.intent.action.EDIT" />
    <action android:name="android.intent.action.INSERT" />
    <action android:name="android.intent.action.DELETE" />
    ...
</intent-filter>
资源值
某些属性的值会显示给用户，例如 Activity 的标题或应用图标。这些属性值可能因用户语言或其他设备配置而异（例如根据设备像素密度提供不同尺寸的图标），因此应通过资源或主题设置，而不是硬编码到清单文件中。这样，实际值就可以根据针对不同设备配置提供的替代资源而改变。

资源采用以下格式表示为值：

"@[package:]type/name"

如果资源由应用提供，可以省略包名（由库依赖项提供时也可以，因为库资源会合并到应用资源中）。唯一其他有效包名是 android，用于引用 Android 框架中的资源。

类型指资源类型，例如 string 或 drawable，名称是标识特定资源的名称。示例如下：

<activity android:icon="@drawable/smallPic" ... >

有关向项目添加资源的更多信息，请阅读应用资源概览。

如果要应用在主题中定义的值，第一个字符必须使用 ?，而不是 @：

"?[package:]type/name"

字符串值
当属性值为字符串时，使用双反斜杠（\\）转义字符，例如使用 \\n 表示换行符，或使用 \\uxxxx 表示 Unicode 字符。

清单元素参考

下表提供了 AndroidManifest.xml 文件中所有有效元素的参考文档链接。

<action>向 Intent 过滤器添加一个操作。
<activity>声明一个 Activity 组件。
<activity-alias>为 Activity 声明一个别名。
<application>声明应用。
<category>向 Intent 过滤器添加一个类别名称。
<compatible-screens>指定应用兼容的各个屏幕配置。
<data>向 Intent 过滤器添加一项数据规范。
<grant-uri-permission>指定父级内容提供程序有权访问的应用数据子集。
<instrumentation>声明一个 Instrumentation 类，用于监控应用与系统之间的交互。
<intent-filter>指定 Activity、服务或广播接收器能够响应的 Intent 类型。
<manifest>AndroidManifest.xml 文件的根元素。
<meta-data>一个名称-值对，用于表示可提供给父组件的任意附加数据项。
<path-permission>定义内容提供程序内特定数据子集的路径及所需权限。
<permission>声明一个安全权限，可用于限制对本应用或其他应用中特定组件或功能的访问。
<permission-group>为一组逻辑上相关的权限声明名称。
<permission-tree>声明权限树的基础名称。
<provider>声明一个内容提供程序组件。
<queries>声明应用打算访问的其他应用集合。详情请参阅软件包可见性过滤指南。
<receiver>声明一个广播接收器组件。
<service>声明一个服务组件。
<supports-gl-texture> 声明应用支持的一种 GL 纹理压缩格式。
<supports-screens> 声明应用支持的屏幕尺寸，并为大于应用支持范围的屏幕启用屏幕兼容模式。
<uses-configuration> 指明应用所需的特定输入功能。
<uses-feature> 声明应用使用的一项硬件或软件功能。
<uses-library>指定应用必须链接的共享库。
<uses-native-library>指定应用必须链接的、由供应商提供的原生共享库。
<uses-permission>指定应用正常运行所需、必须由用户授予的系统权限。
<uses-permission-sdk-23>指定应用需要某项权限，但仅在应用安装于运行 Android 6.0（API 级别 23）或更高版本的设备时才需要。
<uses-sdk>允许通过 API 级别整数，表示应用与一个或多个 Android 平台版本的兼容性。

限制

以下标签在清单文件中的出现次数受到限制：

标签名称上限
<package>1000
<meta-data>1000
<uses-library>1000

以下属性的最大长度受到限制：

属性上限
name1024
versionName1024
host255
mimeType255

清单文件示例

下面的 XML 是一个简单的 AndroidManifest.xml 示例，为应用声明了两个 Activity。

<?xml version="1.0" encoding="utf-8"?>
<manifest
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:versionCode="1"
    android:versionName="1.0">

    <!-- Beware that these values are overridden by the build.gradle file -->
    <uses-sdk android:minSdkVersion="15" android:targetSdkVersion="26" />

    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:roundIcon="@mipmap/ic_launcher_round"
        android:label="@string/app_name"
        android:supportsRtl="true"
        android:theme="@style/AppTheme">

        <!-- This name is resolved to com.example.myapp.MainActivity
             based on the namespace property in the build.gradle file -->
        <activity android:name=".MainActivity">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <activity
            android:name=".DisplayMessageActivity"
            android:parentActivityName=".MainActivity" />
    </application>
</manifest>
