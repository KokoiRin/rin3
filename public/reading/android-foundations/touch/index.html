处理 ViewGroup 的触摸事件时，要特别留意事件该交给谁。ViewGroup 里的子元素，常常要处理与 ViewGroup 自身不同的触摸事件。为了让每个 View 都收到该由它处理的事件，需要重写 onInterceptTouchEvent()。

在 ViewGroup 中拦截触摸事件

只要在 ViewGroup 的区域内检测到触摸，包括触摸到子元素，就会调用 onInterceptTouchEvent()。如果 onInterceptTouchEvent() 返回 true，就表示拦截这个 MotionEvent：事件不再传给子元素，而是交给父元素的 onTouchEvent() 处理。

通过 onInterceptTouchEvent()，父元素能先于子元素看到触摸事件。如果 onInterceptTouchEvent() 返回 true，原本正在处理触摸的子 View 会收到 ACTION_CANCEL。从这时起，后续事件就交给父元素的 onTouchEvent()，按通常的方式处理。onInterceptTouchEvent() 也可以返回 false，只观察事件，让它继续沿 View 层次结构向下传给原来的目标，再由目标自己的 onTouchEvent() 处理。

下面的代码中，MyViewGroup 继承 ViewGroup，MyViewGroup 里有多个子 View。如果手指在某个子 View 上横向拖动，子 View 就不再接收触摸事件，改由 MyViewGroup 滚动自己的内容来处理。但如果只是点按子 View 里的按钮，或在子 View 上纵向滚动，这些操作本来就应该交给子元素，父元素便不会拦截。此时 onInterceptTouchEvent() 返回 false，也不会调用 MyViewGroup 的 onTouchEvent()。

Kotlin

class MyViewGroup @JvmOverloads constructor(
        context: Context,
        private val mTouchSlop: Int = ViewConfiguration.get(context).scaledTouchSlop
) : ViewGroup(context) {
    ...
    override fun onInterceptTouchEvent(ev: MotionEvent): Boolean {
        // This method only determines whether you want to intercept the motion.
        // If this method returns true, onTouchEvent is called and you can do
        // the actual scrolling there.
        return when (ev.actionMasked) {
            // Always handle the case of the touch gesture being complete.
            MotionEvent.ACTION_CANCEL, MotionEvent.ACTION_UP -> {
                // Release the scroll.
                mIsScrolling = false
                false // Don't intercept the touch event. Let the child handle it.
            }
            MotionEvent.ACTION_MOVE -> {
                if (mIsScrolling) {
                    // You're currently scrolling, so intercept the touch event.
                    true
                } else {

                    // If the user drags their finger horizontally more than the
                    // touch slop, start the scroll.

                    // Left as an exercise for the reader.
                    val xDiff: Int = calculateDistanceX(ev)

                    // Touch slop is calculated using ViewConfiguration constants.
                    if (xDiff > mTouchSlop) {
                        // Start scrolling!
                        mIsScrolling = true
                        true
                    } else {
                        false
                    }
                }
            }
            ...
            else -> {
                // In general, don't intercept touch events. The child view
                // handles them.
                false
            }
        }
    }

    override fun onTouchEvent(event: MotionEvent): Boolean {
        // Here, you actually handle the touch event. For example, if the action
        // is ACTION_MOVE, scroll this container. This method is only called if
        // the touch event is intercepted in onInterceptTouchEvent.
        ...
    }
}

        // If this method returns true, onTouchEvent is called and you can do

                if (xDiff > mTouchSlop) {
                    // Start scrolling.
                    mIsScrolling = true;
                    return true;
                }
                break;
            }
            ...
        }

        return false;

另外，ViewGroup 还提供了 requestDisallowInterceptTouchEvent()。如果子元素不希望父元素及更上层的祖先通过 onInterceptTouchEvent() 拦截触摸，ViewGroup 就会调用这个方法。

处理 ACTION_OUTSIDE 事件

如果 ViewGroup 收到的 MotionEvent 带有 ACTION_OUTSIDE，默认不会继续把它交给子元素。要处理这种带有 ACTION_OUTSIDE 的 MotionEvent，有两种方式：重写 dispatchTouchEvent(MotionEvent event)，把事件传给合适的 View；或者在相关的 Window.Callback 中处理，比如 Activity。

使用 ViewConfiguration 常量

前面的代码用当前的 ViewConfiguration 初始化了 mTouchSlop 变量。通过 ViewConfiguration，你能取得 Android 系统常用的距离、速度和时间值。

手指触碰屏幕后，可能会有一点小幅移动，不一定是在滚动。“Touch slop”就是系统把手势认定为滚动之前，允许触点移动的距离，单位是像素。它通常用来避免误滚动，比如用户只是想点一下屏幕上的某个元素。

ViewConfiguration 还有两个常用方法：getScaledMinimumFlingVelocity() 和 getScaledMaximumFlingVelocity()。它们分别给出触发 fling（快速滑动）的最小速度和最大速度，单位是像素/秒。例如：

Kotlin

private val vc: ViewConfiguration = ViewConfiguration.get(context)
private val mSlop: Int = vc.scaledTouchSlop
private val mMinFlingVelocity: Int = vc.scaledMinimumFlingVelocity
private val mMaxFlingVelocity: Int = vc.scaledMaximumFlingVelocity
...
MotionEvent.ACTION_MOVE -> {
    ...
    val deltaX: Float = motionEvent.rawX - mDownX
    if (Math.abs(deltaX) > mSlop) {
        // A swipe occurs, do something.
    }
    return false
}
...
MotionEvent.ACTION_UP -> {
    ...
    if (velocityX in mMinFlingVelocity..mMaxFlingVelocity && velocityY < velocityX) {
        // The criteria are satisfied, do something.
    }
}

private int mMaxFlingVelocity = vc.getScaledMaximumFlingVelocity();

    ...

        // A swipe occurs, do something.
    }
...
case MotionEvent.ACTION_UP: {
    ...
    } if (mMinFlingVelocity <= velocityX && velocityX <= mMaxFlingVelocity
            && velocityY < velocityX) {
        // The criteria are satisfied, do something.
    }
}

扩展子 View 的可触摸区域

Android 提供了 TouchDelegate 类，让父 View 可以把子 View 的可触摸区域扩大到它本身的边界之外。子 View 必须做得很小、但又需要更容易点中时，这就很有用。同样的方法也可以缩小触摸区域。

下面的例子中，ImageButton 是委托 View，也就是那个需要父 View 帮它扩大触摸区域的子 View。布局文件如下：

<RelativeLayout xmlns:android="http://schemas.android.com/apk/res/android"
     android:id="@+id/parent_layout"
     android:layout_width="match_parent"
     android:layout_height="match_parent"
     tools:context=".MainActivity" >

     <ImageButton android:id="@+id/button"
          android:layout_width="wrap_content"
          android:layout_height="wrap_content"
          android:background="@null"
          android:src="@drawable/icon" />
</RelativeLayout>

下面这段代码会依次做这些事：

  • 先取得父 View，再向 UI 线程投递一个 Runnable。这样，调用 getHitRect() 时，父 View 已经给子元素做好布局。getHitRect() 取得的是子元素的命中矩形，也就是可触摸区域，使用的是父 View 的坐标系。
  • 找到 ImageButton 这个子 View，调用 getHitRect()，取得它可触摸区域的边界。
  • 扩大 ImageButton 子 View 的命中矩形。
  • 创建 TouchDelegate 实例，把扩大后的命中矩形和 ImageButton 子 View 传进去。
  • 把 TouchDelegate 设置到父 View 上。之后，只要触摸落在这个委托区域内，事件就会传给子 View。

父 View 作为 ImageButton 子 View 的触摸委托，会接收所有触摸事件。如果触摸点落在子 View 的命中矩形内，父 View 就把事件交给子 View 处理。

Kotlin

public class MainActivity : Activity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        // Post in the parent's message queue to make sure the parent lays out
        // its children before you call getHitRect().
        findViewById<View>(R.id.parent_layout).post {
            // The bounds for the delegate view, which is an ImageButton in this
            // example.
            val delegateArea = Rect()
            val myButton = findViewById<ImageButton>(R.id.button).apply {
                isEnabled = true
                setOnClickListener {
                    Toast.makeText(
                            this@MainActivity,
                            "Touch occurred within ImageButton touch region.",
                            Toast.LENGTH_SHORT
                    ).show()
                }

                // The hit rectangle for the ImageButton.
                getHitRect(delegateArea)
            }

            // Extend the touch area of the ImageButton beyond its bounds on the
            // right and bottom.
            delegateArea.right += 100
            delegateArea.bottom += 100

            // Set the TouchDelegate on the parent view so that touches within
            // the touch delegate bounds are routed to the child.
            (myButton.parent as? View)?.apply {
                // Instantiate a TouchDelegate. "delegateArea" is the bounds in
                // local coordinates of the containing view to be mapped to the
                // delegate view. "myButton" is the child view that receives
                // motion events.
                touchDelegate = TouchDelegate(delegateArea, myButton)
            }
        }
    }
}

Java

public class MainActivity extends Activity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
        // Get the parent view.
        View parentView = findViewById(R.id.parent_layout);

        parentView.post(new Runnable() {
            // Post in the parent's message queue to make sure the parent lays
            // out its children before you call getHitRect().
            @Override
            public void run() {
                // The bounds for the delegate view, which is an ImageButton in
                // this example.
                Rect delegateArea = new Rect();
                ImageButton myButton = (ImageButton) findViewById(R.id.button);
                myButton.setEnabled(true);
                myButton.setOnClickListener(new View.OnClickListener() {
                    @Override
                    public void onClick(View view) {
                        Toast.makeText(MainActivity.this,
                                "Touch occurred within ImageButton touch region.",
                                Toast.LENGTH_SHORT).show();
                    }
                });

                // The hit rectangle for the ImageButton.
                myButton.getHitRect(delegateArea);

                // Extend the touch area of the ImageButton beyond its bounds on
                // the right and bottom.
                delegateArea.right += 100;
                delegateArea.bottom += 100;

                // Instantiate a TouchDelegate. "delegateArea" is the bounds in
                // local coordinates of the containing view to be mapped to the
                // delegate view. "myButton" is the child view that receives
                // motion events.
                TouchDelegate touchDelegate = new TouchDelegate(delegateArea,
                        myButton);

                // Set the TouchDelegate on the parent view so that touches
                // within the touch delegate bounds are routed to the child.
                if (View.class.isInstance(myButton.getParent())) {
                    ((View) myButton.getParent()).setTouchDelegate(touchDelegate);
                }
            }
        });
    }
}
