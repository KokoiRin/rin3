Jetpack Compose 是面向 Android 的现代声明式 UI 工具包。Compose 提供了声明式 API，使你无需以命令式方式修改前端 View，就可以渲染应用 UI，从而简化应用 UI 的编写与维护。这些术语需要一些解释，但其含义对于应用设计很重要。

声明式编程范式

过去，Android View 层次结构可以表示为一棵 UI 控件树。当应用状态因用户交互等因素而变化时，需要更新 UI 层次结构，以显示当前数据。最常见的 UI 更新方式是使用 findViewById() 等函数遍历树，并调用 button.setText(String)、container.addChild(View) 或 img.setImageBitmap(Bitmap) 等方法更改节点。这些方法会改变控件的内部状态。

手动操作 View 会增加出错的可能性。如果某项数据在多个位置渲染，你可能会忘记更新其中一个显示它的 View。当两个更新以意想不到的方式发生冲突时，也可能导致非法状态。例如，某次更新可能尝试给一个刚从 UI 中移除的节点设置值。通常，软件维护的复杂性会随需要更新的 View 数量而增长。

过去几年，整个行业开始转向声明式 UI 模型，它简化了用户界面的构建和更新。

从概念上说，这项技术会从头重新生成整个屏幕，然后只应用必要的变更。这种方式避免了手动更新有状态 View 层次结构的复杂性。Compose 是一个声明式 UI 框架。

重新生成整个屏幕的一个挑战是，它在时间、计算能力和电量消耗方面可能代价高昂。为了减轻这种成本，Compose 会智能地选择在任意时刻需要重新绘制哪些 UI 部分。这确实会影响 UI 组件的设计方式，重组一节对此有所讨论。

可组合函数示例

使用 Compose，可以通过定义一组接收数据并发出 UI 元素的可组合函数来构建用户界面。例如，Greeting 控件接收一个 String，并发出一个显示问候消息的 Text 控件。

关于此函数，有几点值得注意：

  • 注解：函数标有 @Composable 注解。所有可组合函数都必须具有此注解。该注解会告知 Compose 编译器，此函数旨在将数据转换为 UI。
  • 数据输入：函数接收数据。可组合函数可以接受参数，让应用逻辑能够描述 UI。在此例中，控件接收一个 String，从而可以按用户姓名问候用户。
  • UI 显示：函数在 UI 中显示文本。它通过调用 Text() 可组合函数实现这一点，后者实际创建文本 UI 元素。可组合函数通过调用其他可组合函数发出 UI 层次结构。
  • 没有返回值：函数不返回任何内容。发出 UI 的 Compose 函数不需要返回任何内容，因为它们描述的是目标屏幕状态，而不是构造 UI 控件。

  • 特性：此函数快速、幂等，且没有副作用。

    • 使用相同参数多次调用时，函数的行为相同；它不使用全局变量或 random() 调用等其他值。
    • 函数描述 UI，而不产生任何副作用，例如修改属性或全局变量。

    通常，所有可组合函数都必须具备这些特性，原因见重组一节。

声明式范式转变

在许多命令式面向对象 UI 工具包中，通过实例化一棵控件树来初始化 UI。通常，这通过展开一个 XML 布局文件完成。每个控件维护自己的内部状态，并公开 getter 和 setter 方法，让应用逻辑与控件交互。

在 Compose 的声明式方式中，控件相对无状态，并且不公开 setter 或 getter 函数。事实上，控件并不作为对象公开。通过以不同参数调用同一个可组合函数来更新 UI。这简化了为 ViewModel 等架构模式提供状态的过程，如应用架构指南所述。随后，每当可观察数据更新时，可组合项都负责将当前应用状态转换为 UI。

用户与 UI 交互时，UI 会发出 onClick 等事件。这些事件应通知应用逻辑，应用逻辑随后可以更改应用状态。状态变化时，可组合函数会用新数据再次被调用。这会使 UI 元素重新绘制——这个过程称为重组。
