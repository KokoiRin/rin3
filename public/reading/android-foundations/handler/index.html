Handler 用于发送和处理与某个线程的 MessageQueue（消息队列）关联的 Message 和 Runnable 对象。每个 Handler 实例都对应一个线程及其消息队列。创建 Handler 时，需要将它绑定到一个 Looper；随后，它会把 Message 和 Runnable 投递到这个 Looper 的消息队列，并在 Looper 所在的线程上执行。

Handler 主要有两种用途：（1）安排 Message 和 Runnable 在未来某个时刻执行；（2）将操作加入队列，让它在当前线程之外的另一个线程上执行。

可以通过 post(Runnable)、postAtTime(Runnable,long)、postDelayed(Runnable, Object, long)、sendEmptyMessage(int)、sendMessage(Message)、sendMessageAtTime(Message, long) 和 sendMessageDelayed(Message, long) 等方法调度消息。post 系列方法将 Runnable 对象放入队列，由消息队列接收并调用；sendMessage 系列方法则将携带一组数据的 Message 对象放入队列，再交给 Handler 的 handleMessage(Message) 方法处理，为此需要你实现 Handler 的子类。

向 Handler 投递 Runnable 或发送 Message 时，可以让队列一有机会就尽快处理，也可以指定延迟多久处理，或指定处理的绝对时间。后两种方式可以用来实现超时、定时触发等与时间有关的行为。

系统为应用创建进程时，主线程会运行一个消息队列，用于管理 Activity、BroadcastReceiver 等顶层应用对象，以及它们创建的窗口。你可以创建自己的线程，并通过 Handler 与主线程通信：在新线程中调用前面介绍的 post 或 sendMessage 方法，传入的 Runnable 或 Message 就会进入 Handler 的消息队列，等待合适的时机处理。

使用 Handler 时的性能注意事项

Handler 的 has 和 remove 系列方法可能很慢，因为它们需要扫描整个待处理消息队列。如果底层 Looper 的 MessageQueue 中积压了很多消息，这些操作的开销就可能很大。

  • 要取消尚未执行的操作，可以考虑设置一个取消标志，让操作在继续执行前检查它，而不是从队列中移除消息或回调。
  • 要判断待执行的操作是否已经开始，可以让操作在开始时设置一个标志，而不是反复检查队列中是否还存在相应的消息或回调。
如需使用标准的并发原语，请参阅 java.util.concurrent。
