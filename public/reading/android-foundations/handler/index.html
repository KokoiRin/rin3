Handler 可以发送和处理 Message、Runnable 对象，这些对象与某个线程的 MessageQueue（消息队列）关联。一个 Handler 实例只对应一个线程，以及这个线程的消息队列。创建 Handler 时，要把它绑定到一个 Looper。之后，它会把 Message 和 Runnable 放进这个 Looper 的消息队列，再由 Looper 所在的线程执行。

Handler 主要用来做两件事：（1）安排 Message 和 Runnable，等到将来的某个时刻再执行；（2）把一个操作放入队列，交给当前线程之外的另一个线程执行。

安排消息执行，可以使用 post(Runnable)、postAtTime(Runnable,long)、postDelayed(Runnable, Object, long)、sendEmptyMessage(int)、sendMessage(Message)、sendMessageAtTime(Message, long) 和 sendMessageDelayed(Message, long) 这些方法。其中，post 系列放入队列的是 Runnable 对象，消息队列收到后会调用它；sendMessage 系列放入队列的则是 Message 对象，里面带着一组数据。后者会交给 Handler 的 handleMessage(Message) 方法处理，因此你需要实现一个 Handler 子类。

向 Handler 投递 Runnable 或发送 Message 时，你可以让队列准备好后尽快处理，也可以让它等一段时间，或者指定一个处理的绝对时间。后两种方式，就可以用来实现超时、定时触发等与时间有关的行为。

系统为应用创建进程时，主线程会专门运行一个消息队列，管理 Activity、BroadcastReceiver 等顶层应用对象，以及它们创建的窗口。你也可以创建自己的线程，再用 Handler 与主线程通信。做法是在新线程里调用前面说的 post 或 sendMessage 方法：传入的 Runnable 或 Message 会进入 Handler 的消息队列，等到合适的时候处理。

使用 Handler 时的性能注意事项

使用 Handler 的 has 和 remove 系列方法时，要留意性能。它们可能很慢，因为每次都要扫描整个队列，查找还没处理的消息。如果底层 Looper 的 MessageQueue 中积压了很多消息，这样扫描的开销就可能很大。

  • 如果想取消一个还没执行的操作，可以考虑设置一个“已取消”的标志，让操作在继续执行前先检查它。这样就不必从队列里移除消息或回调。
  • 如果想知道排队的操作是否还没发生，可以考虑让操作在开始时设置一个标志，表示“已经开始了”。这样就不必去队列里检查消息或回调是否还在。
如需使用标准的并发原语，请参阅 java.util.concurrent。

把 Runnable r 放进消息队列，安排在 uptimeMillis 指定的时间执行。这里的时间以 SystemClock.uptimeMillis() 为基准。如果设备进入 deep sleep（深度睡眠），睡眠所用的时间会让执行进一步延后。执行 Runnable 的，是当前 Handler 关联的线程。

参数
rRunnable：要执行的 Runnable。
不能为 null。

uptimeMillislong：回调应该在哪个绝对时间运行，时间以 SystemClock.uptimeMillis() 为基准。

返回值
boolean成功把 Runnable 放进消息队列，就返回 true；放入失败则返回 false。失败通常是因为处理队列的 Looper 正在退出。注意，true 只表示已经放进队列，不保证 Runnable 一定会执行。如果还没到消息预定送达的时间，Looper 就退出了，这条消息会被丢弃。
