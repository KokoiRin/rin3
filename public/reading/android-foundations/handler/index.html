Handler 允许你发送和处理与某个线程的 MessageQueue 关联的 Message 和 Runnable 对象。每个 Handler 实例都与一个线程及其消息队列关联。创建一个新的 Handler 时，它会绑定到一个 Looper。它会将消息和 Runnable 传递到该 Looper 的消息队列，并在该 Looper 的线程上执行它们。

Handler 主要有两种用途：（1）调度消息和 Runnable，使其在将来某个时刻执行；（2）将某个操作加入队列，使其在不同于当前线程的线程上执行。

消息调度通过 post(Runnable)、postAtTime(Runnable,long)、postDelayed(Runnable, Object, long)、sendEmptyMessage(int)、sendMessage(Message)、sendMessageAtTime(Message, long) 和 sendMessageDelayed(Message, long) 方法完成。post 系列方法允许将 Runnable 对象加入队列，在消息队列接收到它们时调用；sendMessage 系列方法允许将包含一组数据的 Message 对象加入队列，该数据将由 Handler 的 handleMessage(Message) 方法处理（需要你实现 Handler 的子类）。

向 Handler 投递或发送条目时，可以让条目在消息队列准备好处理时尽快得到处理，也可以指定处理前的延迟时间或处理的绝对时间。后两种方式允许实现超时、定时节拍以及其他基于时间的行为。

为应用创建进程时，其主线程专门用于运行一个消息队列，负责管理顶层应用对象（Activity、广播接收器等）以及它们创建的任何窗口。可以创建自己的线程，并通过 Handler 与应用主线程通信。具体做法与之前相同，调用 post 或 sendMessage 方法，只是从新线程中调用。给定的 Runnable 或 Message 随后会被安排到 Handler 的消息队列中，并在适当时得到处理。

使用 Handler 时的性能注意事项

请注意，Handler 的“has”和“remove”方法可能非常慢，因为这些操作会扫描整个待处理消息队列。如果底层 Looper 的 MessageQueue 中有许多待处理消息，开销可能很大。

  • 与其移除消息或回调来取消待处理操作，不如考虑设置一个表示取消的标志，并让操作在继续之前检查该标志。
  • 与其检查队列中是否存在某条消息或回调来判断待处理操作是否尚未发生，不如考虑让该操作设置一个标志，表明自己已经开始。
有关标准并发原语，请参阅 java.util.concurrent。
