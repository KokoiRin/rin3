当 Activity 获得焦点时，Android 框架会要求它绘制布局。Android 框架负责处理绘制过程，但 Activity 必须提供其布局层次结构的根节点。

Android 框架会绘制布局的根节点，并测量和绘制布局树。绘制时，它会遍历树，渲染每个与失效区域相交的 View。每个 ViewGroup 都负责使用 draw() 方法请求绘制其各个子元素，而每个 View 负责绘制自身。由于采用前序遍历，框架会先绘制父元素，再绘制子元素——也就是说，父元素位于子元素的后面；同级元素则按它们在树中出现的顺序绘制。

注意：框架不会绘制不在有效区域内的 View 对象。它也会替你处理 View 背景的绘制。可以通过调用 invalidate() 强制 View 绘制。

Android 框架通过两次遍历来绘制布局：测量遍历和布局遍历。框架在 measure(int, int) 中执行测量遍历，并自上而下遍历 View 树。递归过程中，每个 View 都会将尺寸规格向树的下层传递。测量遍历结束时，每个 View 都保存了自己的测量值。框架在 layout(int, int, int, int) 中执行第二次遍历，同样是自上而下。在此次遍历中，每个父元素负责使用测量遍历中计算出的大小，为所有子元素定位。

以下各节更详细地介绍布局过程的这两次遍历。

发起测量遍历

当 View 对象的 measure() 方法返回时，设置其 getMeasuredWidth() 和 getMeasuredHeight() 值，以及该 View 对象所有后代的对应值。View 对象的测量宽度和测量高度必须遵守其父元素施加的约束。这有助于确保测量遍历结束时，所有父元素都接受其所有子元素的测量结果。

父 View 可能会对其子元素多次调用 measure()。例如，父元素可能先使用未指定的尺寸对子元素测量一次，以确定它们偏好的大小。如果子元素不受约束时的大小之和过大或过小，父元素可能会再次调用 measure()，传入限制子元素大小的值。

测量遍历使用两个类传达尺寸信息。View 对象通过 ViewGroup.LayoutParams 类传达其偏好的大小和位置。基类 ViewGroup.LayoutParams 描述 View 偏好的宽度和高度。对于每个维度，可以指定以下选项之一：

  • 一个精确的尺寸。
  • MATCH_PARENT，表示 View 偏好的大小是其父元素的大小减去内边距。
  • WRAP_CONTENT，表示 View 偏好的大小是恰好包住其内容，再加上内边距。

不同的 ViewGroup 子类有不同的 ViewGroup.LayoutParams 子类。例如，RelativeLayout 有自己的 ViewGroup.LayoutParams 子类，其中包含使子 View 对象水平和垂直居中的能力。

MeasureSpec 对象用于将要求从父元素沿树向下传递给子元素。MeasureSpec 可以处于以下三种模式之一：

  • UNSPECIFIED：父元素用它来确定子 View 的目标尺寸。例如，LinearLayout 可能对子元素调用 measure()，将高度设为 UNSPECIFIED，宽度设为 EXACTLY 240，以确定在给定 240 像素宽度的情况下，子 View 希望有多高。
  • EXACTLY：父元素用它来为子元素规定精确大小。子元素必须使用此大小，并保证其所有后代都能容纳在此大小内。
  • AT MOST：父元素用它来为子元素规定最大大小。子元素必须保证自身及所有后代都能容纳在此大小内。
