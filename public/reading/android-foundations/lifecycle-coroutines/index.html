Kotlin 协程让你能够编写异步代码。你可以定义一个 CoroutineScope，管理协程该在什么时候运行。每个异步操作都属于一个特定的作用域。

感知生命周期的组件为应用中按逻辑划分的作用域提供了完善的协程支持。本文会介绍怎样把协程与这些能感知生命周期的组件配合使用。

添加依赖项

本文使用的内置协程作用域都来自 Lifecycle API，使用前要加上对应的依赖。

  • 在 Compose 中使用 ViewModel 工具，需要添加 implementation("androidx.lifecycle:lifecycle-viewmodel-compose:$lifecycle_version")。
  • 在 Compose 中使用 Lifecycle 工具，需要添加 implementation("androidx.lifecycle:lifecycle-runtime-compose:$lifecycle_version")。

感知生命周期的协程作用域

Compose 和 Lifecycle 库提供了下面这些内置作用域，可以直接在应用中使用。

ViewModelScope

每个 ViewModel 都有自己的 ViewModelScope。ViewModel 被清理时，这个作用域里启动的所有协程都会自动取消。如果某项工作只在 ViewModel 还活跃时才有意义，就很适合放在这里。比如，为布局计算数据时，把工作放进 ViewModel 的作用域；这样，ViewModel 被清理，计算也会自动取消，不再继续消耗资源。

通过 ViewModel 的 viewModelScope 属性，就能取得它的 CoroutineScope：

class MyViewModel: ViewModel() {
    init {
        viewModelScope.launch {
            // Coroutine that will be canceled when the ViewModel is cleared.
        }
    }
}

如果需要更细致地控制，也可以在 ViewModel 构造器中传入自定义 CoroutineScope，替代默认的 viewModelScope。这样控制更灵活，尤其适合下面两类情况：

  • 测试：注入 TestScope，就更容易在单元测试中控制时间，并验证协程的行为。

  • 自定义配置：在 ViewModel 开始工作之前，就能为作用域指定 CoroutineDispatcher，比如把繁重计算交给 Dispatchers.Default；也可以设置自己的 CoroutineExceptionHandler。

与组合绑定的作用域

动画、网络调用、计时器等副作用，必须跟随 composable（可组合项）的生命周期。这样，composable 离开屏幕、退出 Composition（组合）时，其中正在运行的协程就会自动取消，避免内存泄漏。

Compose 提供了 LaunchedEffect，用声明式方式把工作绑定到 Composition 的作用域。

LaunchedEffect 会创建一个 CoroutineScope，让你可以运行挂起函数。这个作用域跟随的是 composable 的 Composition 生命周期，而不是宿主 Activity 的生命周期。

  • 进入：composable 进入 Composition，协程开始运行。
  • 退出：composable 离开 Composition，协程被取消。
  • 重新启动：传给 LaunchedEffect 的任何一个 key 变了，当前协程就会取消，再启动一个新协程。
注意：LaunchedEffect 绑定的是 Composition，所以 composable 即使不在用户眼前，也可能运行。比如，HorizontalPager 经常会提前在屏幕外组合相邻页面，为滑动做好准备。如果某个副作用要求用户确实看到了页面，比如发送统计事件，就应该使用 LifecycleEventEffect 这样的标准生命周期 API，而不是 LaunchedEffect。

下面用 LaunchedEffect 实现一个脉冲动画。协程会跟随 composable 是否还在 Composition 中，并响应配置变化：

// Allow the pulse rate to be configured, so it can be sped up if the user is running
// out of time
var pulseRateMs by remember { mutableLongStateOf(3000L) }
val alpha = remember { Animatable(1f) }
LaunchedEffect(pulseRateMs) { // Restart the effect when the pulse rate changes
    while (isActive) {
        delay(pulseRateMs) // Pulse the alpha every pulseRateMs to alert the user
        alpha.animateTo(0f)
        alpha.animateTo(1f)
    }
}

感知生命周期的 Flow 收集

在 Jetpack Compose 中安全收集 Flow，可以用 collectAsStateWithLifecycle。它会把 Flow 转成 Compose 的 State 对象，还会自动管理生命周期订阅。默认在生命周期达到 STARTED 时开始收集，到了 STOPPED 时停止。如果想改变这个条件，可以传入 minActiveState，指定所需的生命周期状态，比如 Lifecycle.State.RESUMED。

下面展示了怎样在 composable 中收集 ViewModel 的 StateFlow：

@Composable
private fun ConversationScreen(
    conversationViewModel: ConversationViewModel = viewModel()
) {

    val messages by conversationViewModel.messages.collectAsStateWithLifecycle()

    ConversationScreen(
        messages = messages,
        onSendMessage = { message: Message -> conversationViewModel.sendMessage(message) }
    )
}

@Composable
private fun ConversationScreen(
    messages: List<Message>,
    onSendMessage: (Message) -> Unit
) {

    MessagesList(messages, onSendMessage)
    /* ... */
}

并行收集多个 Flow

在 Compose 中，声明多个状态变量，就能并行收集多个 Flow。每个 collectAsStateWithLifecycle 都会管理自己底层的作用域，因此会自动处理并行收集：

@Composable
fun DashboardScreen(viewModel: DashboardViewModel = viewModel()) {
    // Both flows are collected safely in parallel and will emit updates when either changes, the composables will recompose
    val userData by viewModel.userFlow.collectAsStateWithLifecycle()
    val feedData by viewModel.feedFlow.collectAsStateWithLifecycle()

    // ...
}

使用 Flow 异步计算值

需要异步计算值时，可以将 StateFlow 与 stateIn 操作符配合使用。

下面把普通的 Flow 转成 StateFlow。WhileSubscribed(5000) 会在 UI 消失后继续保留订阅五秒钟，用来应对配置变化。

val uiState: StateFlow<Result> = flow {
    emit(repository.fetchData())
}
.stateIn(
    scope = viewModelScope,
    started = SharingStarted.WhileSubscribed(5_000),
    initialValue = Result.Loading
)

再用 collectAsStateWithLifecycle 把收集到的值转成 Compose State，数据变化时，UI 就能随之更新。

注意：如果只是一次性的异步 UI 工作，而且不需要在配置变化后继续保留，比如解码位图或加载本地化字符串，可以直接在 composable 里用 produceState。但加载页面数据时，建议使用 StateFlow 和 ViewModel。
