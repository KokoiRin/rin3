Kotlin 协程提供了用于编写异步代码的 API。借助 Kotlin 协程，可以定义一个 CoroutineScope，帮助管理协程应在何时运行。每个异步操作都在特定的作用域内运行。

感知生命周期的组件为应用中的逻辑作用域提供一流的协程支持。本文介绍如何有效地将协程与感知生命周期的组件结合使用。

添加依赖项

本文介绍的内置协程作用域包含在 Lifecycle API 中。使用这些作用域时，请确保添加适当的依赖项。

  • 对于 Compose 中的 ViewModel 工具，使用 implementation("androidx.lifecycle:lifecycle-viewmodel-compose:$lifecycle_version")。
  • 对于 Compose 中的 Lifecycle 工具，使用 implementation("androidx.lifecycle:lifecycle-runtime-compose:$lifecycle_version")。

感知生命周期的协程作用域

Compose 和 Lifecycle 库提供了以下可在应用中使用的内置作用域。

ViewModelScope

应用中的每个 ViewModel 都定义了一个 ViewModelScope。如果 ViewModel 被清理，在此作用域中启动的任何协程都会自动取消。当某项工作只应在 ViewModel 处于活动状态时执行，协程就很有用。例如，如果正在为布局计算一些数据，应将该工作的作用域限定为 ViewModel，这样当 ViewModel 被清理时，工作就会自动取消，避免消耗资源。

可以通过 ViewModel 的 viewModelScope 属性访问它的 CoroutineScope，如以下示例所示：

class MyViewModel: ViewModel() {
    init {
        viewModelScope.launch {
            // Coroutine that will be canceled when the ViewModel is cleared.
        }
    }
}

对于更高级的用例，可以直接向 ViewModel 的构造函数传入自定义 CoroutineScope，替换默认的 viewModelScope。这种方式提供更多控制和灵活性，尤其适用于：

  • 测试：允许注入 TestScope，使你更容易在单元测试中控制时间并验证协程行为。

  • 自定义配置：甚至可以在 ViewModel 开始工作之前，用特定的 CoroutineDispatcher（例如用于繁重计算的 Dispatchers.Default）或自定义 CoroutineExceptionHandler 配置作用域。

与组合绑定的作用域

动画、网络调用或计时器等副作用，必须将作用域限定为可组合项的生命周期。这样，当可组合项离开屏幕（退出组合）时，任何正在运行的协程都会自动取消，以防止内存泄漏。

Compose 提供了 LaunchedEffect API，以声明式方式处理组合的作用域。

LaunchedEffect 创建一个允许运行挂起函数的 CoroutineScope。该作用域与可组合项的组合生命周期绑定，而不是与宿主 Activity 的生命周期绑定。

  • 进入：可组合项进入组合时，协程开始运行。
  • 退出：可组合项离开组合时，协程被取消。
  • 重新启动：如果传给 LaunchedEffect 的任何键发生变化，现有协程就会被取消，并启动一个新协程。
注意：由于 LaunchedEffect 与组合绑定，即使可组合项当前对用户不可见，它也可以运行。例如，HorizontalPager 经常会在屏幕之外组合相邻页面，为滑动做好准备。如果副作用依赖用户实际查看屏幕（例如分析事件），应使用标准的感知生命周期的 API（例如 LifecycleEventEffect），而不是 LaunchedEffect。

以下示例展示了如何使用 LaunchedEffect 创建脉冲动画。协程与可组合项在组合中的存在情况绑定，并响应配置变化：

// Allow the pulse rate to be configured, so it can be sped up if the user is running
// out of time
var pulseRateMs by remember { mutableLongStateOf(3000L) }
val alpha = remember { Animatable(1f) }
LaunchedEffect(pulseRateMs) { // Restart the effect when the pulse rate changes
    while (isActive) {
        delay(pulseRateMs) // Pulse the alpha every pulseRateMs to alert the user
        alpha.animateTo(0f)
        alpha.animateTo(1f)
    }
}

感知生命周期的 Flow 收集

要在 Jetpack Compose 中安全地收集 Flow，请使用 collectAsStateWithLifecycle API。单凭这个函数，就可以将 Flow 转换为 Compose 的 State 对象，并自动为你管理生命周期订阅。默认情况下，生命周期为 STARTED 时开始收集，为 STOPPED 时停止收集。要覆盖默认行为，请传入 minActiveState 参数，并指定所需的生命周期状态，例如 Lifecycle.State.RESUMED。

以下示例展示了如何在可组合项中收集 ViewModel 的 StateFlow：

@Composable
private fun ConversationScreen(
    conversationViewModel: ConversationViewModel = viewModel()
) {

    val messages by conversationViewModel.messages.collectAsStateWithLifecycle()

    ConversationScreen(
        messages = messages,
        onSendMessage = { message: Message -> conversationViewModel.sendMessage(message) }
    )
}

@Composable
private fun ConversationScreen(
    messages: List<Message>,
    onSendMessage: (Message) -> Unit
) {

    MessagesList(messages, onSendMessage)
    /* ... */
}

并行收集多个 Flow

在 Compose 中，可以通过声明多个状态变量来并行收集多个 Flow。由于 collectAsStateWithLifecycle 会管理自己的底层作用域，并行收集会自动得到处理：

@Composable
fun DashboardScreen(viewModel: DashboardViewModel = viewModel()) {
    // Both flows are collected safely in parallel and will emit updates when either changes, the composables will recompose
    val userData by viewModel.userFlow.collectAsStateWithLifecycle()
    val feedData by viewModel.feedFlow.collectAsStateWithLifecycle()

    // ...
}

使用 Flow 异步计算值

需要异步计算值时，使用 StateFlow 和 stateIn 操作符。

以下代码片段将标准 Flow 转换为 StateFlow。WhileSubscribed(5000) 参数使订阅在 UI 消失后继续保持活跃五秒，以处理配置变化。

val uiState: StateFlow<Result> = flow {
    emit(repository.fetchData())
}
.stateIn(
    scope = viewModelScope,
    started = SharingStarted.WhileSubscribed(5_000),
    initialValue = Result.Loading
)

使用 collectAsStateWithLifecycle 将收集到的值转换为 Compose State，使 UI 能够在数据变化时响应式更新。

注意：对于无需跨配置变化存活的一次性异步 UI 任务，例如解码位图或加载本地化字符串，可以直接在可组合项中使用 produceState API。不过，对于加载屏幕数据，建议使用 StateFlow 和 ViewModel。

有关状态的更多信息，请参阅状态与 Jetpack Compose。
