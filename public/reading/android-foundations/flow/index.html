在协程中，Flow 是一种可以按顺序发出多个值的类型，与只返回单个值的挂起函数不同。例如，可以使用 Flow 接收数据库的实时更新。

Flow 构建于协程之上，可以提供多个值。从概念上说，Flow 是可以异步计算的数据流。发出的值必须具有相同类型。例如，Flow<Int> 是发出整数值的 Flow。

Flow 与产生一系列值的 Iterator 非常相似，但它使用挂起函数异步生产和消费值。这意味着，例如，Flow 可以安全地发起网络请求来生成下一个值，而不阻塞主线程。

数据流涉及三种实体：

  • 生产者生产要添加到流中的数据。借助协程，Flow 也可以异步生产数据。
  • （可选的）中间环节可以修改发到流中的每个值，或修改流本身。
  • 消费者消费流中的值。

在 Android 中，Repository 通常是 UI 数据的生产者，而用户界面（UI）是最终显示数据的消费者。在其他情况下，UI 层是用户输入事件的生产者，层次结构中的其他层消费这些事件。生产者与消费者之间的层通常充当中间环节，修改数据流，使其满足下一层的要求。

创建 Flow

要创建 Flow，请使用 Flow 构建器 API。flow 构建器函数会创建一个新的 Flow，可以在其中使用 emit 函数手动向数据流发出新值。

在以下示例中，数据源以固定间隔自动获取最新新闻。由于挂起函数无法返回多个连续的值，数据源会创建并返回一个 Flow 来满足这一需求。在此情况下，数据源充当生产者。

class NewsRemoteDataSource(
    private val newsApi: NewsApi,
    private val refreshIntervalMs: Long = 5000
) {
    val latestNews: Flow<List<ArticleHeadline>> = flow {
        while (true) {
            val latestNews = newsApi.fetchLatestNews()
            emit(latestNews) // Emits the result of the request to the flow
            delay(refreshIntervalMs) // Suspends the coroutine for some time
        }
    }
}

// Interface that provides a way to make network requests with suspend functions
interface NewsApi {
    suspend fun fetchLatestNews(): List<ArticleHeadline>
}Flow.kt

flow 构建器在协程内执行。因此，它可以使用同样的异步 API，但也存在一些限制：

  • Flow 是顺序执行的。由于生产者位于协程中，调用挂起函数时，生产者会挂起，直到挂起函数返回。在此示例中，生产者会挂起，直到 fetchLatestNews 网络请求完成。只有此后才会将结果发到流中。
  • 使用 flow 构建器时，生产者不能从另一个 CoroutineContext 中 emit 值。因此，不要通过创建新协程或使用 withContext 代码块，在不同的 CoroutineContext 中调用 emit。在这些情况下，可以使用 callbackFlow 等其他 Flow 构建器。

修改数据流

中间环节可以使用中间操作符修改数据流，而不消费值。这些操作符是一些函数；将它们应用于数据流时，会建立一条操作链，直到将来消费值时才会执行。有关中间操作符的更多信息，请参阅 Flow 参考文档。

在以下示例中，Repository 层使用中间操作符 map，转换将要在 View 上显示的数据：

class NewsRepository(
    private val newsRemoteDataSource: NewsRemoteDataSource,
    private val userData: UserData
) {
    /**
     * Returns the favorite latest news applying transformations on the flow.
     * These operations are lazy and don't trigger the flow. They just transform
     * the current value emitted by the flow at that point in time.
     */
    val favoriteLatestNews: Flow<List<ArticleHeadline>> =
        newsRemoteDataSource.latestNews
            // Intermediate operation to filter the list of favorite topics
            .map { news -> news.filter { userData.isFavoriteTopic(it) } }
            // Intermediate operation to save the latest news in the cache
            .onEach { news -> saveInCache(news) }
}Flow.kt

中间操作符可以依次应用，形成一条操作链；当条目发到 Flow 中时，操作链才会以惰性方式执行。请注意，仅对流应用中间操作符，不会启动 Flow 收集。

从 Flow 收集

使用终止操作符触发 Flow 开始监听值。要在流中的各个值发出时获取它们，请使用 collect。有关终止操作符的更多信息，请参阅 Flow 官方文档。

由于 collect 是挂起函数，它需要在协程中执行。它接收一个 lambda 参数，每出现一个新值，就会调用该 lambda。由于它是挂起函数，调用 collect 的协程可能会挂起，直到 Flow 关闭。

接着前面的示例，下面是一个消费 Repository 层数据的简单 ViewModel 实现：

class LatestNewsViewModel(
    private val newsRepository: NewsRepository
) : ViewModel() {

    init {
        viewModelScope.launch {
            // Trigger the flow and consume its elements using collect
            newsRepository.favoriteLatestNews.collect { favoriteNews ->
                // Update UI with the latest favorite news
            }
        }
    }
}Flow.kt

收集 Flow 会触发生产者，它以固定间隔刷新最新新闻并发出网络请求结果。由于生产者通过 while(true) 循环始终保持活动，数据流会在 ViewModel 被清理、viewModelScope 被取消时关闭。

Flow 收集可能因以下原因停止：

  • 执行收集的协程被取消，如前面的示例所示。这也会停止底层生产者。
  • 生产者结束发出条目。在此情况下，数据流关闭，调用 collect 的协程恢复执行。

除非通过其他中间操作符另行指定，否则 Flow 是冷的、惰性的。这意味着，每次对 Flow 调用终止操作符时，生产者代码都会执行。在前面的示例中，存在多个 Flow 收集者，会导致数据源按照多个不同的固定间隔多次获取最新新闻。要在多个消费者同时收集时优化并共享 Flow，请使用 shareIn 操作符。
