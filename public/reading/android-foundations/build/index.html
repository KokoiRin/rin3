Android 构建结构

    Android 项目包含许多与构建有关的文件和目录结构，用来组织应用的源代码和资源。在深入了解配置细节之前，我们先看看整体结构，以及每个部分应当包含哪些基本内容。

    下表列出了 Android 项目中的典型文件。每个文件或目录的说明都包含应在其中存放哪类内容的提示。最佳实践会随时间变化，因此这些说明可能与你接手的项目或从网上下载的项目不完全一致。

    编写构建文件时，应采用声明式方式；构建逻辑和任务定义应当只出现在插件中。将构建逻辑限制在插件内，可以使构建文件成为数据声明，从而更便于理解和编辑。未来版本可能包含其他规范，例如 Declarative Gradle，从而禁止在这些文件中编写构建逻辑。

    注意：在此表中，如果文件名写作 build.gradle(.kts)，表示构建文件使用 Kotlin 或 Groovy 编写时，文件名会有所不同。Kotlin 版本的文件以 .kts 结尾（Kotlin 文件）；Groovy 版本则没有这一后缀。

    文件夹／文件

    用途

    .gradle/

    Gradle 项目缓存目录

    由 Gradle 管理，包含下载的 Gradle 发行版、项目缓存和配置文件。

    不要修改此目录中的文件！

    .idea/

    Android Studio 项目元数据

    不要修改此目录中的文件！

    build.gradle(.kts)

    根构建文件

    应当只包含插件声明，用来为各子项目设置共用的插件类路径。

    其他代码应放在 settings 文件或嵌套项目级别的构建文件中。

    gradle.properties

    Gradle 执行配置

    包含 Gradle 属性，用来控制 Gradle 构建环境的堆大小、缓存和并行执行等方面。

    一些临时性的 Android 属性也在这里定义，以减少这些属性加入及后续移除时对 AGP DSL 的改动。

    gradlew（Linux、Mac）

    gradlew.bat（Windows）

    Gradle Wrapper 文件

    通过下载 Gradle 发行版并向其转发命令，引导构建过程。这样，无需预先安装 Gradle 就可以运行构建。

    local.properties

    本机配置

    包含与本机有关的属性，例如 Android SDK 的位置。

    不要将此文件纳入版本控制！

    settings.gradle(.kts)

    Gradle 构建初始化

    包含用于 Gradle 初始化和项目配置的全局构建信息，例如：

    • 项目名称
    • 要纳入此次构建的子项目列表
    • 用于查找插件和依赖项的仓库配置
    • 外部版本目录的导入。

    gradle/

    ↳ libs.versions.toml

    版本目录

    为构建中使用的依赖项和插件定义变量。在这里指定要使用的版本，以确保项目中所有子项目的版本保持一致。

    ↳ wrapper/

    ↳ gradle‑wrapper.jar

    Gradle 引导可执行文件

    下载指定的 Gradle 发行版（如果尚不存在），然后运行它，并传递所有参数。

    ↳ gradle‑wrapper.properties

    Gradle Wrapper 的配置

    指定下载 Gradle 发行版的位置，包括要使用的版本。

    app/

    子项目目录

    子项目（在 Android Studio 中称为“模块”）可以构建应用或库，也可以依赖其他子项目或外部依赖项。

    app 是顶层应用子项目的惯用名称，但不是强制名称。其他子项目的结构类似，只是名称不同。

    任何目录都可以成为子项目，但必须至少包含一个 build.gradle(.kts) 文件，并通过 settings.gradle(.kts) 将其纳入构建。

    ↳ build.gradle(.kts)

    子项目级构建文件

    声明如何构建此子项目。每个子项目都需要单独的构建文件，其中应当包含：

    • 用于构建此子项目的插件
    • 插件所需的配置块
    • 构建此子项目时包含的依赖项（库和平台）

    不应在构建文件中加入构建逻辑（例如 Kotlin 函数定义或条件判断）或任务声明。构建逻辑和任务应当只放在插件中。

    ↳ src/

    子项目源文件

    将源文件（应用代码和资源）组织成源集。main 源集包含所有变体共用的源文件，其他源集则包含某个变体特有的源文件。

    ↳ main/

    主源集

    所有构建变体共用的源代码和资源。该源集是所有构建的基础，其他更具体的源集会在此基础上添加或覆盖内容。

    ↳ java/

    ↳ kotlin/

    Kotlin 和 Java 源代码

    java 目录可以混合包含 Java 和 Kotlin 源代码。如果此子项目只包含 Kotlin 代码，可以将该目录重命名为 kotlin。

    Android 是一个 Kotlin 优先的平台。平台支持 Java 源代码，但新的 API 面向 Kotlin 语言。对于所有新代码和对现有代码的重大更新，我们建议使用 Kotlin。

    ↳ res/

    Android 资源文件

    包含应用资源，例如 XML 文件和图片。所有应用都会使用启动图标等一些基本资源，但布局、菜单等许多资源仅用于基于 View 的应用。Compose 应用也会使用此目录下定义的字符串资源。

    ↳ AndroidManifest.xml

    Android 应用元数据

    由 Android 软件包管理器读取，用来向系统说明：

    • 应用定义的组件
    • 所需权限
    • 设备兼容性
    • Android 平台限制

    ↳ androidTest/

    设备测试源集

    包含将在 Android 设备或模拟器上运行的测试源代码。这些测试可以访问真实的 Android 环境，但执行速度比宿主机测试慢。

    main 源集中的所有源文件，都可供 androidTest 下的源代码使用。

    ↳ test/

    宿主机测试源集

    包含在本地 JVM 中运行的测试源代码，而不是在设备上运行的测试。这些测试的运行速度远快于设备测试。不过，所有系统调用（包括驱动应用运行的生命周期）都必须通过 mock、fake、stub 或其他方式进行模拟。

    main 源集中的所有源文件，都可供 test 下的源代码使用。

    ↳ proguard-rules.pro

    R8 配置规则

    定义用于控制应用缩减、优化和混淆的规则。R8 会移除不需要的代码和资源、优化运行时性能，并通过重命名标识符进一步压缩代码。
