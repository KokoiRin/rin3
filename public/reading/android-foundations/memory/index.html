垃圾回收

ART 或 Dalvik 虚拟机这样的托管内存环境，会跟踪每次内存分配。一旦确定某块内存已不再被程序使用，就会将其释放回堆中，无需程序员干预。在托管内存环境中回收未使用内存的机制称为垃圾回收。垃圾回收有两个目标：找到程序中将来无法再访问的数据对象；回收这些对象使用的资源。

Android 的内存堆采用分代机制，这意味着它会根据所分配对象的预期寿命和大小，跟踪不同组的分配。例如，最近分配的对象属于年轻代。当一个对象保持活动的时间足够长时，它可以被提升到更老的一代，之后再进入永久代。

堆的每一代都有各自的内存占用上限，用于限制该代对象能够占用的内存量。每当某一代开始填满时，系统就会执行一次垃圾回收，尝试释放内存。垃圾回收的持续时间取决于正在回收哪一代对象，以及各代中有多少活动对象。

虽然垃圾回收可以相当快，但它仍然会影响应用性能。通常无法在代码中控制垃圾回收何时发生。系统有一组持续生效的判断标准，用于决定何时执行垃圾回收。当这些标准得到满足时，系统会停止执行进程并开始垃圾回收。如果垃圾回收发生在动画等密集处理循环的中间，或发生在音乐播放期间，就可能增加处理时间。这种增加可能使应用中的代码执行时间超过为高效、流畅的帧渲染所建议的 16 毫秒阈值。

此外，代码流程可能执行某些工作，迫使垃圾回收更频繁地发生，或持续时间比正常情况更长。例如，如果在透明度混合动画的每一帧中，都在 for 循环最内层分配多个对象，就可能用大量对象污染内存堆。在这种情况下，垃圾回收器会执行多次垃圾回收，并可能降低应用性能。

有关垃圾回收的更多一般信息，请参阅垃圾回收。

限制应用内存

为了维持正常工作的多任务环境，Android 会对每个应用的堆大小设置硬性限制。具体的堆大小上限因设备而异，取决于设备整体可用的 RAM 容量。如果应用已达到堆容量上限，又尝试分配更多内存，就可能收到 OutOfMemoryError。

在某些情况下，你可能希望查询系统，以确定当前设备上究竟有多少可用堆空间——例如，确定可以安全地在缓存中保留多少数据。可以通过调用 getMemoryClass() 查询这个值。此方法返回一个整数，表示应用堆可用的兆字节数。

切换应用

当用户在应用之间切换时，Android 会将不处于前台的应用保留在缓存中，也就是那些对用户不可见、也没有运行音乐播放等前台服务的应用。例如，用户首次启动某个应用时，系统会为它创建一个进程；但用户离开应用时，该进程不会退出。系统会将进程保留在缓存中。如果用户稍后返回应用，系统会复用该进程，从而加快应用切换。

如果应用有一个缓存进程，而且它保留着当前不需要的资源，那么即使用户没有使用应用，它也会影响系统的整体性能。当系统的内存等资源不足时，会终止缓存中的进程。系统也会考虑哪些进程占用的内存最多，并可以终止它们以释放 RAM。

注意：应用在缓存中消耗的内存越少，就越有可能不被终止，并能够快速恢复。不过，根据系统即时需求，缓存进程可能随时被终止，无论其资源使用情况如何。

如需详细了解进程不在前台运行时如何被缓存，以及 Android 如何决定可以终止哪些进程，请参阅进程与线程指南。
