布局定义了应用中用户界面的结构，例如 Activity 中的界面。布局中的所有元素都使用 View 和 ViewGroup 对象的层次结构构建。View 通常会绘制用户可以看到并与之交互的内容。ViewGroup 是一个不可见的容器，负责定义 View 和其他 ViewGroup 对象的布局结构，如图 1 所示。

View 对象通常称为控件，可以是许多子类之一，例如 Button 或 TextView。ViewGroup 对象通常称为布局，可以是提供不同布局结构的多种类型之一，例如 LinearLayout 或 ConstraintLayout。

可以通过两种方式声明布局：

  • 在 XML 中声明 UI 元素。Android 提供了一套直观的 XML 词汇，与控件和布局等 View 类及其子类相对应。也可以使用 Android Studio 的布局编辑器，通过拖放界面构建 XML 布局。
  • 在运行时实例化布局元素。应用可以创建 View 和 ViewGroup 对象，并以编程方式操作它们的属性。

在 XML 中声明 UI，可以将应用的呈现方式与控制其行为的代码分离。使用 XML 文件也更容易为不同屏幕尺寸和方向提供不同布局。支持不同屏幕尺寸中对此有进一步讨论。

Android 框架允许灵活地选择其中任意一种方式，或同时使用两种方式构建应用 UI。例如，可以在 XML 中声明应用的默认布局，然后在运行时修改布局。

提示：要在运行时调试布局，请使用布局检查器工具。

编写 XML

使用 Android 的 XML 词汇，可以快速设计 UI 布局及其包含的屏幕元素，就像使用一系列嵌套元素在 HTML 中创建网页一样。

每个布局文件必须恰好包含一个根元素，它必须是 View 或 ViewGroup 对象。定义根元素后，可以添加额外的布局对象或控件作为子元素，逐步构建定义布局的 View 层次结构。例如，以下 XML 布局使用垂直的 LinearLayout 容纳一个 TextView 和一个 Button：

<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
              android:layout_width="match_parent"
              android:layout_height="match_parent"
              android:orientation="vertical" >
    <TextView android:id="@+id/text"
              android:layout_width="wrap_content"
              android:layout_height="wrap_content"
              android:text="Hello, I am a TextView" />
    <Button android:id="@+id/button"
            android:layout_width="wrap_content"
            android:layout_height="wrap_content"
            android:text="Hello, I am a Button" />
</LinearLayout>

在 XML 中声明布局后，将文件以 .xml 扩展名保存到 Android 项目的 res/layout/ 目录中，以便正确编译。

有关布局 XML 文件语法的更多信息，请参阅布局资源。

加载 XML 资源

编译应用时，每个 XML 布局文件都会被编译成一个 View 资源。在应用的 Activity.onCreate() 回调实现中加载布局资源。具体做法是调用 setContentView()，以 R.layout.layout_file_name 的形式传入布局资源的引用。例如，如果 XML 布局保存为 main_layout.xml，则按如下方式为 Activity 加载它：

Kotlin

fun onCreate(savedInstanceState: Bundle) {
    super.onCreate(savedInstanceState)
    setContentView(R.layout.main_layout)
}

Java

public void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.main_layout);
}

Activity 启动时，Android 框架会调用其中的 onCreate() 回调方法。有关 Activity 生命周期的更多信息，请参阅 Activity 简介。

属性

每个 View 和 ViewGroup 对象都支持各自的一组 XML 属性。有些属性是某个 View 对象特有的。例如，TextView 支持 textSize 属性。不过，继承此类的任何 View 对象也会继承这些属性。有些属性是所有 View 对象共有的，因为它们从根 View 类继承而来，例如 id 属性。其他属性称为布局参数，它们由对象的父 ViewGroup 对象定义，用于描述 View 对象的某些布局安排。

ID

任何 View 对象都可以关联一个整数 ID，以便在树中唯一标识该 View。应用编译后，此 ID 作为整数引用，但通常是在布局 XML 文件中，将它作为字符串赋给 id 属性。这是所有 View 对象共有的 XML 属性，由 View 类定义。你会经常使用它。XML 标签中 ID 的语法如下：

android:id="@+id/my_button"

字符串开头的 at 符号（@）表示 XML 解析器会解析并展开 ID 字符串的剩余部分，将其识别为 ID 资源。加号（+）表示这是一个新的资源名称，必须创建并添加到 R.java 文件中的资源里。

Android 框架还提供了许多其他 ID 资源。引用 Android 资源 ID 时，不需要加号，但必须按如下方式添加 android 包命名空间：

android:id="@android:id/empty"

android 包命名空间表明你引用的是 android.R 资源类中的 ID，而不是本地资源类中的 ID。

要创建 View 并从应用中引用它们，可以采用以下常见模式：

  1. 在布局文件中定义一个 View，并为其分配唯一 ID，如以下示例所示：
    <Button android:id="@+id/my_button"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/my_button_text"/>
  2. 创建 View 对象的实例，并从布局中获取它，通常在 onCreate() 方法中进行，如以下示例所示：

    Kotlin

    val myButton: Button = findViewById(R.id.my_button)

    Java

    Button myButton = (Button) findViewById(R.id.my_button);

创建 RelativeLayout 时，为 View 对象定义 ID 非常重要。在相对布局中，同级 View 可以定义相对于另一个同级 View 的布局，后者通过唯一 ID 引用。

ID 不必在整棵树中唯一，但必须在你搜索的那部分树中唯一。搜索范围往往可能是整棵树，因此最好尽可能保证 ID 唯一。

布局参数

名为 layout_something 的 XML 布局属性，为 View 定义适用于其所在 ViewGroup 的布局参数。

每个 ViewGroup 类都实现了一个继承 ViewGroup.LayoutParams 的嵌套类。该子类包含一些属性类型，用来以适合该 ViewGroup 的方式定义每个子 View 的大小和位置。如图 2 所示，父 ViewGroup 为每个子 View 定义布局参数，其中也包括子 ViewGroup。

每个 LayoutParams 子类都有自己的值设置语法。每个子元素都必须定义适用于其父元素的 LayoutParams，不过它也可以为自己的子元素定义另一种 LayoutParams。

所有 ViewGroup 都包含通过 layout_width 和 layout_height 指定的宽度和高度，每个 View 都必须定义这两项。许多 LayoutParams 还包含可选的外边距和边框。

可以使用精确的测量值指定宽度和高度，但你可能不希望经常这样做。更常见的做法是使用以下常量之一设置宽度或高度：

  • wrap_content：让 View 将自身大小设置为其内容所需的尺寸。
  • match_parent：让 View 尽可能扩展到父 ViewGroup 所允许的大小。

通常，我们不建议使用像素等绝对单位指定布局宽度和高度。更好的方式是使用相对测量值，例如密度无关像素单位（dp）、wrap_content 或 match_parent，因为这有助于应用在多种设备屏幕尺寸上正确显示。可接受的测量类型在布局资源中定义。
