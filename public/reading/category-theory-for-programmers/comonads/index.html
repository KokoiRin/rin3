Comonad

Bartosz Milewski

Comonad 是 Monad 的对偶：它不把值放入上下文，而是让计算从一个预先充满数据、带当前焦点的上下文中取值并向周围扩展。

既然已经讲完 Monad，就可以收获对偶性的好处：只需反转箭头并在对偶范畴中工作，便免费得到 Comonad。

回忆最基本层面上，Monad 关乎复合 Kleisli 箭头：

a -> m b

其中 m 是具有 Monad 结构的函子。若用 w（倒过来的 m）表示 Comonad，就能把 co-Kleisli 箭头定义为：

w a -> b

Co-Kleisli 箭头的鱼运算符对应物定义为：

(=>=) :: (w a -> b) -> (w b -> c) -> (w a -> c)

要让 co-Kleisli 箭头形成范畴，还必须有恒等 co-Kleisli 箭头，称为 extract：

extract :: w a -> a

它是 return 的对偶。还必须施加结合律、左恒等律和右恒等律。合起来可在 Haskell 中这样定义 Comonad：

class Functor w => Comonad w where
    (=>=) :: (w a -> b) -> (w b -> c) -> (w a -> c)
    extract :: w a -> a

实践中会使用稍有不同的基本操作，马上会看到。问题是：Comonad 在编程中有什么用？

用 Comonad 编程

比较 Monad 与 Comonad。Monad 用 return 把值放进容器，却不给你访问容器内部值的手段。当然，实现 Monad 的数据结构可能额外提供内容访问，但那只是奖励，没有从 Monad 提取值的公共接口。我们还见过以永不暴露内容为荣的 IO Monad。

Comonad 则提供从中提取单个值的手段，却不提供插入值的手段。因此，若把 Comonad 想成容器，它总是预先装有内容，并允许窥视。

正如 Kleisli 箭头接受一个值并产生某种装饰结果——为值增加上下文——co-Kleisli 箭头接受一个值连同完整上下文并产生结果。它体现了上下文计算（contextual computation）。

Product Comonad

还记得 Reader Monad 吗？我们用它处理需要访问只读环境 e 的计算。这种计算可表示为纯函数：

(a, e) -> b

我们用柯里化把它变成 Kleisli 箭头：

a -> (e -> b)

但注意，它原本就具有 co-Kleisli 箭头形式。把参数整理成更方便的函子形式：

data Product e a = Prod e a deriving Functor

让被复合的箭头共享同一个环境，就能轻易定义复合运算符：

(=>=) ::
  (Product e a -> b) ->
  (Product e b -> c) ->
  (Product e a -> c)
f =>= g = \(Prod e a) -> let b = f (Prod e a)
                             c = g (Prod e b)
                         in c

extract 的实现直接忽略环境：

extract (Prod e a) = a

不出所料，Product Comonad 可以执行与 Reader Monad 完全相同的计算。某种意义上，环境的 Comonad 实现更自然——符合“在上下文中计算”的精神；另一方面，Monad 拥有方便的 do 语法糖。

Reader Monad 与 Product Comonad 的联系更深，因为 Reader 函子是 Product 函子的右伴随。不过一般来说，Comonad 覆盖的计算概念与 Monad 不同，稍后还会看到更多例子。

Product Comonad 很容易推广到任意积类型，包括元组和记录。

解剖复合

继续对偶化，可以直接把 Monad 的 bind、join 对偶化；也可以重复解剖鱼运算符的过程。后一种方式更有启发。

起点是：复合运算符必须产生接受 w a 并生成 c 的 co-Kleisli 箭头。产生 c 的唯一办法，是把第二个函数应用于 w b 类型参数：

(=>=) :: (w a -> b) -> (w b -> c) -> (w a -> c)
f =>= g = g ...

但怎样产生可传给 g 的 w b？手上有 w a 参数与函数 f :: w a -> b。解决办法是定义 bind 的对偶，称为 extend：

extend :: (w a -> b) -> w a -> w b

用 extend 可实现复合：

f =>= g = g . extend f

还能继续解剖 extend 吗？你可能想直接把 w a->b 应用于 w a，但随后会发现无法把结果 b 转为 w b；Comonad 不提供提升值的手段。Monad 的类似构造中，这里用了 fmap。若手上有 w (w a)，这里也能使用 fmap。只要能把 w a 变成 w (w a) 即可——而这恰好是 join 的对偶，称为 duplicate：

duplicate :: w a -> w (w a)

所以与 Monad 一样，Comonad 有三种等价定义：用 co-Kleisli 箭头、extend 或 duplicate。下面直接取自 Control.Comonad：

class Functor w => Comonad w where
  extract :: w a -> a
  duplicate :: w a -> w (w a)
  duplicate = extend id
  extend :: (w a -> b) -> w a -> w b
  extend f = fmap f . duplicate

库分别提供 extend 与 duplicate 的默认互相实现，所以只需覆盖其中一个。

这些函数背后的直觉是：一般可把 Comonad 看成装满 a 值的容器（Product Comonad 是只含一个值的特例）。其中有“当前”值，可用 extract 轻易访问。Co-Kleisli 箭头执行聚焦于当前值的计算，同时可访问周围所有值。想象 Conway 生命游戏：每个格子包含一个值（通常是 True 或 False），对应 Comonad 是聚焦于“当前”格子的网格。

duplicate 做什么？它把 Comonad 容器 w a 变成容器的容器 w (w a)，其中每个内层容器聚焦于原 w a 中不同的 a。生命游戏中，会得到“网格的网格”：外层每格包含一个聚焦于不同格子的内层网格。

extend 接受 co-Kleisli 箭头和装满 a 的 Comonad 容器 w a，把计算应用到所有 a，以 b 替换它们，结果是装满 b 的 Comonad 容器。它逐个移动焦点并应用 co-Kleisli 箭头。生命游戏中，箭头根据当前格子的上下文——大概是最近邻——计算新状态。extend 的默认实现正说明这个过程：先用 duplicate 产生所有可能焦点，再对每个焦点应用 f。

Stream Comonad

移动容器焦点的过程，用无限流最容易说明。流像列表，但没有空构造器：

data Stream a = Cons a (Stream a)

它显然是函子：

instance Functor Stream where
    fmap f (Cons a as) = Cons (f a) (fmap f as)

流的焦点是第一个元素，所以：

extract (Cons a _) = a

duplicate 产生流的流，每个内层流聚焦于不同元素：

duplicate (Cons a as) = Cons (Cons a as) (duplicate as)

第一个元素是原流，第二个是原流的尾，第三个是它的尾，以此无限继续。完整实例是：

instance Comonad Stream where
    extract (Cons a _) = a
    duplicate (Cons a as) = Cons (Cons a as) (duplicate as)

这是非常函数式的流视角。命令式语言可能从把流前移一位的 advance 方法开始；这里 duplicate 一次产生所有偏移后的流。Haskell 的惰性使之可能，而且值得。为实用起见还会实现类似 advance 的函数：

tail :: Stream a -> Stream a
tail (Cons a as) = as

但它绝不是 Comonad 接口的一部分。

若有数字信号处理经验，会立刻看出流上的 co-Kleisli 箭头就是数字滤波器，而 extend 产生滤波后的流。

以移动平均滤波器为简单例子。下面函数求流前 n 个元素之和：

sumS :: Num a => Int -> Stream a -> a
sumS n (Cons a as) = if n <= 0 then 0 else a + sumS (n - 1) as

下面计算流前 n 个元素平均值：

average :: Fractional a => Int -> Stream a -> a
average n stm = (sumS n stm) / (fromIntegral n)

偏应用后的 average n 是 co-Kleisli 箭头，所以可把它 extend 到整条流：

movingAvg :: Fractional a => Int -> Stream a -> Stream a
movingAvg n = extend (average n)

结果是运行平均值组成的流。

流是单向一维 Comonad 的例子，很容易改成双向或扩展到二维及更高维。

Comonad 的范畴定义

在范畴论中定义 Comonad，是直接运用对偶性的练习。与 Monad 一样，从自函子 T 开始；定义 Monad 的两个自然变换 η、μ 在 Comonad 中反转：

ε:T→I
δ:T→T²

它们的分量对应 extract 与 duplicate。Comonad 定律是 Monad 定律的镜像，毫不意外。

还有由伴随推导 Monad。对偶会反转伴随：左伴随变成右伴随，反之亦然。既然复合 R∘L 定义 Monad，L∘R 必然定义 Comonad。伴随的余单位：

ε:L∘R→I

正是 Comonad 定义中的 ε，按分量就是 Haskell 的 extract。还可以用伴随单位：

η:I→R∘L

在 L∘R 中间插入 R∘L，产生 L∘R∘L∘R。由 T 制造 T² 定义 δ，完成 Comonad 定义。

还见过 Monad 是幺半群。其对偶需要余幺半群（comonoid）。原先把幺半群定义为单对象范畴时，反转全部自态射只会得到另一个幺半群，没有有趣的对偶。但定义 Monad 时采用了更一般的“幺半范畴中的对象”定义，基于两支态射：

μ:m⊗m→m
η:i→m

反转它们，得到幺半范畴中的余幺半群：

δ:m→m⊗m
ε:m→i

可以在 Haskell 中写出余幺半群定义：

class Comonoid m where
  split   :: m -> (m, m)
  destroy :: m -> ()

但它相当平凡，destroy 显然忽略参数：

destroy _ = ()

split 只是一对函数：

split x = (f x, g x)

考虑与幺半群单位律对偶的余幺半群定律：

lambda . bimap destroy id . split = id
rho . bimap id destroy . split = id

这里 lambda、rho 是左右幺元子。代入定义得到：

lambda (bimap destroy id (split x))
= lambda (bimap destroy id (f x, g x))
= lambda ((), g x)
= g x

这证明 g=id。类似地，第二条定律展开为 f=id。因此：

split x = (x, x)

它说明 Haskell（更一般地说 Set）中每个对象都是平凡余幺半群。

幸运的是，还有其他更有趣的幺半范畴可以定义余幺半群，其中之一是自函子范畴。事实证明，正如 Monad 是自函子范畴中的幺半群：

Comonad 是自函子范畴中的余幺半群。

Store Comonad

另一个重要 Comonad 是 State Monad 的对偶，称为 Costate Comonad，也称 Store Comonad。

此前看到，State Monad 由定义指数的伴随生成：

Lz=z×s
Ra=s⇒a

用同一个伴随定义 Costate Comonad。Comonad 由复合 L∘R 定义：

L(Ra)=(s⇒a)×s

翻译到 Haskell，从左边 Product 函子与右边 Reader 函子的伴随开始。Product 接在 Reader 后的复合等价于：

data Store s a = Store (s -> a) s

伴随余单位在对象 a 处是态射：

εa:((s⇒a)×s)→a

Haskell 中写作：

counit (Prod (Reader f, s)) = f s

它成为 extract：

extract (Store f s) = f s

伴随单位：

unit :: a -> Reader s (Product a, s)
unit a = Reader (\s -> Prod (a, s))

可改写为偏应用的数据构造器：

Store f :: s -> Store f s

把 δ，也就是 duplicate，构造成水平复合：

δ:L∘R→L∘R∘L∘R
δ=L∘η∘R

必须把 η 偷渡过最左侧的 L，即 Product 函子。这表示让 η（或 Store f）作用于二元组左分量——Product 的 fmap 正会这样做。得到：

duplicate (Store f s) = Store (Store f) s

（记住，在 δ 公式中，L、R 表示分量为恒等态射的恒等自然变换。）

完整 Store Comonad 定义为：

instance Comonad (Store s) where
  extract (Store f s) = f s
  duplicate (Store f s) = Store (Store f) s

可以把 Store 的 Reader 部分看成由 s 类型元素作键的广义 a 容器。例如，若 s 是 Int，Reader Int a 就是双向无限 a 流。Store 把这个容器与一个键类型值配对；这里是把 Reader Int a 与一个 Int 配对，extract 用该整数索引无限流。可把 Store 第二个分量想成当前位置。

继续这个例子，duplicate 创建一个由 Int 索引的新无限流，元素本身也是流。在当前位置，它包含原始流；若用另一个正或负 Int 作键，就得到移到新索引位置的流。

一般地，可以确信 extract 作用于 duplicate 后的 Store 会产生原 Store（Comonad 恒等律正是 extract . duplicate = id）。

Store Comonad 是 Lens 库的重要理论基础。概念上，Store s a 封装了使用类型 s 作索引，“聚焦”（像透镜一样）于数据类型 a 某个子结构的思想。特别是，函数：

a -> Store s a

等价于一对函数：

set :: a -> s -> a
get :: a -> s

若 a 是积类型，set 可实现为设置 a 内部类型为 s 的字段并返回修改后的 a；get 则读取 a 中 s 字段的值。下一章会进一步探索这些思想。

习题

  1. 使用 Store Comonad 实现 Conway 生命游戏。提示：为 s 选择什么类型？
    点击展开参考答案

    用二维坐标作为焦点类型：s=(Int,Int)，用函数 (Int,Int)->Bool 表示无限网格。局部规则读取当前焦点的八个邻居，extend 会把规则应用到所有焦点：

    type Coord = (Int, Int)
type Grid = Store Coord Bool

neighbors :: Coord -> [Coord]
neighbors (x,y) =
  [(x+dx,y+dy) | dx <- [-1..1], dy <- [-1..1], (dx,dy) /= (0,0)]

rule :: Grid -> Bool
rule (Store cells p) =
  let alive = length (filter cells (neighbors p))
      here  = cells p
  in alive == 3 || (here && alive == 2)

step :: Grid -> Grid
step = extend rule

    Store cells p 中 cells 是整个棋盘，p 是当前格；duplicate 生成聚焦于每个坐标的棋盘，故 extend rule 同时计算下一代所有格子。
