这一节要解决什么问题

本节把编程语言的几条规则展开成完整过程：代码怎样产生类型约束，类型参数怎样泛化和实例化，为什么可变状态会限制多态；随后用有理数模块说明签名、隐藏表示和客户端能观察到的行为。

本节可以按问题选读。类型推导、值限制、表示独立性与程序等价性各有完整例子和图解；模块命名空间等熟悉内容可以快读。最后明确区分行为相同、计算成本相同，以及等价变换成立所需的条件。

想先看具体推演，可以从这里进入

  • 不运行程序，怎样逐步求出函数的类型？
  • 为什么一个看起来可泛型化的绑定，会受到可变状态的限制？
  • 接口相同的两个模块，什么时候可以互相替换？
  • 一次代码改写，要满足什么条件才保持行为？

图解可以前后切换、直接选择步骤，也可以展开全部状态；关闭脚本仍能阅读。来源与选学范围放在每篇开头的折叠说明中。

第 1 部分

把类型推导变成可执行的推理

从表达式产生约束，统一未知类型，再分清泛化、实例化与可变状态带来的限制。

01类型推导怎样做：产生约束，再让它们同时成立从元组解构和列表递归逐步写出类型方程，理解统一、冲突，以及为什么推导不需要运行程序。对应 V01 / V02 / V03 / V0402哪些类型留下来，哪些要在调用时选定用length、交换元组与compose分清未知类型、泛化和实例化，理解同一类型变量为何必须一致。对应 V0503一个共享的可变格子，为什么不能任意多态沿ref NONE的反例说明类型安全，再看值限制为何会影响没有显式状态的部分应用，以及函数包装的边界。对应 V06
第 2 部分

用边界组织递归与模块

先让一组定义共同建立，再用Rational说明命名空间、签名和抽象类型各自解决什么问题。

04几个函数或类型需要彼此认识时用相互递归的函数和数据定义说明and的作用、整组类型检查，以及相互调用与尾调用的区别。对应 V0705先把一组定义放在同一个名字下面从MyMathLib走到Rational，把命名空间、内部辅助函数与对外接口的职责分开。对应 V0806签名要隐藏的不只是几个函数名用Rational的A/B/C签名逐步封住绕过构造检查的路径，区分类型存在、具体表示和可使用的操作。对应 V09 / V10 / V11 / V1207三种有理数实现，客户端为什么可以分不出来对照立即约分、延迟约分与整数对表示，讲清接口相同、行为等价、类型匹配与模块间不能混用的区别。对应 V13 / V14 / V15
第 3 部分

判断改写保留了什么，又改变了什么

从客户端能观察的行为出发，检查状态、异常、终止与求值顺序，最后单独比较重复计算的成本。

08函数结果相同，还不一定能够互换用重复调用、调整顺序和标准改写检查状态、输出、异常与终止；说明变量捕获和闭包环境为何重要。对应 V16 / V1709行为等价以后，怎样单独比较计算成本回看最大值的重算次数，区分语言行为、渐进复杂度与常数开销，并交代后续语言学习的目的。对应 V18 / V19
