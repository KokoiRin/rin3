Kotlin 协程指南

发出两个请求，等多久能拿到结果？用户关掉页面，谁来叫停它们？从一次挂起开始，读懂并发代码的执行顺序与任务归属。

第一次从哪里读

先读协程基础。等你能指出代码在哪儿挂起，接着读组合挂起函数，预测两段等待会不会重叠，再读取消与超时。想把三件事连起来做一次，打开贡献者实战，从会卡住的窗口开始改。

指南导言

Kotlin 在语言与标准库层面提供了挂起函数和一小组底层接口，让库能在此基础上组织异步操作。调用挂起函数时，可以像普通调用一样沿着代码等待结果。async 和 await 则由协程库提供；在 Kotlin 里它们都是函数。

JetBrains 开发的 kotlinx.coroutines 提供更高层的工具，例如用 launch 启动任务、用 async 启动带返回值的计算。

这份指南按主题介绍协程库的核心功能。各章用代码演示概念，也有能跟着操作的完整实战与调试教程。

要运行示例，请先按项目 README 的说明添加 kotlinx-coroutines-core 依赖。第一章给出了 Gradle 和 Maven 的配置示例。 in the project README

章节目录

下列十二章沿用官方指南顺序。

01协程基础当两个任务都在等数据，一条线程怎样照顾它们？从第一个 delay 开始，找出挂起点、作用域和调度器。 02取消与超时用户已经离开页面，加载任务却还在运行。沿着 Job 追踪一次取消，看看它何时生效，清理又该放在哪里。 03Flow：连续到来的值下载进度会从 0 走到 100。用同一条数据管道比较重新生产、广播事件和保存当前状态三种行为。 04实战：用协程和通道加载 GitHub 贡献者同一份贡献者名单，要经历从窗口冻结，到边加载边显示的八步改造。每次只换一个机制，观察界面、日志与测试时间。 05组合挂起函数两个各需一秒的查询，什么时候总共等两秒，什么时候只等一秒？沿启动、等待与失败三个时刻读代码。 06协程上下文与调度器一段代码启动于主线程，挂起后还会回来吗？同时看线程名、协程名和父 Job，就能分清执行位置与任务归属。 07通道把待处理的数字交给几个工人。观察谁发送、谁接收、缓冲装满时谁等待，以及最后谁来关闭通道。 08协程怎样处理异常一个子任务失败后，先发生取消、清理还是错误报告？对照普通任务树与监督作用域，跟踪同一个异常。 09共享可变状态与并发一百个协程各加一千次，计数却不到十万。借这个反例比较原子操作、线程封闭和互斥锁各自保护了哪一步。 10select 表达式（实验性）两个通道都可能先有消息。看 select 怎样挑一个已经就绪的分支，以及为什么通道关闭也算一次就绪。 11在 IntelliJ IDEA 中调试协程让两个子任务分别计算乘数。在 IDEA 的三个断点之间切换，辨认正在计算、正在等值和已经结束的协程。 12在 IntelliJ IDEA 中调试 Flow在 emit 和打印结果的位置打断点，再只加一行 buffer()。比较两次调试时的协程数和暂停位置。
