在 IntelliJ IDEA 中调试协程

让两个子任务分别计算乘数。在 IDEA 的三个断点之间切换，辨认正在计算、正在等值和已经结束的协程。

跟着这次实验创建两个协程，再用 IntelliJ IDEA 观察它们开始、等待和完成的时刻。

建议先读「协程基础」，熟悉挂起和子协程。 coroutines

准备两个计算任务

  1. 在 IntelliJ IDEA 中打开 Kotlin 项目，或先新建一个。 create one

  2. 如果使用 Gradle，在 build.gradle(.kts) 中加入下面的 kotlinx.coroutines 依赖。

    Kotlin

    dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0")
}

    Groovy

    dependencies {
    implementation 'org.jetbrains.kotlinx:kotlinx-coroutines-core:1.11.0'
}

    其他构建工具的配置见 kotlinx.coroutines README。

  3. 打开 src/main/kotlin 下的 Main.kt。

    src 目录存放源码和资源。新建项目中的 Main.kt 通常带有打印 Hello World! 的示例。

  4. 修改 main()，让它执行下面几步。

    • 用 runBlocking() 包住本次实验，主函数会等协程工作结束。

    • 用 async() 创建两个子协程，分别计算 a 和 b。

    • 用 await() 取得计算结果。

    • 用 println() 打印计算进度及最后的乘积。

    import kotlinx.coroutines.*

fun main() = runBlocking<Unit> {
    val a = async {
        println("I'm computing part of the answer")
        6
    }
    val b = async {
        println("I'm computing another part of the answer")
        7
    }
    println("The answer is ${a.await() * b.await()}")
}

  5. 选择 Build Project 构建项目。

跟着断点观察三个协程

  1. 在图中几处 println() 所在行设置断点。

  2. 点击窗口顶部运行配置旁的 Debug，以调试模式启动。

    程序暂停后，查看 Debug 工具窗口。

    • Frames 标签显示调用栈。

    • Variables 标签显示当前上下文中能查看的变量。

    • Coroutines 标签列出运行或挂起的协程。在图示的第一个断点，主协程为 RUNNING，另外两个刚创建，状态为 CREATED。

  3. 在 Debug 窗口中点击 Resume Program，继续到下一处断点。

    此时再次查看 Coroutines。

    • 主协程处于 SUSPENDED，正在等乘法所需的值。

    • 第二个协程正在计算 a，状态为 RUNNING。

    • 第三个协程仍为 CREATED，还没开始计算 b。

  4. 再点击一次 Resume Program。

    留意列表里发生了哪些变化。

    • 主协程仍为 SUSPENDED，还在等乘法的操作数。

    • 第二个协程已经算完，从列表中消失。

    • 第三个协程正在计算 b，状态变为 RUNNING。

选中某个协程，还可以展开它自己的调用栈，定位代码停在何处。

看不到某个变量时

在挂起函数里，有时会看到变量名旁写着 was optimized out。

这表示编译器缩短了变量的存活期，此时已经取不到它。教程给出的调试办法是使用编译器选项 -Xdebug，以保留更多变量信息。

这个选项只用于调试，在生产环境启用 -Xdebug 可能引起内存泄漏。 cause memory leaks

读完试一题

调试器里主协程显示 SUSPENDED，为什么计算乘数的子任务仍能运行？

展开参考答案

主协程在 await 处挂起，把执行机会让了出来。选中子协程的调用栈，可以看到它正在计算哪个操作数。
