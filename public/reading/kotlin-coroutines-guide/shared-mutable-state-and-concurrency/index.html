共享可变状态与并发

一百个协程各加一千次，计数却不到十万。借这个反例比较原子操作、线程封闭和互斥锁各自保护了哪一步。

在 Dispatchers.Default 这样的多线程调度器上，协程可能并行执行。多个线程同时读写同一份可变状态时，需要协调访问。线程安全的数据结构仍然有用，协程还提供了可以挂起等待的同步手段。

十万次加一会得到多少

启动一百个协程，每个都重复同一操作一千次。顺便记录总耗时，稍后比较不同写法。

suspend fun massiveRun(action: suspend () -> Unit) {
    val n = 100  // number of coroutines to launch
    val k = 1000 // times an action is repeated by each coroutine
    val time = measureTimeMillis {
        coroutineScope { // scope for coroutines 
            repeat(n) {
                launch {
                    repeat(k) { action() }
                }
            }
        }
    }
    println("Completed ${n * k} actions in $time ms")    
}

让这些协程在 Dispatchers.Default 上给共享计数器加一。

import kotlinx.coroutines.*
import kotlin.system.*    

suspend fun massiveRun(action: suspend () -> Unit) {
    val n = 100  // number of coroutines to launch
    val k = 1000 // times an action is repeated by each coroutine
    val time = measureTimeMillis {
        coroutineScope { // scope for coroutines 
            repeat(n) {
                launch {
                    repeat(k) { action() }
                }
            }
        }
    }
    println("Completed ${n * k} actions in $time ms")    
}

//sampleStart
var counter = 0

fun main() = runBlocking {
    withContext(Dispatchers.Default) {
        massiveRun {
            counter++
        }
    }
    println("Counter = $counter")
}
//sampleEnd

查看完整示例。

很难恰好得到 Counter = 100000。两个协程可能读到同一个旧值，各加一再写回，于是其中一次增加消失了。

volatile 能保护哪一步

试着给计数器加上 volatile，再运行相同的操作。

import kotlinx.coroutines.*
import kotlin.system.*

suspend fun massiveRun(action: suspend () -> Unit) {
    val n = 100  // number of coroutines to launch
    val k = 1000 // times an action is repeated by each coroutine
    val time = measureTimeMillis {
        coroutineScope { // scope for coroutines 
            repeat(n) {
                launch {
                    repeat(k) { action() }
                }
            }
        }
    }
    println("Completed ${n * k} actions in $time ms")    
}

//sampleStart
@Volatile // in Kotlin `volatile` is an annotation 
var counter = 0

fun main() = runBlocking {
    withContext(Dispatchers.Default) {
        massiveRun {
            counter++
        }
    }
    println("Counter = $counter")
}
//sampleEnd

查看完整示例。

运行可能更慢，最终值仍可能偏小。volatile 确保对这个变量的单次读取和写入具有相应的可见性与原子性。加一却包含读、算、写三个步骤，其他线程可以插进来。

线程安全的数据结构

对计数器，可以把整个加一操作交给 AtomicInteger.incrementAndGet。数据结构内部完成同步，这种方法对线程和协程都适用。

import kotlinx.coroutines.*
import java.util.concurrent.atomic.*
import kotlin.system.*

suspend fun massiveRun(action: suspend () -> Unit) {
    val n = 100  // number of coroutines to launch
    val k = 1000 // times an action is repeated by each coroutine
    val time = measureTimeMillis {
        coroutineScope { // scope for coroutines 
            repeat(n) {
                launch {
                    repeat(k) { action() }
                }
            }
        }
    }
    println("Completed ${n * k} actions in $time ms")    
}

//sampleStart
val counter = AtomicInteger()

fun main() = runBlocking {
    withContext(Dispatchers.Default) {
        massiveRun {
            counter.incrementAndGet()
        }
    }
    println("Counter = $counter")
}
//sampleEnd

查看完整示例。

在这个简单计数实验里，原子计数器最快。集合、队列也有适合特定操作的线程安全实现。如果一次更新横跨多个字段或多个操作，就要考虑整个更新的边界。

把每次更新交给同一线程

线程封闭指某份状态只由一个线程访问。UI 状态常由事件分发线程维护。在协程里可以用单线程上下文实现同样的约束。

import kotlinx.coroutines.*
import kotlin.system.*

suspend fun massiveRun(action: suspend () -> Unit) {
    val n = 100  // number of coroutines to launch
    val k = 1000 // times an action is repeated by each coroutine
    val time = measureTimeMillis {
        coroutineScope { // scope for coroutines 
            repeat(n) {
                launch {
                    repeat(k) { action() }
                }
            }
        }
    }
    println("Completed ${n * k} actions in $time ms")    
}

//sampleStart
val counterContext = newSingleThreadContext("CounterContext")
var counter = 0

fun main() = runBlocking {
    withContext(Dispatchers.Default) {
        massiveRun {
            // confine each increment to a single-threaded context
            withContext(counterContext) {
                counter++
            }
        }
    }
    println("Counter = $counter")
}
//sampleEnd

查看完整示例。

每加一都要用 withContext(counterContext) 从 Dispatchers.Default 切到专用线程，再切回来。这种细粒度切换代价很高。

把一批更新交给同一线程

实际中可以让整段更新状态的业务逻辑在同一线程运行。下面从协程启动时就指定单线程上下文，一次完成一批更新。

import kotlinx.coroutines.*
import kotlin.system.*

suspend fun massiveRun(action: suspend () -> Unit) {
    val n = 100  // number of coroutines to launch
    val k = 1000 // times an action is repeated by each coroutine
    val time = measureTimeMillis {
        coroutineScope { // scope for coroutines 
            repeat(n) {
                launch {
                    repeat(k) { action() }
                }
            }
        }
    }
    println("Completed ${n * k} actions in $time ms")    
}

//sampleStart
val counterContext = newSingleThreadContext("CounterContext")
var counter = 0

fun main() = runBlocking {
    // confine everything to a single-threaded context
    withContext(counterContext) {
        massiveRun {
            counter++
        }
    }
    println("Counter = $counter")
}
//sampleEnd

查看完整示例。

这样既能得到正确结果，也省去了频繁切换的开销。

用 Mutex 保护临界区

还可以规定，同一时间只有一个协程进入更新状态的代码段。阻塞式程序常用 synchronized 或 ReentrantLock；协程里可用 Mutex。调用 lock 时，如果需要等待，等待者可以挂起，让出线程，执行完再 unlock。

用 withLock 包住临界区，相当于先加锁，在 finally 里解锁；即使更新抛异常，也会释放锁。

import kotlinx.coroutines.*
import kotlinx.coroutines.sync.*
import kotlin.system.*

suspend fun massiveRun(action: suspend () -> Unit) {
    val n = 100  // number of coroutines to launch
    val k = 1000 // times an action is repeated by each coroutine
    val time = measureTimeMillis {
        coroutineScope { // scope for coroutines 
            repeat(n) {
                launch {
                    repeat(k) { action() }
                }
            }
        }
    }
    println("Completed ${n * k} actions in $time ms")    
}

//sampleStart
val mutex = Mutex()
var counter = 0

fun main() = runBlocking {
    withContext(Dispatchers.Default) {
        massiveRun {
            // protect each increment with lock
            mutex.withLock {
                counter++
            }
        }
    }
    println("Counter = $counter")
}
//sampleEnd

查看完整示例。

例子每加一就加一次锁，因此仍有同步成本。当共享状态没有天然所属的线程，又必须不时更新时，互斥锁很合适。

读完试一题

两个工作者都读到 7，各加一再写回。为什么把变量标为 volatile 仍可能得到 8？

展开参考答案

读和写各自可见，也不能让「读、加、写」成为不可分割的操作。这里可用原子自增，或让完整的修改在同一个锁或同一线程内进行。
