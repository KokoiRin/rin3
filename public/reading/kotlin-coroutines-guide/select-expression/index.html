select 表达式（实验性）

两个通道都可能先有消息。看 select 怎样挑一个已经就绪的分支，以及为什么通道关闭也算一次就绪。

有时一个协程需要同时等几件事，哪件先就绪，就执行相应的分支。select 把这些等待写在一个表达式里。

官方将本主题标为实验性。升级 kotlinx.coroutines 时，要核对相关 API 的变化。

从多个通道中选择

先创建两个字符串生产者。fizz 每隔 500 毫秒发送一次 Fizz。

fun CoroutineScope.fizz() = produce<String> {
    while (true) { // sends "Fizz" every 500 ms
        delay(500)
        send("Fizz")
    }
}

buzz 每隔 1000 毫秒发送一次 Buzz!。

fun CoroutineScope.buzz() = produce<String> {
    while (true) { // sends "Buzz!" every 1000 ms
        delay(1000)
        send("Buzz!")
    }
}

单独调用 receive 时，要先决定等哪个通道。用 select 为两个通道各写一个 onReceive，就能等任意一个交付。

suspend fun selectFizzBuzz(fizz: ReceiveChannel<String>, buzz: ReceiveChannel<String>) {
    select<Unit> { // <Unit> means that this select expression does not produce any result 
        fizz.onReceive { value ->  // this is the first select clause
            println("fizz -> '$value'")
        }
        buzz.onReceive { value ->  // this is the second select clause
            println("buzz -> '$value'")
        }
    }
}

连续选择七次，看看每次谁就绪。

选择时处理关闭

使用 onReceive 时，如果选中的是已经关闭且读空的通道，这次 select 会抛异常。onReceiveCatching 可以显式处理关闭。还要注意，select 本身有返回值，即被选中分支的结果。

suspend fun selectAorB(a: ReceiveChannel<String>, b: ReceiveChannel<String>): String =
    select<String> {
        a.onReceiveCatching { it ->
            val value = it.getOrNull()
            if (value != null) {
                "a -> '$value'"
            } else {
                "Channel 'a' is closed"
            }
        }
        b.onReceiveCatching { it ->
            val value = it.getOrNull()
            if (value != null) {
                "b -> '$value'"
            } else {
                "Channel 'b' is closed"
            }
        }
    }

让通道 a 发送四次 Hello，让 b 发送四次 World，再观察结果。

    }

    }
    repeat(8) { // print first eight results

可以先看正常收发，再看通道关闭之后。

多个分支同时就绪时，select 偏向写在前面的分支。因此两个通道都有值时，排在前面的 a 往往先被选中。这里没有缓冲，a 偶尔会在 send 处等待，b 也就有了被选中的机会。

已经关闭并读空的通道可以立即触发 onReceiveCatching。重复选择时，关闭分支仍然就绪。

选择发送的目的地

onSend 允许在多个发送目的地之间选择。把首选目的地排在前面，就能利用 select 的分支顺序。

下面的整数生产者优先发送到主通道，主通道的消费者跟不上时，改发到旁路通道。

fun CoroutineScope.produceNumbers(side: SendChannel<Int>) = produce<Int> {
    for (num in 1..10) { // produce 10 numbers from 1 to 10
        delay(100) // every 100 ms
        select<Unit> {
            onSend(num) {} // Send to the primary channel
            side.onSend(num) {} // or to the side channel     
        }
    }
}

主消费者处理一个数需要 250 毫秒，试着预测哪些数会走旁路。

import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*
import kotlinx.coroutines.selects.*

fun CoroutineScope.produceNumbers(side: SendChannel<Int>) = produce<Int> {
    for (num in 1..10) { // produce 10 numbers from 1 to 10
        delay(100) // every 100 ms
        select<Unit> {
            onSend(num) {} // Send to the primary channel
            side.onSend(num) {} // or to the side channel     
        }
    }
}

fun main() = runBlocking<Unit> {
//sampleStart
    val side = Channel<Int>() // allocate side channel
    launch { // this is a very fast consumer for the side channel
        side.consumeEach { println("Side channel has $it") }
    }
    produceNumbers(side).consumeEach { 
        println("Consuming $it")
        delay(250) // let us digest the consumed number properly, do not hurry
    }
    println("Done consuming")
    coroutineContext.cancelChildren()  
//sampleEnd      
}

选择先完成的 Deferred

用 onAwait 等待 Deferred。先写一个 async 函数，随机等待一段时间再返回字符串。

fun CoroutineScope.asyncString(time: Int) = async {
    delay(time.toLong())
    "Waited for $time ms"
}

启动十二个任务，让每个任务的等待时间独立变化。

fun CoroutineScope.asyncStringsList(): List<Deferred<String>> {
    val random = Random(3)
    return List(12) { asyncString(random.nextInt(1000)) }
}

主函数取得最先完成的结果，并统计还有多少个任务活跃。select 的分支可以用普通 Kotlin 代码构建。遍历任务列表，就能为每个 Deferred 加入一个 onAwait 分支。

import kotlinx.coroutines.*
import kotlinx.coroutines.selects.*
import java.util.*
    
fun CoroutineScope.asyncString(time: Int) = async {
    delay(time.toLong())
    "Waited for $time ms"
}

fun CoroutineScope.asyncStringsList(): List<Deferred<String>> {
    val random = Random(3)
    return List(12) { asyncString(random.nextInt(1000)) }
}

fun main() = runBlocking<Unit> {
//sampleStart
    val list = asyncStringsList()
    val result = select<String> {
        list.withIndex().forEach { (index, deferred) ->
            deferred.onAwait { answer ->
                "Deferred $index produced answer '$answer'"
            }
        }
    }
    println(result)
    val countActive = list.count { it.isActive }
    println("$countActive coroutines are still active")
//sampleEnd
}

查看完整示例。

一次运行的输出如下。

Deferred 4 produced answer 'Waited for 128 ms'
11 coroutines are still active

新任务到来时切换等待对象

下面的生产者从通道里接收 Deferred<String>。等当前结果期间，如果新任务到来，就转而等待新任务；如果输入通道关闭，就结束。将 onReceiveCatching 和 onAwait 放入同一个 select，即可协调这两件事。

fun CoroutineScope.switchMapDeferreds(input: ReceiveChannel<Deferred<String>>) = produce<String> {
    var current = input.receive() // start with first received deferred value
    while (isActive) { // loop while not cancelled/closed
        val next = select<Deferred<String>?> { // return next deferred value from this select or null
            input.onReceiveCatching { update ->
                update.getOrNull()
            }
            current.onAwait { value ->
                send(value) // send value that current deferred has produced
                input.receiveCatching().getOrNull() // and use the next deferred from the input channel
            }
        }
        if (next == null) {
            println("Channel was closed")
            break // out of loop
        } else {
            current = next
        }
    }
}

测试函数用 async 在指定延迟后返回指定字符串。

fun CoroutineScope.asyncString(str: String, time: Long) = async {
    delay(time)
    str
}

主函数启动一个协程打印 switchMapDeferreds 的输出，再向输入通道发送几组测试数据。

import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*
import kotlinx.coroutines.selects.*
    
fun CoroutineScope.switchMapDeferreds(input: ReceiveChannel<Deferred<String>>) = produce<String> {
    var current = input.receive() // start with first received deferred value
    while (isActive) { // loop while not cancelled/closed
        val next = select<Deferred<String>?> { // return next deferred value from this select or null
            input.onReceiveCatching { update ->
                update.getOrNull()
            }
            current.onAwait { value ->
                send(value) // send value that current deferred has produced
                input.receiveCatching().getOrNull() // and use the next deferred from the input channel
            }
        }
        if (next == null) {
            println("Channel was closed")
            break // out of loop
        } else {
            current = next
        }
    }
}

fun CoroutineScope.asyncString(str: String, time: Long) = async {
    delay(time)
    str
}

fun main() = runBlocking<Unit> {
//sampleStart
    val chan = Channel<Deferred<String>>() // the channel for test
    launch { // launch printing coroutine
        for (s in switchMapDeferreds(chan)) 
            println(s) // print each received string
    }
    chan.send(asyncString("BEGIN", 100))
    delay(200) // enough time for "BEGIN" to be produced
    chan.send(asyncString("Slow", 500))
    delay(100) // not enough time to produce slow
    chan.send(asyncString("Replace", 100))
    delay(500) // give it time before the last one
    chan.send(asyncString("END", 500))
    delay(1000) // give it time to process
    chan.close() // close the channel ... 
    delay(500) // and wait some time to let it finish
//sampleEnd
}

读完试一题

一个已关闭且读空的通道一直留在首个 onReceiveCatching 分支里，会发生什么？

展开参考答案

该分支无需等待就能选中。多个分支同时就绪时，靠前者优先；循环若要继续处理其他输入，就需要移除已结束的来源或退出对应循环。
