select 表达式（实验性）

select 表达式可以同时等待多个可挂起操作，选择最先就绪的一个。

select 表达式是 kotlinx.coroutines 的实验性功能。库更新时相关 API 预计还会演进，可能发生不兼容的变化。

从多个通道接收

设有两个字符串生产者 fizz 和 buzz。fizz 每隔 500 毫秒产生字符串 Fizz。

fun CoroutineScope.fizz() = produce<String> {
    while (true) { // 每隔 500 毫秒发送 Fizz
        delay(500)
        send("Fizz")
    }
}

buzz 每隔 1000 毫秒产生字符串 Buzz!。

fun CoroutineScope.buzz() = produce<String> {
    while (true) { // 每隔 1000 毫秒发送 Buzz!
        delay(1000)
        send("Buzz!")
    }
}

调用挂起函数 receive 时，一次只能选定一个通道接收。select 表达式则可以用 onReceive 分支同时等待两个通道。

suspend fun selectFizzBuzz(fizz: ReceiveChannel<String>, buzz: ReceiveChannel<String>) {
    select<Unit> { // <Unit> 表示这个 select 表达式无需返回结果值 
        fizz.onReceive { value ->  // 这是 select 的第一个分支
            println("fizz -> '$value'")
        }
        buzz.onReceive { value ->  // 这是 select 的第二个分支
            println("buzz -> '$value'")
        }
    }
}

运行七次选择。

通道关闭时的选择

如果在已关闭且读空的通道上选中 onReceive，这次 select 会因异常失败。可用 onReceiveCatching 在通道关闭时执行特定操作。下面的例子还说明 select 是一个表达式，返回值就是选中分支的执行结果。

suspend fun selectAorB(a: ReceiveChannel<String>, b: ReceiveChannel<String>): String =
    select<String> {
        a.onReceiveCatching { it ->
            val value = it.getOrNull()
            if (value != null) {
                "a -> '$value'"
            } else {
                "Channel 'a' is closed"
            }
        }
        b.onReceiveCatching { it ->
            val value = it.getOrNull()
            if (value != null) {
                "b -> '$value'"
            } else {
                "Channel 'b' is closed"
            }
        }
    }

用通道 a 产生四次 Hello，通道 b 产生四次 World。

import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*
import kotlinx.coroutines.selects.*

suspend fun selectAorB(a: ReceiveChannel<String>, b: ReceiveChannel<String>): String =
    select<String> {
        a.onReceiveCatching { it ->
            val value = it.getOrNull()
            if (value != null) {
                "a -> '$value'"
            } else {
                "Channel 'a' is closed"
            }
        }
        b.onReceiveCatching { it ->
            val value = it.getOrNull()
            if (value != null) {
                "b -> '$value'"
            } else {
                "Channel 'b' is closed"
            }
        }
    }
    
fun main() = runBlocking<Unit> {
//sampleStart
    val a = produce<String> {
        repeat(4) { send("Hello $it") }
    }
    val b = produce<String> {
        repeat(4) { send("World $it") }
    }
    repeat(8) { // 打印前八个结果
        println(selectAorB(a, b))
    }
    coroutineContext.cancelChildren()  
//sampleEnd      
}

这段代码的结果值得进一步分析。

b -> 'World 0'
a -> 'Hello 2'
a -> 'Hello 3'
b -> 'World 1'

Channel 'a' is closed

输出中有两点值得注意。

select 偏向排在前面的分支。多个分支同时可选时，会选中排在最前面的一个。这里两个通道一直生成字符串，a 对应的分支写在前面，所以往往获选。但它们没有缓冲，a 不时会在 send 时挂起，于是 b 也有机会发送。

另一个现象是，通道已经关闭且读空时，onReceiveCatching 可以立即被选中。

选择向哪个通道发送

select 表达式有 onSend 分支，可以利用前面的分支优先被选中的规则来安排发送。

下面的整数生产者优先使用主通道。主通道的消费者跟不上时，它会把值发送到旁路通道。

fun CoroutineScope.produceNumbers(side: SendChannel<Int>) = produce<Int> {
    for (num in 1..10) { // 生成 1 到 10 共十个数
        delay(100) // 每隔 100 毫秒
        select<Unit> {
            onSend(num) {} // 发送到主通道
            side.onSend(num) {} // 或发送到旁路通道     
        }
    }
}

主通道的消费者较慢，处理每个数字要花 250 毫秒。

import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*
import kotlinx.coroutines.selects.*

fun CoroutineScope.produceNumbers(side: SendChannel<Int>) = produce<Int> {
    for (num in 1..10) { // 生成 1 到 10 共十个数
        delay(100) // 每隔 100 毫秒
        select<Unit> {
            onSend(num) {} // 发送到主通道
            side.onSend(num) {} // 或发送到旁路通道     
        }
    }
}

fun main() = runBlocking<Unit> {
//sampleStart
    val side = Channel<Int>() // 创建旁路通道
    launch { // 旁路通道的消费者处理得很快
        side.consumeEach { println("Side channel has $it") }
    }
    produceNumbers(side).consumeEach { 
        println("Consuming $it")
        delay(250) // 慢慢处理刚收到的数字
    }
    println("Done consuming")
    coroutineContext.cancelChildren()  
//sampleEnd      
}

选择 Deferred 的结果

可以用 onAwait 分支选择已经完成的 Deferred。先写一个 async 函数，让它在随机延迟后返回字符串结果。

fun CoroutineScope.asyncString(time: Int) = async {
    delay(time.toLong())
    "Waited for $time ms"
}

启动十二个任务，让它们各自等待随机时长。

fun CoroutineScope.asyncStringsList(): List<Deferred<String>> {
    val random = Random(3)
    return List(12) { asyncString(random.nextInt(1000)) }
}

主函数等待其中第一个任务完成，并统计尚活跃的 Deferred 数量。select 表达式是 Kotlin DSL，因此可以用任意 Kotlin 代码为它构造分支。这里遍历 Deferred 列表，为每一项添加一个 onAwait。

import kotlinx.coroutines.*
import kotlinx.coroutines.selects.*
import java.util.*
    
fun CoroutineScope.asyncString(time: Int) = async {
    delay(time.toLong())
    "Waited for $time ms"
}

fun CoroutineScope.asyncStringsList(): List<Deferred<String>> {
    val random = Random(3)
    return List(12) { asyncString(random.nextInt(1000)) }
}

fun main() = runBlocking<Unit> {
//sampleStart
    val list = asyncStringsList()
    val result = select<String> {
        list.withIndex().forEach { (index, deferred) ->
            deferred.onAwait { answer ->
                "Deferred $index produced answer '$answer'"
            }
        }
    }
    println(result)
    val countActive = list.count { it.isActive }
    println("$countActive coroutines are still active")
//sampleEnd
}

输出如下。

Deferred 4 produced answer 'Waited for 128 ms'
11 coroutines are still active

在通道传来的多个 Deferred 之间切换

写一个通道生产者，从输入通道取得表示字符串结果的 Deferred。它等待当前结果，直到收到下一个 Deferred 或者输入通道关闭。这个例子将 onReceiveCatching 和 onAwait 放进同一次 select。

fun CoroutineScope.switchMapDeferreds(input: ReceiveChannel<Deferred<String>>) = produce<String> {
    var current = input.receive() // 从收到的第一个 Deferred 开始
    while (isActive) { // 在被取消或通道关闭前持续循环
        val next = select<Deferred<String>?> { // 从本次 select 返回下一个 Deferred，或返回 null
            input.onReceiveCatching { update ->
                update.getOrNull()
            }
            current.onAwait { value ->
                send(value) // 发送当前 Deferred 产生的值
                input.receiveCatching().getOrNull() // 改为等待输入通道送来的下一个 Deferred
            }
        }
        if (next == null) {
            println("Channel was closed")
            break // 已退出循环
        } else {
            current = next
        }
    }
}

为了测试，使用一个简单的 async 函数，在指定时间后交付给定的字符串。

fun CoroutineScope.asyncString(str: String, time: Long) = async {
    delay(time)
    str
}

主函数启动一个协程来打印 switchMapDeferreds 的输出，再向它发送一些测试数据。

import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*
import kotlinx.coroutines.selects.*
    
fun CoroutineScope.switchMapDeferreds(input: ReceiveChannel<Deferred<String>>) = produce<String> {
    var current = input.receive() // 从收到的第一个 Deferred 开始
    while (isActive) { // 在被取消或通道关闭前持续循环
        val next = select<Deferred<String>?> { // 从本次 select 返回下一个 Deferred，或返回 null
            input.onReceiveCatching { update ->
                update.getOrNull()
            }
            current.onAwait { value ->
                send(value) // 发送当前 Deferred 产生的值
                input.receiveCatching().getOrNull() // 改为等待输入通道送来的下一个 Deferred
            }
        }
        if (next == null) {
            println("Channel was closed")
            break // 已退出循环
        } else {
            current = next
        }
    }
}

fun CoroutineScope.asyncString(str: String, time: Long) = async {
    delay(time)
    str
}

fun main() = runBlocking<Unit> {
//sampleStart
    val chan = Channel<Deferred<String>>() // 测试用的通道
    launch { // 启动负责打印的协程
        for (s in switchMapDeferreds(chan)) 
            println(s) // 打印每个收到的字符串
    }
    chan.send(asyncString("BEGIN", 100))
    delay(200) // 留出足够时间产生 BEGIN
    chan.send(asyncString("Slow", 500))
    delay(100) // 时间不足，slow 还没有结果
    chan.send(asyncString("Replace", 100))
    delay(500) // 在最后一次操作前稍等
    chan.send(asyncString("END", 500))
    delay(1000) // 留出处理时间
    chan.close() // 关闭通道…… 
    delay(500) // 稍等片刻，让它执行完
//sampleEnd
}
