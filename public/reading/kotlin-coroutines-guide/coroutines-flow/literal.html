Flow 表示一串可以异步产生、依次发出的值。挂起函数一次只返回一个结果，Flow 则可以处理在一段时间内陆续产生的多个值。

把 Flow 的操作串起来，可以逐步加载数据、响应一连串事件，或实现允许调用方订阅更新的 API。

Flow 管道是一系列操作，其中包含以下角色：

  • 发射者：生成值。

  • 中间操作符（可选）：从 Flow 中获取值，对其应用操作，并返回另一个 Flow。

  • 收集者：从 Flow 中消费值。

以下是一个简单示例，展示了这些管道角色如何协同工作：

import kotlinx.coroutines.flow.*

//sampleStart
suspend fun main() {
    // 发射方产生值
    flowOf(0x4B, 0x6F, 0x74, 0x6C, 0x69, 0x6E)
        // 中间操作符接收这些值，
        // 执行转换，并返回一条新流
        .map { value -> value.toChar() }
        // 收集者接收转换后的值
        .collect { updatedValue ->
            println("Say '$updatedValue'!")
        }
}
//sampleEnd

在 Flow 中，值从发射者流向收集者，从上游流向下游。中间操作符会收集一个上游 Flow，对其值应用操作，并返回一个新的下游 Flow。该下游 Flow 可以成为下一个收集者的上游 Flow。

Kotlin 提供了以下 Flow 类型：

  • 冷流在被收集时开始生成值。每个收集者都会触发 Flow 的一次新的、独立的执行。

  • 热流独立于收集者发出值，并与所有收集者共享同一条值流。

可以用 Turbine 库测试 Kotlin Flow。它简化了单元测试中的收集与断言，包括检查发出的值、正常结束和失败。

冷流

与 Sequence 一样，冷流也是惰性的。

冷流构建器的代码块在被收集者收集之前不会运行。每个新的收集者都会启动一次新的流执行。

创建一个冷流

要创建一个冷流，请使用 flow() 构建器函数。在其代码块内，使用 emit() 函数向收集者输出值：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

//sampleStart
fun main() {
    // 创建一条流
    val pageFlow = flow {
        for (page in 1..3) {
            println("Loading page $page...")

            // 每加载一页，就发出这一页
            emit("Page $page")
        }
    }
    println("Creating a cold flow doesn't run it!")
}
//sampleEnd

flow() 返回 Flow<T>，此时还没有执行传入的代码块。冷流像一份配方，规定了怎样生成值，真正开始收集时才照着做。

你还可以使用以下函数创建冷流：

  • flowOf()：根据提供的值创建一个 Flow。

  • .asFlow()：将现有的可迭代对象（如范围）转换为 Flow。

以下是一个示例：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun main() {
    // 用给定的值创建一条流
    val predefinedPageFlow = flowOf("Page 1", "Page 2", "Page 3")
    // 从区间创建一条流
    val generatedPageFlow = (1..3).asFlow()
}

收集冷流

要收集一个冷流，请使用 collect() 函数，该函数会触发上游流的发射。如果将一个 lambda 表达式传递给 collect()，它将接收每个发射的值：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
suspend fun main() {
    withContext(Dispatchers.Default) {
        val pageFlow = flow {
            for (page in 1..3) {
                println("Loading page $page...")
                emit("Page $page")
            }
        }
        // 收集这条流；每发出一页，就调用一次下面的 lambda
        pageFlow.collect { page ->
            println("Processing $page...")
            delay(100.milliseconds)
            println("Done processing $page.")
        }
    }
}
//sampleEnd

每次调用 collect() 都会从头运行整个冷流。即使多个收集者收集的是同一个冷流，每个人也会触发一次独立的执行。

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
suspend fun main() {
    val pageFlow = flow {
        // 读取当前协程的名称
        val coroutineName = currentCoroutineContext()[CoroutineName]?.name

        println("Starting emissions in $coroutineName")
        for (page in 1..3) {
            println("Loading page $page in $coroutineName")
            emit("Page $page")
        }
        println("Done emitting in $coroutineName")
    }

    withContext(Dispatchers.Default) {
        // 启动一个缓慢处理每一页的收集者
        launch(CoroutineName("a slow coroutine")) {
            pageFlow.collect {
                println("Processing $it slowly")
                delay(100.milliseconds)
                println("Done processing $it slowly")
            }
        }

        // 启动一个快速处理每一页的收集者
        launch(CoroutineName("a fast coroutine")) {
            pageFlow.collect {
                println("Processing $it quickly")
                delay(10.milliseconds)
                println("Done processing $it quickly")
            }
        }
    }
}
//sampleEnd

示例用 CoroutineName 给每个协程命名。它通常用于调试，在这里可以从输出辨认每一次收集是哪个协程发起的。

中间流操作符

中间操作符对上游流应用操作，并返回一个新的下游流。它们是冷流，因此即使上游流是热流，返回的流在被收集之前也不会开始处理值。

kotlinx.coroutines 库提供了种类丰富的中间 Flow 操作符，用于转换和处理 Flow。当内置操作符无法提供所需行为时，你还可以自行定义操作符。

以下是一个简化的自定义 .map() 操作符示例，它会对每个发出的值应用转换：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

//sampleStart
// 内置 map 操作符的一种简化实现
fun <T, R> Flow<T>.myMap(transform: suspend (value: T) -> R): Flow<R> = flow {
    // 从上游收集值
    this@myMap.collect { value ->
        // 转换收集到的每个值，再发出转换结果
        emit(transform(value))
    }
}

suspend fun main() {
    // 创建流，应用自定义 map，再收集转换后的值
    flowOf(1, 2, 3).myMap { 2 * it }.collect {
        println("Collecting $it")
    }
}
//sampleEnd

在 Flow 构建器内部调用挂起函数

与 Sequence 不同，你可以在 flow() 构建器函数内部调用挂起函数：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

//sampleStart
suspend fun loadPage(): Int {
    delay(100)
    return 3
}

suspend fun main() {
    flow {
        emit(loadPage())
    }.collect {
        println(it)
        // 3
    }
}
//sampleEnd

但是，flow() 构建器函数必须从其运行的同一协程上下文中发出值。你不能启动另一个在块中调用 emit() 的协程，也不能使用 withContext() 更改协程上下文：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

//sampleStart
suspend fun main() {
    // 这里会抛出异常！
    flow {
        // 用 withContext() 切换协程上下文
        withContext(Dispatchers.IO) {
            emit('a')
        }
    }.collect { 
        println("This never prints")
    }
}
//sampleEnd

此限制适用于 flow() 构建器函数。

如果需要让上游 Flow 在不同的协程上下文中运行，可以使用 .flowOn() 操作符更改上下文。

或者，你可以使用 channelFlow() 从多个协程中发出值。

使用 .flowOn() 更改冷流的协程上下文

默认情况下，冷流与收集者在同一协程上下文中运行。

若希望 Flow 在不同的协程上下文中运行，请使用 .flowOn() 操作符。该操作符具有上下文保留特性，即它仅更改上游 Flow 的协程上下文，同时保持下游 Flow 处于调用者的上下文中。

以下是一个冷流的示例，它在某个协程上下文中发射值，并在另一个协程上下文中收集这些值：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

//sampleStart
suspend fun main() {
    withContext(Dispatchers.Default + CoroutineName("downstream")) {
        flow {
            val coroutineName = currentCoroutineContext()[CoroutineName]?.name

            // 在 flowOn() 指定的上下文中发射
            println("Emitting '1' in $coroutineName")
            // 上游正在发出 1
            emit(1)

        // 改变上游流的协程上下文
        }.flowOn(Dispatchers.IO + CoroutineName("upstream"))
            .collect {
            val coroutineName = currentCoroutineContext()[CoroutineName]?.name

            // 在调用者的协程上下文中收集
            println("Collecting '$it' in $coroutineName")
            // 下游正在收集 1
        }
    }
}
//sampleEnd

在 Flow 中处理异常

发射者和收集者都可能抛出异常。

收集 Flow 时，如果异常没有得到处理，它会从收集者沿上游传回，最终抛给调用 collect() 的代码。

你可以通过将 collect() 函数包裹在 try-catch 代码块中来处理此类异常，例如：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

class MyFlowException(message: String) : Exception(message)

//sampleStart
suspend fun main() {
    val myFlow = flow {
        try {
            // emit() 会调用传给 collect() 的 lambda
            emit('a')
        } catch (e: MyFlowException) {
            println("Collector threw $e")

            // 重新抛出下游异常
            throw e
        }
    }
    // 用 try/catch 包住流的收集过程
    try {
        myFlow.collect {
            // 从 collect() 的 lambda 中抛出异常
            throw MyFlowException("Can't process '$it'!")
        }
    } catch (e: MyFlowException) {
        println("Flow collection failed with $e")
        // 把异常重新抛给调用者
        throw e
    }
}
//sampleEnd

在此示例中，当收集者从 emit() 函数接收值时会抛出异常。flow() 构建器函数捕获了此下游异常。

当你在 Flow 构建器函数内部捕获由收集者抛出的异常时，请将其重新抛出。这样可以保持异常透明性，并让 collect() 的调用者来处理该异常。

使用 .catch() 操作符处理上游异常

要处理在异常到达收集者之前的异常，请使用 .catch() 操作符。

你可以使用 .catch() 操作符来处理来自上游 Flow 的异常，例如通过 emit() 函数向下游发出备用值：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

//sampleStart
suspend fun main() {
    flow {
        emit("a")
        emit("b")

        // 从上游流抛出异常
        throw UnsupportedOperationException(
            "I am tired of listing letters"
        )
    }.catch { upstreamException ->
        println("Upstream completed with $upstreamException!")

        // 向下游发出一个备用值
        emit("Upstream terminated with an exception!")
    }.collect {
        println("Got '$it'")
    }
}
//sampleEnd

在此示例中，上游 Flow 在抛出异常之前会先发出一些值。.catch() 操作符会处理该异常，并发出 "Upstream terminated with an exception!" 作为备用值。

当预计某个 Flow 在正常运行过程中会抛出某些异常时，应在 .catch() 中处理可恢复的异常，并将任何意外异常重新抛出。

以下是一个 Flow 加载数据并报告其进度的示例：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
sealed interface LoadingState {
    sealed interface Terminal: LoadingState
    object Started: LoadingState
    data class Percentage(val percents: Int): LoadingState
    object Failed: Terminal
    object Done: Terminal
}

fun loadBlob(url: String) = flow {
    emit(LoadingState.Started)

    val failureChancePerStep = 1 - java.lang.Math.pow(0.99, 10.0)

    repeat(10) { step ->
        if (Random.nextDouble() < failureChancePerStep)
            throw IOException("Failed to load!")
        emit(LoadingState.Percentage((step + 1) * 10))
        delay(10.milliseconds)
    }
    emit(LoadingState.Done)
}.catch { e ->
    println("Loading data failed with $e")
    if (e is IOException) {
        // 处理预期内的异常
        emit(LoadingState.Failed)
    } else {
        // 重新抛出意料之外的异常，让 collect() 将失败传给调用者
        throw e
    }
}

suspend fun main() {
    loadBlob("https://example.com/").collect {
        println("Got '$it'")
    }
}
//sampleEnd

在此示例中，如果加载因预期异常而失败，.catch() 操作符会使用 emit() 函数发出一个回退状态。对于意外异常，请在 .catch() 操作符中重新抛出它们。这样，collect() 函数的调用者就能接收到 Flow 未处理的异常。

.catch() 操作符不处理由收集者抛出的异常。如果传递给 collect() 的 lambda 表达式抛出异常，请在 collect() 函数外使用 try-catch 代码块进行处理：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

suspend fun main() {
    val myFlow = flow {
        for (char in listOf('a', 'o', '5', 'c')) {
            try {
                emit(char)
            } catch (e: IllegalArgumentException) {
                println("Collector doesn't support character '$char': $e")

                // 重新抛出下游异常
                throw e
            }
        }
    }.catch { e ->
        // 异常发生在下游，因此这里不会执行
        println("Upstream threw an exception: $e")
    }

    try {
        myFlow.collect {
            require(!it.isDigit()) { "Digits are not allowed!" }
        }
    } catch (e: IllegalArgumentException) {
        // 处理 collect() 的 lambda 抛出的异常
        println("Flow collection failed with $e")
    }
}

collect() 的 lambda 在 .catch() 下游，因此这个 .catch() 捕获不到它抛出的异常。如果希望 .catch() 处理某段逐值执行的代码抛出的异常，把那段代码移到 .catch() 之前的 .onEach() 中。

.onEach() 操作符会在每个值被向下游输出之前执行其 lambda 表达式。如果 .catch() 处理了来自 .onEach() 的异常，则 Flow 将完成执行且不会输出下一个值：

以下是一个示例：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds

suspend fun main() {
    flowOf('a', 'o', '5', 'c')
        // 每个值向下游发出前都会执行
        .onEach {
            require(!it.isDigit()) { "Digits are not allowed!" }
            println("Got '$it'")
        }
        .catch { e ->
            println("Caught an exception: $e")
        }
        .collect()
}

示例把 .onEach() 放在 .catch() 的上游。因此，当 require() 对字符 '5' 的检查失败时，异常会交给 .catch() 处理。

异常发生后重启上游流程

某些操作可能会暂时失败，例如网络请求因连接中断而失败。对于这些情况，你可以使用 .retry() 操作符在异常发生后重启上游 Flow。

.retry() 操作符接收到异常后，当其 lambda 返回 true 时会重新收集上游流，重试次数不超过指定次数。例如，.retry(3) 在首次尝试失败后最多会重试上游 Flow 三次。

如果 lambda 返回 false，.retry() 将停止重试并重新抛出异常。

若需更精细地控制重试逻辑，请使用 .retryWhen() 操作符。与 .retry() 类似，它会接收异常，但还会接收当前重试次数，并且可以在重试前输出值。

下例在发生 IOException 后重新尝试加载，最多重试三次。

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds
import kotlin.time.Duration.Companion.seconds

//sampleStart
sealed interface LoadingState {
    sealed interface Terminal: LoadingState
    object Started: LoadingState
    data class Percentage(val percents: Int): LoadingState
    object Failed: Terminal
    object Done: Terminal
}

fun loadBlob(url: String) = flow {
    emit(LoadingState.Started)

    val failureChancePerStep = 1 - java.lang.Math.pow(0.99, 10.0)

    repeat(10) { step ->
        if (Random.nextDouble() < failureChancePerStep)
            throw IOException("Failed to load!")
        emit(LoadingState.Percentage((step + 1) * 10))
        delay(10.milliseconds)
    }
    emit(LoadingState.Done)
}.retry(3) { e ->
    if (e is IOException) {
        // 这里预期会报错
        // 等一秒后再重试
        delay(1.seconds)
        true
    } else {
        // 遇到意料之外的异常，停止重试并重新抛出
        false
    }
}

suspend fun main() {
    loadBlob("https://example.org/").collect {
        println("Got $it")
    }
}
//sampleEnd

Flow 取消

一旦不再需要结果，例如请求已超时，就可以用取消来结束收集。

收集 Flow 的工作属于调用 collect() 的那个协程。取消这个协程，收集就会停止，上游 Flow 也会被取消。

要停止收集，在收集协程的 Job 上调用 cancel()。

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
val myFlow = flow {
    var i = 0
    try {
        while (true) {
            println("Emitting $i")
            emit(i)
            println("Emitted $i")
            ++i
            delay(10.milliseconds)
        }
    } catch (e: Throwable) {
        println("Upstream finished with $e")
        throw e
    }
}

suspend fun main() {
    coroutineScope {
        val job = launch {
            try {
                myFlow.collect {
                    println("Processing $it")
                    delay(5.milliseconds)
                }
            } catch (e: Throwable) {
                println("Collection finished with $e")
                throw e
            }
        }
        delay(100.milliseconds)

        // 取消收集这条流的协程
        job.cancel()
    }
}
//sampleEnd

收集者还可以在收集协程保持活动状态时取消上游 Flow。要实现这一点，只需从收集者抛出一个 CancellationException。

.take() 操作符利用这一行为，在收集到固定数量的值后停止收集。例如，.take(3) 仅从上游 Flow 中收集前三个值，然后取消该 Flow。

以下是一个使用简化版 .take() 操作符的示例：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
// 实现内置 take 操作符的简化版本
fun <T> Flow<T>.myTake(count: Int): Flow<T> = flow {
    require(count > 0)
    val cancellationException = CancellationException()
    var elementsRemaining = count
    try {
        this@myTake.collect {
            emit(it)
            --elementsRemaining
            if (elementsRemaining == 0) {
                // 取得指定数量的值后，停止收集上游
                throw cancellationException
            }
        }
    } catch (e: Throwable) {
        if (e === cancellationException) {
            // 处理用于停止上游收集的 CancellationException
            // myTake() 取足指定数量的值后结束这次收集
        } else {
            // 重新抛出意料之外的异常
            throw e
        }
    }
}

suspend fun main() {
    (0..1000).asFlow().myTake(3).collect {
        println("Got $it")
    }
}
//sampleEnd

在此示例中，.myTake() 函数会从上游 Flow 发出值，直到所有请求的值都被发出为止。然后它抛出一个 CancellationException 来取消上游 Flow。

使用 channelFlow() 并发地发出值

对于从单个协程中输出值的 Flow 而言，flow() 构建器函数简单且高效。若需从多个协程并发地将值输出到同一个 Flow 中，请使用 channelFlow() 构建器函数。你可以将其用于逐步报告结果的并发任务，例如从多个来源加载数据。

channelFlow() 构建器函数会创建一个冷流，该 Flow 使用通道从多个协程发送值。在构建器内部，请使用 send() 函数代替 emit() 函数来生成值。

下例实现了简化版 .merge()。它用 channelFlow() 并发收集两个 Flow，再把收到的值发出去。

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
// 实现内置 merge 操作符的简化版本
fun <T> Flow<T>.myMerge(other: Flow<T>): Flow<T> = channelFlow {
    // 此处可使用 CoroutineScope 和 SendChannel 两个接收者
    // 启动协程，收集接收者所代表的流
    launch {
        // 收集作为接收者的那条流
        this@myMerge.collect {
            send(it)
        }
    }
    launch {
        // 启动协程，收集另一条流
        other.collect {
            // 调用 SendChannel.send
            send(it)
        }
    }
}

suspend fun main() {
    val flow1 = (0..3).asFlow().onEach { delay(20.milliseconds) }
    val flow2 = (6..9).asFlow().onEach { delay(50.milliseconds) }
    flow1.myMerge(flow2).collect { println(it) }
}
//sampleEnd

channelFlow() 构建函数使用带缓冲的通道，允许生产者向收集者提前发送值，直到缓冲区已满。默认情况下，缓冲区最多可容纳 64 个值。当缓冲区已满时，生产者将暂停发送，直到缓冲区有空闲空间为止。

你可以使用 .buffer() 操作符更改缓冲区容量。例如，.buffer(12) 允许生产者向收集者提前发送最多 12 个值，而 .buffer(0) 则移除了缓冲区，因此每个值仅在收集者能够接收时才会被发送。

以下是一个示例：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
suspend fun main() {
    val oneHundredNumbers = channelFlow {
        repeat(100) {
            println("Sending $it")
            send(it)
        }
    }

    // 使用默认缓冲容量
    oneHundredNumbers.collect {
        println("Processing $it")
        delay(10.milliseconds)
    }
  
    // 移除缓冲，让发送和处理从一开始就交替进行
    oneHundredNumbers.buffer(0).collect {
        println("Processing $it")
        delay(10.milliseconds)
    }
}
//sampleEnd

在此示例中，oneHundredNumbers Flow 使用默认缓冲区容量，而 oneHundredNumbers.buffer(0) Flow 则没有缓冲区。

在默认缓冲区容量的情况下，生产者会快速发送值，直到缓冲区已满。之后，send() 会暂停，直到缓冲区有空闲空间，因此 Sending 和 Processing 消息开始交错。

在 .buffer(0) 的情况下，每次 send() 调用都会等待直到收集者能够接收该值，因此 Sending 和 Processing 从一开始就交错出现。

热流

热流是共享流，其值输出与收集者无关。即使没有活跃的收集者，它们也会持续输出值；多个收集者可以从已活跃的流中收集相同的输出，而无需启动新的执行。

热流（Hot Flow）的收集者被称为订阅者（subscriber）。

当应用程序的多个部分需要响应同一条更新流（例如传入的聊天消息、用户操作或 UI 状态变化）时，可以使用热流。

Kotlin 提供了两种热流类型：

  • SharedFlow 向多个订阅者广播值。当需要广播随时间发生的事件（例如消息或通知）时，请使用它。

  • StateFlow 是一种特殊的 SharedFlow，它始终保持最新的状态值。当需要表示随时间变化的状态（例如 UI 状态）时，请使用它。

创建一个 SharedFlow

SharedFlow 是一种热流，它会向其订阅者广播随时间推移而发出的值。

你可以使用 MutableSharedFlow() 函数创建一个 SharedFlow。

一个 MutableSharedFlow 提供了用于发布值的函数。如果直接将其暴露出来，类外的代码就可以向 Flow 中发布值。

把可变的 Flow 放在私有属性中，用 .asSharedFlow() 对外提供只读的 SharedFlow。需要向订阅者发布值时，在私有的 MutableSharedFlow 上调用 emit()。

data class Message(
    val senderId: Int,
    val time: Instant,
    val text: String,
)

class Chatroom {
    // 把 SharedFlow 保存在私有属性里
    private val _messages = MutableSharedFlow<Message>()

    // 向订阅者公开只读的 SharedFlow
    val messages: SharedFlow<Message>
        get() = _messages.asSharedFlow()

    suspend fun sendMessageToEveryone(message: Message) {
        // 向订阅者发出消息
        _messages.emit(message)
    }
}

与冷流一样，你可以使用 collect() 函数从 SharedFlow 中收集值。

你还可以配置 SharedFlow，使其立即将已发出的值重播给新订阅者。重播缓存就像一个小型历史缓冲区，存储固定数量的先前发出的值。

要设置新订阅者接收的先前发出的值数量，请在 MutableSharedFlow() 中使用 replay 参数：

// 设置新订阅者能重放的历史消息数
const val MESSAGES_TO_REMEMBER = 10

class Chatroom {
    private val _messages = MutableSharedFlow<Message>(

        // 按配置的数量向新订阅者重放最近的消息
        replay = MESSAGES_TO_REMEMBER
    )

    val messages: SharedFlow<Message>
        get() = _messages.asSharedFlow()

    suspend fun sendMessageToEveryone(message: Message) {
        // 向 messages 流的订阅者发出消息 
        _messages.emit(message)
    }
}

收集热流（Hot Flow）不会自动完成，因此当你不再需要它们时，必须取消收集协程。

热流没有关闭或取消操作。取消收集仅会阻止相应的订阅者继续收集。若要停止新的发布，请取消为该热流生成值的协程或作用域。

让我们看一个使用 SharedFlow 来模拟聊天室的示例，该聊天室会将每条新消息发送给活跃的订阅者，并将最近的消息重播给后来加入的订阅者：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.random.*
import java.io.IOException
import kotlin.time.Duration.Companion.milliseconds
import kotlin.time.*

data class Message(
    val senderId: Int,
    val time: Instant,
    val text: String,
)

// 设置新订阅者能重放的历史消息数
const val MESSAGES_TO_REMEMBER = 10

class Chatroom {
    // 把 SharedFlow 保存在私有属性里
    private val _messages = MutableSharedFlow<Message>(

        // 按配置的数量向新订阅者重放最近的消息
        replay = MESSAGES_TO_REMEMBER
    )

    // 向订阅者公开只读的 SharedFlow
    val messages: SharedFlow<Message>
        get() = _messages.asSharedFlow()


    // 向订阅者发出消息
    suspend fun sendMessageToEveryone(message: Message) {
        _messages.emit(message)
    }
}

suspend fun main() {
    val nUsers = 3
    val chatroom = Chatroom()
    withContext(Dispatchers.Default) {
        // 为每位用户启动一个读取消息的协程
        val messageReaders = List(nUsers) { userId ->
            // 在发出消息前开始收集
            launch(start = CoroutineStart.UNDISPATCHED) {
                chatroom.messages.collect { message ->
                    println("User $userId received $message")
                }
            }
        }
        // 每位用户各发一条问候
        repeat(nUsers) { userId ->
            chatroom.sendMessageToEveryone(
                Message(
                    userId,
                    Clock.System.now(),
                    "Hello from $userId!"
                )
            )
        }
        // 等待片刻，让各用户有时间聊天
        delay(100.milliseconds)
        // SharedFlow 的收集不会自行结束，因此要取消这些读取消息的协程
        messageReaders.forEach { it.cancel() }
    }

}

在此示例中，CoroutineStart.UNDISPATCHED 会立即启动每个收集协程。

这可确保每个协程都能到达 collect()，订阅 messages，并在 sendMessageToEveryone() 发出消息之前暂停。如果没有这一机制，当重放缓存过小时，收集协程可能会较晚启动，从而错过早期的消息发布。

使用显式支持字段来暴露热流

你可以使用显式支持字段来暴露一个只读的 SharedFlow，同时在类内部保留一个可变的后备字段。

显式支持字段会在 field 声明中定义实现类型。在类内部，编译器会将该属性智能转换为后备字段的类型，因此你可以直接调用 emit() 函数，而无需单独定义私有的支持属性。

显式支持字段不会生成 .asSharedFlow() 提供的只读封装器。仅当向下转换暴露的 Flow 不是问题时，才应使用此模式。

以下是一个示例：

import kotlinx.coroutines.*

import kotlin.time.ExperimentalTime

        field = MutableSharedFlow<Message>(
            replay = MESSAGES_TO_REMEMBER
        )

    suspend fun sendMessageToEveryone(message: Message) {
        // 通过 Chatroom 内部可写的支持字段发射消息

}
//sampleEnd

    }
}

创建一个 StateFlow

StateFlow 是一个热流，它存储单个状态值，并在该值被新值替换时发出更新。新订阅者在开始收集数据时立即收到当前值，随后在状态每次更新时都会收到新值。

你可以使用 StateFlow 来表示随时间变化的状态，例如加载进度、UI 状态或某个对象的状态。

要创建一个 StateFlow，请使用 MutableStateFlow() 函数并传入初始值：

// 创建 MutableStateFlow，初始值为 LoadingState.Started
val result = MutableStateFlow<LoadingState>(LoadingState.Started)

要设置当前状态，请使用 value 属性：

fun loadBlob(url: String): StateFlow<LoadingState> {
    val result = MutableStateFlow<LoadingState>(LoadingState.Started)

    DownloadManager.startLoading(
        url,
        onPercentageLoaded = { percentage ->
            // 用最新进度更新当前状态
            result.value = LoadingState.Percentage(percentage)
        },
        onCompletion = {
            // 把当前状态替换为已完成
            result.value = LoadingState.Done
        },
        onFailure = {
            // 把当前状态替换为失败
            result.value = LoadingState.Failed
        }
    )
}

设置 value 是线程安全的，且会覆盖当前状态，但根据其前一个值更新 value 并非原子操作。当新状态依赖于前一个状态时，请改用 .update()。

与 MutableSharedFlow 类似，MutableStateFlow 提供了用于发布更新的 API。若直接暴露该值，任何接收它的代码均可通过将其向下转换为 MutableStateFlow 来更新状态。

为防止这种情况，请通过 .asStateFlow() 函数将可变的 Flow 作为只读的 StateFlow 进行暴露：

fun loadBlob(url: String): StateFlow<LoadingState> {
    val result = MutableStateFlow<LoadingState>(LoadingState.Started)

    DownloadManager.startLoading(
        url,
        onPercentageLoaded = { percentage ->
            result.value = LoadingState.Percentage(percentage)
        },
        onCompletion = {
            result.value = LoadingState.Done
        },
        onFailure = {
            result.value = LoadingState.Failed
        }
    )

    // 通过只读 StateFlow 对外提供加载状态
    return result.asStateFlow()
}

以下是一个示例，它使用 StateFlow 来报告基于回调的 API 的加载进度：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.*
import kotlin.time.Duration.Companion.milliseconds
import kotlin.time.Duration.Companion.seconds
import kotlin.io.encoding.*
import java.io.IOException
import kotlin.random.Random

//sampleStart
sealed interface LoadingState {
    sealed interface Terminal: LoadingState
    object Started: LoadingState
    data class Percentage(val percents: Int): LoadingState
    object Failed: Terminal
    object Done: Terminal
}

fun loadBlob(url: String): StateFlow<LoadingState> {
    // 用初始加载状态创建可更新的 StateFlow
    val result = MutableStateFlow<LoadingState>(LoadingState.Started)
    DownloadManager.startLoading(
        url,
        onPercentageLoaded = { percentage ->
            // 用最新进度更新当前状态
            result.value = LoadingState.Percentage(percentage)
        },
        onCompletion = {
            // 把当前状态替换为已完成
            result.value = LoadingState.Done
        },
        onFailure = {
            // 把当前状态替换为失败
            result.value = LoadingState.Failed
        }
    )
    // 通过只读 StateFlow 对外提供加载状态
    return result.asStateFlow()
}

// 定义一个以回调交付下载结果的异步接口
object DownloadManager {
    // 开始异步加载该网址
    fun startLoading(
        url: String,
        onPercentageLoaded: (Int) -> Unit,
        onCompletion: () -> Unit,
        onFailure: (Throwable) -> Unit
    ) {
        // 这里使用 GlobalScope 只是为了演示，
        // 以便这个示例能独立运行
        GlobalScope.launch {
            val failureChancePerStep = 1 - java.lang.Math.pow(0.99, 10.0)

            repeat(10) { step ->
                if (Random.nextDouble() < failureChancePerStep) {
                    onFailure(IOException("Failed to load!"))
                    return@launch
                }
                onPercentageLoaded((step + 1) * 10)
                delay(10.milliseconds)
            }
            onCompletion()
        }
    }
}

suspend fun main() {
    loadBlob("https://example.com/").onEach { state ->
        when (state) {
            is LoadingState.Started -> {
                // 等待进度更新
            }
            is LoadingState.Percentage ->
                println("Loaded ${state.percents}...")
            is LoadingState.Failed ->
                println("Loading failed.")
            is LoadingState.Done ->
                println("Finished loading!")
        }
    }.takeWhile { it !is LoadingState.Terminal }.collect()
}
//sampleEnd

本示例仅使用 GlobalScope 是为了简化基于回调的 API。在你的实际应用中，请将 CoroutineScope 传递给启动该任务的函数（例如本示例中的 startLoading()），并在该作用域内启动协程，以便调用方在不再需要该任务时能够取消它。

StateFlow 是热流，收集不会自动结束。示例使用 .takeWhile()，在加载进入终止状态时结束收集。

StateFlow 仅在新值与当前值不同时才会发出更新。

避免在 StateFlow 中存储可变对象。修改对象本身并不会替换当前值，因此收集者无法收到更新。

你还可以通过根据当前状态计算新状态来更新 StateFlow。请使用 .update() 函数进行此类更新。.update() 函数会以原子方式更新值，这在多个协程更新同一个 MutableStateFlow 时非常有用。

如果你只需更新共享值，且无需观察随时间变化的状态，请使用 Kotlin Atomics API，例如 AtomicInt 或 AtomicReference。

以下示例中，点赞数存储在 StateFlow 中，每个新状态都是根据上一个状态计算得出的：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.*
import kotlin.time.Duration.Companion.milliseconds
import kotlin.time.Duration.Companion.seconds
import kotlin.io.encoding.*
import java.io.IOException
import kotlin.random.Random

//sampleStart
class Post(val id: Long) {
    // 用 StateFlow 保存当前点赞数
    private val _numberOfLikes = MutableStateFlow<Int>(
        // 设置初始点赞数
        0
    )

    // 通过只读 StateFlow 对外提供当前点赞数
    val numberOfLikes: StateFlow<Int>
        get() = _numberOfLikes.asStateFlow()


    // 增加一个赞
    fun like() {
        // 原子地增加点赞数，并发或多线程调用时也能正确累加
        _numberOfLikes.update { it + 1 }
    }
}

suspend fun drawUpdatedNumberOfLikes(likes: Int) {
    // 显示最新的点赞数
    println("${Clock.System.now()}: the number of likes is $likes")
}

suspend fun main() {
    withContext(Dispatchers.Default) {
        val post = Post(15)
        val notifyingJob = launch {
            post.numberOfLikes.collect {
                drawUpdatedNumberOfLikes(it)
            }
        }
        // 模拟用户给帖子点赞
        coroutineScope {
            repeat(10) {
                launch {
                    delay(Random.nextInt(100).milliseconds)
                    post.like()
                }
            }
        }
        // 所有模拟用户完成操作后，取消收集
        notifyingJob.cancelAndJoin()
    }
}
//sampleEnd

在此示例中，.update() 函数会原子地递增点赞数。这可防止当多个协程同时调用 like() 函数时出现更新丢失的情况。

将累积的状态存储在 StateFlow 中

有时，你可能希望订阅者接收所有先前发出的结果，而不仅仅是最新发出的值。

例如，一个聊天室可以将消息历史记录作为单一状态值保存。当新用户加入聊天室时，他们会首先收到当前的消息历史记录。随后，当有新消息到达时，他们将继续接收更新。

你可以使用 StateFlow 来建模这种行为。

具体来说，将完整的消息历史记录作为当前值存储为 StateFlow<List<Message>>，而不是使用 SharedFlow<Message> 将每条聊天消息作为单独的事件进行广播：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.*
import kotlin.time.Duration.Companion.milliseconds
import kotlin.time.Duration.Companion.seconds
import kotlin.io.encoding.*
import java.io.IOException
import kotlin.random.Random

//sampleStart
data class Message(
    val senderId: Int,
    val time: Instant,
    val text: String,
)

class Chatroom {
    // 保存完整的消息历史
    private val _messageHistory = MutableStateFlow<List<Message>>(emptyList())

    // 通过只读 StateFlow 对外提供当前聊天记录
    val messageHistory: StateFlow<List<Message>>
        get() = _messageHistory.asStateFlow()

    // 向 messageHistory 流的所有订阅者发送消息
    suspend fun sendMessageToEveryone(message: Message) {
        // 以原子操作将新消息追加到当前聊天记录
        _messageHistory.update {
            it + message
        }
    }
}

suspend fun main() {
    val nUsers = 3
    val chatroom = Chatroom()
    withContext(Dispatchers.Default) {
        // 为每位用户启动一个读取消息的协程
        val messageReaders = List(nUsers) { userId ->
            launch(start = CoroutineStart.UNDISPATCHED) {
                chatroom.messageHistory.collect { currentHistory ->
                    println("User $userId sees the history as $currentHistory")
                }
            }
        }
        // 每位用户各发一条问候
        repeat(nUsers) { userId ->
            chatroom.sendMessageToEveryone(
                Message(
                    userId,
                    Clock.System.now(),
                    "Hello from $userId!"
                )
            )
        }
        // 等待片刻，让用户有时间收到更新
        delay(100.milliseconds)
        // StateFlow 的收集不会自行结束，因此要取消这些读取消息的协程
        messageReaders.forEach { it.cancel() }
    }
}
//sampleEnd

在此示例中，messageHistory 将先前消息的完整列表存储为当前状态。当发送新消息时，.update() 函数会根据先前历史记录创建一个新列表，并以原子方式将新消息添加进去。

随着集合规模的扩大，通过创建新集合来更新不可变集合可能会耗费更多时间。你可以使用实验性功能 kotlinx.collections.immutable 库创建持久化集合，以提高不可变集合更新的效率。

由于 messageHistory 是一个 StateFlow，订阅者在开始收集时会收到当前的消息历史记录。此后，每当发送一条消息时，他们都会收到一个新列表，该列表会更新聊天历史记录。

将冷流转换为热流

冷流会为每位收集者单独执行上游操作。若多个订阅者需要同一次上游执行产生的数据，可以把冷流转换成热流，让订阅者共享这一轮收集的结果。

下面的简化版 .shareIn() 演示了做法：启动一次对冷流的收集，把收到的每个值发给 MutableSharedFlow，再以只读的 SharedFlow 对外提供它。

import kotlinx.coroutines.flow.*
import kotlinx.coroutines.*

fun <T> Flow<T>.simpleShareIn(scope: CoroutineScope): SharedFlow<T> {
    val sharedFlow = MutableSharedFlow<T>()
    scope.launch {
        this@simpleShareIn.collect {
            sharedFlow.emit(it)
        }
    }
    return sharedFlow.asSharedFlow()
}

suspend fun main() { 
    
}

simpleShareIn() 在给定作用域中启动一个收集协程。取消运行这个协程的作用域，就会停止收集上游流。

上游流如果抛出异常，收集协程就会失败。在共享流之前，先用 .catch() 或 .retry() 等操作符处理上游异常。

内置的 .shareIn() 封装了这种做法，无须自己创建 MutableSharedFlow。它还允许指定何时开始或停止收集上游，以及给新订阅者重放多少个历史值。

要使用内置的 .shareIn() 函数，请提供以下参数：

  • 用于收集上游流的协程作用域。

  • 控制上游何时开始和停止收集的 SharingStarted 策略。例如，SharingStarted.Eagerly 会立即在给定作用域中开始收集，即使还没有订阅者。

  • 可选的 replay 参数，决定给新订阅者重放多少个已经发出的值。

.shareIn() 在指定作用域中收集上游 Flow，把上游发出的值广播给订阅者。

以下是一个示例，其中 .shareIn() 将一个冷流转换为热流，该热流会与多个订阅者共享序列化的聊天消息：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.*
import kotlin.time.Duration.Companion.milliseconds
import kotlin.time.Duration.Companion.seconds
import kotlin.io.encoding.*
import java.io.IOException
import kotlin.random.Random

//sampleStart
data class Message(
    val senderId: Int,
    val time: Instant,
    val text: String,
)

class Chatroom {
    // 保存消息流
    private val _messages = MutableSharedFlow<Message>()

    // 通过只读 SharedFlow 对外提供消息
    // 新订阅者不会收到订阅之前发出的消息
    val messages: SharedFlow<Message>
        get() = _messages.asSharedFlow()
  
    // 向 messages 流的所有订阅者发送消息
    suspend fun sendMessageToEveryone(message: Message) {
        _messages.emit(message)
    }
}

suspend fun main() {
    val nUsers = 3
    val chatroom = Chatroom()
    withContext(Dispatchers.Default) {
        // 在当前协程下建立子作用域
        val derivedFlowsScope = CoroutineScope(
            currentCoroutineContext() + Job(currentCoroutineContext()[Job])
        )
        // 让订阅者共享序列化后的消息
        val serializedMessages: SharedFlow<String> =
            chatroom
                .messages
                .map {
                    // 为共享流序列化消息，每条只处理一次
                    "senderId: ${it.senderId}, time: ${it.time}, text: " +
                        Base64.Default.encode(it.text.encodeToByteArray())
                }
                .shareIn(
                    // 在这个作用域中启动共享协程
                    // 上游流及其中的 map() 都在该协程中运行
                    derivedFlowsScope,

                    // 立即开始收集上游，
                    // 第一位订阅者出现之前就开始工作
                    SharingStarted.Eagerly,

                    // 新订阅者不会收到先前已序列化的消息
                    replay = 0,
                )

        // 为每位用户启动一个读取消息的协程
        val messageReaders = List(nUsers) { userId ->
            launch(start = CoroutineStart.UNDISPATCHED) {
                serializedMessages.collect { serializedMessage ->
                    println("User $userId observes the message $serializedMessage")
                }
            }
        }
        // 每位用户各发一条问候
        repeat(nUsers) { userId ->
            chatroom.sendMessageToEveryone(
                Message(
                    userId,
                    Clock.System.now(),
                    "Hello from $userId!"
                )
            )
        }
        // 等待片刻，让用户有时间收到更新
        delay(100.milliseconds)
        // SharedFlow 的收集不会自行结束，因此要取消这些读取消息的协程
        messageReaders.forEach { it.cancel() }
        // 取消运行派生热流的作用域
        derivedFlowsScope.cancel()
    }
}
//sampleEnd

示例中的 .map() 返回一个冷流，会逐条序列化消息。如果直接由多个收集者收集，每个收集者都会再做一遍序列化。.shareIn() 让大家共用一次上游收集，每条消息只需序列化一次，所有订阅者都可以收到结果。

SharingStarted.Eagerly 会立即开始收集上游。因此，调用 .shareIn() 时，派生的热流便开始收集 chatroom.messages。

同样地，要将一个冷流转换为 StateFlow，请使用 .stateIn() 函数。

与 .shareIn() 不同，.stateIn() 需要一个初始值，因为 StateFlow 必须始终具有当前值。

例如：

val lastUpdateFlow: StateFlow<Instant?> =
    chatroom
        .messageHistory
        .map { currentHistory -> currentHistory.lastOrNull()?.time }
        .stateIn(
            // 在这个作用域中启动共享协程
            // 上游流及其中的 map() 都在该协程中运行
            derivedFlowsScope,

            // 第一位订阅者出现时开始收集
            // 最后一位订阅者离开时停止
            SharingStarted.WhileSubscribed(),
            // 设置上游第一次发射之前的初始状态
            null,
        )

取消热流

当订阅者被取消时，热流不会停止。

当你取消收集热流的协程时，仅会取消该订阅者。热流仍可向其他订阅者发出值，且生成这些值的协程仍可继续运行。

热流本身没有取消操作。要取消一个热流，请取消为其生成值的协程或作用域。

使用 .shareIn() 或 .stateIn() 扩展函数创建的热流会继续收集上游流，直到共享协程被取消为止。若要停止从上游流收集数据，请取消运行该共享协程的作用域。

也可以使用 SharingStarted.WhileSubscribed()。当没有订阅者时，它会自动停止收集上游。

以下是一个示例，其中取消传递给 .stateIn() 的作用域会阻止派生热流收集新值：

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.*
import kotlin.time.Duration.Companion.milliseconds
import kotlin.time.Duration.Companion.seconds
import kotlin.io.encoding.*
import java.io.IOException
import kotlin.random.Random

data class Message(
    val senderId: Int,
    val time: Instant,
    val text: String,
)

class Chatroom {
    // 保存消息历史
    private val _messageHistory = MutableStateFlow<List<Message>>(emptyList())

    // 通过只读 StateFlow 对外提供当前聊天记录
    val messageHistory: StateFlow<List<Message>>
        get() = _messageHistory.asStateFlow()

    // 向 messageHistory 流的所有订阅者发送消息
    suspend fun sendMessageToEveryone(message: Message) {
        _messageHistory.update {
            it + message
        }
    }
}

//sampleStart
suspend fun main() {
    val chatroom = Chatroom()
    withContext(Dispatchers.Default) {
        // 在当前协程下建立子作用域
        val derivedFlowsScope = CoroutineScope(
            currentCoroutineContext() + Job(currentCoroutineContext()[Job])
        )
        val totalMessages = chatroom.messageHistory
            .map { currentHistory ->
                currentHistory.size
            }.onEach {
                println("There are currently $it messages")
            }.stateIn(
                // 在这个作用域中启动共享协程
                derivedFlowsScope
            )
        // 更新 messageHistory
        chatroom.sendMessageToEveryone(
            Message(0, Clock.System.now(), "We are shutting down soon!")
        )
        delay(100.milliseconds)
        // 取消运行派生热流的作用域
        derivedFlowsScope.cancel()
        // 更新 messageHistory，但 totalMessages 已收不到此次更新
        chatroom.sendMessageToEveryone(
            Message(0, Clock.System.now(), "We have shut down.")
        )
        println("Last collected history size: ${totalMessages.value}")
        println("Actual history size: ${chatroom.messageHistory.value.size}")
    }
}
//sampleEnd

在此示例中，当调用 derivedFlowsScope.cancel() 函数时，totalMessages 会停止从 messageHistory 收集更新。

sendMessageToEveryone() 函数仍会更新 messageHistory，因为调用它的协程并未被取消。因此，totalMessages.value 保留了上次收集的大小，而 chatroom.messageHistory.value.size 则显示了实际的消息数量。

在热流中处理异常

在冷流中，上游异常会传播到 collect() 的调用者，除非你先使用 .catch() 之类的操作符来处理它们。

热流不会将异常从生产者传播到订阅者。如果向 MutableSharedFlow 发出数据或更新 MutableStateFlow 的代码抛出异常，请在运行该代码的协程中进行处理。如果订阅者在收集过程中抛出异常，请在收集协程中进行处理。

使用 .shareIn() 或 .stateIn() 扩展函数创建的热流会在共享协程中从上游 Flow 收集数据。如果上游 Flow 抛出异常，该异常将取消共享协程：

import kotlinx.coroutines.flow.*
import kotlinx.coroutines.*

//sampleStart
suspend fun main() {
    withContext(Dispatchers.Default) {
        launch {
            flow<Int> {
                error("An upstream failure")
            }.stateIn(
                this@launch
            )
        }
    }
}
//sampleEnd

如果希望上游失败后重新开始收集，把 .retry() 放在 .shareIn() 或 .stateIn() 之前。

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*
import kotlin.time.Duration.Companion.milliseconds

//sampleStart
suspend fun main() {
    coroutineScope {
        launch {
            var currentAttempt = 0

            val stateFlow = flow {
                delay(10.milliseconds)

                if (currentAttempt++ < 5) {
                    println("An error happened!")
                    error("An upstream failure")
                } else {
                    println("Success.")
                    emit(10)
                }
            }
                // 出现可恢复的故障后，重新收集上游
                .retry(retries = 5)
                .stateIn(
                    // 在这个作用域中启动共享协程
                    this@launch
                )

            stateFlow.collect {
                println("Observed $it")

                // 取消收集，同时取消共享上游的协程
                this@launch.cancel()
            }
        }
    }
}
//sampleEnd

在此示例中，Flow 在发出值之前失败了五次。由于 .retry() 在 .stateIn() 之前运行，因此会在失败传播到共享协程之前处理每次上游失败。

上游 Flow 发出 10 后，收集协程接收该值并取消自身。由于该协程同时也是共享协程的父协程，因此这将停止派生的热流。
