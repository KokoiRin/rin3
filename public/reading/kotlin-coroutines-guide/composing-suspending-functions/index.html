本节介绍组合挂起函数的几种方法。

默认顺序执行

设想有两个挂起函数，各自请求远程服务或做一项计算。为了能直接运行示例，这里用两次各一秒的 delay 来模拟它们的耗时。

编者注

下面两个函数分别返回 13 和 29。对比几种写法时，和始终是 42；真正变化的是两段一秒钟的等待有没有重叠。

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // 模拟一项实际工作
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // 这里也模拟一项实际工作
    return 29
}

要把两项结果加起来，先调用 doSomethingUsefulOne，再调用 doSomethingUsefulTwo，该怎么写？有时这个顺序是必须的，例如要根据第一个结果决定要不要调用第二个函数，或决定传什么参数。

用普通的顺序调用即可。与一般代码相同，协程内的代码默认顺序执行。下面通过测量两个挂起函数的总执行时间来说明。

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        val one = doSomethingUsefulOne()
        val two = doSomethingUsefulTwo()
        println("The answer is ${one + two}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // 模拟一项实际工作
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // 这里也模拟一项实际工作
    return 29
}

查看完整代码。

一次运行可能得到下面的输出。

The answer is 42
Completed in 2017 ms

使用 async 并发执行

如果两项工作互不依赖，就可以用 async 让它们并发执行。第一个函数在等待时，第二个函数已经可以开始，这样就有机会更快拿到总和。

launch 和 async 都会启动一个新的轻量协程。launch 返回 Job，用来管理任务；async 返回 Deferred，代表将来可以取得的计算结果。对 Deferred 调用 await() 就能得到结果。Deferred 本身也是 Job，因此也支持取消。

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        val one = async { doSomethingUsefulOne() }
        val two = async { doSomethingUsefulTwo() }
        println("The answer is ${one.await() + two.await()}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // 模拟一项实际工作
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // 这里也模拟一项实际工作
    return 29
}

查看完整代码。

一次运行可能得到下面的输出。

The answer is 42
Completed in 1017 ms

两个协程并发执行，总耗时约为顺序版本的一半。协程的并发需要显式表达。

惰性启动 async

将 start 参数设为 CoroutineStart.LAZY，可以让 async 惰性启动。此时只有调用 await 请求结果，或调用其 Job 的 start 函数，才会启动协程。运行下面的例子。

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        val one = async(start = CoroutineStart.LAZY) { doSomethingUsefulOne() }
        val two = async(start = CoroutineStart.LAZY) { doSomethingUsefulTwo() }
        // 执行一些计算
        one.start() // 启动第一个任务
        two.start() // 启动第二个任务
        println("The answer is ${one.await() + two.await()}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // 模拟一项实际工作
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // 这里也模拟一项实际工作
    return 29
}

查看完整代码。

一次运行可能得到下面的输出。

The answer is 42
Completed in 1017 ms

这次创建 one 和 two 时，它们都还没开始。先对两者分别调用 start()，让两项计算都开始，再用 await() 依次取回结果。

如果删掉两次 start()，第一个 await() 就要同时负责启动 one 和等它结束。代码走到第二个 await() 时，two 才开始，两次等待又串了起来。惰性 async 适合在确实需要某个值时再计算它，尤其是计算过程需要调用挂起函数时，可以这样替代标准库的 lazy。

异步风格的函数

其他编程语言中常见以下 async 风格。这里只为说明这种写法，原文强烈不建议在 Kotlin 协程中采用它，原因如下。

可以用 GlobalScope 上的 async 构建器异步调用 doSomethingUsefulOne 和 doSomethingUsefulTwo。这样做脱离了结构化并发。函数名加上 Async 后缀，表示它们只启动计算，调用者还需从返回的 Deferred 取得结果。

GlobalScope 是需要谨慎使用的 API，可能带来不易发现的问题，下文举出其中一种。使用前须显式声明 @OptIn(DelicateCoroutinesApi::class)。

// somethingUsefulOneAsync 的结果类型为 Deferred<Int>
@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulOneAsync() = GlobalScope.async {
    doSomethingUsefulOne()
}

// somethingUsefulTwoAsync 的结果类型为 Deferred<Int>
@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulTwoAsync() = GlobalScope.async {
    doSomethingUsefulTwo()
}

这些 xxxAsync 函数没有 suspend 修饰符，可以在任何地方调用；它们启动的工作总会与调用方的代码并发执行。

下面从协程外部调用这些函数。

import kotlinx.coroutines.*
import kotlin.system.*

//sampleStart
// 注意，本例的 main 声明没有在右侧接 runBlocking
fun main() {
    val time = measureTimeMillis {
        // 可以在协程外发起异步操作
        val one = somethingUsefulOneAsync()
        val two = somethingUsefulTwoAsync()
        // 等待结果则需要挂起或阻塞
        // 用 runBlocking 阻塞主线程，等到结果返回
        runBlocking {
            println("The answer is ${one.await() + two.await()}")
        }
    }
    println("Completed in $time ms")
}
//sampleEnd

@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulOneAsync() = GlobalScope.async {
    doSomethingUsefulOne()
}

@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulTwoAsync() = GlobalScope.async {
    doSomethingUsefulTwo()
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // 模拟一项实际工作
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // 这里也模拟一项实际工作
    return 29
}

查看完整代码。

假设从 val one = somethingUsefulOneAsync() 到 one.await() 之间发生逻辑错误，程序抛出异常，这次操作中止。全局错误处理器可能会捕获、记录并报告异常，应用继续处理其他事务。但启动 somethingUsefulOneAsync 的操作已经结束，它却还在后台工作。下面的结构化并发写法能避免这个问题。

使用 async 实现结构化并发

将并发示例封装成函数，并发运行 doSomethingUsefulOne 与 doSomethingUsefulTwo，返回它们的结果之和。async 是 CoroutineScope 的扩展函数，用 coroutineScope 提供所需作用域。 [1]

suspend fun concurrentSum(): Int = coroutineScope {
    val one = async { doSomethingUsefulOne() }
    val two = async { doSomethingUsefulTwo() }
    one.await() + two.await()
}

如果 concurrentSum 内部发生错误并抛出异常，作用域中启动的所有协程都会被取消。

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        println("The answer is ${concurrentSum()}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun concurrentSum(): Int = coroutineScope {
    val one = async { doSomethingUsefulOne() }
    val two = async { doSomethingUsefulTwo() }
    one.await() + two.await()
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // 模拟一项实际工作
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // 这里也模拟一项实际工作
    return 29
}

查看完整代码。

从上述 main 函数的输出可以看到，两项操作仍是并发执行的。

The answer is 42
Completed in 1017 ms

取消会沿着协程的层级关系传播。

import kotlinx.coroutines.*

fun main() = runBlocking<Unit> {
    try {
        failedConcurrentSum()
    } catch(e: ArithmeticException) {
        println("Computation failed with ArithmeticException")
    }
}

suspend fun failedConcurrentSum(): Int = coroutineScope {
    val one = async<Int> { 
        try {
            delay(Long.MAX_VALUE) // 模拟耗时很长的计算
            42
        } finally {
            println("First child was cancelled")
        }
    }
    val two = async<Int> { 
        println("Second child throws an exception")
        throw ArithmeticException()
    }
    one.await() + two.await()
}

查看完整代码。

子任务 two 失败时，第一个 async 和正在等待的父协程都会被取消。

Second child throws an exception
First child was cancelled
Computation failed with ArithmeticException

编者自测

在惰性 async 的例子里，为什么删掉两次 start()，总耗时就可能从约一秒变成约两秒？

查看答案

两个任务都要等到有人启动。第一个 await() 会启动 one 并等它完成，等代码走到第二个 await() 才启动 two。分别先 start()，两个任务的等待时间才有机会重叠。
