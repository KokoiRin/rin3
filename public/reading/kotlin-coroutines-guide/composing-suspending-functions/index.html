组合挂起函数

两个各需一秒的查询，什么时候总共等两秒，什么时候只等一秒？沿启动、等待与失败三个时刻读代码。

两个挂起函数写在一起时，怎样决定先后，又怎样让它们同时工作？下面用同一对函数比较几种写法。

默认按顺序执行

假设两个函数分别调用远程服务或做一段计算。为了专心观察时间，例子让每个函数等待一秒，再返回一个数。

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // pretend we are doing something useful here
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // pretend we are doing something useful here, too
    return 29
}

先调用 doSomethingUsefulOne，再调用 doSomethingUsefulTwo，最后相加。实际项目里，如果第一步的结果决定第二步要不要做，或者决定它的参数，这个顺序就有意义。

像写普通函数一样逐行调用即可。协程每次挂起后，仍会从原处继续。测量整段耗时，就能看到两个等待依次发生。

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        val one = doSomethingUsefulOne()
        val two = doSomethingUsefulTwo()
        println("The answer is ${one + two}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // pretend we are doing something useful here
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // pretend we are doing something useful here, too
    return 29
}

查看完整示例。

一次运行的输出如下。

The answer is 42
Completed in 2017 ms

用 async 并发执行

如果两个调用互不依赖，可以让它们同时等待，缩短拿到总和的时间。这里用 async 启动工作。

async 和 launch 都会启动独立执行的协程。launch 返回 Job，可以管理任务的生命周期。async 返回 Deferred，表示稍后会产生一个结果；调用 await() 即可取得它。Deferred 也实现了 Job，因此也可以取消。

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        val one = async { doSomethingUsefulOne() }
        val two = async { doSomethingUsefulTwo() }
        println("The answer is ${one.await() + two.await()}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // pretend we are doing something useful here
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // pretend we are doing something useful here, too
    return 29
}

查看完整示例。

一次运行的输出如下。

The answer is 42
Completed in 1017 ms

两段各一秒的等待重叠后，总耗时约为原来的一半。这里的并发来自显式启动的两个子协程。

需要时再启动 async

将 start 参数设为 CoroutineStart.LAZY，创建 Deferred 时先不执行。第一次调用 await 或主动调用 start，才会启动协程。运行下面的例子观察时机。 async

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        val one = async(start = CoroutineStart.LAZY) { doSomethingUsefulOne() }
        val two = async(start = CoroutineStart.LAZY) { doSomethingUsefulTwo() }
        // some computation
        one.start() // start the first one
        two.start() // start the second one
        println("The answer is ${one.await() + two.await()}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // pretend we are doing something useful here
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // pretend we are doing something useful here, too
    return 29
}

查看完整示例。

一次运行的输出如下。

The answer is 42
Completed in 1017 ms

先创建两个任务，然后分别调用 start 让它们都开始工作，最后依次取得结果。写下 await 的先后顺序并不妨碍已经启动的任务同时推进。

若省略两个 start，直接在 println 里依次 await，第一次等待会连同启动一起发生，直到它结束才会启动第二个。惰性 async 更适合替代 lazy 的一种情形：值要按需计算，而计算过程需要调用挂起函数。

返回异步任务的普通函数

下面演示其他语言里常见的写法。读这个反例时，请留心谁来收拾调用方已经放弃的工作。

例子用 GlobalScope.async 在调用方的作用域之外运行两个函数。名字末尾的 Async 提醒调用者：返回的是已启动的任务，要从 Deferred 取结果。

使用 GlobalScope 必须通过 @OptIn(DelicateCoroutinesApi::class) 显式选择加入。下面可以看到它为何需要谨慎使用。

// The result type of somethingUsefulOneAsync is Deferred<Int>
@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulOneAsync() = GlobalScope.async {
    doSomethingUsefulOne()
}

// The result type of somethingUsefulTwoAsync is Deferred<Int>
@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulTwoAsync() = GlobalScope.async {
    doSomethingUsefulTwo()
}

这些 xxxAsync 是普通函数，任何地方都能调用。调用一次，就让任务和调用方的后续代码并发执行。

即使当前代码在协程外，也能这样启动任务。

import kotlinx.coroutines.*
import kotlin.system.*

//sampleStart
// note that we don't have `runBlocking` to the right of `main` in this example
fun main() {
    val time = measureTimeMillis {
        // we can initiate async actions outside of a coroutine
        val one = somethingUsefulOneAsync()
        val two = somethingUsefulTwoAsync()
        // but waiting for a result must involve either suspending or blocking.
        // here we use `runBlocking { ... }` to block the main thread while waiting for the result
        runBlocking {
            println("The answer is ${one.await() + two.await()}")
        }
    }
    println("Completed in $time ms")
}
//sampleEnd

@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulOneAsync() = GlobalScope.async {
    doSomethingUsefulOne()
}

@OptIn(DelicateCoroutinesApi::class)
fun somethingUsefulTwoAsync() = GlobalScope.async {
    doSomethingUsefulTwo()
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // pretend we are doing something useful here
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // pretend we are doing something useful here, too
    return 29
}

查看完整示例。

假设启动第一个任务后、调用 one.await() 前，业务代码抛出异常。应用可以记录错误并继续处理其他事情，原来的请求却已经作废。用 GlobalScope 启动的任务仍在后台运行，因为它的生命周期没有接在这次请求上。

让 async 遵守结构化并发

把前面的并发求和封装成 concurrentSum。async 是 CoroutineScope 的扩展函数，coroutineScope 为两个任务提供共同的作用域。 Concurrent using async

suspend fun concurrentSum(): Int = coroutineScope {
    val one = async { doSomethingUsefulOne() }
    val two = async { doSomethingUsefulTwo() }
    one.await() + two.await()
}

若 concurrentSum 内部抛出异常，作用域会取消其中已经启动的子协程。

import kotlinx.coroutines.*
import kotlin.system.*

fun main() = runBlocking<Unit> {
//sampleStart
    val time = measureTimeMillis {
        println("The answer is ${concurrentSum()}")
    }
    println("Completed in $time ms")
//sampleEnd    
}

suspend fun concurrentSum(): Int = coroutineScope {
    val one = async { doSomethingUsefulOne() }
    val two = async { doSomethingUsefulTwo() }
    one.await() + two.await()
}

suspend fun doSomethingUsefulOne(): Int {
    delay(1000L) // pretend we are doing something useful here
    return 13
}

suspend fun doSomethingUsefulTwo(): Int {
    delay(1000L) // pretend we are doing something useful here, too
    return 29
}

查看完整示例。

运行 main，从耗时仍能看出两项工作并发执行。

The answer is 42
Completed in 1017 ms

取消沿任务树传播。下面故意让第二项工作失败，观察第一项和父协程的变化。

import kotlinx.coroutines.*

fun main() = runBlocking<Unit> {
    try {
        failedConcurrentSum()
    } catch(e: ArithmeticException) {
        println("Computation failed with ArithmeticException")
    }
}

suspend fun failedConcurrentSum(): Int = coroutineScope {
    val one = async<Int> { 
        try {
            delay(Long.MAX_VALUE) // Emulates very long computation
            42
        } finally {
            println("First child was cancelled")
        }
    }
    val two = async<Int> { 
        println("Second child throws an exception")
        throw ArithmeticException()
    }
    one.await() + two.await()
}

查看完整示例。

输出里，子任务 two 的失败终止了等结果的父协程，也让第一个 async 进入清理流程。

Second child throws an exception
First child was cancelled
Computation failed with ArithmeticException

读完试一题

把两个 async 都设成 LAZY，然后依次 await，为什么可能花两秒？

展开参考答案

第一个 await 同时负责启动和等待，第二个任务要等它结束才启动。先分别 start 再等待，就有了重叠的机会。
