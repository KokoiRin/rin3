1. 开始之前

市面上多数 Android 应用都会连接互联网，执行从后端服务器获取邮件、消息或其他信息等网络操作。Gmail、YouTube 和 Google Photos 都通过互联网显示用户数据。

本 Codelab 使用开源、由社区推动的库构建数据层，从后端服务器获取数据。这会大幅简化获取过程，也帮助应用遵循 Android 最佳实践，例如在后台线程执行操作。如果网络较慢或不可用，还会显示错误消息，让用户知道连接存在问题。

前置知识

  • 创建可组合函数的基础知识。
  • 使用 Android 架构组件 ViewModel 的基础知识。
  • 用协程处理长时间任务的基础知识。
  • 在 build.gradle.kts 中添加依赖的基础知识。

你将学到什么

  • 什么是 REST Web 服务。
  • 如何使用 Retrofit 库连接互联网中的 REST Web 服务并取得响应。
  • 如何使用 Serialization（kotlinx.serialization）库把 JSON 响应解析为数据对象。

你将做什么

  • 修改起始应用，发起 Web 服务 API 请求并处理响应。
  • 使用 Retrofit 库实现应用的数据层。
  • 用 kotlinx.serialization 把 Web 服务的 JSON 响应解析成应用的数据对象列表，并连接到 UI state。
  • 利用 Retrofit 对协程的支持简化代码。

所需条件

  • 一台安装 Android Studio 的电脑。
  • Mars Photos 应用的起始代码。

5. Web 服务与 Retrofit

火星照片数据保存在 Web 服务器上。要把它们取得应用中，需要建立连接，与互联网上的服务器通信。

注意：本篇只取得记录（URL）的数量，不取得照片本身。后续 Codelab 才会获取照片并用网格显示。

当今多数 Web 服务器使用一种常见的无状态 Web 架构提供服务，称为 REST，即 REpresentational State Transfer（表述性状态转移）。采用这种架构的 Web 服务称为 RESTful 服务。

通过统一资源标识符（URI），可以按标准方式向 RESTful Web 服务发送请求。URI 用名称标识服务器上的资源，不暗示资源位置或访问方式。例如，本课应用通过以下服务器 URI 获取图片 URL；该服务器同时托管火星地产和火星照片数据：

android-kotlin-fun-mars-server.appspot.com

注意：另一款展示火星地产的示例应用也使用上述服务器，因此服务器提供两个不同端点，分别用于地产和照片。本课程使用照片端点。

URL（统一资源定位符）是 URI 的一个子集，指定资源所在位置以及取得资源的机制。

例如：

以下 URL 获取火星上可用地产的列表：

https://android-kotlin-fun-mars-server.appspot.com/realestate

以下 URL 获取火星照片列表：

https://android-kotlin-fun-mars-server.appspot.com/photos

这些 URL 指向 /realestate 或 /photos 等已标识资源，可通过超文本传输协议（http:）从网络取得。本篇使用 /photos 端点。端点是访问服务器上 Web 服务的 URL。

注意：熟悉的 Web URL 实际上是一种 URI。本课程交替使用 URL 和 URI 这两个名称。

Web 服务请求

每个 Web 服务请求包含 URI，并用 Chrome 等浏览器使用的同一 HTTP 协议传给服务器。HTTP 请求包含一个操作，告诉服务器要做什么。

常见 HTTP 操作包括：

  • GET：取得服务器数据。
  • POST：在服务器上创建新数据。
  • PUT：更新服务器上的已有数据。
  • DELETE：删除服务器上的数据。

应用向服务器发出 HTTP GET 请求，获取火星照片信息。服务器随后把包含图片 URL 的响应返回给应用。

Web 服务响应采用 XML（可扩展标记语言）或 JSON（JavaScript 对象表示法）等常见数据格式。JSON 用键值对表示结构化数据。应用通过 JSON 与 REST API 通信，后续任务会进一步介绍。

本任务建立服务器网络连接，与服务器通信并接收 JSON 响应。后端服务器已为你准备好，本篇用 Retrofit 第三方库与之通信。

外部库

外部库或第三方库如同核心 Android API 的扩展。本课程使用的库是开源、由社区开发的，通过全球庞大 Android 社区的共同贡献维护，帮助你这样的开发者构建更好的应用。

警告：社区开发维护的库可以节省大量时间，但应谨慎选择，因为应用最终要对这些库中代码的行为负责。

Retrofit 库

本篇用于访问 RESTful 火星服务的 Retrofit，是一个支持和维护良好的库的例子。可以访问它的 GitHub 页面，查看已关闭和未关闭的问题，其中部分是功能请求。如果开发者经常解决问题并响应功能请求，这个库就可能维护良好，适合应用使用。也可以参阅 Retrofit 文档了解更多。

Retrofit 与 REST 后端通信并生成相应代码，但需要你根据传入参数提供 Web 服务的 URI。后续各节会详细介绍。

添加 Retrofit 依赖

Android Gradle 允许向项目添加外部库。除了依赖，还需要包含托管该库的仓库。

  1. 打开模块级 Gradle 文件 build.gradle.kts (Module :app)。
  2. 在 dependencies 部分添加以下 Retrofit 库依赖：
// Retrofit 
implementation("com.squareup.retrofit2:retrofit:2.9.0")
// Retrofit with Scalar Converter
implementation("com.squareup.retrofit2:converter-scalars:2.9.0")

两个库协同工作：第一个是 Retrofit2 本身，第二个是 Retrofit 的标量转换器。Retrofit2 是 Retrofit 的更新版本。标量转换器让 Retrofit 把 JSON 结果作为 String 返回。JSON 是客户端与服务器之间存储、传输数据的格式，后面会进一步介绍。

  1. 点击 Sync Now，用新依赖重新构建项目。

6. 连接互联网

使用 Retrofit 与火星 Web 服务通信，把原始 JSON 响应显示为 String。占位的 Text 会显示返回的 JSON 响应字符串，或提示连接错误的消息。

Retrofit 根据 Web 服务内容创建应用的网络 API，从服务取得数据，再交给知道怎样解码数据、返回 String 等对象的独立转换器库。Retrofit 内置对 XML、JSON 等常见格式的支持，最终为你创建调用和使用服务的代码，包括在后台线程执行请求等重要细节。

本任务在 Mars Photos 项目中添加数据层，供 ViewModel 与 Web 服务通信。实现 Retrofit 服务 API 的步骤如下：

  • 创建 DataSource，即 MarsApiService 类。
  • 用基础 URL 和字符串转换器工厂创建 Retrofit 对象。
  • 创建描述 Retrofit 怎样与 Web 服务器通信的接口。
  • 创建 Retrofit 服务，通过 API 服务把实例暴露给应用其余部分。

实现上述步骤：

  1. 在 Android 项目面板中右键点击 com.example.marsphotos 包，选择 New > Package。
  2. 在弹窗建议的包名后追加 network。
  3. 在新包下创建 Kotlin 文件，命名为 MarsApiService。
  4. 打开 network/MarsApiService.kt。
  5. 添加以下常量作为 Web 服务的基础 URL。
private const val BASE_URL = 
   "https://android-kotlin-fun-mars-server.appspot.com"
  1. 在常量下方添加 Retrofit builder，用于构建并创建 Retrofit 对象。
import retrofit2.Retrofit

private val retrofit = Retrofit.Builder()

创建 Web 服务 API 时，Retrofit 需要服务的基础 URI 和一个转换器工厂。转换器告诉 Retrofit 怎样处理服务返回的数据。本例希望取得 JSON 响应并作为 String 返回。Retrofit 的 ScalarsConverter 支持字符串及其他基本类型。

  1. 对 builder 调用 addConverterFactory()，传入一个 ScalarsConverterFactory 实例。
import retrofit2.converter.scalars.ScalarsConverterFactory

private val retrofit = Retrofit.Builder()
   .addConverterFactory(ScalarsConverterFactory.create())
  1. 用 baseUrl() 方法添加 Web 服务的基础 URL。
  2. 调用 build() 创建 Retrofit 对象。
private val retrofit = Retrofit.Builder()
   .addConverterFactory(ScalarsConverterFactory.create())
   .baseUrl(BASE_URL)
   .build()
  1. 在 Retrofit builder 调用下方，定义名为 MarsApiService 的接口，用 HTTP 请求描述与 Web 服务器的通信方式。
interface MarsApiService {
}
  1. 在 MarsApiService 接口中添加 getPhotos() 函数，取得 Web 服务的响应字符串。
interface MarsApiService {    
    fun getPhotos()
}
  1. 用 @GET 标注告诉 Retrofit 这是 GET 请求，并指定该服务方法的端点。本例端点是 photos。如前一任务所述，本篇使用 /photos 端点。
import retrofit2.http.GET


interface MarsApiService {
    @GET("photos") 
    fun getPhotos()
}

调用 getPhotos() 时，Retrofit 会把端点 photos 追加到 builder 中定义的基础 URL 后，使用这个地址发起请求。

  1. 把函数返回类型设为 String。
interface MarsApiService {
    @GET("photos") 
    fun getPhotos(): String
}

对象声明

Kotlin 的对象声明用于声明单例对象。单例模式保证只创建一个实例，并提供全局唯一访问入口。对象初始化是线程安全的，在首次访问时进行。

以下示例展示对象声明与访问。对象声明在 object 关键字后总有一个名称。

示例：

// Example for Object declaration, do not copy over

object SampleDataProvider {
    fun register(provider: SampleProvider) {
        // ...
    }
​
    // ...
}

// To refer to the object, use its name directly.
SampleDataProvider.register(...)

警告：单例模式不是推荐实践。单例表示全局状态，难以预测，测试中尤其如此。对象应声明自己需要哪些依赖，而不是描述怎样创建它们。

应优先使用依赖注入而非单例模式，后续 Codelab 会介绍实现方法。

在 Retrofit 对象上调用 create() 函数会消耗较多内存、速度和性能资源。应用只需要一个 Retrofit API 服务实例，因此通过对象声明向其余部分暴露服务。

  1. 在 MarsApiService 接口声明之外，定义公开对象 MarsApi，用来初始化 Retrofit 服务。这是应用其余部分可以访问的公开单例对象。
object MarsApi {}
  1. 在 MarsApi 对象声明中添加一个名为 retrofitService、类型为 MarsApiService 的延迟初始化 Retrofit 对象属性，以确保首次使用时才初始化。暂时忽略错误，后续步骤会修复。

注意：“延迟初始化”是有意推迟对象创建，直到真正需要时才进行，以避免不必要的计算或其他资源消耗。Kotlin 对延迟实例化提供一等支持。

object MarsApi {
    val retrofitService : MarsApiService by lazy {}
}
  1. 用 retrofit.create() 方法和 MarsApiService 接口初始化 retrofitService 变量。
object MarsApi {
    val retrofitService : MarsApiService by lazy { 
       retrofit.create(MarsApiService::class.java)
    }
}

Retrofit 配置完成。每次应用调用 MarsApi.retrofitService，都会访问首次使用时创建、实现 MarsApiService 的同一个单例 Retrofit 对象。下一任务将使用它。

在 MarsViewModel 中调用 Web 服务

本步骤实现 getMarsPhotos() 方法，调用 REST 服务并处理返回的 JSON 字符串。

注意：推荐从 Repository 调用 Web 服务，以隔离数据层和应用其余部分。后续 Codelab 会为应用加入 Repository。

ViewModelScope

viewModelScope 是为应用中每个 ViewModel 定义的内置协程作用域。在其中启动的协程，会在 ViewModel 清除时自动取消。

可以用 viewModelScope 启动协程，在后台发起 Web 服务请求。因为 viewModelScope 属于 ViewModel，即使应用经历配置变化，请求也会继续。

  1. 在 MarsApiService.kt 文件中，把 getPhotos() 改成挂起函数，使其异步执行而不阻塞调用线程。这个函数将从 viewModelScope 内调用。
@GET("photos")
suspend fun getPhotos(): String
  1. 打开 ui/screens/MarsViewModel.kt，找到 getMarsPhotos() 方法，删除把状态响应设置为 "Set the Mars API Response here!" 的那一行，使 getMarsPhotos() 方法为空。
private fun getMarsPhotos() {}
  1. 在 getMarsPhotos() 内使用 viewModelScope.launch 启动协程。
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.launch


private fun getMarsPhotos() {
    viewModelScope.launch {}
}
  1. 在 viewModelScope 中，用单例对象 MarsApi 调用 retrofitService 接口的 getPhotos() 方法，把响应保存到名为 listResult 的 val 中。
import com.example.marsphotos.network.MarsApi

viewModelScope.launch {
    val listResult = MarsApi.retrofitService.getPhotos()
}
  1. 把后端刚返回的结果赋给 marsUiState。marsUiState 是一个可变状态对象，表示最近一次 Web 请求的状态。
val listResult = MarsApi.retrofitService.getPhotos()
marsUiState = listResult
  1. 运行应用。可以看到应用立即关闭，可能显示错误弹窗，也可能不显示。这是一次应用崩溃。
  2. 点击 Android Studio 的 Logcat 标签，查看日志中以“------- beginning of crash”开头的错误。
    --------- beginning of crash
22803-22865/com.example.android.marsphotos E/AndroidRuntime: FATAL EXCEPTION: OkHttp Dispatcher
    Process: com.example.android.marsphotos, PID: 22803
    java.lang.SecurityException: Permission denied (missing INTERNET permission?)
...

该错误说明应用可能缺少 INTERNET 权限。下一任务介绍怎样添加互联网权限并解决问题。

7. 添加互联网权限与异常处理

Android 权限

Android 权限用于保护用户隐私。访问联系人、通话记录等敏感用户数据，以及相机、互联网等某些系统功能时，应用必须声明或请求权限。

应用访问互联网需要 INTERNET 权限。联网会带来安全问题，所以应用默认没有互联网连接能力，必须明确声明需要联网。这个声明属于普通权限。权限类型的更多信息，请参阅 Android 权限。

本步骤通过在 AndroidManifest.xml 文件中添加 <uses-permission> 标签，声明应用所需权限。

  1. 打开 manifests/AndroidManifest.xml，在 <application> 标签前添加以下一行：
<uses-permission android:name="android.permission.INTERNET" />
  1. 重新编译并运行应用。

错误说明应用尝试连接但发生超时。这类异常在真实运行中很常见。与缺少权限不同，这种错误无法直接修复，但可以处理。下一步学习怎样处理这类异常。

异常

异常是运行时而非编译时可能发生的错误，会使应用突然终止而不通知用户，造成较差体验。异常处理是一种机制，用来避免应用突然终止，并以对用户友好的方式处理情况。

异常原因可能简单到除以零，也可能是网络连接错误。这些异常与前面 Codelab 讨论的 IllegalArgumentException 类似。

连接服务器时可能出现以下问题：

  • API 使用的 URL 或 URI 不正确。
  • 服务器不可用，应用无法连接。
  • 网络延迟问题。
  • 设备网络很差或完全没有网络。

编译时无法处理这些异常，但运行时可以用 try-catch 块处理。更多信息请参阅异常。

try-catch 块的语法示例

try {
    // some code that can cause an exception.
}
catch (e: SomeException) {
    // handle the exception to avoid abrupt termination.
}

在 try 块中加入可能抛出异常的代码，本应用中就是网络调用。在 catch 块中实现避免应用突然终止的代码。如果出现异常，catch 块会执行以从错误中恢复，而不是让应用直接终止。

  1. 在 getMarsPhotos() 的 launch 块中，用 try 块包围 MarsApi 调用以处理异常。
  2. 在 try 块之后添加 catch 块。
import java.io.IOException


viewModelScope.launch {
   try {
       val listResult = MarsApi.retrofitService.getPhotos()
       marsUiState = listResult
   } catch (e: IOException) {

   }
}

添加状态 UI

MarsViewModel 类把最近一次请求的状态 marsUiState 保存为可变状态对象，但还不能保存加载、成功、失败等不同状态。

  • Loading 表示应用正在等待数据。
  • Success 表示成功从 Web 服务取得数据。
  • Error 表示网络或连接错误。

使用密封接口表示这三种状态。sealed interface 限制可能的值，使状态管理更容易。在 Mars Photos 中，将 marsUiState Web 响应限制为加载、成功、错误三种状态（数据类对象），代码如下：

// No need to copy over
sealed interface MarsUiState {
   data class Success : MarsUiState
   data class Loading : MarsUiState
   data class Error : MarsUiState
}

上例在成功响应时取得服务器上的照片信息。为保存这些数据，在 Success 数据类中添加构造器参数。

对于 Loading 与 Error 状态，无须设置新数据或创建新对象，只需传递相应 Web 响应状态。把 data 类改为 Object，创建这些响应的对象。

  1. 打开 ui/MarsViewModel.kt，在 import 后添加 MarsUiState 密封接口，使 MarsUiState 对象可取的值成为可穷举的集合。
sealed interface MarsUiState {

    object Error : MarsUiState
    object Loading : MarsUiState

   marsUiState = MarsUiState.Error

8. 用 kotlinx.serialization 解析 JSON 响应

JSON

请求的数据通常采用 XML、JSON 等常见格式。每次调用返回结构化数据，应用需要知道结构，才能读取响应。

例如，本应用从 https://android-kotlin-fun-mars-server.appspot.com/photos 获取数据。在浏览器输入这个 URL，可以看到 JSON 格式的火星照片 ID 和图片 URL 列表。

JSON 响应示例的结构

JSON 响应结构具有以下特征：

  • 响应是用方括号表示的数组，其中包含 JSON 对象。
  • JSON 对象由花括号包围。
  • 每个 JSON 对象包含一组用逗号分隔的键值对。
  • 键值对中的键与值用冒号分隔。
  • 名称由引号包围。
  • 值可以是数字、字符串、布尔值、数组、对象（JSON 对象）或 null。

例如，img_src 是一个 URL，属于字符串。把它粘贴到浏览器，就能看到火星表面的图片。

现在应用已经取得火星 Web 服务的 JSON 响应，这是一个好的起点。不过，显示图片真正需要的是 Kotlin 对象，而不是一大段 JSON 字符串。这个转换过程称为反序列化。

序列化把应用使用的数据转换成可经网络传输的格式。与序列化相对应，反序列化读取服务器等外部来源的数据，并转换成运行时对象。二者都是多数网络数据交换应用的重要组成部分。

kotlinx.serialization 提供将 JSON 字符串转换成 Kotlin 对象的一组库。另有与 Retrofit 配合的社区第三方库 Kotlin Serialization Converter。

本任务用 kotlinx.serialization 把 Web 服务的 JSON 响应解析为表示火星照片的 Kotlin 对象，并把应用从显示原始 JSON 改为显示返回的照片数量。

添加 kotlinx.serialization 库依赖

  1. 打开 build.gradle.kts (Module :app)。
  2. 在 plugins 块中添加 kotlinx serialization 插件。
id("org.jetbrains.kotlin.plugin.serialization") version "1.8.10"

// Kotlin serialization

  1. 找到 dependencies 块中的 Retrofit 标量转换器依赖，将它改为 kotlinx-serialization-converter：

替换为以下代码

实现 MarsPhoto 数据类

Web 服务返回的 JSON 响应条目类似下面的示例，与之前看到的内容相同：

[
    {
        "id":"424906",
        "img_src":"http://mars.jpl.nasa.gov/msl-raw-images/msss/01000/mcam/1000ML0044631300305227E03_DXXX.jpg"
    },
...]

观察每个火星照片条目中的 JSON 键值对：

  • id：以字符串表示的属性 ID。由于被引号（" "）包围，它的类型是 String 而非 Integer。
  • img_src：以字符串表示的图片 URL。

kotlinx.serialization 解析 JSON 数据并转换成 Kotlin 对象。为此，它需要一个 Kotlin 数据类保存解析结果。本步骤创建 MarsPhoto 数据类。

  1. 右键点击 network 包，选择 New > Kotlin File/Class。
  2. 在对话框选择 Class，输入类名 MarsPhoto。这会在 network 包中创建名为 MarsPhoto.kt 的文件。
  3. 在类定义前添加 data 关键字，将 MarsPhoto 变为数据类。
  4. 把花括号 {} 改为圆括号 ()。这时会出现错误，因为数据类必须至少定义一个属性。
data class MarsPhoto()
  1. 在 MarsPhoto 类定义中添加以下属性。
data class MarsPhoto(
    val id: String,  val img_src: String
)
  1. 用 @Serializable 标注 MarsPhoto，使其可以序列化。
import kotlinx.serialization.Serializable

@Serializable
data class MarsPhoto(
    val id: String,  val img_src: String
)

MarsPhoto 类中的每个变量，都对应 JSON 对象中的一个键名。为匹配本例响应的类型，所有值都使用 String 对象。

kotlinx serialization 解析 JSON 时，按名称匹配键，并用相应值填充数据对象。

@SerialName 标注

JSON 键名有时会使 Kotlin 属性难以理解，或不符合推荐编码风格。例如，JSON 中的 img_src 使用下划线，而 Kotlin 属性通常使用大小写混合的驼峰命名。

若数据类的变量名与 JSON 键名不同，可使用 @SerialName 标注。下例中变量名为 imgSrc，通过 @SerialName(value = "img_src") 映射到 JSON 属性 img_src。

  1. 将 img_src 对应的那一行替换为以下内容。
import kotlinx.serialization.SerialName

@SerialName(value = "img_src") 
val imgSrc: String

10. 总结

REST Web 服务

  • Web 服务是经互联网提供的软件功能，让应用发出请求并取得数据。
  • 常见 Web 服务采用 REST 架构，称为 RESTful 服务，使用标准 Web 组件和协议构建。
  • 通过 URI，可以按标准方式向 REST Web 服务发送请求。
  • 使用 Web 服务时，应用必须建立网络连接并与服务通信，然后接收响应数据，解析成可供应用使用的格式。
  • Retrofit 是让应用向 REST Web 服务发送请求的客户端库。
  • 转换器告诉 Retrofit 怎样处理发给服务及服务返回的数据。例如，ScalarsConverter 把服务数据作为 String 或其他基本类型处理。
  • 要让应用连接互联网，应在 Android Manifest 中添加 "android.permission.INTERNET" 权限。
  • 延迟初始化把对象创建推迟到首次使用时。它先创建引用而非对象，首次访问对象时创建引用，并在之后每次使用同一引用。

JSON 解析

  • Web 服务响应经常采用 JSON，这是一种表示结构化数据的常见格式。
  • JSON 对象是键值对的集合。
  • 一组 JSON 对象构成 JSON 数组，Web 服务可以返回这样的数组。
  • 键值对的键由引号包围，值可以是数字或字符串。
  • Kotlin 的数据序列化工具位于独立组件 kotlinx.serialization 中。kotlinx.serialization 提供将 JSON 字符串转换成 Kotlin 对象的一组库。
  • 社区为 Retrofit 开发了 Kotlin Serialization Converter 库：retrofit2-kotlinx-serialization-converter。
  • kotlinx.serialization 把 JSON 响应的键匹配到数据对象中的同名属性。
  • 若要为键使用不同属性名，给该属性添加 @SerialName 标注，并指定 JSON 键 value。
