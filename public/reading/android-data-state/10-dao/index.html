使用 Room 时，通过数据访问对象（DAO）读取和修改数据库。DAO 声明抽象访问函数，Room 在编译时自动生成实现。

用 DAO 而不是查询构建器或直接查询访问数据库，可以保持职责分离这一重要架构原则。DAO 也让你在测试应用时模拟数据库访问。

DAO 的组成

DAO 可以是接口，也可以是抽象类。基础场景通常使用接口，两者都必须添加 @Dao。DAO 不定义属性，而是定义操作数据库的函数。

下例定义一个 DAO，提供在 Room 数据库中插入、删除、查询 User 对象的函数：

@Dao
interface UserDao {
    @Insert
    suspend fun insertAll(vararg users: User)

    @Delete
    suspend fun delete(user: User)

    @Query("SELECT * FROM user")
    suspend fun getAll(): List<User>
}AccessingDataSnippets.kt

定义数据库交互的 DAO 函数分为两类：

  • 便捷函数，无须 SQL 即可插入、更新、删除行。
  • 查询函数，允许编写自己的 SQL 来操作数据库。

以下各节展示如何用这两类函数定义应用需要的数据库交互。

便捷函数

Room 提供便捷标注，无须编写 SQL 即可定义插入、更新、删除函数。

如果需要更复杂的插入、更新、删除，或需要查询数据，应使用查询函数。

插入

@Insert 可以定义把参数插入相应表的函数。下例展示插入一个或多个 User 的有效 @Insert 函数：

@Dao
interface UserDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertUsers(vararg users: User)

    @Insert
    suspend fun insertBothUsers(user1: User, user2: User)

    @Insert
    suspend fun insertUsersAndFriends(user: User, friends: List<User>)
}AccessingDataSnippets.kt

@Insert 的每个参数，都必须是带 @Entity 标注的 Room 数据实体类实例，或实体实例集合。调用 @Insert 时，Room 将每个传入实例插入相应表。

@Insert 接收一个参数时，可返回 Long，表示新插入条目的 rowId。接收数组或集合时，则返回 Long 数组或集合，每个值是相应条目的 rowId。返回 rowId 的详情，请参阅 @Insert 和 SQLite rowid 表文档。

更新

@Update 定义更新特定行的函数。与 @Insert 一样，@Update 接收实体实例。下面的 @Update 示例尝试更新一个或多个 User：

@Dao
interface UserDao {
    @Update
    suspend fun updateUsers(vararg users: User)
}AccessingDataSnippets.kt

Room 用主键将参数中的实体匹配到表中的行。若没有主键相同的行，不进行修改。

@Update 可以选择返回 Int，表示成功更新的行数。

删除

@Delete 用来定义删除特定行的函数。与 @Insert 一样，@Delete 接收实体实例。下例的 @Delete 尝试删除一个或多个 User：

@Dao
interface UserDao {
    @Delete
    suspend fun deleteUsers(vararg users: User)
}AccessingDataSnippets.kt

Room 用主键将参数中的实体匹配到表中的行。若没有主键相同的行，不进行修改。

@Delete 可以选择返回 Int，表示成功删除的行数。

Upsert

@Upsert 表示“没有匹配行就插入，有相同主键就更新”。

与 @Insert、@Update 一样，@Upsert 接收实体实例。下例的 @Upsert 尝试对一个或多个 User 执行 upsert：

@Dao
interface UserDao {
    @Upsert
    suspend fun upsertUsers(vararg users: User)
}AccessingDataSnippets.kt

若 @Upsert 接收单个参数，可以返回 Long。若插入新行，返回新行的 rowId；若更新已有行，返回 -1。参数为数组或集合时，则返回 Long 数组或集合。

查询函数

@Query 允许编写 SQL 并将其暴露为 DAO 函数，用于查询数据，或执行更复杂的插入、更新、删除。

Room 在编译时验证 SQL 查询。因此，查询有问题时会出现编译错误，而不是运行时失败。

简单查询

下例用 SELECT 查询返回数据库中的全部 User 对象：

@Query("SELECT * FROM user")
suspend fun loadAllUsers(): List<User>AccessingDataSnippets.kt

以下各节展示如何针对典型场景修改此示例。

返回表的一部分列

查询通常只需返回页面需要的列。例如，页面只显示姓名，就不必读取用户全部详情。只查询需要的属性，能节省资源并简化执行。

只要结果列可以映射到返回对象，Room 就允许查询返回数据对象。例如，定义以下对象保存用户名字和姓氏：

data class NameTuple(
    @ColumnInfo(name = "first_name") val firstName: String,
    @ColumnInfo(name = "last_name") val lastName: String
)AccessingDataSnippets.kt

随后，查询函数可以返回这个对象：

@Query("SELECT first_name, last_name FROM user")
suspend fun loadFullName(): List<NameTuple>AccessingDataSnippets.kt

查询返回 first_name 和 last_name 列，因此 Room 将值映射到 NameTuple 的属性。若某个返回列无法映射到对象属性，Room 会显示警告。

上例使用自定义数据类返回部分列。为方便起见，查询恰好返回两列或三列时，Room 还支持 kotlin.Pair、kotlin.Triple。列按查询中定义的顺序映射，因此 SELECT 中列的顺序必须与 Pair、Triple 中类型的顺序一致。

向查询传入简单参数

DAO 通常通过参数筛选数据。Room 可以把函数参数绑定到 SQL 查询中的参数位置。

例如，下例返回年龄高于某个值的所有用户：

@Query("SELECT * FROM user WHERE age > :minAge")
suspend fun loadAllUsersOlderThan(minAge: Int): Array<User>AccessingDataSnippets.kt

也可以传入多个参数，或在同一查询中多次引用同一参数，如下所示：

@Query("SELECT * FROM user WHERE age BETWEEN :minAge AND :maxAge")
suspend fun loadAllUsersBetweenAges(minAge: Int, maxAge: Int): Array<User>

@Query(
    """
    SELECT * FROM user
    WHERE first_name LIKE :search OR last_name LIKE :search
    """
)
suspend fun findUserWithName(search: String): List<User>AccessingDataSnippets.kt

向查询传入参数集合

有些查询的参数数量直到运行时才确定。参数若是集合，Room 会根据集合大小在运行时自动展开。

例如，下例返回指定地区子集中所有用户的信息：

@Query("SELECT * FROM user WHERE region IN (:regions)")
suspend fun loadUsersFromRegions(regions: List<String>): List<User>AccessingDataSnippets.kt

查询多张表

有些查询需要访问多张表计算结果，可以使用 JOIN 引用多个表。

下例连接三张表，返回特定用户当前借出的书：

@Query(
    """
    SELECT * FROM book
    INNER JOIN loan ON loan.book_id = book.id
    INNER JOIN user ON user.id = loan.user_id
    WHERE user.name LIKE :userName
    """
)
suspend fun findBooksBorrowedByName(userName: String): List<Book>AccessingDataSnippets.kt

也可以定义数据对象，返回多个连接表的一部分列。详情请参阅返回表的一部分列。下例 DAO 返回用户姓名及其借书名称：

interface UserBookDao {
    @Query(
        """
        SELECT user.name AS userName, book.name AS bookName
        FROM user, book
        WHERE user.id = book.user_id
        """
    )
    fun loadUserAndBookNames(): Flow<List<UserBook>>
}

data class UserBook(val userName: String, val bookName: String)AccessingDataSnippets.kt

返回 multimap

连接操作也可以直接返回 multimap，查询多个表的列，而不必额外定义数据类。

考虑查询多张表的示例。可以直接从查询返回 User 与 Book 的映射，而不是返回把 User、Book 配对的自定义数据类实例列表：

@Query(
    """
    SELECT * FROM user
    JOIN book ON user.id = book.user_id
    """
)
suspend fun loadUserAndBookNames(): Map<User, List<Book>>AccessingDataSnippets.kt

查询返回 multimap 时，可以使用 GROUP BY，利用 SQL 的高级计算和筛选能力。例如，修改 loadUserAndBookNames，只返回借了至少三本书的用户：

@Query(
    """
    SELECT * FROM user
    JOIN book ON user.id = book.user_id
    GROUP BY user.name HAVING COUNT(book.id) >= 3
    """
)
suspend fun loadUserAndBookNamesGrouped(): Map<User, List<Book>>AccessingDataSnippets.kt

如果无需映射完整对象，还可以在返回类型的泛型参数上添加 @MapColumn，直接返回特定列之间的映射。

@Query(
    """
    SELECT user.name AS username, book.name AS bookname FROM user
    JOIN book ON user.id = book.user_id
    """
)
suspend fun loadUserAndBookNamesColumns(): Map<
    @MapColumn(columnName = "username") String,
    List<@MapColumn(columnName = "bookname") String>
    >AccessingDataSnippets.kt

特殊返回类型

Room 提供特殊返回类型，用于整合其他 API 库。

注意：Room 通过 DAO 返回类型转换器支持 RxJava、LiveData、Guava 等特殊返回类型，必须注册相应转换器类。详情请参阅编写异步 DAO 查询。

使用 Paging 库进行分页查询

Room 通过与 Paging 库整合支持分页。要使用 Paging 3 返回类型，必须在数据库或 DAO 中注册相应返回类型转换器：

  1. 在构建配置中包含 androidx.room3:room3-paging 组件。
  2. 为 @Database 或 @Dao 声明添加 @DaoReturnTypeConverters(PagingSourceDaoReturnTypeConverter::class)。

注册后，DAO 可以返回 PagingSource，供 Paging 3 使用：

@Dao
@DaoReturnTypeConverters(PagingSourceDaoReturnTypeConverter::class)
interface UserDao {
    @Query("SELECT * FROM users WHERE label LIKE :query")
    fun pagingSource(query: String): PagingSource<Int, User>
}AccessingDataSnippets.kt

PagingSource 的类型参数选择，请参阅选择键和值的类型。

直接访问数据库连接

若应用逻辑需要直接、低层访问数据库连接，可以使用 Room 连接 API。对 RoomDatabase 实例，用 useReaderConnection 获取只读连接，或用 useWriterConnection 获取写连接，再用 usePrepared 执行语句：

val result: List<Pair<Long, String>> =
    roomDatabase.useReaderConnection { connection ->
        connection.usePrepared(
            "SELECT * FROM user WHERE age > :minAge LIMIT 5"
        ) { stmt ->
            // Bind arguments if needed
            stmt.bindLong(1, minAge.toLong())
            buildList {
                // Step through the results
                while (stmt.step()) {
                    add(stmt.getLong(0) to stmt.getText(1))
                }
            }
        }
    }AccessingDataSnippets.kt

若需要直接在连接上执行低层事务，可在 useWriterConnection 块中的 Transactor 实例上使用 immediateTransaction、deferredTransaction 或 exclusiveTransaction 辅助函数：

roomDatabase.useWriterConnection { transactor ->
    transactor.immediateTransaction {
        // Perform transactional database operations using transactor
    }
}AccessingDataSnippets.kt

若只需在事务中执行高层 DAO 操作，则可对 RoomDatabase 使用 withReadTransaction 或 withWriteTransaction 辅助扩展函数：

// Perform transactional read operations (DEFERRED transaction)
val userCount = roomDatabase.withReadTransaction {
    userDao.countUsers()
}

// Perform transactional write operations (IMMEDIATE transaction)
roomDatabase.withWriteTransaction {
    userDao.insert(newUser)
    userDao.update(existingUser)
}AccessingDataSnippets.kt
重要：Room 3.0 默认不支持标准 Android Cursor、SupportSQLiteDatabase。低层操作改用 androidx.sqlite 包的 SQLiteConnection、SQLiteStatement。如果项目仍大量使用旧 SupportSQLiteDatabase API，可引入 androidx.room3:room3-sqlite-wrapper 兼容组件，再通过 RoomDatabase.getSupportWrapper 取得包装对象，以便逐步迁移。
