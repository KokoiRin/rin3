1. 开始之前

许多应用会直接在设备上保存数据。时钟保存重复闹钟，Google Maps 保存最近搜索列表，通讯录允许添加、编辑和删除联系人信息。

数据持久化就是把数据保存在设备上，是 Android 开发的重要内容。用户创建的数据不会因关闭应用而丢失；从网络下载的数据也可以保存下来，供后续使用，避免重复下载。

SQLite 是 Android SDK 为应用提供的常见持久化方式。它提供关系型数据库，让你以类似 Kotlin 类组织数据的方式表示数据。本篇介绍 SQL（结构化查询语言）基础。它虽不是实际的编程语言，但能用几行代码，以简单灵活的方式读取、修改 SQLite 数据库。

掌握 SQL 基础后，就能在本单元后续课程中，使用 Room 为应用添加持久化能力。

注意：Android 有内部、外部存储等多种数据保存方式。本单元讨论 Room 与 Preferences DataStore。更多方式请参阅数据与文件存储概览。

2. 关系型数据库的关键概念

什么是数据库？

可以先用 Google Sheets 等电子表格理解数据库：如果用过电子表格，就已经熟悉这个类比。

电子表格由不同数据表组成，也就是同一工作簿中的各张工作表。

每张表的列定义数据表示什么，行表示具有各列值的具体条目。例如，可以定义学生 ID、姓名、专业和成绩等列。

每一行包含一名学生的数据，以及每列的值。

关系型数据库的工作方式相同。

  • 表定义要表示的数据的大类，例如学生和教授。
  • 列定义每行包含哪些数据。
  • 行包含实际数据，即各列对应的值。

关系型数据库的结构，也对应你已经学过的 Kotlin 类和对象。

data class Student(
    id: Int,
    name: String,
    major: String,
    gpa: Double
)
  • 类像表一样，对应用中要表示的数据建模。
  • 属性像列一样，定义每个类实例应包含的具体数据。
  • 对象对应表中的行，保存实际数据。每个对象有各属性的值，每行也有各列对应的值。

如同工作簿可以包含多张工作表、应用可以包含多个类，数据库也可以包含多张表。能够建模表间关系的数据库称为关系型数据库。例如，一名研究生只有一位导师，而一位教授可以指导多名研究生。

关系型数据库的每张表都有用于唯一标识行的标识符，例如每行值自动递增的整数列，称为主键。

当一张表引用另一张表的主键时，这个引用称为外键。存在外键就表示表之间存在关系。

注意：与 Kotlin 类一样，数据库表名通常使用单数。因此，上例命名为 teacher、student、course，而不是复数形式 teachers、students、courses。

什么是 SQLite？

SQLite 是常用的关系型数据库，具体指一个轻量级 C 库，用结构化查询语言管理关系型数据库。这种语言简称 SQL，有时读作“sequel”。

使用关系型数据库，无须学习 C 或一种全新的编程语言。SQL 只是一种用几行代码添加、取得关系型数据库数据的方式。

注意：并非所有数据库都按表、列和行组织。NoSQL 等其他数据库的结构类似含嵌套键值对的 JSON 对象，例如 Redis、Cloud Firestore。

用 SQLite 表示数据

Kotlin 的 Int、Boolean 等数据类型你已熟悉。SQLite 也使用数据类型，表的各列必须具有特定类型。下表将常见 Kotlin 类型映射到 SQLite 对应类型。

Kotlin 数据类型

SQLite 数据类型

Int

INTEGER

String

VARCHAR 或 TEXT

Boolean

BOOLEAN

Float、Double

REAL

所有表及其列的定义，合称 schema（结构定义）。下一节通过起始数据集继续认识它。

4. 用 SELECT 语句读取数据

SQL SELECT 语句

SQL 语句有时也称为查询，用于读取或操作数据库。

SELECT 用于读取 SQLite 数据。简单的 SELECT 依次写 SELECT、列名、FROM 和表名，并以分号（;）结束。

SELECT 也可以返回多列数据，列名之间用逗号分隔。

如果希望选中所有列，使用通配符（*）代替列名。

两种情况下，这类简单 SELECT 语句都会返回表中每一行，只需指定返回哪些列。

注意：SQL 语句通常用分号（;）结尾，但 Android Studio 的 Database Inspector 等编辑器可能允许省略。本文图示在每个完整查询后保留分号。

用 SELECT 语句读取邮件数据

显示邮件列表是邮件应用的主要功能之一，可以用 SELECT 从数据库取得所需信息。

  1. 确认在 Database Inspector 中选中 email 表。

  1. 首先尝试选中 email 表每行的每列。
SELECT * FROM email;
  1. 点击文本框右下角的 Run，可以看到整个 email 表被返回。

  1. 现在尝试只选中每行的主题。
SELECT subject FROM email;
  1. 查询仍返回每一行，但仅有这一列。

  1. 也可以同时选多列，尝试选择主题和发件人。
SELECT subject, sender FROM email;
  1. 查询返回 email 表的每一行，但只包含主题和发件人列的值。

你已经执行了第一个查询。这只是起点，可以把它视为 SQL 的“hello world”。

在 SELECT 中加上不同子句，可以指定要读取哪些数据，也可以调整输出方式。下面会介绍 SELECT 常见子句及结果格式化。

5. 在 SELECT 中使用聚合函数与不同值

用聚合函数汇总列

SQL 不只可以返回行，还提供对某列进行操作或计算的函数，例如找最大值，或统计该列不同值的数量。这类函数称为聚合函数。它们可以从列中返回一个值，而不是返回整列数据。

SQL 聚合函数的例子包括：

  • COUNT()：返回满足查询条件的行数。
  • SUM()：返回选定列所有行的值之和。
  • AVG()：返回选定列所有值的平均值。
  • MIN()：返回选定列的最小值。
  • MAX()：返回选定列的最大值。

可以用聚合函数代替列名，并在括号中传入列名。

聚合函数返回单个值，而不是逐行返回该列的值。

如果只需要计算结果，不需要取得全部数据，聚合函数会更高效。例如，求一列的平均值，无须先加载到 List 再自行计算。

通过 email 表观察一些聚合函数：

  1. 应用可能需要知道邮件总数，可使用 COUNT() 与通配符（*）。
SELECT COUNT(*) FROM email;
  1. 查询返回单个值。无需 Kotlin 代码手动统计，可以完全通过 SQL 完成。

  1. 要取得最近邮件的接收时间，可以对接收时间列使用 MAX()，因为最新 Unix 时间戳数值最大。
SELECT MAX(received) FROM email;
  1. 查询返回单个结果，即接收时间列的最大值、最新时间戳。

用 DISTINCT 过滤重复结果

选择某列时，可以在列名前加 DISTINCT，去掉结果中的重复值。

例如，许多邮件应用提供地址自动补全，希望把收到邮件的所有发件人地址列出来。

  1. 执行以下查询，返回每行的 sender 列。
SELECT sender FROM email;
  1. 可以看到结果包含许多重复项，体验并不理想。

  1. 在发件人列前加 DISTINCT，再次运行。
SELECT DISTINCT sender FROM email;
  1. 结果更少，而且每个值都唯一。

也可以在聚合函数中的列名前加 DISTINCT。

假设要知道数据库中不同发件人的数量，可以对 sender 列结合 COUNT() 聚合函数与 DISTINCT 关键字统计。

  1. 执行 SELECT，把 DISTINCT sender 传给 COUNT()。
SELECT COUNT(DISTINCT sender) FROM email;
  1. 结果显示有 14 个不同发件人。

6. 用 WHERE 子句筛选查询

很多邮件应用允许按数据、搜索词、文件夹、发件人等条件筛选邮件。为实现这类功能，可以给 SELECT 查询添加 WHERE 子句。

在表名后换行添加 WHERE，后面跟一个表达式。复杂 SQL 查询通常把各子句放在独立行，便于阅读。

查询会检查每个候选行：条件为 true 就保留，为 false 就排除。

例如，邮件应用可能有垃圾邮件、废纸篓、草稿或用户自定义筛选。以下步骤使用 WHERE 实现：

  1. 执行 SELECT，从 email 表返回全部列（*），并加入 WHERE 检查 folder = 'inbox'。这里没有写错：SQL 用单个等号比较相等，字符串使用单引号而非双引号。
SELECT * FROM email
WHERE folder = 'inbox';
  1. 结果只包含用户收件箱中的邮件。

注意：特别留意 SQL 比较运算符。

与 Kotlin 不同，SQL 使用单等号（=）比较相等，而非双等号（==）。

不等运算符（!=）与 Kotlin 相同。SQL 还提供 <、<=、>、>=。

WHERE 子句中的逻辑运算符

SQL 的 WHERE 不限于一个表达式。可使用 AND，相当于 Kotlin 的与运算符（&&），只返回同时满足两个条件的结果。

也可以使用 OR，相当于 Kotlin 的或运算符（||），返回满足任一条件的行。

为提高可读性，还可以用 NOT 对表达式取反。

许多邮件应用支持组合筛选，例如只显示未读邮件。

对 email 表尝试以下更复杂的 WHERE：

  1. 在只返回收件箱邮件的基础上，再限制为未读邮件，即 read 列为 false。
SELECT * FROM email
WHERE folder = 'inbox' AND read = false;
  1. 执行后，结果只包含收件箱中的未读邮件。

  1. 返回位于 important 文件夹，或（OR）已加星标（starred = true）的邮件。因此，其他文件夹里的星标邮件也会出现在结果中。
SELECT * FROM email
WHERE folder = 'important' OR starred = true;
  1. 观察结果。

注意：SQL 条件 NOT folder = 'spam' 也可以写成 folder != 'spam'。

用 LIKE 搜索文本

WHERE 一个很实用的用途，是在某列中搜索文本：指定列名，接着写 LIKE，然后写搜索字符串。

搜索字符串以百分号（%）开头，接着是搜索词，最后再加百分号（%）。

如果搜索指定文本开头的结果，即前缀匹配，省略第一个百分号（%）。

如果搜索后缀，省略最后一个百分号（%）。

应用有很多文本搜索场景，例如搜索主题包含特定文本的邮件，或在用户输入时更新自动补全建议。

以下步骤在查询 email 表时使用文本搜索。

  1. 数据库里的莎士比亚人物喜欢谈论“fool”。执行以下查询，统计主题包含“fool”的邮件总数。
SELECT COUNT(*) FROM email
WHERE subject LIKE '%fool%';
  1. 观察结果。

  1. 执行以下查询，返回主题以 fool 结尾的所有行和全部列。
SELECT * FROM email
WHERE subject LIKE '%fool';
  1. 可以看到返回两行。

  1. 执行以下查询，返回 sender 列中以字母 h 开头的不同值。
SELECT DISTINCT sender FROM email
WHERE sender LIKE 'h%';
  1. 查询返回三个值：helena@example.com、hyppolytus@example.com、hermia@example.com。

7. 对结果分组、排序和限制数量

用 GROUP BY 分组

前面介绍了聚合函数和 WHERE 对结果的筛选、汇总。SQL 还提供分组、排序、限制数量等子句，帮助组织查询结果。

GROUP BY 可以让给定列值相同的行，在结果中相邻分组。它不改变结果，只改变返回顺序。

为 SELECT 添加 GROUP BY 时，写 GROUP BY，再写作为分组依据的列名。

常见用法是把 GROUP BY 与聚合函数结合，根据不同类别（例如某列的值）分别聚合。假设想知道 'inbox'、'spam' 等每个文件夹中的邮件数量，可同时选择 folder 列和 COUNT() 聚合函数，并在 GROUP BY 中指定 folder 列。

  1. 执行以下查询，选择文件夹列和 COUNT() 的结果，并用 GROUP BY 按 folder 的值分组。
SELECT folder, COUNT(*) FROM email
GROUP BY folder;
  1. 可以看到查询返回每个文件夹的邮件总数。

注意：如需按另一列把各组进一步分成子组，可以在 GROUP BY 中指定多个以逗号分隔的列。

用 ORDER BY 排序

用 ORDER BY 调整结果顺序：写 ORDER BY，指定列名，再指定排序方向。

默认按 a（升序）排列，可在 ORDER BY 中省略方向。若需要降序，在列名后加 DESC。

用户通常希望邮件应用先显示最新邮件，可通过以下 ORDER BY 步骤实现。

  1. 添加 ORDER BY，根据 received 对未读邮件排序。默认升序会先显示最小值、最早邮件，因此需要 DESC。
SELECT * FROM email
ORDER BY received DESC;
  1. 观察结果。

ORDER BY 可以与 WHERE 配合使用。假设用户要搜索含 fool 的旧邮件，可以按升序让最早的邮件先出现。

  1. 选择主题包含“fool”的全部邮件，并按升序排列。升序是未指定方向时的默认顺序，所以在 ORDER BY 中使用 ASC 是可选的。
SELECT * FROM email
WHERE subject LIKE '%fool%'
ORDER BY received ASC;
  1. 筛选后的结果先显示最早邮件，即 received 列值最小的邮件。

注意：同一查询同时使用时，GROUP BY 应放在 ORDER BY 前。

用 LIMIT 限制结果数量

应用往往不需要一次显示所有匹配行，可以加 LIMIT 限制数量：在 LIMIT 后写最大返回行数。有 ORDER BY 时，把 LIMIT 放在它后面。

还可以使用 OFFSET 和另一个数字，指定跳过多少行。例如，想要前十条之后的十条，而非一次返回二十条，可以使用 LIMIT 10 OFFSET 10。

应用可能只返回收件箱最前面的十封邮件，以加快加载，用户再滚动查看后续页面。以下步骤用 LIMIT 实现。

  1. 执行以下 SELECT，以降序取得收件箱邮件，只返回前十条。
SELECT * FROM email
WHERE folder = 'inbox'
ORDER BY received DESC
LIMIT 10;
  1. 可以看到只返回十条结果。

  1. 修改查询，加入值为 10 的 OFFSET，再次执行。
SELECT * FROM email
WHERE folder = 'inbox'
ORDER BY received DESC
LIMIT 10 OFFSET 10;
  1. 查询按降序返回十条结果，但跳过了最前面的十条。

8. 插入、更新和删除数据库数据

插入数据

SQL 不仅能读取数据库，也有不同语句写入数据。数据最初也需要通过某种方式进入数据库。

用 INSERT 添加新行。先写 INSERT INTO 和表名，再在新行写 VALUES，后面用括号列出以逗号分隔的值。INSERT 中这些值必须按表的列顺序排列。

假设用户收到新邮件，需要保存在应用数据库，可以用 INSERT 为 email 表添加新行。

  1. 用以下新邮件数据执行 INSERT。新邮件未读，起初位于收件箱 folder。为 id 提供 NULL，使 id 自动生成下一个可用的自增整数。
INSERT INTO email
VALUES (
    NULL, 'Lorem ipsum dolor sit amet', 'sender@example.com', 'inbox', false, false, CURRENT_TIMESTAMP
);

注意：CURRENT_TIMESTAMP 是一个特殊变量，查询运行时会替换为当前 UTC 时间，插入新行时很方便。

  1. 可以看到数据已插入，id 为 44。
SELECT * FROM email
WHERE sender = 'sender@example.com';

更新已有数据

数据插入后仍可修改。用 UPDATE 更新一列或多列的值。UPDATE 由 UPDATE、表名和 SET 组成。

SET 由 SET 及要更新的列名组成。

UPDATE 中通常用 WHERE 指定要更新哪些行，再给这些行设置相应列值。

例如，用户把邮件标记为已读时，需要用 UPDATE 更新数据库。以下步骤把刚插入的邮件标为已读。

  1. 执行以下 UPDATE，把 id 为 44 的行的 read 设为 true。
UPDATE email
SET read = true
WHERE id = 44;
  1. 针对该行执行 SELECT，验证结果。
SELECT read FROM email
WHERE id = 44;
  1. read 列现在为表示 true 的 1，而非表示 false 的 0。

删除一行

最后，可以用 SQL DELETE 删除一行或多行。DELETE 由 DELETE、FROM、表名及指定目标行的 WHERE 组成。

以下步骤用 DELETE 删除之前插入并更新的行。

  1. 执行以下 DELETE，删除 id 为 44 的行。
DELETE FROM email
WHERE id = 44;
  1. 用 SELECT 验证修改。
SELECT * FROM email
WHERE id = 44;
  1. 可以看到 id 为 44 的行已不存在。
