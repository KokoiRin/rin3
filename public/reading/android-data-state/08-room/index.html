用 Room 在本地数据库保存数据 属于 Android Jetpack。

尝试 Kotlin Multiplatform
Kotlin Multiplatform 允许与其他平台共享数据库层。了解怎样在 KMP 中配置和使用 Room 数据库。
配置 KMP 的 Room 数据库 →

应用需要处理较多结构化数据时，通常值得把它保存在本地。最常见的做法是缓存相关数据，让用户在设备无法联网时仍能浏览。

Room 在 SQLite 上增加了一层抽象，让数据库访问更方便，同时保留 SQLite 的能力。它主要提供：

  • 编译时验证 SQL 查询。
  • 便捷标注，减少重复且容易出错的样板代码。
  • 简化数据库迁移流程。

推荐使用 Room，而非直接使用 SQLite API。

配置

使用 Room 时，在模块的 build.gradle.kts 文件中添加以下依赖。Room 3.0 要求使用 KSP 处理标注。

Kotlin

dependencies {
    val room_version = "3.0.3"

    implementation("androidx.room3:room3-runtime:$room_version")
    ksp("androidx.room3:room3-compiler:$room_version")
}

Groovy

dependencies {
    def room_version = "3.0.3"

    implementation "androidx.room3:room3-runtime:$room_version"

    ksp "androidx.room3:room3-compiler:$room_version"
}

主要组件

Room 有三个主要组件：

  • 数据库类持有数据库，是应用访问底层持久化数据连接的主要入口。
  • 数据实体表示数据库中的表。
  • 数据访问对象（DAO）提供查询、更新、插入、删除数据库数据的函数。

应用先从数据库类取得 DAO，再通过 DAO 读取数据库，得到对应的实体对象。它也可以用实体更新表中的行，或创建新实体用于插入。图 1 展示三个组件之间的关系。

实现示例

本节展示只有一个数据实体和一个 DAO 的 Room 数据库实现。

数据实体

以下代码定义 User 实体，User 的每个实例都对应应用数据库 user 表中的一行。

@Entity
data class User(
    @PrimaryKey val uid: Int,
    @ColumnInfo(name = "first_name") val firstName: String,
    @ColumnInfo(name = "last_name") val lastName: String
)IndexSnippets.kt

实体的更多信息，请参阅用 Room 实体定义数据。

数据访问对象（DAO）

以下代码定义名为 UserDao 的 DAO，UserDao 提供应用其他部分操作 user 表数据所需的函数。

@Dao
interface UserDao {
    @Query("SELECT * FROM user")
    suspend fun getAll(): List<User>

    @Query("SELECT * FROM user WHERE uid IN (:userIds)")
    suspend fun loadAllByIds(userIds: IntArray): List<User>

    @Query(
        """
        SELECT * FROM user
        WHERE first_name LIKE :first AND last_name LIKE :last LIMIT 1
        """
    )
    suspend fun findByName(first: String, last: String): User

    @Insert
    suspend fun insertAll(vararg users: User)

    @Delete
    suspend fun delete(user: User)
}IndexSnippets.kt

DAO 的更多信息，请参阅用 Room DAO 访问数据。

数据库

AppDatabase 类负责持有数据库。AppDatabase 定义配置，是应用访问持久化数据的主要入口。它必须满足以下条件：

  • 使用 @Database 标注，并在 entities 数组中列出关联数据库的全部实体。
  • 是继承 RoomDatabase 的抽象类。
  • 为关联的每个 DAO 定义一个无参数、返回该 DAO 实例的抽象函数。

@Database(entities = [User::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun userDao(): UserDao
}IndexSnippets.kt

注意：如果应用只有一个进程，实例化 AppDatabase 时应采用单例模式。创建一个 RoomDatabase 的成本较高，通常无须在同一进程中使用多个实例。

多进程应用应在数据库 builder 调用中加入 enableMultiInstanceInvalidation()。这样，每个进程各有 AppDatabase 实例时，一个进程使共享数据库文件失效，该失效会自动传播到其他进程的 AppDatabase 实例。

使用

定义好实体、DAO 和数据库对象后，可以用以下代码创建数据库实例：

val db =
    Room.databaseBuilder<AppDatabase>(applicationContext, "database-name")
        .setDriver(AndroidSQLiteDriver())
        .build()IndexSnippets.kt

随后使用 AppDatabase 的抽象函数取得 DAO，再调用 DAO 的函数操作数据库：

val userDao = db.userDao()
val users: List<User> = userDao.getAll()IndexSnippets.kt
